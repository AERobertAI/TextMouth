# TextMouth

TextMouth is a native macOS application that reads books aloud with the Mac's text-to-speech voices and plays audiobooks. It is designed for people who read with VoiceOver and a braille display, and its rule is that every control has a spoken label, every value on screen has a spoken equivalent, and every action can be done from the keyboard.

This file is the guide to using, building, and testing TextMouth. ARCHITECTURE.md, in the same folder, explains how the code is organized and which part of the app owns each kind of data.

## What TextMouth reads

- Text books, spoken with any system voice:
  - EPUB files.
  - Word documents (.docx).
  - DAISY books, versions 2.02 and 3: a book's folder, its navigation or package file (ncc.html or a .opf file), or a ZIP holding the book.
  - PDF files. A page that holds only a scanned image is read with the Mac's own text recognition.
  - HTML, Markdown, and plain text files, whatever their text encoding and line endings.
  - Text you type or paste with New from Text.
  - In EPUB, HTML, Word, and Markdown books, a table is read a row at a time: each row is a paragraph of its own, with a pause after it, and the cells in a row are separate words.
- Audiobooks, played at the speed you choose:
  - Single files in MP3, M4A, M4B, WAV, AIFF, FLAC, ALAC, or AAC format, and video files in MPEG-4 (.mp4), M4V, or QuickTime (.mov) format, whose sound alone plays.
  - A ZIP of audio tracks, which becomes one book with a chapter for each track.
  - A DAISY audio book in a ZIP, which becomes one audiobook whose sections are its headings. A section plays all of its heading's narration, even where it runs on into other audio files. A DAISY audiobook imported by an earlier version keeps one stretch of audio per section until it is imported again.
- Transcripts of audiobooks, on macOS 26 and later:
  - Transcribe Audio… transcribes an audiobook with the Mac's own speech recognizer (SpeechAnalyzer), which asks no permission and sends nothing anywhere: the book's audio never leaves this Mac (see Transcribing an audiobook). The transcript becomes the book's text: the reader shows it around the sentence being narrated, following the narration as the book plays, while positions and bookmarks go on counting time. Where Am I? ends with the sentence being heard, the one the text is shown around, quoting up to 40 words of it. Edit Text opens that text in your own editor (see Editing a book's text).
  - Transcripts are in English unless you choose another language in Settings, under Playback, Transcription, or with transcriptionLocale in config.json (see Editing settings in config.json): English as this Mac's region writes it when the Mac is set to English, such as en-GB in the United Kingdom, and otherwise US English. Each language needs its speech model, which macOS downloads from Apple only when you ask for it in the Transcribe Audio sheet, and keeps for other apps too.
  - Clean Up Transcript (Experimental)… corrects, by rules you write, words the recognizer always writes another way, such as a name in a series of books, and the last cleanup can be undone (see Transcribing an audiobook). TextMouth comes with no rules of its own: measured on 38,834 words read aloud, no correction was right in every book. TRANSCRIPT-CLEANUP-RESEARCH-2026-10-04.md, in the same folder as this file, says which words the recognizer gets wrong, and what a cleanup can fix.
  - TextMouth itself still runs on macOS 14 and 15, which can't transcribe: there Transcribe Audio… only says that transcription needs macOS 26 or later.
- Podcasts and article feeds, in RSS 2.0, RSS 1.0, Atom, or JSON Feed (1.0 and 1.1), with Apple's podcast elements and Podcasting 2.0's:
  - TextMouth can subscribe to a feed by its address, by a feed:, pcast:, or itpc: link, by a web page that names its feed, or by searching Apple's podcast directory, and keeps the feed's episodes and articles in a library folder of its own, named after it (see Podcasts and article feeds). An episode downloads as an audiobook in that folder, a video episode as an audiobook that plays its sound, and an article as an HTML book, read from its web page when the feed gives only a short summary that links one.
  - Feeds refresh when TextMouth opens and every hour while it runs, unless the Feeds tab of Settings says otherwise, skipping an hour in Low Power Mode. Those refreshes, and the downloads of new episodes when they download by themselves, never use a network with data limits, such as Low Data Mode or a phone's hotspot: an episode that would download by itself on such a network says it waits for one without them, and downloads at the next refresh TextMouth makes by itself on a network without them. A finished episode or article counts among Books Finished, and its download is deleted for good a day after it finished, or as the Feeds tab of Settings says, unless a reader has it open.
  - The feeds, and a search of Apple's podcast directory, are the only things TextMouth itself reaches the network for, and its connections keep no cookies and cache nothing on disk; a feed or episode at a plain http address loads too, since many still use one. A transcription language's speech model is downloaded by macOS, and only when you ask for it (see Transcribing an audiobook).
- TextMouth packages (.tmb folders) from another TextMouth library. A package keeps its reading position, bookmarks, and per-book settings.

## Finding your way around

- Adding books:
  - File menu, Open Book… (Command-O) imports the files you choose. Opening a supported file from Finder imports it and opens it.
  - File menu, New from Text… (Shift-Command-T) makes a book from text you type or paste.
  - File menu, New Recording… (Option-Command-N), also in the Library menu, records from a microphone into a new audiobook (see Recording from a microphone).
  - Library menu, Import DAISY Folder… imports DAISY books kept as loose files, one folder per book.
  - Library menu, Add Feed… (Shift-Command-F), or the Library window's Add Feed button, subscribes to a podcast or article feed (see Podcasts and article feeds).
  - A ZIP of several books imports each of them, and TextMouth offers to create a folder for them. The progress overlay's Cancel button stops a ZIP import after the book in progress.
  - When a book's content is already in the library, TextMouth asks whether to keep both, replace the existing book, or cancel.
  - Storage settings decide what happens to the original file after an import: keep it (the default), delete it, or ask each time.
  - With Offer to transcribe after importing an audiobook on, in the Playback tab of Settings, TextMouth asks after each audiobook it imports, on a Mac that can transcribe, whether to transcribe it, after that import's other questions (see Transcribing an audiobook).
  - These questions wait their turn. They are asked one at a time, in the order they arose, in the Library window where the import started, or in another Library window if that one has closed. When there is more than one, each title gives its place, as in "Duplicate Book Found, 2 of 5". Return chooses Keep Both, Create Folder, or Transcribe, and Escape chooses Cancel, Keep, No Thanks, or Not Now; Replace Existing and deleting an original file are never on a key. A question that appears while you are working in another window, such as a reader, waits in its Library window without taking focus or speaking.
  - A book opened from Finder opens once it is in the library and its questions are answered.
  - The progress overlay's Cancel button also withdraws the questions of the imports started before it was pressed, those waiting and any still to come: a duplicate's new copy is discarded, an original file is kept, a ZIP's books stay where they are, and an offer to transcribe is dropped.
- The Library window:
  - Choose a category, Folders, All Items, Unopened, Recent, or Reading List, in the picker VoiceOver calls Library category. Unopened lists every book you have never opened, from every folder, and a book leaves it once you open it. It took the place of No Folder on October 7, 2026: the books in no folder, which No Folder listed, are at the top of the library in Folders. Where there are feeds, a Feeds section follows the folders, and in Unopened it lists every feed with an episode or article not yet played (see Podcasts and article feeds).
  - Sort by title, author, date added, last opened, file size, or your own manual order. Each folder and category remembers its own sort, except the Reading List, which always shows the order you give it (below). Until you choose a sort in Unopened, it uses the sort you chose for No Folder, unless that was manual order, and otherwise sorts by date added, newest first.
  - A book's author comes from its file. An EPUB names its author in a creator element, or, in files some converters write, only in a dcterms:creator meta element or in a contributor marked as the author; TextMouth reads them all, since October 7, 2026, preferring a creator marked as the author to one listed before it, such as an illustrator, and reading a creator that says only Unknown as naming no one. On that day, 150 of a library's 729 EPUBs named their author in a meta element alone, and every one was listed under Unknown. A book whose file names no one is listed under Unknown, and Book Info, or an EPUB's metadata editor, lets you type an author in, which is kept whatever the file says.
  - In manual order, Move Book Up and Move Book Down (Library menu, Shift-Command-Up Arrow and Shift-Command-Down Arrow), or dragging, rearrange a folder in Folders, the top of the library included, and at the Reading List they rearrange the list. All Items, Unopened, and Recent mix books from many folders, which share no one order, so nothing rearranges them there.
  - Reading List, the fifth category, lists books from any folder in an order you arrange, each book once. Add to Reading List, in a book's context menu, its actions in VoiceOver's Actions menu, and the Library menu, adds the selected books to its end, and Remove from Reading List takes them off it, leaving them in the library. For several books selected, each command counts them, as in "Add 3 Books to Reading List", and a selection holding books of both kinds offers both. VoiceOver says what changed, as in "Added to reading list: Moby-Dick", or why nothing did, as in "Moby-Dick is already in the reading list." Neither command has a key until you give it one in the Shortcuts tab of Settings, under Library. In every other category, VoiceOver says "In reading list" after the row of a book in the list. At the Reading List, Move Book Up, Move Book Down, and dragging rearrange the list, its Sort menu names its one order, Reading List Order, and an empty list says how to add a book; Remove from Library… and the Delete key still remove a book from the library there, so take a book off the list alone with Remove from Reading List. Above the list, When a book ends chooses what a book opened from the list does at its end: Play the book below, the default, Play the book above, or Stop. Skip finished books, checked unless you clear it, passes over the books Books Finished counts, in the Stats tab of Settings: a book joins them when it is played or read to its end and doesn't start again, and stays when you read it again.
  - Edit Mode selects several books at once to move or remove them.
  - The Move dialog puts the selected books in a folder chosen from its pop-up, or in one its New Folder fields make: while those fields are shown, Return presses their Create, and Cancel New Folder closes them and keeps the folder chosen; once they close, Return presses Move again. A move, a folder's rename or move, or Delete Folder's Move Contents that fails keeps its sheet open with the reason, which VoiceOver hears once, and trying again clears that reason until the new attempt answers. Book Info, in a book's context menu, edits a plain text, Markdown, or HTML book's title and author (an EPUB's or an audiobook's metadata opens in an editor of its own): Save waits for a title of more than spaces, and drops the spaces typed around the title or the author. Command-I opens Book Info for the selected book and Feed Info for a feed's row, and, for a folder, which has no Info sheet, speaks the folder's information, as Speak Info does (below). With several rows selected it acts on the first in the list's order, in Edit Mode on the first book selected, and with none it does nothing.
  - TextMouth records which of a book's details you typed yourself. When you save Book Info, or the metadata editor of an EPUB or an audiobook, each field whose value you changed is marked as edited by hand, in library.json and in the book's record: the title, the author (an audiobook's artist), an EPUB's publisher and publication date, and an audiobook's album, genre, and year. The next time you open Book Info, from the Library window or from a reader, VoiceOver says "edited by hand" after the label of each such field, as in "Book title, edited by hand"; in a reader, that includes a field you saved there a moment before. A field you leave as the editor showed it isn't marked, even where the editor showed what the book's file says, with two exceptions in the simple sheet of a plain text, Markdown, or HTML book, which compares with the book as it is when you save: it marks, and writes back, a field another window changed while the sheet was open, and a title or author from which Save trimmed spaces. A field once marked stays marked, even if you later type back what the file says. The metadata refresh after an update never replaces a field edited by hand (see library.json, under Where TextMouth keeps your library).
  - Speak Info, the I key or Library menu, Speak Info, speaks the selected row's information in TextMouth's own voice, the voice and speed set in the Voice tab of Settings, as Where Am I? speaks a position in a reader, so it works with VoiceOver off too. A book's summary gives its title, its author unless none is known, its format, its folder or "Not in a folder", its progress and time left as its row says them, and "Unopened" for a book never opened, as in "Middlemarch. By George Eliot. EPUB. In Classics. 42 percent. 2 hours, 5 minutes remaining." A folder's gives its name, "Folder", its books, in it and in every folder inside it, with how many are unopened, and its feeds, when it holds any. A feed's gives its title, "Feed", "Folder missing" when its folder is gone, its items counted as its row counts them (see Feeds in the library, under Podcasts and article feeds), and its last check. With nothing selected it says "Nothing is selected."
  - A press of Speak Info while a summary speaks only stops it. Once nothing is speaking, a press within three seconds of the press that started the last summary speaks the full summary. A brief summary usually lasts longer than three seconds, so the usual way to the full one is three quick presses: the first speaks the brief summary, the second stops it, and the third speaks the full one. Where Am I? works the same way. A book's full summary adds when it was added and last opened, its bookmarks, its file size, unless its files are in the cloud, which are never downloaded to measure them, its cloud note and whether it is kept on this Mac, and whether a reader window has it open; a folder's adds its subfolders and the time left in all its books; and a feed's adds its folder and its address. The I is a plain key, so in the search field, or any text field, it types an I. The Shortcuts tab lists Speak Info under Information, beside Where Am I?, and leaves it without a key if you had already given the I to another action.
  - A book's context menu, and its actions in VoiceOver's Actions menu (VO-Command-Space), include Show in Finder, which selects the book's package in Finder. In a library in the cloud they also offer Download Now, Remove Download, and Keep on This Mac (see Keeping your library in the cloud). An audiobook's also offer Edit Audio… (see Editing audio) and Transcribe Audio…, and a transcribed audiobook's Clean Up Transcript (Experimental)… and Delete Transcript… (see Transcribing an audiobook).
  - File menu, Export… exports the books selected in the Library window, and a book's context menu (VO-Shift-M) has Export… too, or Export 3 Books… for a selection of three (see Exporting books); with no book selected, VoiceOver says "No books are selected." With neither a Library window nor a book's window in front, as when only Settings is open, File menu, Export… says so instead: "No Library window or book is open, so there is nothing to export." or "To export, switch to a Library window or a book's window, then choose Export again." A text book's context menu, and a transcribed audiobook's, also has Edit Text in Default Editor and Edit Text With…, unless several books are selected (see Editing a book's text). These commands aren't among the row's actions in VoiceOver's Actions menu.
  - A summary line gives each location's book count and its listening time remaining at the current speed, and, in a library in the cloud, how many of its books are in the cloud and how many are kept on this Mac.
  - If a file cannot be saved (a full disk or a missing volume, for example), a banner in the Library window says what is unsaved, with Retry and Dismiss buttons. Quitting while something is unsaved asks first.
- Reader windows:
  - Each book opens in its own window, and several can be open at once.
  - In a library in the cloud, a book whose files are only in the cloud downloads in its reader window before it opens (see Keeping your library in the cloud).
  - An open book follows what the library does to it elsewhere: a new title or author, a move to another folder, or a renamed folder. Nothing reloads and speech carries on; an audiobook playing while its files move stops for a moment and plays on from the same place, and one playing from its working copy in a library in the cloud doesn't stop at all. The data directory itself can't move while any book is open.
  - The Playback menu holds Play / Pause, Skip Forward and Skip Backward, speed, Where Am I?, Copy Reading Position, Search in Book, and Release Media Controls.
  - The Navigate menu holds Go to Library, Next Heading and Previous Heading, Show Headings, Show Sleep Timer, and Book Info.
  - The Bookmarks menu holds Toggle Bookmark, Show Bookmarks, and Next Bookmark and Previous Bookmark.
  - The Book menu holds Edit Text in Default Editor and Edit Text With…, available for a text book and a transcribed audiobook, then Transcribe Audio…, available for an audiobook, and Clean Up Transcript (Experimental)… and Delete Transcript…, for a transcribed one, and last Edit Audio…, for an audiobook (see Editing audio). File menu, Export… exports the reader's book.
  - Headphone and media keys control the reader that is playing, or, when none is, the reader window used most recently. A book that ends and stops there, rather than starting again, rests finished at its end while its window stays open: Now Playing shows it paused at its end, so the AirPods and the media keys still reach TextMouth, and Previous Track or Skip Backward, from them or from the reader's own Skip Backward, moves back by the skip unit from the end and plays from there, so you can hear its last words again, with the skip's sound and then Play's. Skip Forward or Next Track by a number of seconds stays at the end and plays nothing, while a forward skip by sentence, paragraph, heading, or bookmark that finds a later place moves there without playing. That move, or any other jump, such as to a heading, ends the finished state, as Release Media Controls and closing the window do, and a relaunch doesn't keep it: the book is then an ordinary stopped book, whose skips move the cursor without playing until you press Play. Release Media Controls, in the Playback menu while the book plays, is paused, or has finished, hands the controls back to the system.
  - The sleep timer runs for a set number of minutes, a preset or typed, or stops at a place in the book: its sheet's Stop At section sets one that stops at the end of the heading, or at the end of the book, for text books and audiobooks alike. Headings are one concept for any book: where the next heading of any level begins, as Next Heading finds it, or the book ends, in a text book of any format or an audiobook, whose chapters, tracks, and chapter markers are its headings. End of heading pauses playback where the heading playing ends: within a chapter, where the next heading begins, with the cursor put back at that heading for Play to start it; at a chapter's end, when the next chapter opens with the next heading, as every audiobook chapter does, with the reader waiting at the start of that chapter, which Play starts; and at the book's end, which ends the last heading. A next chapter that has text before its first heading, or no heading at all, goes on under the same heading, so playback goes on into it. End of heading took the place of End of chapter on October 6, 2026, and Restart Sleep Timer after a timer saved as End of chapter, or as End of document, arms End of heading. VoiceOver says "Sleep timer: stops at the end of this heading." as the timer is set, reads its status the same way in the sheet and in the reader, and says "Sleep timer expired at the end of the heading. Playback paused." where it stops; stopped at the book's end, the reader says instead that the book finished and why nothing follows, as in "Finished: Moby-Dick. Next book not started because of the sleep timer." End of book pauses playback when the book ends, before the book starts again or the next book starts. An audiobook fades out toward a stop at a chapter's end over the sleep timer's Fade out time, in Playback settings, when one is set; speech is not faded, and an m4b's chapter marker inside one file stops the timer a moment past the marker, without a fade, the cursor put back at the marker. One timer serves the whole app, and it belongs to the reader window that set it: another window's playback, even of the same book, never pauses or ends it.
  - When a book ends, TextMouth stops, starts the book again, or continues to the next book in the folder, as Playback settings say. Each book can override that choice.
  - A book's text can hold what looks like markup, such as the <sm> and </sm> one novel marks its silent messages with, and the speech engine of macOS 26.3.1 takes such tags for speech markup: it skipped the rest of a passage after an opening tag, and refused a passage holding a closing tag alone, after which the book's speech stopped and couldn't be started again. Since October 7, 2026, TextMouth hands the voice each tag with its two angle brackets changed to single angle quotation marks, which the engine doesn't take for markup, so the brackets are silent and what is between them, a tag's name included, is spoken. A less-than or greater-than sign that isn't part of a tag is still read aloud, and the text on screen and on a braille display is unchanged. Where Am I?, which can quote the book, and Speak Info, which speaks titles, are spoken the same way. Should the speech engine still refuse a passage of a text book, TextMouth tries it once more with a fresh start of the voice, from the last word heard in it or from its start. Refused there again, speech stops with the cursor at that passage, and VoiceOver says "Speech stopped: the Mac's speech engine refused this text." TextMouth treats that stop as a pause: the AirPods and the media keys stay with TextMouth, and their next press is Play, which speaks from that passage; no time after the stop counts as listening; the place is saved; and a sleep timer's countdown waits until Play. Pressing Play there usually brings the same refusal and the same announcement, so move past the passage first, with a forward skip by sentence or paragraph, or with Next Heading or Show Headings, and then press Play. Should the speech engine stop a Where Am I? announcement before its end, the announcement ends without its end sound and the book stays paused, so Play/Pause plays it at once, and the next Where Am I? speaks with a fresh start of its voice.
- Exporting books:
  - The Export dialog lists what the books hold: a checkbox for each kind, labelled with its size and with its number of files when there are several, or, for several books, with how many of them hold it, as in "Original file, 1.2 MB", "Audio, 12 files, 340 MB", or "Audio, 2 books, 680 MB". The kinds are Audio, an audiobook's file or its tracks; Original file, a text book's own file; Text as Markdown, the text TextMouth reads, with a line marking each chapter; Text as plain text, each chapter's words under its title, before any substitution rules; Original recording, a recording as it was made, before any edits; Original audio (before edits), an edited audiobook's audio as it was before its first edit, which TextMouth keeps while the Original audio setting does: one file named after the book, as in "Moby-Dick - Original Audio.mp3", or, for a book of tracks, the edited tracks' originals in a folder of that name; and Transcript, its transcript.json and, for an audiobook, the transcript's text as Markdown. Kinds that none of the books hold aren't listed. VoiceOver starts on the first checkbox, and the first kind that can be exported is checked.
  - The files go to your Documents folder, or to the folder you last exported to since TextMouth opened. Choose Folder… chooses another, and its New Folder button makes one; TextMouth's own data directory is refused. One book's items go straight into the folder, except its tracks, or a DAISY book's loose files, which go into a folder named after the book: tracks are numbered in the order the book plays them and named for their chapters, as in "01 - The Harbour.mp3". Several books get a folder each. A name already in use gets a number, as in "Moby-Dick - Text 2.md", so nothing is ever replaced.
  - Return presses Export, and Escape presses Cancel, or Stop while the export runs, which ends it before the next file. A progress bar says how far it has got, as in "Exporting 3 of 40 items…". At the end VoiceOver says how it went, as in "Exported 3 items to Documents.", and the dialog closes, unless the export was stopped or left something out: then it stays open, saying what couldn't be exported and why, and Cancel becomes Close.
  - Nothing is downloaded. In a library in the cloud, a kind whose files are only in the cloud says "in the cloud" and can't be checked, and the books it leaves out are named, as in "Moby-Dick isn't downloaded. Download it first: select it in the library, then choose Download Now."
- Editing a book's text:
  - Edit Text in Default Editor, in a reader's Book menu or the context menu of a text book or a transcribed audiobook, opens the book's text in the app this Mac opens Markdown files with, or in TextEdit when there is none; Edit Text With… asks which app. The first time, TextMouth explains what happens, with Continue and Cancel; it explains once on each Mac.
  - The text is Markdown: the book's text cache, content.md. Each line beginning with <!-- chapter: starts a chapter; keep those lines. The book's own file is never changed.
  - When you save, TextMouth takes the change within a moment, or when you switch back to it. The book's chapters, headings, and word counts follow it, and an open reader shows the new text with its cursor at the same words, as near as it can find them, speaking on from there if it was speaking. VoiceOver says "Text updated" once TextMouth is in front.
  - A save that isn't UTF-8 text, that leaves no chapter with anything in it, or that the book's record can't take now, isn't taken. VoiceOver says why, and that your edited text was also kept in the book's package as content.md.edited- followed by the date and time. Nothing replaces your edit meanwhile: the book keeps the text it had, and opening it shows why in place of the book until you save text TextMouth can take, when that window opens the book with it.
  - When the book's own file has changed too, your edit isn't taken either, and is kept the same way; the book's text is read from that file again the next time the book opens.
  - While your edit session lasts, Redo Text Extraction leaves a book whose edit wasn't taken as it is, and keeps a copy of other text it replaces, saying where. Storage settings then say how many books it left, as in "Done. 1 book whose edited text can't be used yet was skipped."
  - A text book's edit saved while TextMouth was closed, or while no Edit Text session was open for the book, is found at TextMouth's next launch, or when its library next opens. It is then taken as the book's text, as Edit Text takes one but without an announcement, when it is UTF-8 text with a chapter in it and the book's own file hasn't changed. Otherwise it is kept in the book's package as content.md.edited- followed by the date and time, and the text is read from the book's own file again. Whatever else reads a book's text from its own file again, such as opening the book before TextMouth has found the edit, or Redo Text Extraction, first keeps text in content.md that TextMouth didn't write or take the same way, and leaves the book as it is when no copy can be kept. An edit TextMouth took stays the book's text after it quits, until Redo Text Extraction runs or a new version of TextMouth reads the book's format better, either of which reads the text from the book's own file again, without a copy. Bookmarks keep their chapter and position, so an edit earlier in a chapter can shift the words they point at.
  - A transcribed audiobook's text, its transcript's, is edited the same way, and an open reader shows the edited text as the book plays on. A save is taken into the transcript itself, transcript.json, so the edit stays the book's text: each sentence keeps its time in the audio, a sentence whose words you changed no longer has each word's timing, and one whose every word you deleted is gone. An edit that changes the number of chapters, which must stay one for each of the audio's, or an edit of a book whose audio changed since it was transcribed, isn't taken, and is kept beside content.md as above; meanwhile the book plays without its text. When the transcript changed too, as when the book was transcribed again on another Mac, the edit isn't taken either, and is kept the same way; the book's text is written from that transcript again the next time the book opens. An edit saved while TextMouth is closed, or outside Edit Text, is replaced the next time the book opens by the text written from the transcript, after TextMouth keeps it beside content.md. An audiobook without a transcript has no text to edit: transcribe it first.
- Transcribing an audiobook, on macOS 26 and later:
  - Transcribe Audio…, in an audiobook's context menu, its actions in VoiceOver's Actions menu, and an open audiobook's Book menu, opens the Transcribe Audio sheet for the book. Transcription works on one audiobook at a time, and chosen for several books the sheet only says so. On macOS 14 and 15 it only says that transcription needs macOS 26 or later, and on a Mac that can't run the speech model, that it can't.
  - The sheet gives the audio's length, how long transcribing should take (about a minute for each hour of audio), and the language set in Settings, with its speech model's status, as in "Language: English (United States), installed." A model not yet on this Mac is offered as a button, as in "Download the English model, about 140 MB": nothing downloads until you press it, the download shows its progress, and Cancel Download stops it. VoiceOver moves to the sheet's first control, then hears its lines. Return presses Transcribe, and Escape presses Cancel. While another book is being transcribed, the sheet names it, and Transcribe is unavailable until that finishes.
  - While the book is transcribed, the sheet shows the file it is on, how much of the audio is done, the time elapsed, and a progress bar VoiceOver reads as "40 percent, file 3 of 12". Cancel, which Escape presses, stops it and leaves the book as it was. VoiceOver hears the start, as in "Transcribing Moby-Dick, about 6 minutes.", each quarter, as in "Moby-Dick: 25 percent transcribed.", and the end, as in "Transcribed Moby-Dick: 7,077 words in 51 seconds." A transcription goes on when the window it began in closes, and Transcribe Audio… for that book shows it again. Quitting TextMouth cancels it without asking.
  - Once the transcript is saved, an open reader of the book shows its text at once. The book's row says Transcribed after its title, or Transcribing while it is being transcribed, after any cloud note, on screen and to VoiceOver alike. For a book transcribed already, the sheet says when and in which language, and Transcribe Again replaces that transcript, saying first when that replaces your edits of it.
  - Clean Up Transcript (Experimental)…, in the same places for a transcribed audiobook, opens the Clean Up sheet, which corrects words the recognizer always writes another way, by rules, and changes nothing until you press Apply. The sheet names the rules in use, as in "Rules: your copy, version 1 of October 4, 2026, 2 rules.", says what they would change, as in "23 corrections in 19 sentences.", and lists each rule that changes something, with its count and up to three examples, before and after, each read by VoiceOver as one line. It says when the transcript was last cleaned up. VoiceOver moves to Apply when the rules change something, and to Cancel otherwise, then hears the sheet's lines. Return presses Apply, and Escape presses Cancel. Coming back to TextMouth, as after editing the rules, shows what the rules would change then. While the book is being transcribed, or its transcript can't be read, the sheet only says so.
  - Apply keeps the transcript as it was beside it, as transcript.json.before-cleanup, rewrites each sentence the rules changed, keeping its time in the audio and dropping its words' timings, as an edit in your own editor does, notes the cleanup in the transcript, and writes the book's text again from it. Open readers show the cleaned text as the book plays on, and VoiceOver hears "Cleaned up the transcript of Moby-Dick: 23 corrections." Positions and bookmarks stay as they were, since they count time. Apply is refused, saying why, when the book is being transcribed, when the transcript changed after the sheet showed it, as when another Mac transcribed the book again, or when the book's audio changed after it was transcribed.
  - Undo Cleanup, in the sheet while the transcript is cleaned up, puts back the transcript from before the last cleanup, with its text, and removes the copy. Only the last cleanup can be undone: the next replaces the copy with the transcript it cleans. Undo Cleanup also undoes the edits you made since the cleanup, as the sheet says first. A cleanup and its undo each end the book's Edit Text session, as transcribing again does: to edit the new text, choose Edit Text again, since an edit saved in an editor opened before counts as one made outside Edit Text (see Editing a book's text).
  - The rules: TextMouth comes with none of its own, and the sheet then says how to add some. Edit Rules… opens your own copy, transcript-cleanup.json in the data directory, in your default text editor, making it the first time from TextMouth's own file, which explains the format and holds two worked examples, used only once you move them into its rules. A name the recognizer always spells another way in a series is the case a rule fits. For British spelling, choose English (United Kingdom) as the transcription language instead: the recognizer then writes it without any rule.
  - A rule has a pattern and a replacement; wholeWord, true unless set, which matches whole words only, keeping the punctuation around them and a possessive "'s" after them, as "Bennett's" becomes "Bennet's", where false matches inside words too; evidence, how many places it was right in, 0 for a rule of your own; and an optional note. Matching ignores case and the kind of apostrophe, the replacement takes the case of the words it replaces, and the rules apply in order. Your copy can't be used when TextMouth can't read it in that format, or when its version is below 1, its date isn't a day written as 2026-10-04, or one of its rules has an empty pattern or replacement, a pattern without a letter or figure, or a replacement holding its own pattern, which every cleanup would change again: the sheet says why, naming the field, as in "rules[2].replacement is empty", a copy of it is kept beside it, its name followed by .unreadable- and the date and time, and TextMouth's own rules stand in until you correct it. While your copy is only in the cloud, TextMouth asks the sync service for it, and its own rules stand in meanwhile. When TextMouth's own rules are newer than your copy, the sheet says so.
  - Delete Transcript…, in the same places for a transcribed audiobook, asks first, naming the book and saying when your edits go too, then deletes the transcript, the copy kept from before its last cleanup, the text made from it, and the reading text kept for the book. The audio, your place, and your bookmarks stay, and the book can be transcribed again. While the book is being transcribed, Delete Transcript… says to cancel the transcription first.
  - The Playback tab of Settings has a Transcription group. Transcription language lists the languages the recognizer supports, each marked installed or needs download. Offer to transcribe after importing an audiobook, off by default, asks after each audiobook TextMouth imports, after the import's other questions, "Transcribe the Audiobook?": Transcribe, which Return presses, opens the sheet, which starts at once when the language's model is on this Mac, and otherwise offers the model's download, after which you choose Transcribe, and Not Now, which Escape presses, leaves the book as it is.
- Settings, in tabs:
  - Voice, Playback, Shortcuts, Text (substitution rules and repeated symbols), Sounds, Stats (listening time, streak, and books finished), Feeds (podcast and article feeds), Storage, and Miscellaneous.
  - The Shortcuts tab changes the shortcuts for reading, navigation, bookmarks, the sleep timer, information (Where Am I? and Speak Info), the library's actions, and the audio editor, whose group, Audio Editor, works only in an editor window (see Editing audio). Open Book…, New from Text…, New Recording…, and Add Feed… always use Command-O, Shift-Command-T, Option-Command-N, and Shift-Command-F.
  - The Storage tab's Audio Editing group sets how long the original audio of recordings and edited audiobooks is kept, whether an installed ffmpeg runs the audio editor's filters, whether the editor previews a filter before applying it and plays half a second after each move, and, through Filter Presets…, the editor's filter presets (see Editing audio).
  - The Storage tab's Find Duplicate Books… groups the library's books by the criteria you check: Identical File (MD5), checked as the sheet opens, Same ISBN, Same Title, and Same Author. Checked criteria combine, so Same Title with Same Author groups by both, and no separate Same Title & Author is offered; a book without an author is left out while Same Author is checked, so check Same Title alone to find two copies of it. Scan for Duplicates says how many duplicate groups it found, or that it found none; each group's heading names the criteria and what its books share, as in "Same Title and Same Author" over "Moby-Dick by Herman Melville"; each row speaks the book's title, author, format, folder, and the date it was added, which tells two copies apart; and the books you check are moved to the Trash or deleted, as Removal Behavior says, after asking when it says to.
  - The Playback tab's Reader Toolbar section has Show Export in the reader toolbar, off by default, which puts an Export button in every reader's toolbar. File menu, Export… is there either way.
  - The Playback tab's Transcription group chooses the language audiobooks are transcribed in, and whether TextMouth offers to transcribe each audiobook it imports (see Transcribing an audiobook).
  - The Text tab's Repeated Symbols group sets how the voice reads one symbol written several times in a row, directly or with single spaces between, such as a separator line of asterisks. Say how many, the default, reads a run of 4 or more as a count, such as "7 asterisks"; Leave out skips the run with a pause; Repeat each symbol reads every one. "Collapse runs of at least" sets the shortest run that is counted or left out (2 to 99), and "Never collapse: read every symbol" reads every symbol whatever the style. The Symbols field lists the characters that can form runs; Reset to Default restores the standard list of ASCII symbols, bullets, dashes, the ellipsis, and box-drawing lines. Only speech changes: the text on screen and on a braille display keeps every symbol. A change applies from the next chapter spoken.
  - The Stats tab's Books Finished This Year and Books Finished All Time count text books, audiobooks, and podcast episodes apart as well as together, under each count and spoken with it as one sentence, as in "7 books finished this year: 4 text books, 2 audiobooks, and 1 podcast episode". An article from a feed counts as a text book. A book finished before TextMouth counted kinds counts by its kind while it is in the library, and among other books once it has left.

## Recording from a microphone

File menu, New Recording… (Option-Command-N), also in the Library menu, opens the New Recording window, which records from a microphone into a new audiobook in your library. One such window is open at a time, and the command brings it forward. VoiceOver starts on its Microphone pop-up, Tab reaches every control, and each control's label, value, and hint say in speech and braille what the screen shows.

- Choosing what to record:
  - Microphone lists the microphones connected to this Mac by name: its own, AirPods or other headphones, or an external one. Two of the same name are numbered, as in "USB Microphone (2)". Virtual and aggregate devices, which carry other apps' sound, aren't listed, so TextMouth can't record other apps. The list follows microphones as they connect and disconnect, even while recording, though the choice can't change while a recording is under way.
  - TextMouth remembers its own choice of microphone, which the audio editor's punch-ins use too, and leaves the input macOS uses for everything else alone. When the remembered microphone isn't connected, recordings use the system's input, and the window says so as it opens, as in "The microphone TextMouth used last isn't connected, so recordings use MacBook Pro Microphone.". While nothing is recording, the window says when the microphone in use disconnects, and which one recordings use now; when one connects that recordings now use, the remembered one coming back or the first connected at all, as in "AirPods Pro was connected, so recordings use it."; and when others connect, as in "USB Microphone was connected; choose it in the Microphone pop-up to record from it."
  - Title starts as "Recording" followed by the date and time, as in "Recording 2026-10-04 06:30". Save in chooses the library folder, the top of the library, Library, by default.
- Recording:
  - Record (Command-R), Pause or Resume (Command-P), and Stop (Command-Period). The first recording asks macOS's permission to use the microphone, once. After a no, the window says where to change it, System Settings, Privacy & Security, Microphone, offers Open Privacy Settings, and records nothing.
  - Record says "Recording from" and the microphone's name, and recording starts a second later; Pause says "Paused.", and Resume says "Resuming." a second before recording goes on. Through speakers, VoiceOver's speech can be recorded too.
  - Record and Resume first pause every book playing in a reader, so the microphone doesn't pick it up, and say so first, as in "Paused the book that was playing. Recording from AirPods Pro."; resuming the books is yours to do.
  - Elapsed is the time recorded, pauses left out, which VoiceOver reads as "1 minute, 4 seconds". Level is the microphone's peak and average in decibels and how loud that is: silent, quiet (below minus 36 decibels), good, loud (from minus 6 decibels), or too loud (above minus 1 decibel); VoiceOver reads it as "minus 12 decibels, good". Both change once a second and are read when you move to them, never spoken on their own. A drawn meter beside the level, for sighted helpers, is hidden from VoiceOver.
  - Announce level every 10 seconds, off by default, has VoiceOver speak the level while recording, as in "Level minus 12 decibels, good", and the stepper after it sets how often, from 5 to 60 seconds in steps of 5. TextMouth remembers both, and config.json keeps them too.
  - When a recording has held no sound at all for five seconds, as a muted microphone gives, the window says once, "No sound is reaching TextMouth from" the microphone's name, "Check that the microphone is on and not muted."
- Saving:
  - Stop saves without asking: an M4A audiobook (AAC, one channel, at most 64 kilobits a second, tagged with its title, its author Unknown) in the chosen folder. VoiceOver says "Saved Recording as" and the title, after "Saving the recording…" when saving takes more than a second, and Open in Reader opens the book. It plays, keeps its place and bookmarks, and syncs like any other audiobook.
  - When recording stops on its own, because the microphone was disconnected, the disk has less than 512 megabytes free, or the microphone reported a problem, the window says why and saves what was recorded.
  - A save that fails keeps the recording, with Save Again and Discard Recording.
  - Closing the window while recording asks "Stop and save the recording?", with Stop and Save, which Return presses, Discard, and Cancel, which Escape presses. Closing it while a recording waits unsaved asks "Save the recording?", with Save, Discard, and Cancel.
  - Quitting TextMouth asks the same question, the window brought forward: saving or discarding then quits, and Cancel keeps TextMouth open with the recording as it was. A save that fails keeps TextMouth open, the window saying why, and the next quit asks again; a quit while a recording is starting or being saved waits for it, then asks if anything is left to ask.
- Recovered recordings:
  - A recording cut off by a crash, a forced quit, or a power cut stays in this Mac's Recordings folder, readable up to where it stopped, as does one whose save failed after its window closed. The New Recording window lists them first, under Recovered recordings, each by when it was recorded and how long it lasts, as in "Recording of October 4, 2026 at 6:30 AM, 1 minute, 4 seconds", and says how many it kept when it first lists them. When TextMouth starts and finds any, it opens the window on them, VoiceOver starting on the first one's Save as Audiobook. A recording an audio editor is making is never listed.
  - Save as Audiobook saves one as Stop does, titled for when it was recorded, as in "Recording 2026-10-04 06:30", in the Save in folder; Discard deletes it. Each button's label names its recording; one that holds no sound can only be discarded, and both wait while a recording is under way, being saved, or waiting to be saved. Nothing is deleted on its own: a recording neither saved nor discarded is listed again next time.
- The original take:
  - A recording is first made as its original take, lossless audio of about 345 megabytes an hour, from which the audiobook's audio is encoded. What happens to it follows the original audio policy of Editing audio, below: Original audio, in the Storage tab's Audio Editing group, offers Keep, Don't keep, and Keep for a number of days, the default, with Days to keep an original, from 1 to 365, 1 by default, counted from when the recording was saved, or from its last edit. A change applies to the originals already kept too.
  - Originals whose time is up are deleted when TextMouth starts and after each recording or edit is saved, and nothing is downloaded to do it. In a library in the cloud, an original syncs with its book.

## Editing audio

TextMouth edits an audiobook's audio, a recording's or an imported one's, in an editor window made for the keyboard, VoiceOver, and a braille display; nothing in it needs a waveform.

- Opening the editor:
  - Edit Audio… is in a reader's Book menu, after Delete Transcript…, and first among the audio commands of a library row's context menu and its actions in VoiceOver's Actions menu, for one audiobook kept in a package of its own.
  - A book of several tracks asks which one to edit, in a pop-up listing them by chapter name: the editor works on one track at a time. A book whose manifest plays stretches of its tracks as sections, as a DAISY audiobook's does, can't be edited yet.
  - A book open in a reader is closed there first, VoiceOver saying why, and opens again when the editor closes.
  - Each book has one editor window, titled "Edit Audio:" and the book's title, followed by the track's name for a book of several; choosing Edit Audio… again brings it forward. When the book's edit history can't be read, a copy of it is kept in the book's package, and the editor asks whether to start over with no edits.
- The window:
  - VoiceOver starts on Position, which says where the cursor is in words, as in "12 minutes, 4.3 seconds of 48 minutes", and shows it as a clock, as in "12:04.3 of 48:00". Status says the same with the chapter and the selection, and Last message repeats the last announcement, for a braille display. Nothing is announced while the audio plays unless you ask, as with Where Am I.
  - Every command is also a button, in four groups under the headings Listen and Move, Select and Mark, Edit, and Save and Export, and each button's hint says what it does and its shortcuts in words, as they are set. A command that needs a selection, or something to paste, is dimmed without one.
  - The editor's shortcuts are a group of their own, Audio Editor, in the Shortcuts tab of Settings. They work only while an editor window is in front, never in a sheet over it, so they can share keys with the reader. The keys below are the defaults.
- Listening and moving:
  - Space or K plays and pauses; S stops, and goes back to where playing began.
  - J or Comma moves back one second, and L or Period forward one; Shift-J and Shift-L move ten seconds; Option with J, Comma, L, or Period moves a tenth of a second.
  - Command-Up Arrow and Command-Down Arrow go to the start and the end; G goes to a time you type, such as 12:04.3, 1:02:03, or 75.5.
  - Option-Command-Up Arrow and Option-Command-Down Arrow go to the previous and the next chapter marker.
  - N and Shift-N go to where the sound after the next or the previous pause begins, saying how long the pause was; W says where the cursor is.
  - While the audio plays, a move carries it on from the new place; otherwise a move plays half a second there, when "Play half a second after each move", in the Audio Editing group and on by default, says so. The small steps say nothing, since Position and the half second tell where they went; every jump says where it landed.
- Selecting and marking:
  - I and O mark the selection's start and end at the cursor.
  - Option-N selects from the cursor to the next pause, and Option-Shift-N back to the previous one: that is how a phrase is selected.
  - C selects the chapter the cursor is in, Command-A selects everything, and Escape clears the selection.
  - Shift-W says where the selection starts and ends, and how long it is; P plays it.
  - A pause is at least 0.4 seconds, longer than a breath between words, quieter than a level 15 decibels above the recording's background (the level of its quietest tenth), that level kept between minus 60 and minus 30 decibels.
  - M drops a marker at the cursor, even while playing. Shift-M lists the markers, the chapter markers, and the pauses, each row read whole, once, as in "Marker 3, Intro, at 1 minute, 4 seconds", then its buttons, which name the row, as in "Delete Marker 3": Go To, Rename, and Delete for a marker, Go To, Rename, and Remove for a chapter marker, and Go To and Select for a pause, as buttons and among its VoiceOver actions. Rename opens a field in the row, with Save Name, which Return presses, and Cancel; while a name is being typed, Escape presses that Cancel, once the keyboard has left the field, and Close takes Escape only while no name is being typed. Markers follow the sound through edits and are kept with the edits of the file they are in, so the next window on that file, the book's or one of its tracks, shows them again, in its list too. Revert to Original deletes them, saying so before and after, and Redo doesn't bring them back.
- Editing:
  - Delete or Command-X cuts the selection, Command-C copies it, and Command-V pastes at the cursor or over the selection. A Paste right after a Cut, with nothing selected, moves the audio, as one edit. Up to ten minutes is kept for Paste, while the disk keeps a gigabyte free; a longer cut can still be moved by a Paste right after it.
  - T trims to the selection, as one edit. Shift-S inserts silence of a length you type. Shift-C sets a chapter marker at the cursor with a title you type, renaming one already there. In Go to Time, Insert Silence, Insert Chapter Marker, and a rename row, one press of Return runs the command once.
  - F applies a filter preset to the selection or the whole file. Its Preview plays up to 20 seconds of it filtered without applying anything, and while "Preview filters before applying", on by default, says so, the first Apply previews and the second applies. Apply's hint says what a press does now: that it plays the filtered audio first, until that preset has been previewed on that target, through Apply or Preview, since the sheet opened; or that it applies the filter. With every preset deleted in Settings, Apply Filter starts VoiceOver on Cancel, since there is no preset to start on.
  - R punches in: it says what it will record and from which microphone, beeps, and records over the selection, or, with nothing selected, inserts at the cursor. R, S, or Space ends the recording and selects it, and Escape discards it. Microphone for Punch In chooses the microphone, the one the Record window remembers too, apart from the input macOS uses for everything else.
  - Command-Z and Shift-Command-Z undo and redo; their buttons are named for the edit, as in "Undo Cut 2.5 Seconds".
  - The main Edit menu's Undo, Redo, Cut, Copy, Paste, and Select All are the editor's own while its window is in front, Undo and Redo named as their buttons are, and each available when its button is; in a sheet over the editor, and in every other window, they keep their usual meaning.
- Saving and exporting:
  - Command-S saves into the book's file, in the format it keeps, saying the length and the format first; a save that takes a while announces each quarter.
  - A save moves the book's bookmarks and its saved reading position with the sound: one before every edit stays, one after an edit moves with the sound, and one inside a stretch cut or trimmed away goes to where that stretch was. In a book of several tracks, only those in the track saved move. A bookmark keeps its number and note.
  - Shift-Command-E exports to a file and a format you choose.
  - WAVE, AIFF, and CAF files can't hold chapter markers, and saving or exporting one says they are left out.
  - Option-Command-Z, after asking, reverts to the original audio, when the original is kept; Redo brings the edits back.
  - Command-I shows Audio Info: the length, the file, the format a save writes, the edits, whether the original is kept, and Original audio for this book, which gives the book a policy of its own (below).
  - Closing the window with edits not saved asks Save, Discard, or Cancel. Discard returns to the audio as saved, and the next time you edit the book, Redo brings the edits back. The window stays open while a change is under way or a punch-in records, saying so. Quitting TextMouth asks the same about each editor with edits not saved, one at a time, in the order of their books' titles, its window brought forward: Discard there undoes the edits, which Redo brings back the next time you edit the book. Cancel, or a save that fails, keeps TextMouth open, and an editor still working, or recording a punch-in, keeps it open and says so.
- A waveform of the audio, with the cursor, the selection, the chapter markers, and the markers, is drawn for sighted helpers; VoiceOver never meets it, and no command needs it.
- Edits: trimming either end, cutting, moving a stretch, inserting silence or audio (a paste, or a recording at the cursor), replacing a stretch with a new take (punch-in), adding, renaming, and removing chapter markers, filters, and volume changes. Every edit lands on the same sample however often it is applied, and an edit that doesn't fit the audio is refused with a sentence saying why. Chapter markers follow the sound: a marker where sound is inserted, replaced, or filtered stays at the stretch's start, markers inside a cut move to where it was, and markers inside a replaced or filtered stretch move in proportion.
- Undo and redo go back through every edit of a file, across launches and Macs, since the edits are kept in the book's package. Saving writes the edits into the book's file, in its own format where TextMouth can write it: AAC in .m4a or .m4b, MP3, which TextMouth writes itself (below), Apple Lossless, WAVE, AIFF, or uncompressed CAF. A FLAC book becomes Apple Lossless, and any other becomes AAC in .m4a. Its chapters, length, and index are measured afresh. A book open in a reader can't be saved; close it there first.
- The original audio: unless the policy below keeps none, the first save keeps a copy of the audio the edits started from, and a recording keeps its original take, so every edit can be undone while the original is kept. Original audio, in the Storage tab's Audio Editing group, decides how long: Keep; Don't keep, which edits the book's file in place, so undo then stops at the audio as last saved; or Keep for a number of days (1 to 365, 1 by default) after the last edit, or, for a recording never edited, after it was saved. A change applies to the originals already kept, too. A book can also have a policy of its own, set in the editor's Audio Info, which wins. Originals whose time is up are deleted when TextMouth starts, after a recording or an edit is saved, and when a book's own policy changes, never while the book is open in a reader or being edited, nor while undone edits or edits not yet saved need them, and nothing is downloaded to do it.
- Filters are written as ffmpeg writes them, such as highpass=f=80,equalizer=f=3000:t=q:w=1:g=3. Without ffmpeg, TextMouth runs volume, highpass, lowpass, equalizer, afade, atempo, loudnorm, silenceremove, acompressor, and areverse itself, as ffmpeg does, though its loudnorm applies one gain, as ffmpeg's two-pass normalization does, where ffmpeg in one pass changes its gain as it goes; it says which filters it runs when a chain asks for another. With ffmpeg installed (Homebrew's, MacPorts', or one on PATH), Use ffmpeg for filters, in the Audio Editing group and on by default, runs every filter ffmpeg has; the switch's help names where TextMouth found ffmpeg, and without one, a line says that it isn't installed. TextMouth bundles nothing of ffmpeg. Twelve premade presets, such as Remove Rumble, Audiobook Loudness, and Shorten Long Pauses, can be edited, reordered, removed, added to, and reset, in Filter Presets… (below), and work with or without ffmpeg.
- MP3 needs no ffmpeg: TextMouth writes it with the LAME encoder built into the app (see Third-party code), at a constant bit rate, an MP3 book's own or 64 kilobits a second a channel for speech, tagged with the title and author, the chapter markers as ID3 chapter frames (at most 255, the most one table of contents lists; past that, the 255th runs to the end), and the iTunes gapless numbers, so TextMouth and Apple's players measure it exactly as long as its sound. Export lists it as MP3. Should that encoder ever fail to start, an installed ffmpeg the switch allows writes MP3 instead.
- Export writes the edits as they stand, saved or not, to a new file in any of those formats, with its chapter markers where the format holds them, leaving the book's file alone.
- Settings: "Preview filters before applying" and "Play half a second after each move", in the Audio Editing group of Storage settings, are on by default, and config.json keeps them as audioEditorPreviewsFilters and audioEditorPlaysAfterMoves. Filter Presets…, in the same group, lists the presets, to edit, add, reorder, delete, or reset them, each command a button of the preset's row and, when it can act, one of the row's VoiceOver actions and context menu items.

## Podcasts and article feeds

TextMouth subscribes to podcasts and article feeds, and keeps each feed's episodes and articles in a library folder of its own (What TextMouth reads, above, gives the formats, the refreshes, and the downloads). A feed's commands, and an episode's, are in their rows' context menus and among the rows' actions in VoiceOver's Actions menu (VO-Command-Space), under the same names.

- Subscribing:
  - Library menu, Add Feed… (Shift-Command-F), or the Library window's Add Feed button, opens the Add Feed sheet. Type or paste the feed's address, or the address of a web page that names its feed, and choose where the feed's folder goes with the Move dialog's folder picker, whose New Folder makes one; it offers every folder but a feed's own, starting at the folder the window shows. Return presses Subscribe, and Escape presses Cancel. While the picker's New Folder fields are shown, Return presses their Create instead, and nothing until a name is typed; once they close, Return presses Subscribe again, as in the Move dialog.
  - Below the address, Search for a podcast searches Apple's podcast directory for the words you type, from a podcast's title or its publisher's name, when you choose Search, or press Return, which in that field searches instead of subscribing; only those words go to Apple. Up to 50 podcasts are listed, each with its publisher and number of episodes, which VoiceOver reads as one line, beside a Subscribe button of its own, which puts its feed's address in the address field and subscribes to it. VoiceOver hears how many were found, as in "3 podcasts found for “braille”."; a search that finds nothing, or fails, as when the directory refuses more than about 20 searches a minute, says so in the sheet and to VoiceOver.
  - TextMouth reads the feed first, then makes a folder named after it, numbered when the name is taken, so a failure leaves the library as it was: the failure stays in the sheet with its reason, which VoiceOver hears. A page naming several feeds lists them, to choose one. Once the sheet closes, VoiceOver hears what came, as in "Subscribed to Planet Money: 10 of 381 episodes kept." (see Feeds in the library, below), or, for a feed that uses plain http, an alert warns once, saying the subscription was made.
  - Library menu, Import OPML… subscribes to each feed in another feed reader's export, each into a folder of its own inside the folder you pick, taking the first feed of a web page that names several, and then says which were subscribed already, which failed and why, and which use plain http. Cancel stops it after the feed under way. Return presses Import, and Escape presses Cancel; while the picker's New Folder fields are shown, Return presses their Create instead, and once the import has ended Return presses Done. Export OPML… saves every subscription as OPML 2.0, or says there is none to export.
- Feeds in the library:
  - Where there are feeds, a Feeds section follows the folders: at the top of the library and in All Items it lists every feed, in a folder the feeds whose folders are inside it, and in Unopened every feed with an episode or article not yet played, until its last one is played, marked played, or deleted; Recent and the Reading List list none. Each row says, in one sentence, the feed's title, Feed, its episodes counted, and its last check, or why it failed, as in "Planet Money, Feed, 10 of 381 episodes kept, 3 downloaded, 1 downloading, 2 new, 5 unplayed, checked today at 3:05 PM". Opening the row opens the feed's folder; when that folder is gone, VoiceOver says so and Feed Info opens, where you can choose another.
  - A feed's episodes are counted the same way wherever TextMouth counts them: on its row, on its folder's summary bar, entering its folder, in VoiceOver's Folders rotor, in Feed Info, and in Speak Info. The count begins with how many of the feed's entries TextMouth keeps, of how many the feed lists, as in "10 of 381 episodes kept": the newest, as many as Keep the newest allows, in the Feeds tab of Settings or the feed's own Feed Info, 10 unless you change it, besides its downloads, which are always kept. Then come the episodes downloaded, downloading, and new, and last those not yet played, each left out when it is 0. When TextMouth keeps every entry the feed lists, the count is the number alone, as in "12 episodes"; a feed longer than the 2,000 entries TextMouth reads says "10 of more than 2000 episodes kept"; and articles count "unread" rather than "unplayed". The feed's size counts the episodes you deleted too, since the feed still lists them. A feed subscribed before October 7, 2026 gives its size after its next check, which reads the whole feed once.
  - Each feed is listed once. In Folders, a feed's folder has no row of its own, since the feed's row in the Feeds section stands for it: the row opens the folder, and its context menu ends with the folder's Rename Folder…, Move Folder…, and Delete Folder…. VoiceOver's Folders rotor still lists the feed, as in "Planet Money, Feed, 10 of 381 episodes kept, 3 downloaded", and moves to its row. Entering the folder says its name, Feed, and its episodes counted. It lists the episodes newest first, under a heading that counts them, as in "Episodes (12)", or "Episodes (10 of 381 kept)" when the feed lists more than TextMouth keeps, and "Episodes (2)" while a search narrows them: a downloaded one as its book's row, and any other with, in this order, Played (Read for an article), its download's state, New, its date, and its duration. The folder's other books follow, under Books. The summary bar gives the feed's count and its last check, as its row does, beside the listening time left in the folder's books.
  - An episode is New when it was published after you subscribed, and has been neither played nor opened.
- Commands:
  - For a feed, on its row: Check Feed, which says what came; Feed Info…, which Command-I opens too; Mark All Played (Mark All Read for articles); and Unsubscribe…, which asks first, naming the books the feed's downloads made, which stay in the library.
  - For an episode or article: Open, which downloads it first; Download, or Cancel Download while it downloads; Mark Played or Mark Unplayed (Mark Read or Mark Unread for an article); Show Description…; for a downloaded one, Show in Finder and Delete Download, which is refused while it is open in a reader; and Delete Episode… (Delete Article…), which asks first, deletes its download, and keeps it out of the list for good. A downloaded episode's book row offers these beside the book's own commands.
  - Feed Info… shows the feed's address, web site, publisher, episodes, counted as its row counts them, last check, the date you subscribed, and a plain-http warning when it applies, each read as one line, and its description, under a Description heading, in a text area labelled with the feed's title, as "Description of Planet Money", so VoiceOver says Description once. It chooses the folder the feed's downloads go to from then on, and holds This Feed's Settings: how many entries the feed keeps, and how many days after playing its downloads are deleted, each with Use the global setting. Unsubscribe… is there too, and Done, which Escape presses. Return stays with the number fields, entering the number typed, except while the folder picker's New Folder fields are shown, when it presses their Create. Each change applies as you make it.
  - Show Description… shows an episode's text in a text area that VoiceOver reads by line, word, and character; Return or Escape closes it.
- Saving and quitting:
  - A feed's record that can't be saved is reported as any unsaved change is: the Library window's banner names the feed, with Retry and Dismiss, and quitting asks first.
  - Quitting while episodes download, or wait to, keeps their place: the one under way keeps what it has downloaded, when its server allows, and at the next launch they download again, that one going on from where it stopped. Quitting waits at most three seconds for this.
- The Feeds tab of Settings:
  - Refreshing: Refresh every feed when TextMouth opens, on by default; Refresh feeds every 1 to 168 hours, 1 by default, or Only at launch and when I ask; and Refresh All Feeds Now, also in the Library menu as Refresh All Feeds, which says what came, as in "Refreshed 3 feeds: 2 new episodes."
  - Episodes and Articles: Keep the newest 0 to 2,000 entries of each feed, 10 by default, besides its downloads, which are always kept, or Keep every entry; Download new episodes and articles by themselves, off by default; and Delete downloads after playing, from 0, at once, to 365 days, 1 by default, or Never delete played downloads. A feed can keep its own number of entries and days, in its Feed Info.
  - When New Episodes Arrive: Show an alert when a refresh brings new episodes, and Post a notification for each feed with new episodes, both off by default. They follow only the refreshes TextMouth makes by itself, at launch and on the interval; a refresh you ask for is answered by VoiceOver instead. The alert names each feed and what came, in the Library window in front, and a notification shows even while TextMouth is in front. macOS asks permission for notifications the first time they are turned on, and while they are refused, the setting says how to allow them in System Settings.

## Speed and memory

TextMouth was measured against a library the size of its developer's on October 3, 2026, and changed wherever a listener could notice what it cost. What changed in use:

- Starting to listen:
  - A session's first Play no longer waits while the system loads the voice: a text book's reader loads its voice silently, in the background, when it opens and whenever the voice changes.
  - When a text book opens, TextMouth prepares the speech of the chapter you are in (or, after a cover page, the first chapter with words) in the background, with your rules and settings, so Play starts without first preparing it. A setting changed before Play is applied as always. If you press Play on a long chapter before that is done, Play waits for it instead of preparing the chapter again, and TextMouth stays responsive meanwhile: the button reads Pause at once, and speech begins when the chapter is ready (for a 20 MB book of one chapter, about 4 seconds after it opens). Pressing Play/Pause while it waits stops it. When the chapter is ready while Where Am I? is speaking, speech begins once the announcement ends, and Play/Pause pressed during the announcement leaves the book paused. A shorter chapter is prepared at once, as before.
  - Opening a large book again, one whose text is a megabyte or more, reads the text TextMouth kept from the last open instead of reading the book's Markdown again, so the largest books open in about a tenth of the time with far less memory (see Where TextMouth keeps your library).
  - Speech starts with a short passage, so the first word follows Play, a seek, or a skip sooner, and each next passage is handed to the voice while the one before it speaks, so speech runs on without waiting for TextMouth between passages.
  - A reader makes its speech engine only when speech first needs one, so it opens sooner, and an audiobook's reader never makes one.
  - The installed voices are listed once, in the background, after the first window opens, and again only when the system's voices change, as when a voice finishes downloading; only the very first launch, which must choose a default voice, lists them before that. The Voice tab and a reader's voice sheet show that list rather than asking the system each time.
- Long chapters:
  - Each substitution rule, the punctuation pauses, and the repeated symbols are applied in one pass through a chapter, so even a chapter as long as a whole book starts without a pause that grew with its length.
  - Each chapter's speech is prepared once, and used again for as long as everything it was prepared from stays the same: the chapter's text, its skipped sections, the substitution rules, the repeated-symbol settings, and the punctuation pause level. Changing the speed or pitch prepares nothing again, and the next chapter starts with the speech prepared for it while the chapter before it played.
  - A coming chapter too long to render ahead has its speech prepared in the background meanwhile.
- Audiobooks:
  - In an audiobook whose chapters are files of their own, each chapter follows the one before without the short silence of starting the player again. Where playback may have to stop or wait, it does so as before: at the book's last chapter, while the reader's own End of heading sleep timer stops at the chapter's end, as it does in an audiobook, whose chapters are its headings, and before a chapter whose file is only in the cloud, which downloads first.
- Memory:
  - The audio rendered for a chapter takes half the memory it did, and far less while it is being made. It is handed to the player a few seconds at a time, so a seek within the chapter prepares only the few seconds it is about to play.
  - macOS keeps a closed window for the rest of the session. A closed reader window now lets go of its book's text, headings, and audio, and a closed Library window stops drawing its list until it is shown again.
  - Importing a DAISY audiobook copies its audio out of the ZIP a piece at a time, instead of reading each audio file into memory whole.
- The library list:
  - The list is worked out once for each change of the library, and only the rows that changed are drawn again. While a book plays, only its row and the summary line follow its reading position, and a window in which nothing changes draws nothing.
  - When TextMouth rebuilds the text of many books at once, as at the first launch after an update that reads a format better, the finished books reach the list together, in batches, instead of one at a time.
  - A playing reader's Headings, Voice, Bookmarks, and Sleep Timer sheets are drawn again only when what they show changes, such as the heading being read.
  - Moving books to another folder, and renaming, moving, or deleting a folder while keeping its contents, move the books' packages in the background. The sheet says what it is doing, as in "Moving 3 books...", and keeps its buttons unavailable until it is done, and a change that moved 25 books or more ends with an announcement, as in "Done. Moved 30 books." Such a change first waits for an import, text extraction, or analysis under way, and VoiceOver hears what it waits for. It is refused while the data directory moves, while Rebuild Directory runs, or while another such change moves books, and the refusal says which, as in "TextMouth is moving books between folders. Try again when that finishes."
- Saving your place:
  - While a book plays, its position is saved every 30 seconds into the book's own small record in its package, as before, but library.json, the index of the whole library, takes it within five minutes, or as the reader closes or TextMouth quits, rather than every 30 seconds. A crash loses no more than before: the next launch takes the newer positions from the records (see Where TextMouth keeps your library).
  - Saving a book's place no longer rewrites its index of chapters and headings, which has a file of its own, and library.json is written without line breaks, so listening writes a small fraction of what it did, which matters most in a library in the cloud, where every write is uploaded.
  - A change in Settings is saved to config.json a moment after the last one, so dragging a slider writes the file once.
- Opening and importing books:
  - Opening an EPUB no longer reads the book's package metadata from its file. The library keeps it for books imported since it began to, and for an older book the reader reads it in the background once the book shows, so Book Info has it a moment later, and keeps it on the book's row and in its record, so the book's later opens read nothing. Reopening a 1,447-chapter anthology from its kept text went from 112 to 65 milliseconds.
  - Importing a book, and rebuilding the text of the library's books, take far less time for large EPUB, HTML, Word, DAISY, and plain-text books: each EPUB document is parsed once, each file inside a book's archive is found without searching the whole archive, and HTML's emphasis and links, word counts, white space, and plain-text headings take time that grows only with the text. The text TextMouth makes is unchanged, byte for byte.
  - Opening a book whose text is cached copies far less of that text while splitting it into chapters.
  - Launch checks each book's package with fewer file-system calls, and works out in the background which text caches need rebuilding.
- Elsewhere:
  - In a library in the cloud, each reading of the books' states looks once at where the library lives, and while a book downloads, the frequent checks read only the downloading books. A library outside a cloud location stops at that one look.
  - Storage settings check the data directory in the background, so a slow or unplugged drive can't hold up the window.
  - A VoiceOver focus request for a window that closes before the request runs is dropped; it once could crash TextMouth.

PerformanceBaselineTests keep these gains: a number they measure that grows to more than twice its recorded baseline fails the test suite (see The performance baselines, under Building and testing).

## Where TextMouth keeps your library

TextMouth keeps everything in one data directory: .TextMouth in your home folder unless you chose another folder in Storage settings. Any folder can hold it, hidden or not: on this Mac, on an external or network drive, or in a cloud folder such as iCloud Drive, Dropbox, or Google Drive (see Keeping your library in the cloud). That choice itself is kept in TextMouth's preferences, with a bookmark of the folder and the identity of the library in it, because config.json lives inside the directory it names.

- Choosing a location:
  - Change Location… in Storage settings opens a folder chooser that shows hidden folders and can make a new folder; its button says Choose Location. The folder you choose becomes the data directory itself, with nothing added to its name.
  - TextMouth first looks at the folder, reading only what the file system says about it and downloading nothing, while the status line says "Checking" and the folder's path. Then it offers what the folder can hold, and VoiceOver announces each status line as it appears:
    - Move Library Here, for an empty folder, such as one just made in the chooser. The confirmation says that the library is copied there, checked, and used, with the current folder kept as recovery data, and what the place means: in a cloud folder, that the library, with its size, uploads in the background, and that a book only in the cloud needs an internet connection to open; on another drive, that the drive must be connected to open the library.
    - Use This Library, for a folder that holds a TextMouth library: its library-identity.json, or a library.json beside a Library folder. TextMouth switches to that library as it is, copying nothing, then quits and opens again on it. This is how another Mac restores a library from the cloud. The confirmation names both libraries, and says when the folder holds another copy of the library in use, such as the folder an earlier move left behind, which may lack the latest changes. Changes not yet saved are written first, and the switch is refused while some still can't be saved: choose Retry Saving, then try again. It is refused too while a move, Rebuild Directory, or a change that moves books between folders is under way, saying which, and while it runs those are refused in turn: "TextMouth is switching to another library and opening again on it."
    - For the folder the library is in already, the status line says it is the library TextMouth is using.
    - Anything else is refused, with the reason: a file rather than a folder, a folder holding other items, which it names, a folder inside the library, a folder in the Trash, one TextMouth can't read or isn't allowed to change, a cloud folder that isn't on this Mac yet, a missing folder whose enclosing folder is missing too, or another drive without room for the library.
  - Reset to Default moves a library in another folder back to ~/.TextMouth, the same way.
- Moving the library:
  - A move is refused while any book is open, naming the open books, and while books in a library in the cloud aren't downloaded: "3 books aren't downloaded. Download them first: select them in the library, then choose Download Now." It is refused too while another move, Rebuild Directory, or a change that moves books between folders is under way, saying which, as in "TextMouth is rebuilding its data directory. Try again when that finishes."
  - An import, text extraction, or book analysis under way finishes first, and the move's progress says which it waits for; any that start meanwhile wait until the move is over.
  - Moving copies everything into a hidden folder beside the new location, a book at a time, checks the copy, then renames it into place in one step and switches to it. The new location must be an empty folder or one that does not exist yet. If anything else appears there, or the location is changed to lead somewhere else, while the copy is made, the move stops: TextMouth deletes only its own copy, leaves what appeared alone, keeps using the old folder, and says what appeared and where. A location that is a symbolic link counts as the folder it leads to, and messages name that folder too. The old folder is left where it was.
  - While the library moves, every Library window shows a sheet with its progress, as in "Moving the library… 40 percent", and Cancel, which Escape also presses; Storage settings show the same. VoiceOver moves to the progress bar, and announces what the move waits for, where the library is going as the copy starts, each quarter of the copy, and how the move ended. Books can't be opened or added meanwhile; a book opened from Finder is imported once the move is over.
  - Cancel deletes the partial copy and leaves the library where it was, with no setting changed, and the status then says so, as in "Move cancelled. The library is still at /Users/you/.TextMouth." Once every item is copied, the move can only finish.
  - Quitting during the copy stops the move first, as Cancel does, or lets it finish once every item is copied, and then quits. A move still waiting to start its copy doesn't hold up quitting.
- When the library isn't available:
  - TextMouth checks the data directory at launch, before it creates or loads anything, reading only metadata. It checks again when the drive holding it is unmounted, or when a save finds its folder gone.
  - The default location is always available: it is created when it is missing, as on a first launch. A folder you chose is never created, nor any folder above it: a missing one is an unplugged drive, a signed-out cloud service, or a folder that was moved or deleted, and creating it would start an empty library in its place. A folder that was renamed, or a drive that mounted under another name, is found again through its bookmark, unless that leads into the Trash or to another library.
  - Otherwise every Library window shows Library Not Available in place of the library: the reason, such as "The drive “Backup” isn't connected." or "The folder is there, but it holds a different TextMouth library.", then where to choose another folder instead, "To use another folder, open Settings, Storage, and choose Choose Another Library or Use Default Location.", the folder's full path, which you can select and copy, and two buttons, Try Again, which Return presses, and Quit TextMouth. VoiceOver moves to the reason and announces it once. Meanwhile the library index isn't saved, and no book can be opened or added.
  - When library.json is only in the cloud, the reason says so, and TextMouth asks the sync service to download it; Try Again opens the library once it has arrived.
  - Try Again opens the library once it is back. When the library went missing while TextMouth was open, library.json is read afresh, and the session's newer reading positions are carried into it.
  - Storage settings say Library Not Available, with the same reason, and offer the ways out: Choose Another Library…, for a folder that holds a TextMouth library, and Use Default Location…, which uses the library in ~/.TextMouth or starts a new, empty one there. Either quits and opens TextMouth again on that library, and the confirmation lists the changes that couldn't be saved, which switching loses. Nothing is created at the missing location.

The data directory holds:

- library.json: the library index. It lists every book (title, author, format, folder, file path, reading position, bookmarks, and per-book settings), every folder, each location's sort, and the reading list, with its order and options, as compact JSON, without line breaks. While a book plays, its reading position reaches the index within five minutes, or sooner when anything else in the library changes, when the book's reader closes, or when TextMouth quits; meanwhile the book's record in its package holds it (below). Each book's row also records which version of TextMouth's metadata reader last read its file for its title and author, and which of its details you edited by hand (see The Library window, under Finding your way around). The first launch after an update that reads a format's metadata better reads every older row's file again, in the background before the text caches, and takes the author the file names where the row still says Unknown; an author you typed stays, and a file that still names no one leaves Unknown. It never replaces a field edited by hand. For a book imported from its own file since October 7, 2026, by Open Book, from Finder, in a ZIP of books, or with Import DAISY Folder, whose record of hand edits begins at its import, it also brings up to date the title, author, publisher, and publication date the file names. For every other book, from before then, or made with New from Text, by a recording, from a feed's episode or article, or from a ZIP of audio tracks or a DAISY audio book's ZIP, whose names come from elsewhere than the file it reads, it replaces nothing but that Unknown author, and only with a name, so a title or an author you typed stays. A book whose files are only in the cloud waits for a launch that finds them on this Mac. The October 7, 2026 update does this once for every book.
- reading-checkpoints.json: present only while some books' records hold reading positions that library.json doesn't have yet. It names those books, so that a launch after a crash takes their newer positions from their records.
- library.json.unreadable- followed by a date and time: a preserved copy of an index that could not be read. When library.json cannot be read, TextMouth never overwrites it, and the Library window's Recovery Options… offer Try Again and Rebuild Library Index, which rebuilds the index from the books on disk.
- library-identity.json: which library this is, an identifier and the date the library was given it. It is written once, when TextMouth creates the library or first opens one an earlier version made, and never overwritten, so the library keeps its identity wherever its folder goes. TextMouth remembers the identifier it expects, so a folder that only has the right name, such as another drive called Backup, is never taken for your library.
- config.json: your settings, which you can edit by hand (see Editing settings in config.json).
- substitutions.json: the text substitution rules from the Text tab of Settings.
- audio-filters.json: the audio editor's filter presets. Until one is changed, the premade presets stand in and nothing is written. In a library in the cloud it is read and written as substitutions.json is (see Keeping your library in the cloud).
- transcript-cleanup.json: your own rules for Clean Up Transcript (Experimental)…, once Edit Rules… has made it from TextMouth's own (see Transcribing an audiobook). TextMouth writes it only then, never over a copy of yours. It is read as substitutions.json is: one only in the cloud is asked for and waits there, and a copy of one that can't be used is kept beside it, its name followed by .unreadable- and a date and time; TextMouth's own rules stand in for either.
- reading_stats.json: listening statistics, kept by day, and the books finished, each with its kind once TextMouth began to record kinds.
- Sessions: in a library on another drive or in a cloud folder, a small file for each Mac that has the library open, holding the computer's name, when TextMouth was last active there, and its version. TextMouth writes this Mac's when the library opens, refreshes it every minute, and removes it at quit, and it removes any left untouched for 30 days (see Keeping your library in the cloud).
- Feeds: one file for each feed subscribed to, Feeds/ followed by the feed's identifier and .json, holding the feed's address, title, folder, and own settings, and the episodes and articles it keeps, with whether each is downloaded, played, or deleted. It moves and syncs with the library. A file that can't be read is kept beside itself, its name followed by .unreadable- and a date and time, and its feed is left out until the file can be read; a file only in the cloud is read once it has arrived, at the next refresh of every feed; and a sync service's conflict copy is never read.
- Library: your books. Its folders are the library's folders, and each book is a package: a folder named after the book's title, author, date added, and identifier, ending in .tmb. A package holds:
  - The book's own file, under its original name. An audiobook made of several tracks keeps them in a folder instead; one converted from a DAISY audio ZIP also has a manifest.json listing its sections and the stretches of audio each one plays.
  - bookInfo.json: the book's record, with its metadata (for an EPUB, its publisher, publication date, ISBN, language, identifier, and EPUB version, read at import or, for a book imported before TextMouth kept them, the first time a reader opens it), which of its metadata fields you edited by hand, reading position, bookmarks, and per-book settings, written within half a second of each change, and every 30 seconds while the book plays. It can rebuild a book's library entry if library.json is lost. While a record is only in the cloud, TextMouth neither reads nor writes it, and the book's changes are saved in library.json alone, without waiting, until the record is on this Mac again. A downloaded episode's or article's record also names its feed and item, which library.json never holds.
  - contentIndex.json: the index of the book's chapters and headings, with their word counts and, for an audiobook, its timing, written when the book is imported or its content is analyzed again, so saving the book's place never rewrites it. Earlier versions of TextMouth kept the index inside bookInfo.json: TextMouth moves it out the next time it saves such a book, and an earlier version that opens a book saved since finds no index there and analyzes the book once more.
  - content.md: the text cache, the book's text as Markdown, so a text book opens without parsing its source again. TextMouth rebuilds it when the source file changes or when a newer version of TextMouth reads that format better. Edit Text opens it in your own editor, and TextMouth takes what you save while it's open (see Editing a book's text). A transcribed audiobook's content.md holds its transcript's text instead (see transcript.json, below).
  - content.md.edited- followed by a date and time: a copy of text in content.md that Edit Text couldn't take, or that TextMouth replaced, reading the text again from the book's own file or, for a transcribed audiobook, writing it again from the transcript. TextMouth never reads these copies, and Delete Transcript leaves them; delete them when you no longer need them.
  - transcript.json: an audiobook's transcript, present once the book has been transcribed: the language, the recognizer and its model, the version of TextMouth, the date, the date of your last edit of it, once you have edited it, its last cleanup, once it has been cleaned up (when, whose rules, their version and date, and how many corrections), and, for each audio file, its fingerprint (its size, modification time, and digest) and every sentence heard in it, with each word's start and end in milliseconds and the recognizer's confidence. TextMouth writes the book's content.md from it, a heading for each chapter and a paragraph for every few sentences, and writes content.md again from it when the book next opens if content.md is missing or holds text TextMouth didn't write or take, which it first keeps beside content.md as content.md.edited- followed by a date and time, or if a newer version of TextMouth writes it differently. The transcript itself changes only when the book is transcribed again, Edit Text takes an edit of its text, or a cleanup is applied or undone, and Delete Transcript deletes it. One whose audio file has changed since it was made is kept, but its text is no longer shown; one written by a later version of TextMouth, as on another Mac sharing the library, is left as it is, unread; and one that can't be read is kept beside itself as transcript.json.unreadable- followed by a date and time.
  - transcript.json.before-cleanup: the transcript as it was before its last cleanup, which Undo Cleanup puts back and removes. The next cleanup replaces it, and Delete Transcript deletes it.
  - origin.json: only in a recording's package: when the recording started, how long it lasts, the microphone it was recorded from, and, until the book's audio is first edited, whether its original take is kept, with when the book's audio was last made from it, which the original audio policy counts from; after that, audioEdits/edits.json (below) records the take instead. Earlier versions of TextMouth leave it alone.
  - original-take.caf: a recording's original take, lossless, for as long as the original audio policy keeps it (see Editing audio).
  - audioEdits: present once a book's audio has been edited, or a marker dropped in its editor: edits.json, the edit history of each of its audio files, with the editor's markers, and the book's own original policy; originals, the original audio of an imported book's files, for as long as the policy keeps it; and takes, the new takes of punch-ins and the audio pasted or recorded at the cursor, as Apple Lossless when that loses nothing. A history that can't be read is kept beside itself as edits.json.unreadable- followed by a date and time; one written by a later version of TextMouth is left alone. Earlier versions of TextMouth leave the folder alone.
  - removedFromLibrary.json: present only when you chose Remove from Library Only. It keeps the package on disk without the book returning to the library.
  - A folder whose name starts with .import- is an import in progress. Imports build their packages here only while the data directory is on another drive than this Mac's own folders (below), and otherwise in this Mac's Import Staging folder. Nothing else in TextMouth treats such a folder as a book. The next import into the same library folder removes one that an interrupted import, or an earlier version, left behind, and each import that builds in this Mac's folder clears what interrupted imports left there.
- Archive Extraction: the working folder of ZIP imports while the data directory is on another drive than this Mac's own folders; otherwise ZIPs are extracted in this Mac's Archive Extraction folder (below). Each import removes its own folder when it ends. At startup TextMouth removes any left over, here and in this Mac's folder, and, while this Mac's folder is the one in use, removes this one once it is empty.
- Logs: the diagnostic logs, which TextMouth writes here unless Storage settings put them on this Mac, so they sit beside your books, move with the library, and sync with it when it is in the cloud. They never hold your substitution rules, and they name files by their place inside the data directory or this Mac's TextMouth folder. They hold none of your books' text either: a CONTENT_INDEX_REJECTED line, written when a book's saved index is set aside and rebuilt, names a heading that changed by where it changed, never by its words. A transcript is a book's text too: the TRANSCRIPT_FILE, TRANSCRIPT_STALE, and TRANSCRIPT_TEXT_REBUILT lines name a book's files by their place in the book, and never quote what was heard, a transcription's TRANSCRIPTION_STARTED line names the book and the language, and the line that ends it, TRANSCRIPTION_FINISHED, TRANSCRIPTION_CANCELLED, or TRANSCRIPTION_FAILED, the seconds it took and the words it found, or why it failed, never a word heard, the TRANSCRIPT_CLEANUP_RULES, TRANSCRIPT_CLEANED_UP, and TRANSCRIPT_CLEANUP_UNDONE lines of a cleanup give counts and file names, never the words it changed or its rules, an AUDIO_EDITS_FILE line, for an audio edit history that can't be used, never quotes the history, which can hold chapter titles, and an AUDIO_EDITOR line, for an editor that couldn't open a book or finish a save or an export, names the error by its kind, never by a file's path. A feed is named by its host, never by its whole address, which can carry a private feed's token.
  - textmouth_debug.log, the main log.
  - textmouth_timer.log, the sleep timer's log.
  - textmouth_transition.log, the speech engine's log. Its DIRECT_SYNTH_REPLACED, DIRECT_RETRY, DIRECT_RETRY_FAILED, and RENDER_REFUSED lines tell of a passage the speech engine refused and what TextMouth did then, by offsets and lengths, never the passage's words.
  - Routine trace lines are written only while tracing is on: set the TEXTMOUTH_TRACE_LOG environment variable for one launch, or run `defaults write com.textmouth.TextMouth diagnosticTraceLogging -bool YES` until you turn it off again with `-bool NO`.
  - A log that reaches 2 MB is renamed with .previous added to its name, replacing the older one in the same step, and a fresh one starts, so each log keeps at most two generations and a cloud drive uploads little. When the rename is refused twice, as a cloud drive can refuse one while it uploads the file, the log starts over instead, beginning with a LOG_ROTATION line saying why. TextMouth never downloads a log to add a line to it: one whose content is only in the cloud becomes the .previous generation, and a fresh one starts.
  - The Logs group in Storage settings chooses where they go: Log location offers Inside the data directory, the default, and In this Mac's Logs folder (~/Library/Logs/TextMouth). A change applies from the next line written; logs already written stay where they are. The line under the picker names the folder in use, and why while the logs can't go where it asks, and Show Logs in Finder opens that folder, saying so, aloud too, when Finder can't.
  - While the library isn't available, or the data directory or its Logs folder is missing, the logs go to ~/Library/Logs/TextMouth, and back to the data directory once it can take them. Each time they change place, the debug log they arrive in says why in a LOG_LOCATION line. TextMouth never creates a folder in the data directory to write a log: the Logs folder is made with the data directory's other folders.

TextMouth also keeps folders of this Mac's own, which never sync and keep working while the data directory isn't available:

- ~/Library/Logs/TextMouth: the diagnostic logs (see Logs, above), when Storage settings put them on this Mac, and while the data directory can't take them. Logs that earlier builds wrote only here stay here.
- ~/Library/Application Support/com.textmouth.TextMouth:
  - Working Copies: the copies that open audiobooks in a library in the cloud play from. Each is deleted when its reader window closes, and any that a crash left behind are removed the next time a copy is made.
  - Import Staging: the packages imports are building, while the data directory is on the same disk as this folder: the startup disk, which also holds the folders of iCloud Drive and other cloud drives. A data directory on another drive keeps them in its own library folders instead, so a new book is always put in place with one rename on one disk.
  - Archive Extraction: the working folders of ZIP imports, under the same condition.
  - Recordings: the takes being recorded, and any not yet saved as a book, each a CAF file named for when it started, as in "Take 2026-10-04 06.30.12 1A2B3C4D.caf". A take leaves once its book, with the original the original audio policy keeps, is in the library, or when Discard Recording deletes it. A take cut off by a crash or a forced quit, or whose save failed after its window closed, stays here, still readable, and the New Recording window lists it under Recovered recordings until it is saved or discarded (see Recording from a microphone). A punch-in's take, recorded in the audio editor, leaves once its edit holds it, or when it is discarded.
  - Feed Downloads: episodes downloaded and not yet imported, for a moment each. Whatever an interrupted download left here is removed at the next launch.
  - Kept Books.json: the books kept on this Mac (see Keep on This Mac, in Keeping your library in the cloud), a choice another Mac sharing the library never reads.
- ~/Library/Caches/com.textmouth.TextMouth/Audio Edits: one folder for each book being edited, with the filtered stretches and the silence its preview and saves read, removed when the edits are saved or the editing session ends, or, after TextMouth quit or crashed with an editor open, at its next launch. macOS may empty it, and everything in it can be made again from the book's package: a filtered stretch macOS removed is made again when the editor next needs it.
- ~/Library/Caches/com.textmouth.TextMouth/Audio Editor Clips: a folder for each open editor window, holding the audio Copy or Cut keeps for Paste, removed when the window closes, or, after TextMouth quit or crashed with the window open, at its next launch.
- ~/Library/Caches/com.textmouth.TextMouth/Feeds: how this Mac last checked each feed (Fetch State), which lets a refresh skip a feed that hasn't changed, and the partial downloads a stopped download resumes from (Resume Data, kept a week), with the list of downloads under way or waiting when TextMouth last quit (Downloads at Quit.json), which the next launch asks for again and removes. macOS may empty it; the next refresh then reads each feed whole once.
- ~/Library/Caches/com.textmouth.TextMouth/Reading Text: the reading text of the large books this Mac opened lately, those whose content.md is a megabyte or more, so that opening one again reads it from here instead of re-reading the book's Markdown. The largest anthology reopens in about a tenth of a second instead of three quarters of one, and a 20 MB book in one chapter in about 50 ms instead of a second or more. Nothing about speech is kept here, so changing substitution rules or speech settings never makes it wrong. A book's file is removed a day after the book was last opened, at once when its text is extracted again or the book is deleted, and whenever its content.md or title changes or a new version of TextMouth is installed. Time Machine leaves it out of backups, and macOS may empty it when the disk runs low; the next open simply reads the book again.

## Keeping your library in the cloud

A data directory in iCloud Drive, Dropbox, Google Drive (streaming), or another cloud drive that macOS keeps in ~/Library/CloudStorage works as any other, and lets the sync service keep books only in the cloud to free space on this Mac: macOS removes the downloads of files it can fetch again when it needs space, and you can remove a book's download yourself. TextMouth recognizes such a folder from its path, tells each book's state from file-system metadata without downloading anything, and downloads a book when you open it. To put your library there, choose a folder in the drive with Change Location… and then Move Library Here; on another Mac signed in to the same drive, choose that folder and Use This Library (see Where TextMouth keeps your library). CLOUD-STORAGE-RESEARCH-2026-10-03.md and CLOUD-STORAGE-PLAN-2026-10-03.md, in the same folder as this file, explain the design.

- How each drive keeps a book: iCloud Drive syncs a book's package, its .tmb folder, as one item, while Google Drive and Dropbox sync each file in it. TextMouth tells which from the package's own sync flags and acts on what the drive syncs. On iCloud Drive it reads a book's state, and whether its changes have uploaded, from the package, and Download Now, opening a book, and Remove Download ask for the whole package, which comes to this Mac, or leaves it, all at once; on the other drives it does each of these file by file.
- In the Library window:
  - Each book's row shows and speaks its state after the New or Now Reading badge: Downloaded, In Cloud, Downloading 40%, Download Failed, or Waiting for Sync, which means the book's package hasn't arrived on this Mac yet. While a row speaks a download's percentage, it speaks the reading progress as "42 percent read", so the two never sound alike. A book kept on this Mac (below) shows and speaks "Kept on this Mac" after its state. A library on this Mac or on another drive looks and reads as before.
  - The summary line adds how many of the books shown are in the cloud, as in "3 books in the cloud": those not wholly on this Mac; and how many are kept on this Mac, as in "2 books kept on this Mac".
  - The states are read again when a Library window opens, when TextMouth becomes the active app, after books are added, moved, or removed, and every minute while a Library window is open. While any book downloads, even one Finder started, the downloading books are read every 2 seconds; a download that starts meanwhile shows when every book is next read, within a minute.
  - A book's context menu, and its actions in VoiceOver's Actions menu (VO-Command-Space), offer Download Now for a book in the cloud or one whose download failed, Remove Download for a downloaded book, Keep on This Mac, or Stop Keeping on This Mac for a book kept already (below), and Show in Finder, which selects the book's package. Each cloud service also has its own command for keeping a book on this Mac, in Finder: Keep Downloaded for iCloud Drive, Offline Access for Google Drive, and Make available offline for Dropbox.
  - With several books selected, these commands act on the selection and count the books they act on: "Download 3 Books", "Remove Downloads of 3 Books", "Keep 3 Books on This Mac", "Show 3 Books in Finder".
  - Download Now downloads the books one at a time, each showing Downloading 0% until its turn. It announces when it starts, and gives one summary when every book has ended, naming any book that wasn't downloaded and why.
  - Remove Download frees the space a downloaded book takes on this Mac, leaving it in the cloud. It deletes nothing from the cloud, so it doesn't ask first. It refuses a book open in a reader, a book kept on this Mac, and one with changes not yet uploaded, and says why in an announcement and an alert.
  - Book Info never waits for a download. For a book only in the cloud, it shows the details the library keeps, with "Some details appear once the book is downloaded.", and refuses to write changes into the book's EPUB file until the book is downloaded.
- Keep on This Mac:
  - A book's context menu, and its VoiceOver actions, offer Keep on This Mac, or Stop Keeping on This Mac for a book kept already, for any book in a library in the cloud, even one whose package hasn't arrived yet. With several books selected, each counts the books it acts on, as in "Keep 3 Books on This Mac". The Library menu has both commands too, for the books selected in the Library window in front; when nothing would change, VoiceOver says why, as in "No books are selected."
  - A kept book stays downloaded. One only in the cloud, or whose download failed, downloads at once, as Download Now downloads it, and VoiceOver hears "Keeping Moby-Dick on this Mac. Downloading it now", then the summary when the downloads end. One whose download the sync service removes, while TextMouth runs or before it started, downloads again, without an announcement, when the books' states are next read, and one whose download failed then waits five minutes before it is tried again.
  - Remove Download refuses a kept book: "The book is kept on this Mac, so its download can't be removed. Choose Stop Keeping on This Mac first." Stop Keeping on This Mac removes nothing: the download stays until the sync service or Remove Download removes it.
  - Keeping is this Mac's own choice, as Finder's Keep Downloaded is: another Mac that opens the same library keeps only the books chosen there. The choice is saved in this Mac's own Kept Books.json (see Where TextMouth keeps your library), never in the library.
- Opening a book:
  - A downloaded book opens at once. A book with files only in the cloud downloads first, in its reader window: "Downloading" and the book's title, the sync service's name, and a progress bar that VoiceOver moves to and reads as "2 of 3 files, 40 percent". While a single file is left and nothing has been counted yet, the bar gives that file's size and the time waited instead. Where the sync service reports how much of a file, or of a package iCloud Drive downloads whole, has arrived, the percentage counts that part too, never going back, so a book of one large file shows how far it has got.
  - VoiceOver hears the download start, then 25, 50, and 75 percent (or, while there is no percentage, the time waited, every 30 seconds), then "Downloaded. Loading."
  - Cancel, which Escape also presses, stops waiting, and the window then says the book isn't downloaded, with two buttons: Download, which Return presses, and Close.
  - A failure shows the reason with Try Again, which Return presses, and Close. Offline, the download fails at once: "This Mac is offline, so the book can't be downloaded from Dropbox. Connect to the internet and try again." A sync service that downloads nothing for 60 seconds is reported as perhaps paused, signed out, or not running. A book whose package hasn't arrived on this Mac yet says so.
  - The book is then read without ever waiting on the network. A file that went back to the cloud meanwhile is downloaded once more; if it has gone again, the reader says that part of the book isn't on this Mac.
- Playing an audiobook:
  - An open audiobook plays from a working copy: a copy of its package in this Mac's Working Copies folder, which on the same disk takes almost no extra space. So it keeps playing offline, or after the sync service removes the book's download. The copy is deleted when the reader window closes, and positions and bookmarks still save to the library.
  - When no copy can be made, a chapter whose file is only in the cloud downloads before it plays, in the same view, while the reader shows Playing. Pausing, with Play/Pause or when the sleep timer runs out, stops waiting, so the chapter doesn't start by itself later; it downloads again when you next play it, if it still has to. A failure stops at that chapter with a Chapter Not Downloaded alert offering Try Again.
  - A text book is read into memory when it opens, so it needs no copy.
- Background maintenance never downloads a book. The startup repair, the metadata refresh, the text cache and statistics passes, and Redo Text Extraction leave a book whose files are in the cloud as it is, decide nothing from what only the cloud knows, and catch the book up once its files are on this Mac; opening a book also rebuilds its text cache when that is out of date. Each pass that skipped books writes one MAINTENANCE_SKIPPED_IN_CLOUD line in the debug log, saying how many, and Redo Text Extraction says so in Storage settings too, as in "Done. 12 books in the cloud were skipped."
- Logs: they live in the library's Logs folder and sync with it, each kept to 2 MB with one older generation, so the uploads stay small, and TextMouth never downloads a log to write to it. To keep them off the cloud, choose In this Mac's Logs folder in Storage settings (see Where TextMouth keeps your library).
- Several Macs:
  - Use a library on one Mac at a time. While a library on another drive or in a cloud folder is open, TextMouth keeps a file for this Mac in its Sessions folder. When another Mac's file was refreshed in the last three minutes, TextMouth warns, once a session: "TextMouth is also open on “Study iMac” (active 2 minutes ago). Using one library on two Macs at the same time can lose reading positions and changes." Continue, which Return presses, keeps the library open here, and Quit TextMouth quits. It is only a warning: nothing is locked. A sync service's conflict copy of this Mac's own file never counts as another Mac. The file is written and read away from the main thread, so a Sessions folder that hasn't synced yet never stalls TextMouth; at quit, removing the file is given up to two seconds.
  - config.json travels with the library, so a dataDirectoryPath that another Mac wrote is ignored when it names a folder this Mac doesn't have (see Editing settings in config.json).
  - TextMouth leaves alone the conflict copies a sync service makes of library.json, library-identity.json, config.json, reading_stats.json, substitutions.json, a feed's record, and a book's package and record, such as "library 2.json" or "library (1).json": it never reads one in place of the file it copies, nor adopts a copied package as a second book, and leaves each where it is. It doesn't merge what two Macs wrote.
  - While reading_stats.json or substitutions.json is only in the cloud, TextMouth neither waits for it nor saves over it, and asks the sync service for it. Meanwhile the statistics count only this session's listening, which is added to the file's totals once the file is on this Mac. The standard substitution rules stand in, and a change to them is reported as unsaved, with Retry; the file is read again whenever TextMouth becomes the active app and before each save, and once it is on this Mac its rules take the place of the standard ones, and that change is dropped. Where there is no substitutions.json at all, as on a Mac's first launch before the sync service has brought it down, the standard rules stand in without being written: the file is written only when a rule changes, so one that arrives later is adopted without a conflict copy.
  - Either file, when it can't be read, as a write cut short on another Mac can leave it, is kept beside itself before anything replaces it, its name followed by .unreadable- and the date and time, as an unreadable library.json is; the statistics then start afresh, and the standard rules stand in.
- Feeds: their records sync with the library, and each Mac refreshes them on its own. A played episode's download is deleted only by a Mac that holds the whole book, as its cloud state says.
- What was tested: the opt-in tests in Testing on real cloud drives, below, passed against Dropbox, Google Drive, and iCloud Drive, and CLOUD-STORAGE-MANUAL-TESTS-2026-10-03.md lists the checks, with VoiceOver steps, still to be made by hand on each drive.

## Building and testing

### What you need

- A Mac with macOS 14 or later runs TextMouth. Development uses macOS 26 and Xcode 26.0.1, the version the continuous-integration job selects.
- XcodeGen generates TextMouth.xcodeproj from project.yml. Install it with `brew install xcodegen`; the development Mac and CI use version 2.45.3.
- `make check` reads the package pins with jq, which macOS 15 and later include as /usr/bin/jq.
- Recording needs macOS's microphone permission, which macOS keeps from one build to the next only while the builds are signed with the same certificate: run `make signing-identity` once on each Mac you build on (see Make targets).

### Make targets

Run these from the repository root:

- `make build` regenerates the project and builds the Release app as build/TextMouth.app, about 15 MB: without the code coverage Xcode's scheme gathers for tests, with code nothing reaches left out, and with its symbols stripped into build/DerivedData/Build/Products/Release/TextMouth.app.dSYM, which the next Release build replaces. The app includes LAME 3.100's MP3 encoder, which project.yml builds from Vendor/lame as a static library the app links, about 0.13 MB of it (see Third-party code). The full build log is build/xcodebuild-Release.log. It then signs build/TextMouth.app with this Mac's TextMouth Developer identity, when it has one, so that macOS keeps the app's microphone permission from one build to the next, and prints the app's designated requirement; without one, the app keeps the ad hoc signature Xcode gave it, and a note says so. The build products in build/DerivedData stay as Xcode made them.
- `make debug` builds the Debug configuration instead.
- `make run` and `make open` build the app and open it.
- `make install` builds the app, copies it to /Applications, registers it so it appears in Open With menus, and keeps the build's dSYM in build/installed-dSYMs as TextMouth-<build number>-<UUID>.app.dSYM, keeping those of the last five installs only. `make uninstall` removes the app and leaves the dSYMs; `make clean` removes them with the rest of build/.
- A crash report from the installed app gives TextMouth's own frames as offsets, such as TextMouth + 0x372e00, because the Release app's symbols are stripped. The build number (CFBundleVersion) and TextMouth's UUID in the report name the dSYM `make install` kept for that build in build/installed-dSYMs, which turns the offsets back into functions, files, and lines: `atos -o build/installed-dSYMs/TextMouth-<build number>-<UUID>.app.dSYM/Contents/Resources/DWARF/TextMouth -arch arm64 -l <TextMouth's load address in the report> <address>`.
- `make signing-identity`, once on each Mac, makes that identity: a self-signed code-signing certificate named TextMouth Developer, valid for 20 years, with its key in the login keychain, where codesign may use it without asking. Run again, it says the identity is there and changes nothing. It asks for no password and sets no trust, so Keychain Access lists the certificate as not trusted, which signing doesn't need. Keep the certificate: a new one changes the app's designated requirement, and macOS asks for the microphone once more. When codesign can't use the key, as over SSH with the login keychain locked, `make build` fails and says so; run `security unlock-keychain ~/Library/Keychains/login.keychain-db`, then build again.
- `make test` runs the hosted test suite, described below.
- `make check` runs the reproducibility gate, which also reports the Release app's size, and `make check-selftest` tests the gate, the baseline-recording script, `make install`'s dSYM keeping, and the signing script, all described below.
- `make perf-baselines` records new performance baselines after a deliberate change, as The performance baselines describes below.
- `make generate` regenerates TextMouth.xcodeproj from project.yml. Run it after adding or removing a source or test file, and commit the changed project file with that file.
- `make resolve-packages` resolves the Swift packages exactly as Package.resolved pins them, and `make update-packages` resolves them again after a deliberate version change.
- `make xcode` regenerates the project and opens it in Xcode.
- `make clean` removes the build products.
- `make help` lists these targets.

### The hosted test suite

The tests are one XCTest bundle, TextMouthProductionTests, hosted by the app itself: Xcode launches TextMouth.app and runs the tests inside it, so they exercise the real code through `@testable import TextMouth`. New tests belong in TextMouthProductionTests/. The files under TextMouthTests/Sources/Tests are older scenario groups that project.yml lists one by one.

A process hosting tests never touches your data. When the XCTestConfigurationFilePath environment variable is set, as XCTest sets it, TextMouth keeps its data directory, this Mac's own folders (its Logs folder, its folders in Application Support, and its caches), and its preferences in a sandbox folder named TextMouthTests- followed by the process number, in the temporary directory. In that process, VoiceOver announcements made through the app's announcer are recorded instead of spoken, macOS is never asked for the microphone unless you run the microphone test (below), and a test that leaves a reader window open fails. That process also takes no part in the system's media session: it never registers for the commands of headphones and media keys, nor tells the system it is playing, so a suite running while you listen can't take those commands from the TextMouth you are listening to. Nor does it reach the network: its feed connections refuse every request, the feed tests answer theirs from a stub server of their own, and the feed engine never refreshes or deletes anything by itself there. Nor does that process post a notification, or ask permission for one.

Each run deletes its sandbox as it finishes, and, as it starts, deletes in the background the sandboxes that earlier runs left behind, such as one that crashed. The system reuses process numbers, so a sandbox counts as left behind once no process with its number is running, or the one running started more than an hour after the sandbox was made. With TEST_RUNNER_TEXTMOUTH_KEEP_SANDBOX=1, a run keeps its sandbox for you to look inside, with a KEPT-SANDBOX.txt file in it that keeps later sweeps away; a later run given the same process number moves it aside, adding -kept- and a short suffix to its name. Delete a kept sandbox when you are done with it.

- `make test` runs the whole suite. It runs `swift run` in TextMouthTests/, whose small runner calls:
  - With `TEST_DERIVED_DATA=<folder>`, as in `make test TEST_DERIVED_DATA=build/DerivedData`, the runner builds in that folder, counted from the repository root, instead of Xcode's default DerivedData folder.
  - `xcodebuild test -project TextMouth.xcodeproj -scheme TextMouth -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO`
- Every target compiles in the Swift 6 language mode: `project.yml` sets `SWIFT_VERSION` to `6.0` for the whole project, beside `SWIFT_STRICT_CONCURRENCY` set to `complete`, and TextMouthTests/Package.swift builds the test runner in the same mode, so Xcode, `make build`, `make test`, and `make check` all report the same diagnostics, and a data race the compiler can find is an error. The mode also checks at run time that main-actor code called from Objective-C, such as a closure handed to a framework callback, runs on the main thread, and stops the app if it does not. The project's coding agents run the suite without parallel testing and with a build folder of their own; the `SWIFT_STRICT_CONCURRENCY=complete` in their command is redundant, and harmless:
  - `xcodebuild test -project TextMouth.xcodeproj -scheme TextMouth -destination 'platform=macOS' -parallel-testing-enabled NO CODE_SIGNING_ALLOWED=NO SWIFT_STRICT_CONCURRENCY=complete -derivedDataPath /tmp/TextMouth-DerivedData`
- To run one test class, add `-only-testing:TextMouthProductionTests/` followed by the class name, such as `-only-testing:TextMouthProductionTests/CountWordingTests`.
- A full run compiles the app and takes four to five minutes. Some tests skip in an ordinary run:
  - Opt-in tests that need a copied book or a library to profile, set up as TextMouthTests/README.md describes. That file also explains the playback profiling script, Scripts/profile-production-playback.sh.
  - Tests that read the accessibility structure SwiftUI builds, which it builds only while an assistive client such as VoiceOver is running.
  - Tests that read, through accessibility, the AppKit controls SwiftUI draws in a hosted window, such as steppers, sliders, and pop-up buttons, in a session that exposes none of them. Each run looks once, at a stepper of its own, and where it finds none exposed, every such test skips with one message, "This session exposes no accessibility elements for the AppKit controls in a hosted window", and the test log has one HOSTED_ACCESSIBILITY_UNAVAILABLE line. Where the controls are exposed, as on the development Mac, a control missing from a view, or left without its label, still fails its test.
  - The bookmark keyboard tests, which need Keyboard navigation turned on in System Settings.
  - The microphone test, which records about three seconds, with a pause, from this Mac's default microphone, and runs only with TEST_RUNNER_TEXTMOUTH_MICROPHONE=1; its first run may show macOS's microphone prompt. Every other recording test uses a stand-in microphone and an answer of its own to the permission question, so the suite never shows the prompt.
  - The real-drive tests, which run only when you name folders on cloud drives for them (see Testing on real cloud drives).
  - The transcription tests that use this Mac's own speech recognizer (TranscriptionFixtureTests), which run only on macOS 26 or later, on a Mac that can run the recognizer, with the English speech model installed, and in a checkout whose TestData holds the two untracked DAISY audio ZIPs; each transcribes one short file. With TEST_RUNNER_TEXTMOUTH_TRANSCRIPTION_LONG=1 they also transcribe both books whole, about a minute and a half more. No test downloads a speech model.
  - The measurement behind TRANSCRIPT-CLEANUP-RESEARCH-2026-10-04.md (TranscriptAccuracyMeasurementTests), which runs only when `TEST_RUNNER_TEXTMOUTH_TRANSCRIPT_MEASUREMENT` names a folder, on a Mac that can transcribe, with the English speech model installed, and takes minutes. It measures the recognizer on the two DAISY audio ZIPs a checkout keeps, against their books' text, and on each audio file in the folder's audio folder, named as in `audio/<text>--<voice>.m4a` (or .wav, .caf, or .aiff), against `texts/<text>.txt`, the text it was made from. It keeps each transcript in the folder's transcripts folder, so a second run doesn't transcribe again, and writes measurement.md, the document's tables, and differences.json, every difference with its confidences and context. `TEST_RUNNER_TEXTMOUTH_TRANSCRIPT_MEASUREMENT_LOCALE=en-US,en-GB` measures in both Englishes. It downloads and plays nothing.
  - The two tests that need an installed ffmpeg, which TextMouth looks for in Homebrew's and MacPorts' folders and along PATH: one that writes MP3 through it, the route MP3 takes only should the LAME built in fail to start, and one that runs every premade filter preset through it and through TextMouth's own filters and compares them. They skip on a Mac without ffmpeg.
  - The opt-in benchmarks of the performance work (below).
  - The performance baselines tests, while the Mac is busy, and on a Mac model or in a build configuration other than their baselines' (see The performance baselines).
- GitHub's macOS runner, where `make check` runs for every push to main and every pull request (see The make check gate), skips more tests than the development Mac. There SwiftUI builds no accessibility structure, a hosted window exposes none of its AppKit controls to accessibility, and keyboard navigation is off, so the three kinds of test above that read accessibility or need keyboard navigation skip rather than fail, as do the opt-in tests and benchmarks, and the performance baselines tests, whose baselines belong to the development Mac's model.
- The benchmarks of the performance work of October 3, 2026, time what each change made faster and print their figures in the test log. They are opt-in, since they take minutes or need a run of their own, and each group runs when its variable is 1; xcodebuild hands a variable whose name starts with TEST_RUNNER_ to the test host without that prefix:
  - TEST_RUNNER_TEXTMOUTH_LARGE_BENCHMARKS: the speech-preparation benchmarks at the sizes too slow to time in every run, and four that time the system synthesizer, muted, and the first speech engine. Three of those four mean something only when each runs alone, named with -only-testing, in a process of its own.
  - TEST_RUNNER_TEXTMOUTH_VIEW_BENCHMARKS: ViewsAndWindowsBenchmarks, which measure what a change of the library costs the list, what a playing reader costs its sheets, what a closed reader still holds, and how many test sandboxes the temporary folder holds.
  - TEST_RUNNER_TEXTMOUTH_BENCHMARKS: TextPipelineBenchmarkTests, which time the text pipeline's old and new code side by side, best in a Release build, as in `xcodebuild test -configuration Release ENABLE_TESTABILITY=YES -only-testing:TextMouthProductionTests/TextPipelineBenchmarkTests` with the rest of the usual arguments.
  - TEST_RUNNER_TEXTMOUTH_RENDER_BENCHMARK: what rendering a chapter's speech costs in memory and main-thread time. It takes about half a minute, and nothing is heard.
  - TEST_RUNNER_TEXTMOUTH_TRACK_CHANGE_BENCHMARK: how long an audiobook's next file takes to start playing, timed with silent files.
  - PersistenceCostTests and LibraryModelBenchmarkTests run in every run instead. They check what a change costs in counts that follow from the code alone, such as bytes written, file-system calls, and publishes of the library, never in time, which a busy Mac would change, and print their figures on lines beginning PERSISTENCE_COST: and PERFMODEL:.

### The performance baselines

PerformanceBaselineTests keep what the performance work of October 3, 2026 made faster from slipping back. They measure a library and books generated to the size of the developer's, never your own library, and run in every run of the suite, in about half a minute. They measure:

- launch with a 643-book library: reading library.json, the startup repair, and finding the text caches that need rebuilding;
- the first sort of the library by File Size, and one derivation of the All Items list for each of the six sorts;
- one live reading position update, and the bytes one 30-second reading checkpoint writes for a book whose record is as large as the developer's largest;
- opening a 1 MB EPUB for the first time until the speech of its first chapter is prepared, and opening it again from the text TextMouth kept, and opening a 3-file audiobook until it has loaded;
- preparing the speech of a 1,000,000-character chapter with the developer's 16 substitution rules, which TextMouthProductionTests/performance-substitutions.json keeps a copy of;
- the most memory a 40,000-character chapter's rendered speech takes while it is built, and what it keeps;
- extracting the 1 MB EPUB's text;
- the processor time of one cloud refresh of a library outside the cloud;
- the main-thread time one reader publish costs the open Headings sheet.

How they judge:

- Each number is the median of five runs, after one more that warms caches and is not counted. TextMouthProductionTests/performance-baselines.json holds each one's baseline, with the Mac model, build configuration, and date they were recorded on.
- A number more than twice its baseline is measured five times more, and the test fails only when the lower median is still more than twice its baseline. A number at 1.5 times its baseline or more prints a line beginning PERFORMANCE WARNING:, and one at half its baseline or less a line beginning PERFORMANCE NOTE:, since new baselines would tighten the check. Every number is printed on a line beginning PERFORMANCE:.
- The tests skip, printing PERFORMANCE SKIPPED: and why, while the Mac is busy (its one-minute load average above its number of cores), so other work cannot fail them, and on any Mac model or build configuration other than the baselines', where the numbers say nothing. With TEST_RUNNER_TEXTMOUTH_PERFORMANCE_STRICT=1 a busy Mac measures anyway: `make test PERFORMANCE_STRICT=1` sets it, and `make check` uses it. A baselines file that is missing or can't be read fails the tests rather than skipping them.

Recording new baselines:

- After a deliberate change to what they measure, run `make perf-baselines` on an otherwise idle Mac, adding `TEST_DERIVED_DATA=<folder>` to build in a folder of your own. It runs the tests alone with TEST_RUNNER_TEXTMOUTH_PERFORMANCE_RECORD=1: each test waits, for up to five minutes, until the Mac is quiet, and once every number is measured the file is rewritten with this Mac's model and today's date.
- It prints each old and new number, keeps xcodebuild's output in build/perf-baselines.log, and ends with PASSED or FAILED. Nothing changes unless the whole run succeeds. Review the file's diff and commit it with the change it records.
- The baselines recorded on October 3, 2026, on the development Mac (a Mac15,12: Apple M3, 8 cores, 8 GB), in a Debug build, each the median of five runs:
  - Launch with 643 books: 134.252 milliseconds.
  - First sort by File Size: 26.243 milliseconds.
  - One list derivation, in milliseconds: Title 4.221, Author 4.453, Date Added 1.090, Last Opened 2.893, File Size 2.811, Manual Order 4.230.
  - One live reading position update: 145.621 microseconds.
  - One 30-second checkpoint: 851 bytes.
  - Opening the 1 MB EPUB to its first chapter's speech, the first time: 207.571 milliseconds; again, from its kept text: 11.799 milliseconds.
  - Opening the 3-file audiobook: 4.539 milliseconds.
  - Speech for the 1,000,000-character chapter with the 16 rules: 235.522 milliseconds.
  - Rendered speech of a 40,000-character chapter: 43.358 megabytes at its peak, 43.354 megabytes kept.
  - Extracting the 1 MB EPUB: 1,193.865 milliseconds.
  - One cloud refresh of a local library: 0.178 milliseconds of processor time.
  - One reader publish to the Headings sheet: 1.652 milliseconds of main-thread time.

### Testing on real cloud drives

CloudDriveIntegrationTests runs the cloud services against real sync services. It is opt-in: its tests skip unless the TEXTMOUTH_CLOUD_TEST_ROOTS environment variable lists folders for them.

- Make a folder named TextMouth Cloud Tests in each drive to test, and list the folders' full paths, separated by colons. xcodebuild hands a variable to the test host when you set it with the prefix TEST_RUNNER_, as in:
  - `TEST_RUNNER_TEXTMOUTH_CLOUD_TEST_ROOTS="$HOME/Library/CloudStorage/Dropbox/TextMouth Cloud Tests" xcodebuild test -project TextMouth.xcodeproj -scheme TextMouth -destination 'platform=macOS' CODE_SIGNING_ALLOWED=NO -only-testing:TextMouthProductionTests/CloudDriveIntegrationTests`
- When any entry isn't the full path of an existing folder with that name inside a cloud drive, or is listed twice, the tests fail and use no folder at all. CloudDriveTestSupportTests checks these rules in every ordinary run.
- Each test works only inside a new folder of its own, writes small files of random bytes there (the small-library test uses the repository's TestData books), and deletes the folder when it ends, even after a failure. Nothing else on the drive is read or changed, and the app's library stays in the test sandbox. With TEST_RUNNER_TEXTMOUTH_CLOUD_TEST_KEEP_SMALL_LIBRARY=1, the small library stays on the drive, for the checks made by hand. A run moves about 36 MB up and 10 MB down for each drive.
- On October 3, 2026, every test passed against Dropbox, which showed that:
  - Download and removal requests work: a test book's files uploaded within 5 seconds, their downloads were removed at once, and they downloaded again within a second through TextMouth's book service.
  - A file whose download was removed reports its real size, and a clone made before the removal stays readable.
  - A package renamed into the drive, as an import puts a new book in place, syncs as one book, and a hidden folder syncs within 4 seconds.
  - Remove Download refuses a book whose new file hasn't finished uploading.
  - Progress is reported only at 0 and 100 percent for small files, and a file's modification time moves by up to 118 nanoseconds when it downloads again, which is why TextMouth compares the times of a text cache's files to the microsecond.
- Later that day, after TextMouth learned to treat a book's package that iCloud Drive syncs whole as one item, every test passed against iCloud Drive and Google Drive too. Dropbox, whose files each carry their own flags, was not run again. The runs showed that:
  - iCloud Drive syncs a book's package as one item: the package carries the sync flags and the files inside it none, and a request to download or remove one of those files is refused as if the file didn't exist. Removing the package's download leaves the whole package in the cloud at once, nothing inside it can be looked up until it downloads again, and TextMouth's book service brought it back within a second. Google Drive syncs each file, as Dropbox does, though its package folders carry sync flags too.
  - iCloud Drive uploaded a test book within 10 seconds, and Google Drive within half a minute, since Google Drive waits 15 to 30 seconds before it starts uploading.
  - iCloud Drive publishes the progress of a package as a whole and none for the files inside it, and Google Drive each file's; on a quick download both reported only 0 and 100 percent.
  - Google Drive reports an evicted file's real size. iCloud Drive gives a file it downloads again a modification time in whole seconds, so a text book whose package came back has its files read once for their digests when it next opens, before its text cache is trusted; Google Drive moves the time by up to 107 nanoseconds, as Dropbox does.
  - On both, a clone made before a removal stays readable, a package renamed into the drive syncs as one book, a hidden folder syncs within half a minute, and Remove Download refuses a book whose new file hasn't finished uploading.
- CLOUD-STORAGE-MANUAL-TESTS-2026-10-03.md, in the same folder as this file, gives the commands for every drive and the matrix of checks to make by hand, with VoiceOver steps, for what these tests can't reach: TextMouth's own screens and commands on a real drive, and a drive that is paused, signed out, or offline.

### The make check gate

**Reproducible builds and `make check`.** TextMouth locks its Swift packages deliberately: `project.yml` requires an exact version of each direct dependency, and the committed `TextMouth.xcodeproj/project.xcworkspace/xcshareddata/swiftpm/Package.resolved` pins every exact revision, including the transitive swift-cmark. Run `make check` before merging. It regenerates the project, resolves packages strictly from `Package.resolved` (failing if anything would change), builds Release and runs the hosted test suite, with the performance baselines tests measuring even on a busy Mac, and fails on any Swift warning in either build, about concurrency or anything else, naming the first five. It also reports the size of the Release app it built, build/TextMouth.app, the app `make install` copies, counted as Finder counts it (the sizes of its files, a megabyte being a million bytes), as in "build/TextMouth.app is 15.4 MB (15,387,034 bytes), within the 50 MB limit", and fails when the app is larger than 50 MB, a limit set once, as APP_SIZE_LIMIT_MB in Scripts/check.sh. It repeats, once each, the PERFORMANCE WARNING: and PERFORMANCE SKIPPED: lines those tests print; neither kind fails the gate, since a number more than twice its baseline has already failed its test. Both builds start from scratch: the gate first removes `build/DerivedData/Build` and `TextMouthTests/.build`, keeping the package checkouts, because xcodebuild prints a file's warnings only when it compiles that file. It prints one line per step and ends with PASSED or FAILED, with full logs in `build/check/` and the Release build's in `build/xcodebuild-Release.log`. A run takes about seven minutes on the development Mac (2 minutes for the Release build, 5 for the tests). To upgrade a package, change its version in `project.yml`, run `make update-packages`, review the `Package.resolved` diff, run `make check`, and commit both files. `make check-selftest` and `make check CHECK_ARGS=--dry-run` test the gate itself in seconds, and `make check-selftest` also tests the baseline-recording script, that `make build` builds without code coverage, that `make install` keeps the dSYMs, running install and uninstall in a sandbox folder, never /Applications; and the signing script, Scripts/make-signing-identity.sh, once for real, run twice against a throwaway keychain it creates unlocked, and otherwise with stand-ins for security and codesign, so it never asks for a password or touches the login keychain. GitHub Actions runs the same gate (`.github/workflows/check.yml`) on macOS 26 with Xcode 26.0.1 for every push to main and every pull request.

## Editing settings in config.json

config.json, in the data directory, mirrors TextMouth's settings so you can read and change them in a text editor, and copy them to another Mac.

- When it is read:
  - At launch, TextMouth applies the file first, because it may have been edited while TextMouth was closed.
  - While TextMouth runs, it notices a saved edit within a moment and applies it.
  - Every change you make in Settings saves the file again, a moment after the last change, so a slider dragged through many steps writes it once, and quitting writes a save still waiting. An edit saved to the file in that moment is merged with the changes, not written over.
  - When config.json is only in the cloud, TextMouth neither reads it, which would wait for a download, nor writes over it, which would replace what another Mac saved: the settings on this Mac stand, and the first save that finds the file on this Mac merges it as an edit.
  - While the library isn't available, TextMouth neither reads, writes, nor watches the file, which may hold another library's settings. Once the library is back, a setting changed meanwhile keeps its new value, and every other one takes the file's.
- How values are checked:
  - Each field is read on its own, so one mistake never discards the rest of the file. A number out of range is moved to the nearest allowed value, a value that cannot be read counts as missing, and each repair is noted in the debug log (textmouth_debug.log, in the data directory's Logs folder, or in ~/Library/Logs/TextMouth when Storage settings put the logs there).
  - If the whole file is not valid JSON, TextMouth leaves it alone at launch and notes why in the debug log. The next settings change saves a fresh file over it.
  - An empty text field, an empty or unknown choice, and a speed or pitch of 0 all leave the current setting as it is.
  - A missing field also leaves its setting as it is, except for these, which are read as their defaults, so applying the file sets the default: rewindSmartMode, rewindSmartThreshold, sleepFadeOutDuration, sleepTimerAutoClose, punctuationPauseLevel, autoPlayOnNavigate, bluetoothMonitoringEnabled, bluetoothDisconnectDelay, restartTimerGestureEnabled, restartTimerGesturePattern, restartTimerGestureWindow, importDeleteBehavior, confirmBeforeDelete, and moveToTrashInsteadOfDeleting.
- Which settings it carries, by Settings tab:
  - Voice: selectedVoiceID, wordsPerMinute (50 to 650), pitchMultiplier (0.5 to 2), and selectedLanguage.
  - Playback: skipForwardUnit, skipBackwardUnit, shiftSkipForwardUnit, shiftSkipBackwardUnit, rewindOnResumeUnit, rewindSmartMode, rewindSmartThreshold, punctuationPauseLevel, autoPlayOnNavigate, endOfBookBehavior, sleepFadeOutDuration, sleepTimerAutoClose, playbackNavigationUnitControlMode, showBookmarkInPlaybackControls, showSpeedInPlaybackControls, and showExportInReaderToolbar.
  - Shortcuts: keyboardShortcuts, an object naming each action as Settings shows it, the audio editor's with its group's name first, as in "Audio Editor: Play / Pause", with a list of shortcuts written like `option+shift+command+b`. An empty list leaves the action without a shortcut, and a shortcut given to one action is taken from any other that works in the same windows: the audio editor's actions work only in its windows, and the rest everywhere else, so one key can do one thing in an editor window and another elsewhere. An action the file leaves out keeps its shortcuts.
  - Text: substitutionsEnabled, the switch for the substitution rules, and the repeated-symbol settings: repeatedSymbolStyle ("repeat", "count", or "omit"), repeatedSymbolThreshold (2 to 99, or -1 to read every symbol; any negative number reads as -1, and 0 or 1 as 2), and repeatedSymbolSet (the symbols written together, such as "*-=_~#", each counted once, with letters, digits, and spaces ignored; empty keeps the current ones). The rules themselves are in substitutions.json.
  - Sounds: soundEffectsEnabled, soundEffectsVolume (0 to 1, in hundredths), and soundEffectAssignments, an object naming each playback event as Settings shows it, with the sound it plays; "None" plays nothing. An event the file leaves out keeps its sound.
  - Storage: logLocation, where the diagnostic logs are written ("dataDirectory", the default, or "machine"); recordingOriginalPolicy, what happens to the original audio of recordings and edited audiobooks ("keep", "delete", or "deleteAfterDays", the default; the name is from when only recordings kept an original), and recordingOriginalDays, the days "deleteAfterDays" keeps it (1 to 365); useInstalledFFmpeg, whether an installed ffmpeg runs the audio editor's filters (true by default); audioEditorPreviewsFilters and audioEditorPlaysAfterMoves, whether the editor's Apply Filter previews a filter before applying it, and whether the editor plays half a second at the cursor after each move (both true by default); and importDeleteBehavior ("Keep Original", "Delete After Import", or "Ask Each Time"), confirmBeforeDelete, and moveToTrashInsteadOfDeleting, which config.json alone keeps.
  - Miscellaneous: bluetoothMonitoringEnabled, bluetoothDisconnectDelay (1 to 10 seconds), restartTimerGestureEnabled, restartTimerGesturePattern, and restartTimerGestureWindow (0.5 to 10 seconds).
  - The New Recording window, which isn't a Settings tab: recordingInputDeviceID, the macOS identifier of the microphone it records from, which TextMouth writes empty until one is chosen. An empty value keeps the current choice, and a microphone this Mac doesn't have, such as one chosen on another Mac sharing the library, gives way to the system's input. recordingAnnouncesLevel, whether it announces the level while recording (false by default), and recordingLevelAnnouncementSeconds, how many seconds apart (5 to 60, 10 by default).
  - Feeds: feedRefreshAtLaunch (true by default); feedRefreshIntervalHours (1 to 168, the default 1, or 0 to refresh only at launch and when asked; any number below 1 reads as 0); feedKeepEntries, how many of each feed's newest entries are kept beside its downloads, which are always kept (0 to 2,000, the default 10, or -1 for every entry; any negative number reads as -1); feedAutoDownload, whether new episodes download by themselves (false by default); feedDeleteDownloadsDaysAfterPlayed (0, at once, to 365, the default 1, or -1 never; any negative number reads as -1); and feedRefreshAlert and feedNotifications (false by default), whether a refresh TextMouth makes by itself that brings new items shows an alert, and posts a notification for each feed.
  - Transcription, the Playback tab's Transcription group: transcriptionLocale, the language transcriptions use, as an identifier such as "en-US" or "en-GB". An underscore reads as a hyphen, as in "en_GB"; an empty value, or anything that can't be a language identifier, keeps the current language. TextMouth writes the language in use, this Mac's English until one is chosen. offerTranscriptionAfterImport, whether TextMouth offers to transcribe each audiobook it imports (false by default).
- Two fields describe this Mac rather than your preferences:
  - dataDirectoryPath: where the data directory is, empty for the default location. TextMouth always writes the folder in use. Changing it asks TextMouth to move the library there, exactly as Storage settings do, and emptying or deleting it names the default location. config.json can come from another Mac with a library in the cloud, so a request is ignored, with one CONFIG_FILE line in the debug log, when the folder it names doesn't exist on this Mac or already holds a TextMouth library: emptying the field moves the library back only when ~/.TextMouth exists and holds no library. A move needs an empty destination; a value TextMouth cannot read keeps the folder in use.
  - lastOpenedBookID: the book opened most recently, which TextMouth records itself.
- What stays out of config.json: window positions, the last sleep timer you used, the preferences that record where the data directory is (its path, a bookmark of its folder, and the identity of the library expected there), this Mac's identifier for the Sessions folder, whether Edit Text has explained itself on this Mac (editTextExplained), and the hidden switch for trace logging.

## Working on TextMouth with coding agents

Task agents run on Claude Opus, launched with an explicit `model: "opus"`, in git worktrees of their own; the orchestrating session, which may run on a larger model, writes their briefs, reviews their reports and diffs, merges after a green suite, and records the merge. An agent launched without a model override inherits the orchestrator's model, which spent a weekly usage window on October 6 and 7, 2026; AGENTS.md carries the rule. The briefs of each day's wave are kept under `Scripts/agents/briefs/`, and `Scripts/agents/probes/` holds the offline speech-engine probes behind the October 7 speech guard.

Several coding agents can work on TextMouth at once, each in its own git worktree on its own branch, coordinated through a shared message board: the agent-bbs skill, in .claude/skills/agent-bbs/. Its SKILL.md is the full reference. AGENTS.md, in the repository root, is the protocol those agents and their orchestrator follow: the user's standing rules, the build wrapper and the crash-proof tests rule, the board routine, the report format, and how a branch is merged with Scripts/agents/merge-chain.sh and recorded in TODO-2026-09-04.md; AGENT-NOTES-2026-10-04.md lists what past agents left unverified.

- The board is one SQLite file, .claude/agent-bbs/board.sqlite in the repository's main working tree, which git ignores. A standard-library Python script drives it, with no server: `python3 .claude/skills/agent-bbs/scripts/bbs.py`.
- Each agent registers its role, branch, and the files it expects to edit, claims files as it takes them on, and sees any overlap with another agent's claims.
- Agents post short messages about builds, commits, findings, and questions. A message tied to a file reaches whoever has claimed it.
- `bbs.py protocol` prints the rules for an agent's brief: register on start, read the inbox before each build and commit, post each commit, and release claims when done.
- `.claude/skills/agent-bbs/scripts/build-slot-with-bbs.sh` runs a build while holding one of three machine-wide build slots, so that at most three wrapped builds share the development Mac's memory at once, and shows the agent as building meanwhile. `make check` uses such a wrapper when the TEXTMOUTH_BUILD_SLOT variable names one.
- The board's tests run with `python3 -m unittest discover -s .claude/skills/agent-bbs/tests`.
