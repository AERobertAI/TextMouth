## What goes wrong
The launch's batch rebuilds a book's text, moves its places, and commits the analysis and the moved places to the book's record (`LibraryPersistenceService.saveContentAnalysis(for:index:cacheFormatVersion:movedPlaces:)`, called in `TextMouth/ViewModels/LibraryViewModel+Migration.swift` lines 941-946). The library row gets them later: the summary waits in `ContentAnalysisSummaryBuffer` (up to half a second), and library.json is written after that. A stop in between leaves library.json's row with the old analysis and the old places.

At the next launch the row still needs a rebuild, and `committedTextCache(of:force:reading:access:)` (lines 905-955) takes its recovery branch (lines 912-922): `BookContentAnalysisService.recoveredTextCacheIndex` (`BookContentAnalysisService.swift` lines 415-466) finds the record already committed for this content.md, and the summary gives the row the analysis fields only. The row keeps its old places, and its next write (any change of the row) copies them into the record, over the moved ones.

## The lead's decision: the recovery brings the record's moves to the row
In the recovery branch the record describes content.md as it is now, and the row's analysis is behind it. So the summary of a recovered book carries the record's places as moves from the row's places, and the row takes them by the guarded take every other path uses (`Book.takeMovedPlaces(original:moved:)`, `Book.swift` lines 1493-1517): only where the row still holds the place as it did when the pass began, so a place saved meanwhile wins. This needs no new file or format, reuses the one guarded take, and also brings another Mac's committed moves to this Mac's row.

1. **Read the record once.** `recoveredTextCacheIndex` already loads the record (`BookInfo.load(from:)`). Do not read it twice: for example, a variant that also returns the loaded `BookInfo`, with `recoveredTextCacheIndex` built on it so that `completedTextCacheIndex` and every other caller behave as now. The record as a `Book` is `Book(record:filePath:folderPath:tmbDirectoryName:)`, as the tests' `recordedBook(like:)` builds it (`TextMouthProductionTests/PlaceRelocationTestSupport.swift` lines 269-279); its places are `relocatablePlaces` (`Book.swift` line 1451).
2. **The moves.** `MovedPlaces(bookID:original:moved:snapshot: nil)`, with `original` the row's places as the pass began (`book.relocatablePlaces`) and `moved` the record's, except:
   - **The reading position** moves only when the record's is at least as new as the row's (`lastUpdated`, compared as the files store dates: ISO 8601, to the second). A move is dated at the move, so it is newer than the place it moved; an older position in the record never replaces the row's. Otherwise `moved.position` is the row's own.
   - **A bookmark** moves only when the record's bookmark of its ID differs from the row's in nothing but where it is and its saved words (`chapterIndex`, `characterOffset`, `anchor`): a move. A bookmark that differs otherwise (a label edited on one side) keeps the row's.
   - **The skips** move as one, as `takeMovedPlaces` already does.
3. **No moves when nothing differs.** When the moves would change nothing, the summary carries none (`movedPlaces` nil).
4. **No narrowing by the row.** `ContentAnalysisSummary.init(committed:movedPlaces:)` (`ContentAnalysisSummaryBuffer.swift` lines 30-34) narrows the moves with `taken(by: committed)`. In the recovery branch `committed` would be `recovered`, the row with the analysis applied, which holds the old places, so every move would be put back. Narrow by the record's book instead, or add a small init for moves already taken from the record. Keep it DRY: one place builds the recovered summary.
5. **Comments.** Correct `ContentAnalysisSummaryBuffer.swift` lines 61-64 ("A summary a crash loses is not lost work: ..."): the next launch's batch recovers the analysis and brings the record's moved places to the row. Update the doc of `committedTextCache` and the recovery branch's comment.
6. **Unchanged:** `saveContentAnalysis`, `MovedPlaces.taken(by:)`, `Book.takeMovedPlaces`, and the PlaceSnapshot code.
