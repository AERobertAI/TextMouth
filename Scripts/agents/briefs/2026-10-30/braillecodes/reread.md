# Task `reread`: reading a braille book again with other braille file characters, through the encoding's re-read

Team `braillecodes`, lead `braillecodes-lead`. Your slug is `braillecodes-reread`, your branch `braillecodes/reread`, made from `team/braillecodes`. Read `Scripts/agents/briefs/2026-10-30/teams-common.md`, "The worker's part", first, and follow it.

## Background

Book Information lets the listener read a text book's file again in another encoding (encodingchoice): `TextMouth/ViewModels/LibraryViewModel+TextEncoding.swift` (read it whole, 473 lines) is that re-read, refusals and all, reviewed several times and pinned by `TextEncodingRereadTests` and `TextEncodingChoiceTests`. A braille book (a BRF or BRL) now records the braille file characters its file is read with (`Book.brailleFileCode`, a `BrailleFileCode` id; `TextMouth/Parsers/BrailleFileCode.swift`), and a later task gives Book Information a pop-up to choose others. This task is the re-read behind that pop-up, and it must be **the same re-read**, not a copy (the project's DRY rule): every step but three is the encoding's.

What is already on the team branch: the record (`saveContentAnalysis(..., brailleFileCode:)` writes a decision into the package record, which then stands over a lagging row); every reading path reads a braille book with its row's code when `decidingEncoding` is true (`MarkdownCacheService.generateReportedCacheAnalyzeAndStamp(for:replacingEditedText:decidingEncoding:)`), and with the code that stands between row and record otherwise; `BrailleFileReader.read(_:as:code:)` refuses a byte a code has no cell for with the sentences of `BrailleFileError`. The design is `BRAILLE-CODES-RESEARCH-2026-10-25.md`, sections 8.3 (Book Information) and 8.9.
