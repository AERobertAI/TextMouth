# Task `movewriter`: find the writer that races a data-directory move's copy, and make the move wait for it

Slug `tests-movewriter`, branch `tests/movewriter` from `team/tests`. Read `_common.md` beside this file first. This task is investigative: step 2 ends with a post to the lead, who confirms the fix before you make it.

## Why
Under load, a move of the data directory fails its copy with "Failed to move directory: The file “.dat.nosyncXXXX.YYYYYY” couldn’t be opened because there is no such file." It happened in a merge suite on October 7 (`StorageGenerationMoveTests.testBookRemovedWhileTheMoveWaitsIsNotInTheMovedDataDirectory`) and again tonight, in run 4 of 10 under a load average near 11, in another test of the same class (`testDuplicateQuestionAskedBeforeTheMoveKeepsTheMovedCopy`, line 245). `.dat.nosync…` is the temporary file Foundation makes beside a file it writes with `Data.write(to:options: .atomic)`, then renames over it. So some writer writes atomically inside the data directory while the move copies it, and the move neither waited for it nor flushed it.

How the copy works: `DataDirectoryMigrator.copyItems(of:into:fileManager:)` (`TextMouth/Services/DataDirectoryMigrator.swift` 416-458) first lists everything (`DataDirectoryCopyPlan`, 780-829: `contentsOfDirectory`, then `attributesOfItem` for each name, and whole `.tmb` packages sized by enumeration), then copies item by item (`copyItem`; a package is copied whole). A file listed and then renamed away fails the plan or the copy. Before copying, `LibraryViewModel.withStorageWorkHeld` (`TextMouth/ViewModels/LibraryViewModel+Migration.swift` 1696-1737) holds new storage work, waits for the work under way (`hold.waitForWorkUnderWay`), and flushes `LibraryPersistenceService.flushPendingSave()`, `configService.flushScheduledSave()`, and `TextMouthPaths.flushLogs()`, then copies off the main actor (`copyAndPublish`, 1756-1800); the main actor is free during that copy, so main-actor work can run and schedule writes meanwhile.

The failure is SAFE as it is: the move refuses and the old data directory stays complete. Do NOT make the copy skip or tolerate vanished `.dat.nosync` files: that would turn a refused move into a move that silently copies a file before its latest write.

Candidate writers, unconfirmed (find the real one; do not guess): `ReadingStatsService.save()` (asynchronous on a static `saveQueue`, `ReadingStatsService.swift` 603-614; `waitForQueuedSaves()` at 677 exists and nothing in the move calls it); a debounced save scheduled by main-actor work that runs while the move awaits its copy (the import pipeline publishing the duplicate question, or an import's follow-up: text extraction, content analysis, metadata refresh); the 35 files with atomic writes under `TextMouth/` (`grep -rlE "options: \[?\.atomic|atomically: true" TextMouth`).

## Step 2: the fix (once the lead confirms)
Whatever step 1 finds, this task also takes the reading-statistics flush that `bughunt-lead` handed over (board #4111): call `ReadingStatsService.waitForQueuedSaves()` (it touches only the stats save queue; any thread may wait) beside the other flushes in `withStorageWorkHeld`, with a test that queues a held stats save before a move and sees the move wait for it. bughunt edits `ReadingStatsService.swift` tonight (sleep and wake), so do not edit that file; it will not touch `withStorageWorkHeld` or `DataDirectoryMigrator.swift`.

The move must wait for, or flush, that writer before it plans the copy, in `withStorageWorkHeld` beside the other flushes, or the writer must be held as storage work while a move holds it; whichever matches how the writer works. No change in what the app does otherwise. Then a regression test that fails deterministically without the fix: hold the writer mid-write at a test seam (an injected queue, a gate in a test-only hook with no effect in the app), start the move, and assert the move waits for it and succeeds, with the write's latest bytes in the moved directory. Prove it fails with the fix removed. Run `--repeat 10 StorageGenerationMoveTests DataDirectoryMoveTests` at the end: all pass.
