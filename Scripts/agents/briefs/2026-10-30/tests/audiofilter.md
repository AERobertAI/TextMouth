## U02: the audio editor's biquads (data written to disk: a render is saved over the book)
- `TextMouth/Models/AudioBuiltInFilter.swift` 168-176: the `equalizer`'s `frequency` defaults to 0, below its own range (0.0001 to 999,999); `ValueReader.number` (350-362) returns the default without checking it. `TextMouth/Services/AudioEditing/AudioFilterRunner.swift` 119-161 (`coefficients`) guards only `frequency < sampleRate / 2`: at f = 0 with width type h or k alpha is 0/0, with o it is 0 times sinh(x/0), so every coefficient and every sample is NaN; and with width type o and a width above about 2,000 octaves `sinh` overflows to infinity. Nothing checks `isFinite` before the render is saved.
1. Tests first, in a new class `AudioFilterCoefficientTests` in a new file `TextMouthProductionTests/AudioFilterCoefficientTests.swift` (`xcodegen generate`):
   - `equalizer=t=h:w=200:g=6` (no frequency) is refused (see the fix below) and so are `t=k` and `t=o`, and the default `t=q`.
   - `AudioFilterRunner.coefficients` for highpass and lowpass at one and two poles and for peaking, with every width type (q, h, k, o), at f = 0.0001 Hz, 1 kHz, and sampleRate/2 - 1 Hz, and widths at 0.0001, 1, and 99,999 where the parse allows them: every one of the five coefficients is finite, or the call throws `badValue` naming the width; never a non-finite coefficient.
   - f = sampleRate/2 and f = sampleRate: `badValue` whose sentence ends "give a frequency below half the audio's sample rate, 22050 Hz" at 44.1 kHz (this refusal exists today and no test pins it).
   - Render a one-second ramp (`AudioTestFixtures.writeIdentityRamp`) through `equalizer=f=1000:g=6`: every output sample is finite. Read how `AudioFilterTests` (lines 16, 49, 70) runs a chain through the built-in engine and reuse that.
2. The fix:
   - A new case in `AudioFilterError` (`TextMouth/Models/AudioFilterChain.swift` 151 on): `/// An option a filter needs that wasn't given: the filter, the option, and what it takes.` `case missingValue(filter: String, option: String, expected: String)`, whose sentence is exactly `"The \(filter) filter needs its \(option): \(expected)."` (as the editor shows it and VoiceOver reads it). Pin that sentence in a test.
   - `ValueReader` gets `func requiredNumber(_ name: String, range: ClosedRange<Double>) throws -> Double`, which throws `.missingValue(filter: filter, option: name, expected: "give a number from 0.0001 to 999999")` (built with the reader's own `Self.number` formatting, as `number` builds its sentence) when the option is absent, and otherwise checks as `number` does. The equalizer's frequency uses it; nothing else changes. (ffmpeg's own default frequency for `equalizer` is 0, which makes no usable filter either; refusing it says what to do.)
   - In `coefficients`, after the five values are computed: when any is not finite, throw `.badValue(filter: <name>, option: "width", value: <the width as given>, expected: "give a narrower width, since this one makes no usable filter at \(<frequency>) Hz")`. Reuse the name switch above it (move it into a small private helper rather than repeating it).
   - Lessons: `AudioFilterError` is `Equatable`; any `switch` over it gains the case.
   - Before the fix, `grep -rn "equalizer" TextMouth/Services/AudioEditing/AudioFilterPresets.swift TextMouth/Models TestData` for a premade or saved chain that gives no frequency; if one exists, post it to `tests-lead` and wait, since refusing it would break a preset the listener has.

## U06: line breaks in ffmpeg's chapter metadata (data written to disk: an exported MP3's chapter frames)
- `TextMouth/Services/AudioEditing/FFmpeg.swift` 129-138, `escapeMetadata(_:)`, walks `Character`s and escapes `"\n"`; but `"\r\n"` is ONE `Character` in Swift and is not `"\n"`, so a title holding a Windows line break, or a lone `"\r"`, is written raw and splits its `title=` line. `M3UPlaylist.swift` line 81 shows the right test: `$0 == "\n" || $0 == "\r" || $0 == "\r\n"`.
3. Tests first, in a new class `FFmpegMetadataTests` (new file, `xcodegen generate`): `escapeMetadata` for each of `=`, `;`, `#`, `\`, `"\n"`, and for `"a\r\nb"`, `"a\rb"`, emoji, a title in another script, and the empty string; `ffmetadata(chapters:)` (117-125) with a title holding `"\r\n"`: exactly one `title=` line per chapter and `1 + 6 * chapters` lines in all; START and END rounding at 0.0004 s and 1.0005 s; a chapter of zero length; no chapters gives the header line alone.
4. The fix: `"\r\n"` and `"\r"` are each written as an escaped `"\n"` (a backslash, then a line feed), as ffmpeg's ffmetadata reads one line break in a value. Update the doc comment.
- The same gap in `TextMouth/Services/Feeds/FeedOPML.swift` 182-198, `escaped(_:)`: add `case "\r\n": result += "&#13;&#10;"`, with a test in `FeedUIOPMLTests` (or a new small class beside the FFmpeg one) that a feed title holding `"\r\n"` round-trips through `FeedOPML.document(listing:title:date:)` and back; read the file for the reader's entry point.
