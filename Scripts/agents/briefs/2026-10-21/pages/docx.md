## Rules (settled)
1. **With `includesPages: false`, the Markdown is byte for byte what it was**: no first pass, no marker, and a page `w:br` is the newline it is now.
2. **Page starts.** Page 1 begins at the document's start. A page also begins at:
   - a `w:br` with `w:type="page"`, where it stands (only `page`: `column` and text-wrapping breaks stay newlines);
   - a paragraph whose properties hold `w:pageBreakBefore`, directly or through its style's `w:basedOn` chain (a direct `w:val` of "0", "false", or "off" turns a style's off);
   - the first paragraph or table of a section whose break starts a page: its `w:sectPr`'s `w:type` is `nextPage` (also when `w:type` is missing), `oddPage`, or `evenPage`, and not `continuous` or `nextColumn`;
   - a `w:lastRenderedPageBreak`, where it stands (Word's last layout put a page there).
3. **Merging.** Page starts with no text between them (nothing but whitespace) are one page: Word writes a rendered break after its own explicit one, and a section break and a `w:pageBreakBefore` often begin the same paragraph. So a page start sets a pending page; the next text that is not whitespace writes its one marker first, at the place rule 5 says; and a page start while one is pending changes nothing but its numbering (rule 4). The page at the start of the document is pending from the start, so a break before the first words merges with it.
4. **Labels.** Pages are counted from 1. A section's `w:pgNumType w:start` restarts the count at its first page (a whole number from 0 to 999,999; anything else is ignored), and its `w:fmt` writes the number: `decimal`, `lowerRoman` and `upperRoman` (i, ii, iii, iv, … up to 3999, decimal beyond), `lowerLetter` and `upperLetter` (a to z, then aa to zz, and so on, as Word counts; decimal past 32 letters), and every other format as decimal. A `w:sectPr` comes at its section's end (inside the last paragraph's `w:pPr`, or the body's last `w:sectPr` for the last section), so a first pass over `word/document.xml` (only when pages are included) collects every section's type, start, and format in order, skipping tracked-change records (`w:sectPrChange`) as the converter skips them. A merged page takes the numbering of the last page start merged into it.
5. **Placement.** The paragraph is built in `currentParagraphText` and written at `endParagraph`, so:
   - a page pending when a paragraph's first text comes (its start: a section start, `w:pageBreakBefore`, or a break before any text of it) is written as a block marker before that paragraph, whatever it is (heading, list item, or paragraph); before a list item the open list is closed first (`openListItems.removeAll()`), since an HTML block cannot stand between items of a list, which changes no reading text;
   - a page pending when text comes in the middle of a paragraph is an inline marker in `currentParagraphText`, right before that text: a run holding the break is split there, the first piece formatted and appended as runs are now, then the marker, then the rest as a new piece of the same run with the same formatting. Whitespace at the end of the first piece or the start of the rest moves outside the emphasis delimiters, and for a page `w:br` one space separates the words (`keepingWordsApart`, the space being that whitespace when there is some), so "runs on and" + break + "continues" reads "runs on and continues" as the newline read before;
   - in a paragraph that is a heading, a page beginning in its middle is written as a block before the heading instead: never inside a heading line;
   - a page beginning inside a table (any paragraph of a cell) is written as a block after the table, merged with any other page beginning in it; a page pending when a table begins is written as a block before the table;
   - the marker never begins a line: write it through `MarkdownMarkerWriter`, block or inline.
6. **The reading text is unchanged** for every file, page `w:br` included (a newline read as a space before, a space now). Check that on every DOCX sample.
