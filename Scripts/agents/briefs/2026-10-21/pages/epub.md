## Rules (settled)
1. **With `includesPages: false`, everything converts exactly as before:** no marker, and a page-break element's text is read as it was (cache format 3.0.7). PG09 relies on this to tell a hand-edited book from an unedited one.
2. **The page list names the pages** when the book has one: the EPUB 3 navigation document's `nav` typed `page-list` (`epub:type="page-list"`, or `role="doc-pagelist"`), else the EPUB 2 NCX's `pageList`. It is the publisher's list, in its order, with its labels. Each entry links to a place: a document, or an element of it by id.
   - EPUB 3: each `a` with an `href` inside the page-list nav, its label the link's text (normalized as `MarkdownPageMarker` normalizes).
   - NCX: each `pageTarget` in `pageList`, its label the `navLabel/text`, else its `value` attribute; its place `content/@src`.
   - An empty label is the entry's ordinal: its 1-based position in the list.
   - Resolve hrefs exactly as `navigationTarget(href:label:level:relativeTo:)` resolves a TOC entry's (relative to the navigation document or NCX, fragment percent-decoded, web links refused).
3. **Without a page list, every page-break element is a page:** an element with `epub:type` listing `pagebreak` or `role` listing `doc-pagebreak` (`PublicationSemantics.isPageBreak(_:)`, new, any tag). Its label is its `aria-label`, else its `title`, else its text (`HTMLReadingText.inlineText(of:)`), normalized. A page-break element with no label at all is not a page.
4. **A page-break element's own text is never read** while `includesPages` is true, whether or not it is a page (with a page list, the ones the list does not name are not pages, and their text is still not read). It usually holds the page number, which CSS that TextMouth does not apply hides from sighted readers. This changes the reading text of such books; PG09 moves their places.
5. **Placement**, through `MarkdownMarkerWriter`, as heading annotations are placed in `convertElement` and `headingAnnotations(inside:context:)`:
   - at an element a page-list entry names, or at a page-break element: `inline: boundary != .paragraph`, before the element's content, so a page beginning a paragraph is a block before it and one inside a paragraph is inline where it begins;
   - inside a heading, a `pre`, or a `code`, the page is written before that element (block before a heading or `pre`, inline before `code`), never inside it;
   - an entry naming a document without a fragment is a page at that chapter's start: a block marker at the very start of the document's Markdown;
   - an entry whose element is hidden (`hidden`, or inside a page list or landmarks nav) is dropped with that content; an entry naming a document not in the spine, or an id no element has, is dropped;
   - an id two elements share is the first one's (keep a set of the ids written, in a small reference-type state object that `Context` holds, so the walk shares it);
   - an element that is both a page-list target and a TOC target gets the page marker first, then the heading annotation.
6. **Blank documents stay blank:** the check in `preparedChapter(from:markdown:targets:bookTitle:)` that drops a document with no text ignores page markers (strip every complete `<!-- page: … -->` before the whitespace check), so a document holding only page markers is blank, as before, and its pages go with it. Document-level page markers are added to the Markdown before `MarkdownDocParser.parseChapter` runs on it, so the prepared `Chapter.pages` holds them.

## What to build
1. **`PublicationSemantics`**: `static func isPageBreak(_ element: Element) -> Bool` and `static func isPageList(_ element: Element) -> Bool` (a navigation container typed `page-list` or with role `doc-pagelist`; `isSupplementaryNavigation` then uses it). `ReadingFlow` is unchanged.
2. **The converter** (`HTMLToMarkdownConverter.swift`): a new `struct HTMLPageTargets` (documented, PG05) holding `markers: [String: MarkdownPageMarker]` (by element id, or a legacy `a` element's `name`, as `headingTargets` are looked up) and `pageBreaksArePages: Bool` (default true: a document of a book with no page list, and standalone HTML). Both `convert` functions gain `pages: HTMLPageTargets = HTMLPageTargets()` before `includesPages`. `Context` carries it and the written-ids state. In `convertElement`, after the reading-flow guard and the boundary: when `context.includesPages`, a page-break element writes its page (rule 3, or its target's marker under rule 2) and returns without converting its children, after writing its closing boundary as any element does; any other element with a page target writes its marker (rule 5) before its heading annotation. Headings, `pre`, and `code` write the pages inside them first (extend `headingAnnotations(inside:context:)`'s walk, or write a sibling `pageMarkers(inside:context:)`; keep one walk if you can, so DRY holds). With `includesPages` false none of this runs.
3. **Navigation** (`EPUBParser+Navigation.swift`): a `private struct PageTarget { path, fragment, marker }`; `readPageList(archive:opfPath:opfData:) -> [PageTarget]` (EPUB 3 nav first: the manifest item with property `nav`, its `nav` elements for which `isPageList` holds, walked in document order for links, pruning nothing inside the list; else the NCX's `pageList`); `preparedChapters` reads it only when `includesPages`, groups it by document path, and passes each document's `HTMLPageTargets` (fragment targets as `markers`, `pageBreaksArePages` true only when the book has no page list) to both conversions (`readSpineDocument` and `finishedMarkdown`), and its document-level markers to `preparedChapter`. `prepareBook(url:includesPages:)` passes `includesPages` to `preparedChapters`.
4. **Standalone HTML** gets rule 3 and 4 through the converter's defaults; nothing else changes for it.
