## What the probe found (verified on this Mac, section 3.3)
- textutil reads `\page` in RTF, a .doc's page break, and a WordML `w:br w:type="page"`; `\pagebb` and `\sect` are lost when it reads.
- **Its HTML keeps no page break** and joins the words on either side of one: "First page paragraph two runs on andcontinues here" (B13: such books are heard that way today).
- **Its plain text (`-convert txt`) keeps each break as a form feed (U+000C)** at exactly its place: "runs on and\fcontinues".

## Rules (settled)
1. **With `includesPages: false`, nothing changes**: one conversion to HTML, converted as now. B13 then stays as it was, so PG09 can tell an unedited book.
2. **With pages:** a second watched textutil run writes plain text (`-convert txt`, the same options otherwise, under the same watchdog, size limit, cancellation, and working folder). Page 1 begins at the document's start; each form feed begins the next page; labels are "1", "2", … (a .doc holds no numbering textutil passes on). A plain-text run that fails or is stopped logs one line (`TEXTUTIL_PAGES_FAILED: <file name>: <why>`) and the document is read without pages (never refused for it).
3. **Alignment by letters and digits.** Count, in the plain text, the letters and digits (`Character.isLetter || Character.isNumber`) before each form feed. Walk the HTML document (after `TextutilHTMLStructure.restore`), its text nodes in document order, skipping what the converter skips (`script`, `style`, and `PublicationSemantics.isExcludedFromReadingFlow`), counting letters and digits the same way. A page begins right before the HTML text's letter or digit whose count matches.
   - **The check:** the 16 letters and digits before the break and the 16 after (fewer at the document's ends) must be the same in both texts. A break that fails it is dropped and logged (`TEXTUTIL_PAGE_UNALIGNED: <file name>: page <n>`), never placed wrongly.
4. **Writing it:** insert into the HTML document, at that place, an empty `<span role="doc-pagebreak" aria-label="N"></span>` (splitting the text node), so the converter writes the marker. When the place is inside a text node whose character before it is not whitespace (textutil joined the words, B13), insert a text node holding one space before the span, so the words stay apart. Page 1 is a span at the start of the body. Several breaks at one place keep a span each.
5. **Convert** with `includesPages` passed to the converter.
