## Finding 7: the temporary name is too long
`convert` stages the result as `.<stem>.<UUID>.ogg-conversion.m4a` (:284-285), 57 characters longer than the stem, so a valid source with a stem of more than 198 characters fails with ENAMETOOLONG at every attempt. Measured on this Mac's APFS: a name of 255 ASCII characters is accepted and 256 is refused; 204 two-byte characters (404 bytes) are accepted, so APFS counts characters; exFAT and HFS+ count UTF-16 code units (255). Make the temporary name from the UUID alone: `.<UUID>.ogg-conversion.m4a` (56 characters), built by one small `static func temporaryURL(beside source: URL) -> URL` that `convert` uses (and tests call). Update the comments that describe the old shape.

## Finding 3: exFAT answers ENOTSUP to RENAME_EXCL
`givingFinalName` (:378-395) takes each final name with `renamex_np(..., RENAME_EXCL)` and treats any errno other than EEXIST as `cannotName`. exFAT answers ENOTSUP even for a free name (measured on an exFAT image), and an exFAT library or staging folder is supported, so every conversion there fails at the last step. Required:
1. Put the exclusive rename behind a seam: `givingFinalName(_ conversion:, exclusiveRename: (_ from: String, _ to: String) -> Int32 = <the renamex_np call>)`, so a test can make it fail with a chosen errno (the closure sets `errno` and returns -1).
2. On ENOTSUP or EOPNOTSUPP (the two values differ on Darwin), fall back for that name: `open(target, O_CREAT | O_EXCL | O_WRONLY, 0o644)` and close it; EEXIST there means the name is taken, so try the next number exactly as the normal path does; any other errno is `cannotName`. Then `rename(converted, target)` over the placeholder; if that fails, remove the placeholder and throw `cannotName`. No file already there is ever replaced, and no two conversions can take the same name (the exclusive create is the reservation).
3. A numbered name ("<stem> 2.m4a") must also fit: when a candidate's UTF-16 length would pass 255, drop whole characters (never half of a grapheme cluster; iterate `Character`s) from the end of the stem until it fits, for that candidate only.

## Tests (new class `OggNamingTests`, no audio; each in its own temporary folder from `AudioTestFixtures.makeTemporaryDirectory()`, removed in `tearDown`)
- `temporaryURL`: hidden, ends with the suffix, 56 characters long, beside the source, different on each call, the same length for a 5-character and a 251-character stem; a file can actually be created under the name for a stem of 251 characters (the case that failed), and `removeLeftovers(in:)` removes it.
- `givingFinalName`: the normal path names `x.m4a`, then `x 2.m4a`, `x 3.m4a` when taken, replacing nothing (existing contents intact); the converted file's contents arrive at the final name.
- ENOTSUP and EOPNOTSUPP injected: the fallback names `x.m4a`; with `x.m4a` and `x 2.m4a` taken, `x 3.m4a`; existing files keep their contents; an injected other errno (EACCES) throws `cannotName` and leaves the hidden file; when the final `rename(2)` cannot succeed (the converted file is gone), the placeholder is removed and `cannotName` is thrown.
- Long numbered names: a stem of 251 characters whose `.m4a` is taken gets a numbered name of at most 255 UTF-16 units that still starts with the beginning of the stem; the same with a stem of two-unit characters (emoji) and with a combining sequence, never cutting a character in half.
