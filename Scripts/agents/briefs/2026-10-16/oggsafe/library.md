## The problem
`convertOggAudio(ofBook:access:)` (:188-239) converts every Ogg track of a folder book (`convertEach`, :213) and only then commits (`commitConvertedTracks` :245, `commitTracks` :280-321). `commitTracks` first reads the book's saved index, `try BookContentAnalysisService.load(book: book).index` (:287). For an audio book whose saved index is missing or not trusted, `load` falls back to `analyzeAudio`, which cannot probe Ogg tracks (the probe refuses Ogg since B09), and throws. That `throw` is outside every discard block, and `convertOggAudio` does not discard on `.waiting(.failed)`, so a book of 176 tracks converts for minutes, fails, and leaves gigabytes of hidden `.ogg-conversion.m4a` files until the next conversion of that folder; and the next launch does it all again.

## Required behavior
1. **Check first.** Before `oggConversion.begin` and any conversion, a folder book loads its saved index off the main thread (`OffMainWork.run`, the same `BookContentAnalysisService.load(book:)` the commit uses, so what passes here passes there). If it throws, the book waits: `oggConversion.markFailed(bookID)` and `wait(.failed(Self.loggable(error)), for: book)` (the same as a failed conversion: not tried again before the next launch). Nothing is converted, no hidden file is made, no `afconvert` is started. A one-file book (`commitConvertedFile`) does not use the saved index the same way: leave its flow as it is.
2. **Discard when the commit throws.** `commitTracks` must remove every hidden converted file (`OggAudioConverter.discard(conversions)`) on any throw before a file is named, and its existing discards on later failures stay. Make `commitTracks` internal (drop `private`) so a test can call it with hand-made `OggAudioConverter.Conversion` values.
3. **Also covered:** a `.waiting(.failed)` or `.waiting(.bookChanged)` result from `commitConvertedTracks` leaves no hidden converted file of this book in its folder.

## Tests (new class `OggBookCommitTests`, `@MainActor` like `OggLibraryConversionTests`; reuse its helper pattern with `makeIntegrationWorld`, a folder book of three `.ogg` junk files, and no saved index)
- The check: `convertOggAudio(ofBook:)` on that book returns `.waiting(.failed(...))` whose reason is not the track error that used to come first ("The Ogg audio file … could not be read for converting to AAC."), so the index was judged before any track was looked at; the folder holds exactly the three `.ogg` files and no hidden file; `oggConversion.hasFailed(book.id)` is true; the book is not left counted as converting.
- The discard: call `commitTracks` directly with three `Conversion`s whose `converted` files are real hidden files you create (`.01.<uuid>.ogg-conversion.m4a` and so on) for a book with no saved index: it throws, and none of the hidden files remains; the Ogg sources and any `manifest.json` are untouched.
- A book that has a trusted saved index still gets through the check (use the helper `indexAndList` pattern with the stand-in prober, as `OggLibraryConversionTests` does) and the existing tests keep their results.
