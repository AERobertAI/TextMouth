## The bug, confirmed

`LibraryViewModel.setTitleAndAuthor(ofManifestBook:title:author:sessions:written:)` (`TextMouth/ViewModels/LibraryViewModel+ManifestEdits.swift:182-217`) is the one write of an audiobook of tracks' title and author. It changes the row first (:195-200), then on `sessions.queue` calls `BookManifestFile.keepTitleAndAuthor(of:title:author:sessions:isDataless:)` (`TextMouth/Services/BookManifestEditing.swift:287-316`), which writes the manifest only when the folder and the manifest are on this Mac (`isTrackFolder(...) == true`, :297) and the manifest is one JSON object (`change(manifestAt:…)` returns false otherwise, :227-229). Otherwise it returns false (or throws), and `updateBookMetadata` (`LibraryViewModel+BookOperations.swift:708-731`) passes no `written:`, so nothing records or retries the edit. The row then holds the user's title R and the manifest the old title M. At the next look (launch, TextMouth becoming active, a reader's load) `BookManifestEditSessions.manifest(_:at:arranges:as:tracks:showingPauses:)` (:669-697) sees `M != R`, the take (:758-825) returns `title: M`, and `LibraryViewModel.commitManifestEdit` (:17-21 of the same file) calls `setTitleAndAuthor` with M: the user's retitle is silently gone. Real triggers: a retitle while manifest.json is evicted to the cloud, or while it has a typo (a half-saved edit in Edit Manifest). A session's own check (`BookManifestEditSessions.check` instance :515-533, static :559-592) adopts the stale M the same way when the user fixes the typo and saves.

## The design (decided by the lead; reasons in the last section)

A persisted, per-book, per-field record of what the manifest is **owed**: the fields (title, author) whose current row value a write could not put into the manifest yet.
- While a field is owed, the manifest's value for it is **neither compared nor adopted**: the row's value stands.
- The owed fields are **written** (from the row's current values) at every look, before it compares, and the record is cleared as soon as the manifest holds the row's values.
- The record survives a quit: it lives in `UserDefaults`.

## The reasons for the design (so you do not reopen it)
- Re-arming the launch's one-time pass (`keepHandEditedTitlesInManifestsOnce`) would write EVERY hand-edited book's title over a manifest edited outside TextMouth for as long as one book waits in the cloud. Per-book, per-field owing touches only what TextMouth failed to write.
- Writing before a session's check would move the session's baseline past the user's save (`noteWritten`), so the user's arrangement edit would not be taken until the session ended. So a session's check only declines to adopt the owed field, and the write waits for the next look.
- A flag on the book row (`Book.HandEdits`) would travel with the library but needs `Book.swift`, another file's region, and a main-actor write from the sessions' queue.
- Known limit, to report: the record lives in this Mac's preferences, so a retitle owed on one Mac is not known to another Mac that opens the same library.
