# Team feedopts: FR19, listening options for feeds and folders, and a Feed Settings / Folder Settings button

Read `Scripts/agents/briefs/2026-10-16/teams-common.md` first: it is the pattern you follow, and it stands in for AGENTS.md. You are the lead, `feedopts-lead`, on branch `team/feedopts` made from `main`. Your workers' briefs go in `Scripts/agents/briefs/2026-10-16/feedopts/`.

## What the user asked for (October 16, 2026, in their words)

"One newish feature, to have a similar options for Feeds as for the reader list view with an option to continue to the next book and to skip finished books and one to delete items as there finished / download them as you approach the end... maybe actually add a option when in a folder or feed to the toolbar for "Folder Settings" or "Feed Settings" that would just be another to popup the sheet you get with cmd+i but for the folder/feed you're in."

## The design (the orchestrator's decisions; the user confirms them in the morning, so keep each one in one place, easy to change)

1. **Per-feed listening options**, kept on `Feed` (`TextMouth/Models/Feed.swift:14`, synthesized Codable) as new **optional** fields, so an older record decodes unchanged (template: `FeedRecordTests.swift:135`). An unknown stored value must read as "not set", never fail the record's decoding: a feed whose record fails to decode is a feed the listener loses.
   - **"When an episode ends"**: a pop-up with "Use the global setting" (not set, the default: today's behavior exactly), "Play the episode below", "Play the episode above", and "Stop". Reuse `ReadingList.Continuation` (`TextMouth/Models/ReadingList.swift:24-54`) for the value, with wording for episodes beside `ReadingListWording` (`TextMouth/Models/ReadingListWording.swift:39-51`). "Below" and "above" are in the order the feed's folder lists its items (`FeedRecord.listedItems`, newest first, `Feed.swift:242`), as "below" in the reading list is its list order.
   - **"Skip finished episodes"**: a checkbox, on by default (today's Continue to Next Book always skips finished books, `nextBookInFolder`, `LibraryViewModel+SortAndOrder.swift:143`). It applies whenever playback goes on from one of the feed's episodes to another, whether the feed's own option or the global Continue to Next Book sends it there.
   - **"Download the next episode before this one ends"**: a checkbox, on by default, enabled only while playback would go on to another episode. When the episode playing has ten minutes or less left (`ReaderViewModel.timeRemaining`, `ReaderViewModel.swift:783`; the throttled `updateLiveReadingPosition`, `LibraryViewModel+BookOperations.swift:649`, is a natural place to look), the episode that would play next is downloaded if its file is not here and no download of it is running. It downloads with origin `.listener` (`FeedItem.swift:313`), so the newest-N rule (`FeedNewestRule.swift:217`) never removes an episode the listener is about to hear.
   - **Deleting finished episodes already exists**: "Delete downloads after playing" in the Feed Info sheet's "This Feed's Settings" (`FeedInfoSheet.swift:336-351`, `deleteDownloadsDaysAfterPlayedOverride`, `Feed.swift:81`; 0 days means at once; the sweep is `FeedLifecycle.swift:427`). Add no second control for it (the user's standing rule: no two controls that do the same thing). The new options sit beside it in the same section, so the sheet reads as the feed's listening settings.
2. **The episode that follows.** At an episode's end, when the feed's option (or the global Continue to Next Book) goes on, the next episode is the next listed item in the chosen direction, passing over finished ones while "Skip finished episodes" is on. Today `laterFeedItems` (`LibraryViewModel+SortAndOrder.swift:167`) passes over items whose files are not here; for a serial drama that would jump over a part. Instead, when the next item's file is not here, download it and play it once it arrives (`FeedDownloadManager.download(_:of:origin:opening:)`, `FeedDownloadManager.swift:266`, already opens a book when its download finishes; find how an opened book is told to play). The listener hears what is happening: "Downloading the next episode: <title>", and if the download fails, why playback stopped. With nothing after the last episode, playback stops as it does today, with the same spoken words.
3. **Per-folder listening options**, for a plain folder (not a feed's folder, not the root), kept on `BookFolder` (`TextMouth/Models/BookFolder.swift:3`, synthesized Codable) as new optional fields so they follow the folder through renames and moves: "When a book ends" (Use the global setting, Play the book below, Play the book above, Stop) and "Skip finished books" (on by default). They apply to the books directly in that folder, not to its subfolders. "Below" is the order `laterBooksInFolder` already uses (`ManualBookOrder.orderedBooks`, `LibraryViewModel+SortAndOrder.swift:153`).
4. **Which setting wins**, from strongest: the reading list, when the book was opened from it (unchanged, `ReaderViewModel+Playback.swift:2525-2531`); the book's own end behavior (`Book.localEndOfBookBehavior`, `Book.swift:163`); the feed's or folder's option; the global setting (`effectiveEndOfBookBehavior`, `ReaderViewModel+Playback.swift:2749`). "Use the global setting" means the folder or feed adds nothing, so every existing library behaves exactly as before.
5. **Reuse, do not copy.** The reading list already continues below or above, skipping finished books (`ReaderViewModel+ReadingList.swift:93-200`, `LibraryViewModel+ReadingList.swift:248-291`, `ReadingList.neighbor(of:_:where:)` at `ReadingList.swift:197`). Generalize that machinery so the reading list, a folder, and a feed share one neighbor search and one "go on past this book" path, keeping every existing reading-list test green unchanged. Decide the shape after reading that code; a refactor task with a completion check comes first if it is needed.
6. **The Folder Settings sheet** (new; a plain folder has none today: Command-I on a plain folder speaks its full info, `LibraryInfoRow.swift:66-77`, `FolderInfoFacts` at `LibraryInfoWording.swift:53`). Titled with the folder's name; the folder's facts as read-only labelled values (the facts Command-I speaks, as text a braille display can read); the two listening options; a Done button that Return and Escape both reach. Leave Command-I on a plain folder as it is (it speaks; `LibraryInfoSpeakerTests.swift:388,754` pin that): whether it should open the new sheet is a question for the user.
7. **The toolbar button.** In the library toolbar (`LibraryView.swift:493-555`, after New Folder at :549), shown only while the library shows a folder other than the root: "Feed Settings" while it shows a feed's folder (`shownFeedID`, `LibraryView.swift:1301`), opening the Feed Info sheet for that feed through the same path as Command-I on its row (`showFeedInfo`, :1657, `FeedCommandRunner.swift:69,86-87`); "Folder Settings" for a plain folder, opening the new sheet for the folder shown (`currentFolderPath`, `ContentView.swift:11`). Each has an accessibility label and hint, pinned by tests. If the keyboard-shortcut system (`KeyboardShortcut.swift`, FR12) can hold an action with no default key, add one ("Folder or Feed Settings") so the listener can bind a key; add no default key, and check the shortcut list's tests.
