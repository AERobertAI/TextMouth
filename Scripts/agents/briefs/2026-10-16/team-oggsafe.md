# Team oggsafe: REV17a's findings in the Ogg conversion, the child-process watchdog, and the memory guard

Read `Scripts/agents/briefs/2026-10-16/teams-common.md` first: it is the pattern you follow, and it stands in for AGENTS.md. You are the lead, `oggsafe-lead`, on branch `team/oggsafe` made from `main`. Your workers' briefs go in `Scripts/agents/briefs/2026-10-16/oggsafe/`.

## Why this matters
On October 14, 2026 Apple's Vorbis decoder locked up inside AVPlayer, TextMouth grew to 34 GB, and the user's Mac had to be reset. B06 to B09 (merges 70a74208, d7f4f527, 32dc2036, c067ab9a) made the rule: **Ogg never reaches Apple's decoders or AVFoundation's probing in the app's process; only `afconvert`, in a child process under a watchdog, reads it.** Tonight a read-only review (REV17a) confirmed the gaps below on main 8cfdc5bb. **Never open, play, probe, or decode an Ogg file in a test or experiment**: tests use a file named `.ogg` whose contents are not Ogg, or stub the probe, as the B06 and B09 tests do (read them first: `grep -ln "ogg" TextMouthProductionTests/*.swift`).

## The findings (REV17a's words, lightly cut; confirm each in the code before you brief it)
1. **high.** `TextMouth/Services/AudioPlaybackService.swift:1580,1614,1671`: `extractChapters`, `extractFullMetadata`, and `getDuration` open an `AVURLAsset` on any URL with no Ogg guard (the player's own guard is at :889). Ogg URLs reach them from `FileImportService.swift:163` (through `ImportedFileMetadata.read`, called at :808 before staging or afconvert), `ReaderViewModel.swift:1409`, `Views/Library/LibraryBookInfoLoader.swift:61`, `ViewModels/LibraryViewModel+MetadataRefresh.swift:172`, and `FileImportService+Packages.swift:398`. `AsyncBridge.waitForResult` has no timeout, so a spinning demuxer hangs the import thread for good. Fix: return empty metadata or nil for `OggAudioConverter.isOgg` URLs in the three functions (one guard, shared, not three copies). `OggAudioConverter.swift:173` (`inspect`) also opens Ogg in the app's process with `AudioFileOpenURL`: decide with evidence whether what it needs can come from the child process (`afinfo` under the same watchdog) or from reading the Ogg page header by hand.
2. **high.** `TextMouth/Services/PlaybackMemoryGuard.swift:81-93,475-480`: the guard reads the memory footprint only while some reader is playing and not paused (`isWatching`, `takeTheNextReading`), so once playback stops it schedules no more readings and the 6 GB quit cannot fire. On October 14 the converter thread allocated about 60 MB/s; if the stall watchdog or the listener's Pause marks the reader stopped under 1 GB while a wedged thread keeps allocating, it grows unwatched. Fix: keep reading for some minutes after any stop, stall failure, or pause (or always, slowly), letting the quit ceiling act whether or not anything plays. `testNothingPlayingNothingHappens` pins today's disarm: that test changes on purpose; say how in your report.
3. **medium.** `TextMouth/Services/OggAudioConverter.swift:385-392`: `givingFinalName` takes the final name with `renamex_np(RENAME_EXCL)` and treats any errno but EEXIST as `cannotName`; exFAT answers ENOTSUP even for a free name (measured on an exFAT image), and an exFAT library or staging folder is supported (`StorageDestinationAssessment.swift:9`), so every Ogg conversion there fails. Fix: on ENOTSUP, fall back to an exclusive create (`open(O_CREAT|O_EXCL)`) and `rename(2)` over it.
4. **medium.** `TextMouth/Services/WatchedProcess.swift:118-164` (and `TextMouth/App/AppDelegate.swift:189`): only the watching thread kills afconvert; nothing kills it when TextMouth quits, is force-quit, or `_exit`s (the memory guard), and the child has no CPU limit of its own. `onCancel` at :102 does nothing if it fires before the pid is published at :133, so `cancelAll` lets a just-started child run to its end. A force-quit child is reparented to launchd and runs until reboot. Fix: start the child so it dies with TextMouth (for example a small `/bin/sh` wrapper that polls its parent's pid and SIGKILLs afconvert when TextMouth is gone, with `ulimit -t`), close the cancel race, and at launch sweep any leftover afconvert whose output is one of TextMouth's own hidden `.ogg-conversion.m4a` names (only those, never another app's).
5. **low.** `WatchedProcess.swift:136-151`: elapsed and no-growth times use `Date()` (the wall clock), while the poll wait uses `DispatchTime`; after a sleep the next poll kills every healthy child. Fix: `ProcessInfo.processInfo.systemUptime`.
6. **low.** `TextMouth/ViewModels/LibraryViewModel+OggConversion.swift:213,287`: `commitTracks` reads the saved index (`BookContentAnalysisService.load`) only after every track is converted, outside its discard blocks; a book with a missing or untrusted index converts for minutes, then fails, leaving gigabytes of hidden conversions, and every launch repeats it. Fix: load and verify the index before converting, and discard the conversions when `commitTracks` throws.
7. **low.** `OggAudioConverter.swift:285`: the hidden temporary name is `.<stem>.<UUID>.ogg-conversion.m4a`, 58 characters longer than the stem, so a long but valid stem exceeds 255 characters (ENAMETOOLONG) and that book fails every time. Fix: build the temporary name from the UUID alone, keeping the `.ogg-conversion.m4a` ending the launch sweep (item 4) and the existing clean-ups look for.
