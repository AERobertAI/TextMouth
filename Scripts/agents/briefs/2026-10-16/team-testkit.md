The user is blind and checks the app by hand with VoiceOver and a braille display; the TODO's manual acceptance matrix (TODO-2026-09-04.md lines 3634-3645, items A01 at 3541, P09 at 3483, T10 at 3535) lists what is still checked only by hand. ## Ground truth (checked on main 8cfdc5bb)
- `make test` runs the whole hosted suite (`TextMouthTests/ProductionTestRunner/main.swift:31-36`); `Scripts/check.sh` is the release gate; `Scripts/perf-baselines.sh` runs one class with `TEST_RUNNER_TEXTMOUTH_PERFORMANCE_RECORD=1`: the `TEST_RUNNER_` prefix is how a script hands an environment variable to the test host. Read `Scripts/perf-baselines.sh` as the model for a script that runs one class.
- Hosted tests run inside the real app against a sandbox (`TextMouth/App/TextMouthRuntime.swift:117-139`: `$TMPDIR/TextMouthTests-<pid>`, kept with `TEXTMOUTH_KEEP_SANDBOX=1`). The built app has no switch for another data directory, so **no script may launch the app outside the test host**: it would read and write the user's real preferences and library.
- There is no UI-test target and no AX scripting. In-process accessibility walks (`TextMouthProductionTests/AccessibilityTestSupport.swift:269` `accessibleControls(in:)`) only work while hosted windows expose accessibility (`skipUnlessHostedWindowsExposeAccessibility`, :391), which they often do not; do not build on them.
- Fixtures: `TestData/` (alice.epub, two DOCX, seven PDFs, six DAISY and audio ZIPs, pride.txt, sample.md, frankenstein.html); `DAISYPackageFixtures.swift`, `PDFTestFixtures.swift` (multi-column and rotated pages built in code, used at `PDFPageTextMergerTests.swift:164`).
- End-behavior cells that exist: `IntegrationSleepTimerTests.swift:341` (audio end of book) and :391 (text end of book), `ContinueToNextBookTests.swift`.

## Tasks (a suggestion; plan your own, one or two commits each)
- **A. The area runner.** `Scripts/test/areas.txt` (named areas such as feeds, reading-list, playback-end, speech, audio, import, reader-text, headings, bookmarks, library, sheets, settings, shortcuts, storage, transcripts, recording, each listing its hosted test classes) and `Scripts/test/run-area.py` (Python 3, standard library only, every function commented): `run-area.py feeds bookmarks` runs every class of those areas in **one** `xcodebuild test` (each test-host launch adds about 23 MB to a system cache only the user can purge) through `.claude/skills/agent-bbs/scripts/build-slot-with-bbs.sh` with `-jobs 4`, its own build folder, and prints only the `Executed` line, each failure with its file and line, and any new Swift warning. Options: `--list`, `--classes A,B`, `--dry-run` (print the command), `--unassigned` (classes in no area), `--clean` (unregister the build's app with `lsregister -u`, then delete the folder). It must work for the user at a terminal with no board registration: read the wrapper to see what it needs. A self-test (run by `run-area.py --selftest`, no build) fails when a listed class no longer exists, so the list cannot rot. A `make test-area AREAS="feeds bookmarks"` target.
- **B. Document goldens.** A hosted class that imports every text document in `TestData/` (EPUB, DOCX, PDF, TXT, Markdown, HTML, DAISY text) into the sandbox and compares a normalized dump of each (title, author, the heading list with levels, text length, a checksum of the text, its first and last 300 characters) with a golden file under `TestData/golden/`, naming every difference. `TEXTMOUTH_UPDATE_GOLDENS=1` rewrites the goldens instead (`Scripts/test/update-goldens.sh`); a missing golden fails with the command that makes it. Audio packages: the track list and durations only, with no playback.
- **C. A report on any folder of documents.** An opt-in hosted class (it skips unless `TEXTMOUTH_CORPUS_DIR` is set) that copies each file of that folder into the sandbox, imports it, and writes a Markdown report (`TEXTMOUTH_CORPUS_REPORT`, default in the scratch folder the script names): per file its format, title, author, headings with levels, text length, the first lines, and every warning or refusal. `Scripts/test/corpus-report.sh <folder> [report.md]`. This is for T10 (PDF reading order and headings on the user's own documents) and the matrix's "Real documents" row. Never read the user's library; the script takes only the folder it is given. Skip Ogg files with a line in the report (never decode Ogg in the test host: AGENTS.md's B06 lesson).
- **D. The end-behavior matrix.** First list the cells {Stop, Stop and Play Starts Over, Loop to Start, Continue to Next Book} by {text, single-file audio, chaptered audio (m4b), multi-file ZIP, DAISY}, by sleep timer {none, End of book, End of chapter or heading, minutes}, and find the existing test for each cell by grep. Then add a table-driven hosted class for the uncovered cells, its header comment mapping every cell to the test that covers it. Use the global end-of-book setting only: team feedopts is adding per-folder and per-feed options tonight whose default must leave these behaviors unchanged, so your matrix is their safety net. No test plays sound.
- **E. Keyboard reachability.** Read the existing shortcut tests first (`grep -l "KeyboardShortcut" TextMouthProductionTests/*.swift`) and add only what they lack: every shortcut action (`TextMouth/Models/KeyboardShortcut.swift`) has a default key or a menu item, or sits on an explicit list of unbound actions with a reason; no two default keys collide where both apply; every menu command maps to an action or is listed. Team feedopts may add one unbound action ("Folder or Feed Settings", reachable from the library toolbar): make the list of unbound actions easy to extend, and say so in your report.
- **F. A voice sweep** (opt-in, `TEXTMOUTH_VOICE_SWEEP=1`, `Scripts/test/voice-sweep.sh [report.md]`): every installed voice renders a fixed sample (numbers, punctuation, a bracketed aside, a long sentence) offline with `AVSpeechSynthesizer.write`, never aloud, each under a watchdog timeout because some voices hang; a Markdown report per voice: identifier, name, language, quality, rendered duration, buffers, error or timeout. This covers the scriptable part of P09.
- **G. If budget remains:** a storage-failure script (opt-in) with a small disk image (`hdiutil create`, `attach -nobrowse`, `detach -force` part-way through an import, a save, and a data-directory move; a tiny image for a full disk), checking the originals by checksum afterwards, in the test host only. `DataDirectoryLaunchTests.swift:119` and `LibraryIndexRecoveryTests` cover launch and a corrupt index already.

Each script prints a usage line with `-h`, needs nothing beyond the Mac's own tools and Python 3, and is commented like the code. Each opt-in class skips cleanly (no failure) when its variable is unset, so the full suite's counts change only by the new skips and the always-on tests.
