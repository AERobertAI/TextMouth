# Task drill (REV18c findings 11, 12, 13): the storage drill's disk-image tools stay safe, and its script says PASSED only when tests ran

Slug `rev18fix-drill`, branch `rev18fix/drill` (made from `team/rev18fix`). Read `Scripts/agents/briefs/2026-10-17/teams-common.md`: "The worker's part", "Rules for everyone", "The board", "Builds", "Usage", "Lessons from October 16", "Keeping the cost down".

**Safety first (the user's Mac).** `DiskImage.fillToCapacity` writes zeros until the disk reports it is full. Run on a folder that is NOT a mounted image, it fills the Mac's own startup disk. So: write the guards of commit 1 before you ever call `fillToCapacity` from a test, never call it on a detached image or a plain folder in an experiment, and never run the opt-in drill (`TEXTMOUTH_STORAGE_DRILL=1`) or `Scripts/test/storage-drill.sh` before commit 1's guards and cap are in your working tree. Nothing here reads or writes `~/.TextMouth`.

## Commits (one each, each with its tests; build and test after each)

### 1. `fillToCapacity` writes only on the mounted volume (finding 11)
Today `fillToCapacity(leavingFree:)` opens `ballast.bin` in the mount point and writes until `ENOSPC` without checking the image is still attached. After a detach (a concurrent drill's sweep can do it), the mount point is an empty folder on the Mac's own disk. Required:
1. Before any file is made, refuse unless the volume is attached: throw a `DiskImageError` (action "filling the volume", a detail that says the image is not attached). Make one helper that reads the mounted volume's device (the mount point's `st_dev`, only when it differs from its parent folder's, as `isAttached` decides now) and have `isAttached` use it too (DRY).
2. After `open`, `fstat` the descriptor: its `st_dev` must be that volume's device, else close the descriptor, remove the file it just made, and throw. Take the volume's device once, before the `open`, so a detach in between cannot change what is compared.
3. A cap, so no bug here can ever fill a real disk: remember the size an image was created with (`create(sizeMegabytes:)`) and stop with an error, removing the ballast, when `written` passes twice that size without the disk having reported `ENOSPC`. An image of 3 MB can never take 6 MB of ballast.
4. Put the decisions in small pure functions the always-on tests can call (a refusal reason from `attached`, the descriptor's device, the volume's device; the cap check from `written`, the capacity), with comments.
Tests: in `DiskImageDrillTests`, the pure decisions (attached or not, same or different device, under and over the cap, the exact boundaries); in `StorageDrillTests` (opt-in, after the guards exist), `fillToCapacity` on a 3 MB image that was detached throws, makes no file in the mount point folder (`contentsOfDirectory` is empty), and a normal fill of an attached image still leaves about the reserve free (the existing full-disk test at :90 covers that: keep it green).

### 2. The sweep spares a running test run's images (finding 12)
`DiskImage.sweepLeftovers()` (:258-275) detaches every `TMDrill-` image under any `TextMouthTests-*` sandbox, including the sandbox of a test run that is going on at the same moment. Required: skip an image whose sandbox folder is `TextMouthTests-<pid>` for a pid that is running (`TextMouthRuntime.isProcessRunning(_:)`, `TextMouth/App/TextMouthRuntime.swift:221`) and is not this process (`getpid()`); the folder's pid comes from `TextMouthRuntime.sandboxProcess(named:)` (:209). A sandbox name with no readable pid stays swept as today. Do NOT change `LeftoverImages.drillImages(inInfoPlist:sandboxPrefixes:)`: its existing test `testOnlyTheDrillsOwnImagesAreFound` names arbitrary pids (777 to 780) that may be running on a real Mac. Add a second pure step that `sweepLeftovers()` applies after it, taking the current pid and a liveness function as parameters so a test passes its own (the default being the real ones).
Tests (pure, in `DiskImageDrillTests`): an image under a running foreign pid's sandbox is kept out of the sweep; under a dead pid's sandbox it is swept; under this process's own sandbox it is swept even though "running"; an unreadable pid is swept; the folder's name is read from the path whichever way the base is spelled (`/var` and `/private/var`); the sweep still returns only what it detached.
