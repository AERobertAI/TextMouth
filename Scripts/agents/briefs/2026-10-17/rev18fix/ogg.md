## The file
`TextMouth/Services/OggHeaderReader.swift` (372 lines), pure Swift over two windows of the file: `head` (its first 256 KiB) and `tail` (its last 70,000 bytes). `parse(head:tail:)` (:112-129) takes `streamStart(in: head)` (:278-301: codec, channels, rate, Opus pre-skip, tags, serial) and `lastGranule(in: tail, serial:)` (:198-220), and gives the length from the last granule alone (:116-125). `PacketAssembler` (:227-258) joins one stream's pages into packets. `identify(_:)` (:306-322) accepts only a Vorbis or Opus first packet. Nothing may trap or loop without a bound, whatever the bytes are; keep the bounded searches, the CRC check on every page, and all arithmetic overflow-safe. Every function and non-obvious block gets a comment.

Do not guess a format detail: fetch the primary source (WebFetch) first. Vorbis I specification (xiph.org/vorbis/doc/Vorbis_I_spec.html): 4.2.2 (identification header; both block sizes are in byte 28, low nibble `blocksize_0`, high nibble `blocksize_1`, each as a power of two), 4.2.4 (setup header; the modes are at its end), 4.3.1 (an audio packet's first bit is 0, then the mode number in `ilog(mode_count - 1)` bits, least significant bit first), 1.3.2 and A.2 (granule position; a stream's first audio page). Opus: RFC 7845 section 4 (granule position, and a stream that starts at a nonzero position) and RFC 6716 section 3.1 (the TOC byte) and 3.2 (frame packing codes 0 to 3).

## Commits (one each, each with its tests; build and test after each)

### 1. The stream is found among the leading start-of-stream pages (finding 9)
Today `streamStart` fixes the stream to the first page's serial, so a file whose first page is another stream's start (an Ogg Skeleton "fishead", which ffmpeg2theora writes, or any file with a Skeleton) is unreadable, although the comment at :286 says multiplexed files work. Required:
1. From offset 0, walk the leading pages while each has the start-of-stream flag (0x02) (a page with a bad CRC or length ends the walk; keep what was found). For each such page of a serial not seen yet, its first packet is the packet that ends on that page (a lacing value below 255); a page where no packet ends, or no payload, is passed over. The first stream whose first packet `identify` accepts is the stream; its serial goes on as `StreamStart.serial`.
2. From the first page again, assemble only that serial's packets, as now (pages of other serials, Skeleton's included, are passed over). Everything after that is as today: tags from the second packet, and `lastGranule` for that serial only.
3. A file whose leading start pages hold no Vorbis or Opus stream is still nil (FLAC, Speex, Theora, an unknown codec); a first page without the start flag is still refused (`testAFirstPageWithoutTheFirstPageFlagIsRefused`); two start pages of one serial count once.
Tests (new `OggHeaderReaderTests` cases, synthetic): a Vorbis file whose first page is a fishead (serial 1, `"fishead\0"` plus filler), then the Vorbis start page (serial 2), then a fisbone page of serial 1, then the Vorbis comment, setup, and audio pages, reads with the same format, duration, and tags as the same file without Skeleton; the same for Opus; a Theora start page before the Vorbis one; fishead plus Theora only gives nil; a later page of the Skeleton serial with a granule larger than the stream's is ignored for the length; a Skeleton page between the comment packet's pages is passed over (the existing `testAnotherStreamsPageBetweenCommentPagesIsSkipped` pattern).

### 2. The stream's start offset is subtracted (finding 8)
Today the length is the last granule alone (Vorbis `granule / rate`, Opus `(granule - preSkip) / 48000`), so a stream that starts at a nonzero granule (a recording cut from a live Icecast stream an hour in; Vorbis I A.2, RFC 7845) reads long: a 30-minute episode an hour in reads 5,400 s, `OggAudioConverter.check` then refuses afconvert's true 1,800 s, and the import fails (or a library book fails at every launch). Required, as libvorbisfile (`_initial_pcmoffset`) and opusfile (`op_find_initial_pcm_offset`) do it:
1. The stream's **start offset** is the granule of its first audio page less the samples that page's packets produce (every audio packet that completes on the pages up to and including the first one with a granule of 0 or more, counted in the packets' own order), never below 0. A page that completes no audio packet is not the first audio page, whatever its granule; header pages are the identification, comment, and (Vorbis only) setup packets, so Vorbis has three header packets and Opus two. If a page completes audio packets beyond the headers on the same page, those count as audio.
2. **Opus:** a packet's samples are its TOC byte's frame size times its frame count at 48,000 Hz (RFC 6716 3.1 and 3.2: config 0-11 gives 10/20/40/60 ms by `config & 3`; 12-15 gives 10/20 ms by `config & 1`; 16-31 gives 2.5/5/10/20 ms by `config & 3`; frame count code 0 is one frame, 1 and 2 are two, 3 is the byte after the TOC, `& 0x3F`, and 0 there is invalid). Confirm these against the RFC before you rely on them. An empty packet or one over 120 ms is invalid. The length is `(lastGranule - startOffset - preSkip) / 48000`, not below 0.
3. **Vorbis:** a packet's samples are `(previousBlock + thisBlock) / 4` using each packet's block size (`blocksize_0` or `blocksize_1`, from its mode's block flag); the first audio packet of the stream produces none and only sets `previousBlock`. The mode's block flag comes from the setup header: the modes are its last part, `mode_count - 1` in 6 bits, then per mode a block flag bit, two 16-bit zero fields (window type and transform type), and an 8-bit mapping, then the framing bit; since the setup header's earlier parts are variable, read them backwards from the end of the packet (the last set bit is the framing bit) as ffmpeg's Vorbis parser does, accepting a mode count only when every mode record reads back with both 16-bit fields zero and the count field matches. The length is `(lastGranule - startOffset) / rate`.
4. **Fallbacks keep today's behavior, never a failure:** whatever cannot be read (the first audio page is not wholly inside `head`, a packet that is not an audio packet, no setup header the mode search can make sense of, no page with a granule within a bounded number of audio pages) gives start offset 0, which is the old length. A normal stream's first page granule equals its own samples, so its offset is 0 and nothing changes for it: the existing tests, including the two real-fixture tests that read within 0.1 s, must stay green untouched.
5. `streamStart` today stops after two packets and returns the file as readable though the comment packet is unfinished; keep that exactly (tags empty, header still read), and let a setup header or audio page that cannot be completed only cost the offset.
6. Expose the offset to the tests through one internal, documented accessor (not a new field of `Header`, which other code and tests compare), so that a test can assert it.
Tests (synthetic, with a small least-significant-bit-first `BitWriter` in the test file for the setup header's modes): Opus cut an hour in (first audio page granule 172,800,000 + the page's samples; e.g. three 20 ms CELT packets, TOC `0xF8`, 960 samples each; last granule 172,800,000 + 86,400,000 + ...) reads its true duration, and the same stream with the first granule equal to its samples reads as before; a code-3 packet with 3 frames and a 2-frame code-1 packet are counted right; Vorbis cut an hour in with two modes (one short, one long block, different block sizes in the identification header) and a mixed run of short and long packets reads its true duration to the sample; a one-mode setup header (0 mode bits); a setup header with filler that holds a false zero run before the real modes; a first audio page with granule -1 followed by a page with a granule; and each fallback in item 4 gives the old length without failing. Both real fixtures report offset 0 through the accessor (one added assertion in each of the two existing real-fixture tests; no new read of a real file). The seeded random and corrupted-stream tests must stay green and cover the new paths: extend their generators if they cannot reach them.
