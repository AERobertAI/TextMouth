# Task index (REV18c finding 10): a write that throws makes the library forget what it remembered of the file

Slug `rev18fix-index`, branch `rev18fix/index` (made from `team/rev18fix`). Read `Scripts/agents/briefs/2026-10-17/teams-common.md`: "The worker's part", "Rules for everyone", "The board", "Builds", "Usage", "Lessons from October 16", "Keeping the cost down".

## The problem
`LibraryPersistenceService` skips a write of library.json, or of a feed's index, when the freshly encoded bytes equal what this process last read or wrote of that file and the file is still there (`SavedFile.OnDiskMemory`, `TextMouth/Services/SavedFile.swift:136-195`; `holds` :177, `remember` :185, `forget` :192). A skipped write counts as a success and clears the checkpoint journal (`writeIndexFile`, `LibraryPersistenceService.swift:438-456`). The memory is only updated after a write succeeds, so after a write **throws**, it still holds the older bytes although the file's state is then unknown: a rename on a network volume (SMB) can land yet report failure. Then an undo (or any later save whose bytes equal the older ones) is skipped, counted a success, and clears the journal, while the file holds the newer bytes. Two places do it:
- `writeLibraryFileIfChanged` (`LibraryPersistenceService.swift:475-487`): `try data.write(to: file, options: .atomic)` then `libraryIndexOnDisk.remember(data, for: libraryIndexMemoryKey)`.
- `writeFeedIndexes(of:)` (:520-542): `try FeedIndexFiles.write(index, in: root)` wrapped to throw `FeedIndexWriteError`, then `feedIndexesOnDisk.remember(index.data, for: index.feedID)`.

## The fix (one commit)
1. One helper on `SavedFile.OnDiskMemory`, with a doc comment, that both callers use (DRY): it runs the write it is given and, when that throws, forgets what the memory held for the key before rethrowing; when it succeeds, it remembers the new bytes. For example `mutating func write(_ data: Data, for key: Key, using write: () throws -> Void) rethrows`. Rewrite both call sites with it; the feed index's wrapping of the error into `FeedIndexWriteError` stays inside the closure it passes. The two `remember` calls that follow a write today go away; the `remember` for a feed whose index is not made (:531-534, no folder) stays as it is.
2. Fix the doc comments that say "the bytes are remembered only once they are on disk, so a write that failed is made again by the retry" (:469-474, `OnDiskMemory.remember`'s :181-184): a failed write now also forgets the older bytes.
