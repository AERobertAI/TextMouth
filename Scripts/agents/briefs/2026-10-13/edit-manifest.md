## Part A: Edit Manifest (one commit per item, each with its tests)
1. **Which books.** One predicate: an audiobook of the library's own (not a feed's item), in a package of its own, whose audio is a folder of tracks played one per heading (the multi-file layout). Not a single-file audiobook, and not a book whose manifest has `segments` (a converted DAISY book). Pin it with tests.
2. **The commands.** Mirror Edit Text exactly (`TextMouth/Services/BookTextEditor.swift`, FR05): "Edit Manifest in Default Editor" and "Edit Manifest With…", offered wherever Edit Text's two commands are offered (a reader's Book menu, a book's context menu, and its actions in VoiceOver's Actions menu), for the books in item 1 only. Open `manifest.json` with the default app for JSON (`public.json`), or the app the user chooses, after the same first-use explanation, worded for a manifest. If Edit Text's commands have Shortcuts entries, add matching ones with no default key. Share Edit Text's session, watcher, and app-choosing machinery rather than copying it: generalize it to a file in the package where needed (DRY), keeping Edit Text's behavior and tests unchanged.
3. **A manifest for a book without one.** Edit Manifest writes one first, from the book as it is: its tracks in their present order, each with its heading's present title, in the `tracks` format, the book's present `title` and `author`, and `"pauseBetweenTracksMs": 0`. A book without a manifest plays its tracks gaplessly, and opening it for editing must not change that. Write it where FR15's locator will find it.
4. **Taking an edit.** As Edit Text takes one: a change seen by the watcher, or when TextMouth becomes active, is checked with FR15's import checks against the book's own tracks. A manifest with a problem changes nothing: the alert names the problem, in the same words an import uses, and the session stays open, so the next save is taken. A good one rebuilds the book's headings from its audio folder, through the reader's own parse, and does everything below. It saves the content index and the record, updates the library row (the duration and counts its list shows), and refreshes the book's open readers. It announces "Manifest updated", at once while TextMouth is active, or when it becomes active.
   - Title and author stay the same in the manifest and the book, both ways. The user, October 13: "I kind of think hand edited meta data in TextMouth in this case should just be synced / stored in the MANIFEST since it's both user editable and them diverging might get someone confused." An edited manifest's `title` and `author` become the book's. An edit of the book's title or author in TextMouth (the metadata editor, Get Info) is written into its manifest at once. The launch's metadata refresh never sets a manifest book's title or author on the row alone: whatever it would change, it changes in both, or not at all. Route every write through one function, so no path can make them diverge, and test each path.
5. **Places follow their tracks.** No track is added or removed by a manifest (a track it leaves out is still a heading), so an edit only renumbers chapters. The reading position, every bookmark, and anything else saved by chapter and offset move to the same track, at the same time into it: map each old chapter to its file, and the file to its new chapter. Use the existing place-moving path (T06's `MovedPlaces` and its commit) if it fits, so the row, the record, and open readers agree. Tests: reorder the tracks; the position and a bookmark stay on their tracks at their times; group headings and titles change nothing but headings.
6. **A book open, or playing, while the edit is taken.** An open reader shows the new headings, with its cursor on the same track at the same time. A playing reader keeps playing the same file without a break, and goes on to the next track in the new order. Read how Edit Text refreshes an open reader that is speaking, follow it, and test a playing reader with silent fixtures.
