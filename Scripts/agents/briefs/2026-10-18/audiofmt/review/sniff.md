# Review fix sniff: the content decides, not the extension (review item 3, medium)

Slug `audiofmt-sniff`, branch `audiofmt/sniff` made from `team/audiofmt`. Read `../common.md`, then `common.md` in this folder, then this brief.

## The bug
Every guard trusts the extension, while Core Audio reads the content: an Ogg Vorbis file named .m4a or .flac opens as 'Oggf' through AudioFile. A feed episode's extension comes from the server's MIME type (`TextMouth/Services/Feeds/FeedEpisodeImporter.swift` lines 30-59): MP2, MP1, and .mpa arrive as audio/mpeg and are saved as .mp3, and AIFC arrives as audio/x-aiff and is saved as .aiff. Neither is converted, so the probe, the player, and transcription run Apple's MP2, IMA4, and µ-law decoders in TextMouth's process. The review's renamed samples: `/private/tmp/claude-501/-Users-roberteggleston-programming-ai-claude-swift-TextMouth/8d971e15-7103-46cf-b45e-5c4d099f2f74/scratchpad/review-audiofmt-c/liars/` and `liars.sh`, `mp2asmp3.sh` beside it.

## What to build
1. **`AudioContentSniffer`**, a new file `TextMouth/Parsers/AudioContentSniffer.swift`: what a file holds, from its first bytes, read in the app with no Apple audio API. Open it with `open(2)` and `O_RDONLY | O_NONBLOCK`, `fstat` the descriptor and read only a regular file, at most 64 KiB, and never a file that is only in the cloud (`DatalessFiles.isDataless`, checked first). The kinds:
   - Ogg ("OggS"); AC-3 and E-AC-3 (the sync word 0x0B77); CAF ("caff"); AIFC and AIFF ("FORM", then "AIFC" or "AIFF" at byte 8); AU (".snd"); Wave64 ("riff" and its GUID); AMR ("#!AMR"); 3GPP (`ftyp` with a `3gp` or `3g2` brand); other MPEG-4 and QuickTime (`ftyp` of any other brand, or a file starting with a `moov`, `mdat`, `wide`, `free`, or `skip` box); WAVE ("RIFF", "RF64", or "BW64", with "WAVE"); FLAC ("fLaC");
   - MPEG audio by its frame header's layer bits, after any ID3v2 tag (whose size is a synchsafe integer), the first frame confirmed by the next frame's header (a stray 0xFFE sync is common): layer I, II, or III; ADTS AAC (sync 0xFFF, layer 00); and unknown.
2. **The rule.** In the app's safe set: MPEG layer III; ADTS AAC; WAVE whatever its codec (coded WAVs are the user's question 4, not for now); AIFF; FLAC; and MPEG-4 or QuickTime whose first audio track afinfo names AAC (`aac `, `aach`, `aacp`), Apple Lossless (`alac`), or MP3 (`.mp3`). Converted, whatever the extension: Ogg, AC-3, E-AC-3, CAF, AIFC, AU, Wave64, AMR, 3GPP, and MPEG layers I and II. MPEG-4, QuickTime, and unknown content are settled by `AudioFileInfo.read` (afinfo in its child process): converted when afinfo names another codec (`ac-3`, `ec-3`, `opus`, `flac`, `samr`, `lpcm`, …) or another container; left as they are when afinfo cannot read the file at all (afconvert could not convert it either, and the probe refuses it as today).
3. **At import, on every path.** `FileImportService.convertImportedAudio` (`TextMouth/Services/FileImportService+AudioConversion.swift` lines 32-55) decides by content: in a folder, for every track the import's scan finds (`ImportAudioConverter.filesToConvert(in:)`), and for a single file whatever its extension. A feed episode reaches this as a single file and needs nothing of its own; prove it with a test through `FeedEpisodeImporter.importEpisode`. Run afinfo only where the bytes do not settle it, at most `maximumConcurrentConversions` at once, and measure what it adds to an import of a folder of 50 .m4a tracks (report it).
   - **Names.** A converted file takes its source's stem with .m4a, as today. When that is its source's own name (`x.m4a` holding AC-3), the converted file takes the name once the source is removed or kept, never "x 2.m4a" (find where the final name is taken: `convertEach`, `givingFinalName(_:)`; the source must give way first).
4. **`isNeverDecodedInApp`** (`ImportAudioConverter.swift` about lines 172-174) also says yes for a file whose first four bytes are "OggS", read as above (non-blocking, regular files only, never a dataless file), so an old book's misnamed Ogg is never opened in the app. The probe, the player, transcription, and the editor ask it, some on the main thread: keep it to one open and four bytes.
5. `plan(for:info:)` and `filesToConvert(in:)` follow the new rule. Keep `isConvertedAtImport` for what it still answers (the import's extension list; `metadataAsset`), and say in its doc comment that at import the content decides.

## Tests (a new class `AudioContentTests`, and one fixture)
- **The sniffer's kinds**, each from a few bytes written in the test (no audio API): an MP3 frame pair after an ID3v2 tag; an MPEG layer II pair; a lone 0xFFE sync that no second header confirms (unknown); an empty file; a three-byte file.
- **Misnamed files import converted:** `tones.mp2` named `.mp3`, an AIFC of IMA4 (made in the test with `/usr/bin/afconvert -f AIFC -d ima4`) named `.aiff`, and the Ogg Vorbis fixture (`TestData/audio/ogg-vorbis-tone.ogg`) named `.m4a`. Each imports as a single file whose book file is an `.m4a` of AAC; the `.m4a`-named one keeps its name. Commit a one-second MP2 fixture, `TestData/audio/tone.mp2`, made with `/opt/homebrew/bin/ffmpeg -c:a mp2` (the doc comment gives the command). One of the three goes through `FeedEpisodeImporter.importEpisode` as well.
- **Real files stay as they are:** an MP3, an AAC .m4a, a WAV, an AIFF, and a FLAC (made in the test with afconvert, or from `TestData/format-samples/`).
- **`isNeverDecodedInApp`** says yes for the Ogg named `.m4a` and named `.flac`, and no for a real `.m4a`; it returns at once for a FIFO named `x.m4a` (made with `mkfifo`), on which it must not block.
