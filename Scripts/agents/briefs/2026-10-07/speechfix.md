## Why
On October 7 the user reported "suddenly my audio is randomly pausing and I can't restart it" (B01). `fix/speech-markup-guard` (merge aec5c91b) guarded tag-shaped text and added a recovery: an utterance the engine cancels is spoken again once on a fresh synthesizer, and a second cancel at the same place ends speech with "Speech stopped: the Mac's speech engine refused this text." A read-only review that evening found the recovery can bring back the "can't restart" symptom, and that the guard is untested on some shapes of text. The B01 entry in TODO-2026-09-04.md (section "Feature requests and bugs (October 7)"), the speechguard agent's notes in AGENT-NOTES-2026-10-04.md, and its brief `speechguard.md` beside this file hold the diagnosis. The offline probes it used are in `Scripts/agents/probes/` (they render with `AVSpeechSynthesizer.write(_:toBufferCallback:)`, which plays nothing).

## A rule from earlier work
Never switch from direct speech (`AVSpeechSynthesizer` speaking aloud) to the engine (rendered audio) while an utterance plays: `willSpeakRangeOfSpeechString` runs ahead of the audio by an unknown few words, so a handoff mid-utterance repeats or cuts text. Switch only where nothing plays: a seek, a pause and resume, a chapter boundary, or, as here, after the engine refused an utterance that never started.

## Items, one commit each, each with its tests
1. **A refusal that ends speech lets go of the synthesizer that refused** (review finding 1, confirmed by the orchestrator). `endDirectSpeechRefused(at:)` (SpeechService.swift about line 1080) calls `stopDirectSynthesizer()` and keeps the synthesizer that took the retry and refused it. By the guard branch's own measurement, such a synthesizer never speaks again and reports nothing, so the next Play speaks into silence with `isSpeaking` true: the original symptom. Replace it there (`replaceDirectSynthesizer()`, which stops the old one first). `testSpeechSpeaksAgainAfterARefusalEndedIt` (SpeechDirectChunkingTests.swift about line 393) passes for the wrong reason, since its recorder never reaches a synthesizer: make it assert that the synthesizer after the end is not the one that refused, through a seam no production code uses.
2. **The retry speaks the refused chunk strictly guarded.** Today the retry speaks the same guarded text again, so any shape the guard misses is refused twice and speech stops, and Play at that place is refused again. Add `SpeechMarkupGuard.neutralizedStrictly(_:)`: every `<` and `>` (and `&`, if the probes in item 3 show the engine's markup parser chokes on it) becomes a same-length character the engine does not speak or parse, so offsets stay exact. The retry after an unexpected cancel speaks the rest of the refused chunk strictly guarded; later chunks go back to the normal guard. A lone "less than" inside that one chunk is then not spoken, which is acceptable there; say so in a comment. Tests: the strict guard keeps every length; the retry uses it for that chunk only.
3. **Measure the shapes the guard leaves alone** (review finding 3). The opening-tag pattern (SpeechMarkupGuard.swift about line 82) needs the name's first character to be a letter, digit, `_`, or `:`, but `<5>` already swallowed text, so the engine does not follow XML's name rules. Add probe variants and run them offline: `the omitted <...> passage`, `a <=> b`, `x <-> y`, `<$fh>`, `<*>`, `<-- aside -->`, `<!-- comment -->`, `<?xml version="1.0"?>`, `<!DOCTYPE html>`, `fish & chips`, `&amp;`, `&#60;`, `AT&T`, each inside a longer sentence so swallowing is audible as missing words in the rendered length. Record each result in the probe file. Where a shape swallows text silently (no cancel, so no recovery runs), widen the default guard (the reviewer suggests the first name character be anything but `<`, `>`, whitespace, or `/`, and checked that every string in `untouchedTexts` stays unchanged under that rule). Pin every measured shape in SpeechMarkupGuardTests.
4. **A refusal uses the chapter's rendered audio when it matches** (review finding 6). The watchdog's recovery (about lines 963-992) switches to the engine at the offset when `renderedAudioMatchesSpeech`; the cancel recovery (about lines 1034-1044) never does, though for a refused direct chunk the whole-chapter render may have succeeded (B01's own case: balanced tags rendered while a chunk holding only `</sm>` was refused). After an unexpected cancel, when rendered audio matches, switch to the engine at the retry offset instead of retrying direct speech; nothing plays at that moment, so the rule above holds. The engine-switch block appears in about four places (lines near 974, 1146, 1319, 1504): extract one helper they all use, behavior unchanged, and say so. If the extraction proves risky, do only the switch at the cancel and report the duplication as a follow-up.
5. **`RenderCancellationObserver` needs no `@unchecked Sendable`** (finding 7). The SDK marks `AVSpeechSynthesizerDelegate` `NS_SWIFT_SENDABLE`, the observer's two stored properties (a semaphore and a lock) are Sendable, and main compiles `LibraryInfoSpeechDelegate` with no annotation. Drop it if Swift 6 accepts that, correct its comment, and move `UncheckedConcurrencyPolicyTests`'s pin from 27 to 26 (if `followups7` changes the pin too, the rebase keeps both changes).
6. **`testARenderHandsTheSynthesizerTheTextGuarded` pins something** (finding 8). It passes even unguarded wherever the engine accepts the raw chunk. Render the raw chunk first through `_spokenTextForTesting = { $0 }` and skip unless the engine refuses it, as its sibling test does.
