# Editing settings in config.json

Part of [TextMouth's documentation](../../README.md).

config.json, in the data directory, mirrors TextMouth's settings so you can read and change them in a text editor, and copy them to another Mac.

- When it is read:
  - At launch, TextMouth applies the file first, because it may have been edited while TextMouth was closed.
  - While TextMouth runs, it notices a saved edit within a moment and applies it.
  - Every change you make in Settings saves the file again, a moment after the last change, so a slider dragged through many steps writes it once, and quitting writes a save still waiting. An edit saved to the file in that moment is merged with the changes, not written over.
  - When config.json is only in the cloud, TextMouth neither reads it, which would wait for a download, nor writes over it, which would replace what another Mac saved: the settings on this Mac stand, and the first save that finds the file on this Mac merges it as an edit.
  - While the library isn't available, TextMouth neither reads, writes, nor watches the file, which may hold another library's settings. Once the library is back, a setting changed meanwhile keeps its new value, and every other one takes the file's.
- How values are checked:
  - Each field is read on its own, so one mistake never discards the rest of the file. A number out of range is moved to the nearest allowed value, a value that cannot be read counts as missing, and each repair is noted in the debug log (textmouth_debug.log, in the data directory's Logs folder, or in ~/Library/Logs/TextMouth when Storage settings put the logs there).
  - If the whole file is not valid JSON, TextMouth leaves it alone at launch and notes why in the debug log. The next settings change saves a fresh file over it.
  - An empty text field, an empty or unknown choice, and a speed or pitch of 0 all leave the current setting as it is.
  - A missing field also leaves its setting as it is, except for these, which are read as their defaults, so applying the file sets the default: rewindSmartMode, rewindSmartThreshold, sleepFadeOutDuration, sleepTimerAutoClose, punctuationPauseLevel, autoPlayOnNavigate, bluetoothMonitoringEnabled, bluetoothDisconnectDelay, restartTimerGestureEnabled, restartTimerGesturePattern, restartTimerGestureWindow, importDeleteBehavior, confirmBeforeDelete, moveToTrashInsteadOfDeleting, and keepsOriginalOfConvertedAudio.
- Which settings it carries, by Settings tab:
  - Voice: selectedVoiceID, wordsPerMinute (50 to 650), pitchMultiplier (0.5 to 2), and selectedLanguage.
  - Playback: skipForwardUnit, skipBackwardUnit, shiftSkipForwardUnit, shiftSkipBackwardUnit, rewindOnResumeUnit, rewindSmartMode, rewindSmartThreshold, punctuationPauseLevel, autoPlayOnNavigate, endOfBookBehavior, nextBookWindow ("This Window", the default, or "A New Window", the choice's name as Settings shows it, like endOfBookBehavior; see [Settings](settings.md)), sleepFadeOutDuration, sleepTimerAutoClose, playbackNavigationUnitControlMode, showBookmarkInPlaybackControls, showSpeedInPlaybackControls, showExportInReaderToolbar, includeSpeedWithTimes, showsPageInReader, and saysPageInWhereAmI (the Pages group's two checkboxes, true by default; see [Settings](settings.md)).
  - Shortcuts: keyboardShortcuts, an object naming every action as Settings shows it, the audio editor's and the New Recording window's with their group's name first, as in "Audio Editor: Play / Pause" and "New Recording: Stop"; TextMouth reads a name in any letter case, and one ending in "…" with three periods or none, and still reads the names earlier versions wrote, as in "Recording Window: Stop" for the New Recording window's buttons and "Add Bookmark" for the bookmark command, now Toggle Bookmark in the menu, the Shortcuts tab, and config.json, writing only the new names. An action whose shortcuts you changed (see the Shortcuts tab, under [Finding your way around](../../README.md)) is a list of its shortcuts, written like `option+shift+command+b`, as in "Release Media Controls": ["shift+r"], and an empty list leaves it without a shortcut. An action you changed whose Works in differs from its default is an object, as in "New from Text…": {"keys": ["shift+command+t"], "worksIn": "Every window"}. TextMouth writes the Works in pop-up's words, and reads them, or "every", "app", "library", or "reader", in any letter case, as it reads "keys" and "worksIn"; "keys" may be one shortcut written as text, an object without "worksIn" counts as a list, and a list works where its action does by default. An object naming no kind of window TextMouth knows isn't read. One naming a kind its action can't work in, such as Add Feed… in reader windows, is left out, noted in the debug log, and the file is saved again; so is an entry giving an action a key one of macOS's own commands has, unless it is that action's default, or giving a menu command or a New Recording window button anything but one shortcut with Command or Control that a text field doesn't edit with. A double press is written with "twice" after the shortcut, as in "w twice", and TextMouth also reads "W Twice", "wtwice", and "double w"; a named key is written by its name, as in "command+pageDown" or "f5", and a file holding the key's own character reads the same. Every other action is text: "default", a colon, and the shortcuts it has, as in "Where Am I?": "default: w", or "default: none"; an action that works in Library or reader windows by default names that kind of window after "default", as in "Show Sleep Timer": "default in reader windows: shift+command+t", and editing those words changes nothing. Write a list to make an action yours, even with its default keys (a file of only lists is the exception, described below), and text beginning with "default" to give it back to TextMouth's defaults; TextMouth never reads the words after "default", and reads any other text as one shortcut. A shortcut given to one action is taken from any other that works in any of the same windows (see Works in, under the Shortcuts tab), so one key can do one thing in an editor window or a Library window and another elsewhere. If an edit leaves one key on two actions you changed, the one whose entry you changed keeps it (when you changed both, the one the Shortcuts tab lists first), and the other goes without that key, keeping its others; TextMouth notes it in the debug log and saves the file again a moment later, to show the shortcuts in force. An action the file leaves out keeps its shortcuts. shortcutDoublePressSeconds is the double-press time (see the Shortcuts tab, under [Finding your way around](../../README.md)), 0.2 to 2 seconds: a value out of range, or between tenths, is read as the nearest allowed one and noted in the debug log, and a file without it leaves the time alone.
    - A file in the form earlier versions wrote, a list for every action with no text beginning with "default" and no object, is read as the old form it is: a list that equals a default its action has or once had edits nothing, and so does one that equals a default without the keys other actions' lists in the file hold, so an action you changed in the app keeps your change, an action you didn't change keeps following TextMouth's defaults, and only a list that differs from every default makes its action yours. A file you write by hand holding only lists is read the same way, so in it a list of an action's default keys pins nothing; add one entry that is an object or text beginning with "default", and every list in the file makes its action yours, even with its default keys. When TextMouth leaves a list out for being a default, it saves the file again a moment later, in the new form, to show the shortcuts in force.
  - Text: substitutionsEnabled, the switch for the substitution rules, and the repeated-symbol settings: repeatedSymbolStyle ("repeat", "count", or "omit"), repeatedSymbolThreshold (2 to 99, or -1 to read every symbol; any negative number reads as -1, and 0 or 1 as 2), and repeatedSymbolSet (the symbols written together, such as "*-=_~#", each counted once, with letters, digits, and spaces ignored; empty keeps the current ones). The rules themselves are in substitutions.json.
  - Braille: brailleTable, the table braille files are read and written with, by its file name: "en-ueb-g1.ctb" or "en-ueb-g2.ctb" for Unified English Braille, uncontracted or contracted, and "en-us-g1.ctb" or "en_US.tbl" for English Braille, American Edition, uncontracted or contracted, or "mac:" and the file name of one of this Mac's VoiceOver tables, such as "mac:fr-bfu-g2.ctb" (see the Braille tab, under [Settings](settings.md)). TextMouth writes the table in use, "en-ueb-g2.ctb" until one is chosen. A missing, empty, or other value, such as a name that is not exactly one of these four or "mac:" and a bare file name (no slash or comma, and not starting with a dot), leaves the current table as it is. A "mac:" name is taken as it is, without reading this Mac's tables: TextMouth checks the table before its first use, and an import or an export that needs a table this Mac lacks or refuses fails by name (see [Adding books](adding-books.md)). It chooses the table for books imported and braille exported from then on; a book already in the library keeps the table it was imported with. brailleFileCode, the braille file characters a BRF or BRL file is read with, by id: "ascii-na", North American Braille ASCII, or "ascii-eurobraille", Eurobraille, six-dot (see the Braille tab, under [Settings](settings.md)). TextMouth writes the one in use, "ascii-na" until one is chosen. A missing, empty, or other value, "unicode" included, since TextMouth recognizes Unicode braille patterns by a file's bytes and never takes them from the setting, leaves the current choice as it is. It chooses the characters for books imported from then on, and the Export dialog starts a BRF with them; a book already in the library keeps the characters it was imported with (see [Where TextMouth keeps your library](where-your-library-lives.md)).
  - Sounds: soundEffectsEnabled, soundEffectsVolume (0 to 1, in hundredths), and soundEffectAssignments, an object naming each playback event as Settings shows it, with the sound it plays; "None" plays nothing. An event the file leaves out keeps its sound.
  - Storage: logLocation, where the diagnostic logs are written ("dataDirectory", the default, or "machine"); recordingOriginalPolicy, what happens to the original audio of recordings and edited audiobooks ("keep", "delete", or "deleteAfterDays", the default; the name is from when only recordings kept an original), and recordingOriginalDays, the days "deleteAfterDays" keeps it (1 to 365); useInstalledFFmpeg, whether an installed ffmpeg runs the audio editor's filters (true by default); audioEditorPreviewsFilters and audioEditorPlaysAfterMoves, whether the editor's Apply Filter previews a filter before applying it, and whether the editor plays half a second at the cursor after each move (both true by default); and importDeleteBehavior ("Keep Original", "Delete After Import", or "Ask Each Time"), confirmBeforeDelete, moveToTrashInsteadOfDeleting, and keepsOriginalOfConvertedAudio (false by default), whether an import keeps the original of the audio it converts, which config.json alone keeps.
  - Miscellaneous: bluetoothMonitoringEnabled, bluetoothDisconnectDelay (1 to 10 seconds), restartTimerGestureEnabled, restartTimerGesturePattern, and restartTimerGestureWindow (0.5 to 10 seconds).
  - The New Recording window, which isn't a Settings tab: recordingInputDeviceID, the macOS identifier of the microphone it records from, which TextMouth writes empty until one is chosen. An empty value keeps the current choice, and a microphone this Mac doesn't have, such as one chosen on another Mac sharing the library, gives way to the system's input. recordingAnnouncesLevel, whether it announces the level while recording (false by default), and recordingLevelAnnouncementSeconds, how many seconds apart (5 to 60, 10 by default).
  - Library: libraryViews, the Library window's views in the order its View pop-up offers them (see the Library tab, under [Settings](settings.md)). It is a list, and each entry is an object. A built-in view's entry names the view by "id", one of "Folders", "All Items", "Unopened", "Recently Opened", "Reading List", or "Feeds", and gives its "visibility", "always", "whenApplicable", or "hidden"; it holds "name" or "filter" only once you have changed them, so a later TextMouth can improve the views it ships. A view of your own holds "id", a UUID, "name", "visibility", and "filter", all four. A filter is an object with "lists", any of "books", "episodes", "articles", and "feeds", at least one; "match", "all" or "any"; "conditions", a list; "onePerFeed", written only when true; and "limit", written only when set, an object with "count", 1 to 9,999, and "chosenBy", "lastOpened", "dateAdded", or "viewSort". A condition is an object with "test" and, by the test, "value", "folderID" and "includingSubfolders", "days", or "text"; and "not": true when the condition is negated. The tests are "format" (with "value", a format's name such as "epub"), "folder" ("folderID", a folder's UUID, or null for the top of the library, and "includingSubfolders", true or false), "readingState" ("value", "unopened", "inProgress", or "finished"), "inReadingList", "addedWithin" and "openedWithin" ("days", 1 to 3,650), "titleOrAuthorContains" ("text", up to 200 characters), "hasNewItems", and "subscribed". A view holds at most 20 conditions, a name is at most 60 characters, and the list holds at most 200 views in all, the built-in views among them. For example:
    - `{ "id" : "6F9619FF-8B86-D011-B42D-00C04FC964FF", "name" : "Unread EPUBs", "visibility" : "always", "filter" : { "lists" : [ "books" ], "match" : "all", "conditions" : [ { "test" : "format", "value" : "epub" }, { "test" : "readingState", "value" : "unopened" } ], "limit" : { "count" : 20, "chosenBy" : "dateAdded" } } }`
  - How libraryViews is read: each entry on its own. An entry this TextMouth cannot read, with an id, test, format, state, or kind it does not know, a view of your own without a name or a filter, a filter that lists nothing, or an id an earlier entry has, is kept exactly as it is, in its place, written back, and never offered; the Library tab says how many there are. A number out of range is moved to the nearest allowed value, a text is cut to its limit, and an unknown visibility reads as the view's own default, Always for a view of your own; Folders is always Always. These repairs are noted in the debug log, and, since they only make the entry fit for showing, the file keeps what it said until you change that member in Settings. Entries past 206 are dropped, with a note in the log. A built-in view the list lacks is added at its end as TextMouth ships it, so a hand edit cannot lose one; a second entry of a built-in view that holds only its id and visibility is dropped. A built-in view whose filter cannot be read shows its shipped filter, in its place, and its entry is kept as it is. Two views with one name show the later one numbered, as "Feeds 2". An empty list, or none, changes nothing. An older TextMouth drops libraryViews from config.json when it saves the file, but this Mac keeps the views in its preferences, and a config.json without the key changes none, so the next TextMouth writes them back.
  - Where each view's sort is kept: not in config.json. Every view's sort stays in library.json with the folders' sorts, a view of your own's and Feeds' under a key that begins with "/views/", as "/views/Feeds" (see [Where TextMouth keeps your library](where-your-library-lives.md)).
  - Library, the Titles section: leadingArticles, what a title's leading article does in the Library's lists (see the Library tab, under [Settings](settings.md)): "partOfTitle", the default, "ignoredWhenTyping", or "ignoredWhenTypingAndSorting". TextMouth writes the choice in force. A missing or empty value, or a name that is not exactly one of these, leaves the current choice as it is.
  - Feeds: feedRefreshAtLaunch (true by default); feedRefreshIntervalHours (1 to 168, the default 1, or 0 to refresh only at launch and when asked; any number below 1 reads as 0); feedItems, the List and download choice (see Listing and downloading, under [Podcasts and article feeds](feeds.md)): "everyListedNewestDownloaded", the default, "everyListedDownloadsByHand", or "onlyNewestListed", a name TextMouth doesn't know, or none, leaving the choice as it is; feedNewestCount, the number that goes with it (1 to 2,000, the default 5; a number outside reads as the nearer of the two); feedDeleteDownloadsDaysAfterPlayed (0, at once, to 365, the default 1, or -1 never; any negative number reads as -1); and feedRefreshAlert and feedNotifications (false by default), whether a refresh TextMouth makes by itself that brings new items shows an alert, and posts a notification for each feed. feedKeepEntries and feedAutoDownload, which feedItems and feedNewestCount replaced on October 10, 2026, are no longer read from config.json or written to it: the first launch of that version moved them to the choice, once, and left them in the preferences as they were.
  - Transcription, the Playback tab's Transcription group: transcriptionLocale, the language transcriptions use, as an identifier such as "en-US" or "en-GB". An underscore reads as a hyphen, as in "en_GB"; an empty value, or anything that can't be a language identifier, keeps the current language. TextMouth writes the language in use, this Mac's English until one is chosen. offerTranscriptionAfterImport, whether TextMouth offers to transcribe each audiobook it imports (false by default).
- Two fields describe this Mac rather than your preferences:
  - dataDirectoryPath: where the data directory is, empty for the default location. TextMouth always writes the folder in use. Changing it asks TextMouth to move the library there, exactly as Storage settings do, and emptying or deleting it names the default location. config.json can come from another Mac with a library in the cloud, so a request is ignored, with one CONFIG_FILE line in the debug log, when the folder it names doesn't exist on this Mac or already holds a TextMouth library: emptying the field moves the library back only when ~/.TextMouth exists and holds no library. A move needs an empty destination; a value TextMouth cannot read keeps the folder in use.
  - lastOpenedBookID: the book opened most recently, which TextMouth records itself.
- What stays out of config.json: window positions, the last sleep timer you used, a feed's and a folder's own listening choices, among them its Open the next book in, which a feed keeps in its own record and a folder in library.json (see [Podcasts and article feeds](feeds.md), [The Library window](library-window.md), and [Where TextMouth keeps your library](where-your-library-lives.md)), the preferences that record where the data directory is (its path, a bookmark of its folder, and the identity of the library expected there), this Mac's identifier for the Sessions folder, whether Edit Text has explained itself on this Mac (editTextExplained), whether this Mac has made the one-time move of finished books to their ends (library.finishedBooksAtEndVersion), the copy of every action's shortcuts that earlier versions saved, which TextMouth reads once to make the record of the ones you changed (customKeyboardBindings), and the hidden switch for trace logging. It also keeps out whether this Mac has written each library's hand-edited titles and authors into their manifests (library.manifestHandEditsKeptVersion).
