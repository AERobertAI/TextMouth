# Adding books

Part of [TextMouth's documentation](../../README.md).

- Add to Library, the plus button in the Library window's toolbar, opens a sheet with every way to add to the library. On October 17, 2026 it took the place of the toolbar's Import, New from Text, and Add Feed buttons, whose commands are all in the sheet.
  - VoiceOver calls the button "Add to Library", and its hint is "Opens a sheet with the ways to add to the library: open a book, import a folder, make a book from text, record audio, or add a feed". When the window lists no books and has no Continue button, VoiceOver's focus starts on it, where it started on the Import button before.
  - The sheet has a heading, "Add to Library"; a button for each way to add, in the order below, with what it does written under it, which VoiceOver speaks as the button's hint; and Cancel, which Escape presses. VoiceOver starts on the first button.
    - Open Book…: "Opens a file picker to import books in any format TextMouth reads."
    - Import Folder…: "Chooses a folder that holds a DAISY book or audio tracks and imports it as one book."
    - New from Text…: "Makes a new book from text you paste or type."
    - New Recording…: "Records from a microphone into a new audiobook."
    - Add Feed…: "Opens a sheet where you type a feed's address and choose where its folder goes"
  - Each button is named by its menu command, and VoiceOver adds the command's key in words when it has one, as in "Open Book…, Command + O". Choosing a button closes the sheet and then does what its menu command does, each described below. Cancel, or Escape, closes the sheet and does nothing.
  - A button is dimmed when you have set its action to work only in reader windows, which you can for Open Book…, New from Text…, and New Recording…, under Works in in the Shortcuts tab of Settings. Its hint then ends "Not available in this window."
- File menu, Open Book… (Command-O) imports the files you choose. Opening a supported file from Finder imports it and opens it.
  - TextMouth declares itself a viewer of rich text, rich text with attachments, Word 97-2003 documents and templates, Word templates and macro documents, OpenDocument text and templates, web archives, SSML files, BRF, BRL, and PEF braille files, M3U and M3U8 playlists, the audio formats it converts, and every .xml file, so Finder offers it in the Open With menu for them. It declares them at Alternate rank, as it does for every format but its own .tmb packages, so it never asks to be the default app for any of them. A .pef file is also a Pentax raw photo to macOS, so Open Book… accepts whatever type the system gives a .pef, and the import tells a braille file from a photo by reading it: a photo is refused with the sentence for a PEF that cannot be read (below).
- File menu, New from Text… makes a book from text you type or paste. Its key, Shift-Command-T, works in Library windows, and with no window open, when it opens New from Text… in a new Library window. In a reader window the same key opens or closes the Sleep Timer sheet (Show Sleep Timer); there, and in Settings, the New Recording window, and an audio editor's window, File > New from Text… is dimmed and shows no key, so choose it from a Library window. Either action can have another key, or work in another kind of window, from the Shortcuts tab of Settings (see Works in, under the Shortcuts tab).
- File menu, New Recording… (Option-Command-N), also in the Library menu, records from a microphone into a new audiobook (see [Recording from a microphone](recording.md)).
- Library menu, Import Folder… (Shift-Command-O, in a Library window) imports a DAISY book kept as loose files, by its folder, one folder per book, or a folder of audio tracks as one audiobook, as a ZIP of the same tracks imports. It was called Import DAISY Folder… before October 14, 2026, and a key you gave it keeps working. Opening such a folder from Finder imports it the same way.
  - The folder's tracks, and its manifest, at its top level or inside its one folder, are copied into the book's package, and the folder is left as it was. The book takes the folder's name unless the manifest gives a title. A folder holding neither a DAISY book nor tracks is refused, and the alert says what it holds.
  - A folder you import is never deleted or offered for deletion, whatever Storage settings say about originals, since it holds files that were not copied. Deleting an original also refuses a folder, or a link to one, whatever asked for it: nothing is deleted or sent to the Trash, and the debug log records ORIGINAL_KEPT with the folder's name.
  - A folder holding DAISY books in folders inside it is not a book itself and is refused: choose the book folders instead, several at once. The alert for it says that the folder holds no DAISY book and no audio tracks to import as one book, and lists the files found anywhere inside it, which does not say that the books are in the folders within.
- An M3U or M3U8 playlist (.m3u, .m3u8), chosen with Open Book…, imports as one audiobook of the files it lists, as a folder of the same tracks imports.
  - The book is named by the playlist's #PLAYLIST line, else by the playlist's file name without its extension, and has a heading for each entry, in the playlist's order, titled by its #EXTINF line, else by the file's name. The tracks are copied into the book's package, and those that need converting are converted (see [What TextMouth reads](what-textmouth-reads.md)). Importing the same playlist again finds a duplicate.
  - Only ordinary files inside the playlist's own folder, or in folders beneath it, are used. Each other entry is skipped and named with its reason: "a web address", "outside the playlist's folder", "not found", "a folder", "not an audio file", "hidden", "not an ordinary file", or "listed before". Once the book is in the library, an alert titled Book Imported lists them, as in "TextMouth skipped 2 entries of “mix.m3u”: “https://example.com/a.mp3” (a web address) and “More/c.mp3” (not found).", and the book is not opened. At most ten entries are named, fewer when the list would pass 600 characters, then "and N more", and an entry of more than 60 characters is shortened with "…", keeping its start and its file name.
  - A playlist and its tracks are never changed, deleted, or offered for deletion, whatever After Importing a Book says. TextMouth never fetches an address: a streaming playlist, for audio on the web, is refused, and so is one that lists only web addresses.
- Library menu, Add Feed… (Shift-Command-F, in a Library window), or the Add Feed… button of the Add to Library sheet (above), subscribes to a podcast or article feed (see [Podcasts and article feeds](feeds.md)).
- A ZIP of several books imports each of them (an .rtfd folder inside is one book, not its separate files), and TextMouth offers to create a folder for them. The progress overlay's Cancel button stops a ZIP import after the book in progress, or at once when that book is a rich text, Word 97-2003, OpenDocument, or Word 2003 XML document that textutil is converting, or a braille file that the braille helper is translating: textutil or the helper is stopped, that book is not imported, and the alert says after how many books the import stopped. A single file's import that Cancel stops that way ends with no alert.
- While books import, the import overlay in the Library window shows how far the import has got, and VoiceOver reads all of it there. For a ZIP archive it first counts the items and bytes extracted, as in "Extracting “Library Export.zip”: 120 of 300 items, 1.2 GB of 3.4 GB...", then the books processed, as in "2 of 100 books processed", with the book under way, by its name in the archive, and the step it is at, as in "Book 3 of 100: “Moby Dick.epub”, reading its text"; a single file, or a ZIP holding one book, shows its name and its step the same way, as do a TextMouth package opened from the Finder, from "checking the package" on, and a book made with New from Text, by the title you typed. A package's line says "copying it into the library" while it copies, and a recording saved from the New Recording window is named by its title the same way, its line going quietly once the save ends, since its window says how the save ended. The count's noun agrees with the total, as in "0 of 1 book processed", as it does in the overlay of a text cache update or of Redo Text Extraction, as in "0 of 1 book extracted". A ZIP holding one audiobook also counts the items and bytes extracted while it extracts, as in "“Harbor Talks.zip”, extracting the archive: 12 of 30 items, 120 MB of 340 MB". Once a book of several is done, the overlay gives the time left, as in "About 4 minutes left" or "Less than a minute left": it weighs each book still to come by its size where that tells its time, as an EPUB's, PDF's, Word document's, or text file's does, so a large book still to come counts for more, while an audiobook's file, a DAISY book, or an .rtfd folder counts at the average time such books took. When more imports wait behind the one shown, the overlay says how many, as in "2 more imports waiting", until Cancel is pressed. Once a book has taken 10 seconds, the overlay says for how long, as in "1 minute, 5 seconds on this book", in steps of 5 seconds, so a stuck book shows as a time growing on one step. For an import that runs 10 seconds or more, VoiceOver also hears, wherever you are, each quarter of a ZIP's books, as in "Importing “Library Export.zip”: 25 of 100 books processed, about 4 minutes left.", and how it ended, as in "Finished importing “Library Export.zip”: 97 books imported, 2 skipped as duplicates, 1 failed." A ZIP import that brings no new book, and in which nothing failed, says what it found in the Library window's alert, titled Nothing Imported, however quickly it ends: "No new books in “Library Export.zip”: all 24 were already in your library." ("both" for two, and "its one book" for one), or, for an archive holding no book TextMouth reads, what it holds instead, most files first, as in "No books were found in “Radio.zip”. It holds 176 .wma files, which TextMouth does not import." Up to three kinds are named, the rest counted as other files. The alert waits on screen, and VoiceOver reads it as it appears, so it is never missed as an announcement made while you were in another app could be. One with a failure says so in its alert instead. Cancel says at once "Cancelling after this book...", or "Cancelling..." before the first book, and the alert of a cancelled import says where it stopped. Library menu, Speak Import Progress has VoiceOver speak the overlay's lines on request, or say "No import is under way."; give it a key in the Shortcuts tab of Settings, under Information, to use it in every window but an audio editor's, a reader's included (see Works in, under the Shortcuts tab).
- When an import fails, an alert names the file, the step that failed, and why, as in "Could not import “notes.md”. Reading its text failed: This file has no text to read." Nothing is added to the library, and the original file stays where it was, whatever Storage settings say about originals. A ZIP batch lists each failed file by name with the same reason after it, while the batch's other books import, and the debug log records the same words in an IMPORT_FAILED line. These reasons have plain words of their own:
  - A plain text, Markdown, HTML, web archive, SSML, rich text, Word 97-2003, OpenDocument, Word 2003 XML, or braille file, or a DTBook on its own, with no text in it is refused with "This file has no text to read." That covers a file of no bytes, a file of only white space or only a byte-order mark, an HTML file or a web archive of only markup, a document of only empty paragraphs, an SSML file of only markup, and a braille file of only blank lines or one that translates to nothing but white space, so no silent, empty book is added. A Markdown file that is only a heading still imports. An .xml file of no bytes or only white space is refused the same way, but at the step "Checking its format", as in "Could not import “empty.xml”. Checking its format failed: This file has no text to read." Open Book…, Finder, and the files inside a ZIP are checked; New from Text… and the rebuilding of a book already in the library are not.
  - A disk without room for the book is reported as "There isn’t enough free space on the disk.", as in "Could not import “Middlemarch.epub”. Copying it into the library failed: There isn’t enough free space on the disk." The words never name the hidden package the import was building.
  - A rich text, Word 97-2003, OpenDocument, or Word 2003 XML document that textutil can't read is refused with a sentence that names its kind, as in "Could not import “Letter.doc”. Reading its text failed: This file could not be read as a Word 97-2003 document. It may be damaged, or another kind of file." The kind is "a rich text document", "a rich text document with attachments", "a Word 97-2003 document", "an OpenDocument text document", or "a Word 2003 XML document".
  - A document that textutil was stopped on, for passing one of its limits (see [Where TextMouth keeps your library](where-your-library-lives.md)), says why: "TextMouth stopped reading this document because it ran longer than 31 seconds." The reason can instead be "it held more than 1024 MB of memory" or "it used more than 121 seconds of processor time". The 31 seconds are the 30 allowed and one more for each million bytes of the document, rounded up, here for a small document, and the 121 are four times the time allowed.
  - A Word 97-2003 or OpenDocument document protected by a password is refused with "This document is protected by a password. Save a copy without the password, then import that copy."
  - A document, web archive, SSML file, or DTBook past the limit of 64 MB (see [What TextMouth reads](what-textmouth-reads.md)) is refused with "This document holds more than 64 MB, the most TextMouth reads from one document."
  - A web archive that can't be read as one is refused with "This file is not a web archive TextMouth can read. It may be damaged, or another kind of file." One whose main file is not a page or text says "This web archive holds a file of the type “image/png”, not a web page or text, so it has nothing to read.", naming the type the archive gives.
  - An SSML file that begins with another element is refused with "This file is not SSML: it begins with the element “html”, not “speak”.", naming that element. One whose markup is broken is refused with "This SSML file is damaged or incomplete: " and how and where, as in "its markup breaks off early or has extra content after the end (line 1, column 27)."
  - An .xml file that is not a DTBook, Word 2003 XML, or a PEF braille file is refused before anything is copied, at the step "Checking its format", as in "Could not import “catalog.xml”. Checking its format failed: This XML file is not a DTBook book, a Word 2003 XML document, or a PEF braille file, the kinds of XML file TextMouth reads."
  - A braille file that can't be read is refused with a sentence that says what is wrong, as in "Could not import “Emma.brf”. Reading its text failed: Line 12 holds “é”, which is not braille ASCII." The sentences are:
    - For a BRF or BRL file with something in it that is not braille ASCII: "Line 12 holds “é”, which is not braille ASCII." Lines are counted from 1 by their ends. What shows as nothing, or joins the character before it (white space, an invisible character, or a combining mark), is named by its code, as in "Line 1 holds the character U+00A0, which is not braille ASCII."; so is a control character, as in "Line 12 holds the control character U+0007, which is not braille ASCII."; and a byte that begins no valid character is named by its value, as in "Line 12 holds the byte 0xE9, which is not braille ASCII."
    - For a PEF file that is not well-formed XML, is not a PEF document, or has a row that is not braille, which is also what a Pentax photo named .pef gets: "This file could not be read as a PEF braille file. It may be damaged, or another kind of file."
    - For a PEF file in eight-dot braille: "This file is eight-dot braille, which TextMouth does not read."
    - For a file past a limit (see [What TextMouth reads](what-textmouth-reads.md)): "This braille file holds more than 32 MB, the most TextMouth reads from one braille file.", "This file has more than 100,000 braille pages, the most TextMouth reads.", or "This file has more than 4,000,000 lines of braille, the most TextMouth reads."
    - For a book that names a braille table this TextMouth does not have, as a library written by a newer TextMouth with more tables can: "TextMouth has no braille table named “en-xx.ctb”." The same sentence refuses one of this Mac's tables that this Mac no longer has or that its check refused (see [Settings](settings.md)), named with "mac:" before its file name, as in "TextMouth has no braille table named “mac:el.ctb”."; a TextMouth from before it offered this Mac's tables reads every "mac:" name so.
    - For one of this Mac's tables that could not be checked, as when the braille helper failed: "TextMouth could not check this Mac's braille table “mac:el.ctb”: the braille helper failed. Try again." The table is not refused, and trying again checks it again; the other reasons are listed in [Settings](settings.md).
    - For a translation that TextMouth stopped on, for passing one of the helper's limits (see [Where TextMouth keeps your library](where-your-library-lives.md)): "TextMouth stopped the braille translation because it ran longer than 11 seconds." The 11 seconds are the 10 allowed and the share of the book's size, rounded up, here for a small book. The reasons are the watchdog's, in the words listed under "Converting X was stopped because ...", below.
    - For a translation that failed any other way, because the helper is missing, could not start, ended with an error, or wrote output that does not match what it was given: "TextMouth could not translate this braille."
  - A playlist that can't be imported is refused at the step "Reading the file", as in "Could not import “radio.m3u8”. Reading the file failed: It is a streaming playlist for audio on the web, which TextMouth does not import." The other reasons are "It lists only web addresses, and TextMouth imports only files on this Mac."; "It names no audio file in its own folder that TextMouth can import.", followed, when entries were skipped, by "It skipped 3 entries: " and the entries, named as the notice above names them; and "The playlist “mix.m3u” is too large to read." for a playlist file of more than 4 MiB.
- An import that adds its book but has something to tell ends with an alert titled "Book Imported", where a failure's alert is titled "Error": the entries a playlist skipped, the original of an .rtfd that was kept, or chapters or pages that were left out. The book is in the library, but it is not opened, so the alert is not left behind a reader window. A ZIP batch's alert that sums up its failed and incomplete books is still titled "Error".
- When a book's content is already in the library, TextMouth asks whether to keep both, replace the existing book, or cancel. A feed's episode or article holding the same file doesn't count. The question says which file matches which book, as in "“Moby-Dick.epub” matches “Moby-Dick”, which is already in your library. Replace the existing copy, or keep both as separate books?", and then, after a blank line, what Replace Existing keeps of the existing copy and where its files go:
  - For a text book: "Replacing keeps the existing copy's reading position and bookmarks, found again in the new text, and its settings, folder, and place on the reading list. An edit of its text is kept beside the new text as a copy, not applied to it."
  - For an audiobook: "Replacing keeps the existing copy's reading position, bookmarks, settings, folder, and place on the reading list, and its transcript when the audio is the same. Edits of its audio are not kept."
  - Then one more sentence, by Move to Trash instead of deleting, under Removal Behavior in the Storage tab of Settings: "The existing copy's files go to the Trash, where you can recover them until the Trash is emptied." while it is on, and "The existing copy's files are deleted permanently and cannot be recovered." while it is off.
  - A copy that is missing chapters adds "The copy just imported is incomplete." and what it lacks.
  - The Replace Existing button's hint says "Puts the new copy in place of the one already in the library, keeping its reading position, bookmarks, and settings."
- Replace Existing makes the new copy the same book as the existing one, under the same ID, so it keeps more than the question names:
  - It keeps the existing copy's date added, its place among the books of its folder when you ordered them by hand, when it was last opened and played, the details you edited by hand in Book Info, and its own voice, speed, pitch, end-of-book choice, and skip units. Everything else is the new copy's: its file and text, and its title and author where you edited neither.
  - The reading position, the bookmarks with their notes, and the skipped headings of a text book are found again in the new text by the words they were saved with, as when a book's text is read again (see [Reader windows](reader-windows.md)). An audiobook's places count time in its recording, and stay as they are.
  - The copies of edited text that Edit Text kept for the existing copy go with it into the new copy's package, and so does the existing copy's own text, kept as a content.md.edited- copy beside the new text, when it holds an edit you made or a save that no edit took (see [Where TextMouth keeps your library](where-your-library-lives.md)). An audiobook's transcript comes along when each audio file of the new copy is the same size with the same contents as the audio transcribed, a single file imported under another name included; a transcript you edited that stays behind, because the audio is not the same, leaves its text beside the new copy as such a copy too, and an audiobook that kept its transcript is not offered for transcription afterwards.
- Replace Existing waits while the existing copy is in use, or while something it would keep is only in the cloud, where nothing is downloaded for it. The question stays open, nothing has changed, and the reason appears above its buttons, which VoiceOver reads as "Error: " and the sentence, and speaks once as it appears. Once the cause is gone, choose Replace Existing again. With X the title of the existing copy, the sentences are:
  - Open in a reader: "“X” is open in a reader. Close it, then choose Replace Existing again."
  - Being transcribed: "“X” is being transcribed, and replacing it now would lose the transcript. Wait until the transcription ends, or cancel it, then choose Replace Existing again."
  - Being exported: "“X” is being exported, and replacing it now would stop the export. Wait until the export ends, then choose Replace Existing again."
  - Its audio being edited in the audio editor, or saved from it: "The audio of “X” is being edited. Close the audio editor, or wait until it has saved, then choose Replace Existing again."
  - Files only in the cloud: "Some of the files of “X” are only in the cloud, and replacing it now would leave them behind. Download the book, then choose Replace Existing again."
- A replacement that fails leaves the question open with "Could not replace duplicate: " and the reason, and both copies as they were, the new copy as it was imported. When the existing copy's edited text cannot be kept beside the new copy's, the reason is "TextMouth couldn't keep the edited text of the copy in your library beside the new copy's text, so it left both copies as they are." Any other failure, such as files that cannot be deleted, gives the system's own reason.
- If the replaced book was open in Edit Text, VoiceOver says, once, "Edit Text has stopped for X, since a new copy replaced it. Choose Edit Text again to edit the new copy's text.", with X the book's title, so that you are not left saving into an editor nothing listens to (see [Editing a book's text](editing-book-text.md)). An Edit Manifest session for the replaced book ends without a word.
- Storage settings decide what happens to the original file after an import: keep it (the default), delete it, or ask each time. A folder imported with Import Folder… is the exception, as described there, and so is an .rtfd, which is a folder too: it is never deleted or offered for deletion. When After Importing a Book is set to Delete After Import or Ask Each Time, an alert titled "Book Imported" says "The original file was kept: it is a folder, and an import never deletes a folder.", and the book is added without opening, even if it came from Finder.
- With Offer to transcribe after importing an audiobook on, in the Playback tab of Settings, TextMouth asks after each audiobook it imports, on a Mac that can transcribe, whether to transcribe it, after that import's other questions (see [Transcribing an audiobook](transcribing.md)).
- These questions wait their turn. They are asked one at a time, in the order they arose, in the Library window where the import started, or in another Library window if that one has closed. When there is more than one, each title gives its place, as in "Duplicate Book Found, 2 of 5". Return chooses Keep Both, Create Folder, or Transcribe, and Escape chooses Cancel, Keep, No Thanks, or Not Now; Replace Existing and deleting an original file are never on a key. A question that appears while you are working in another window, such as a reader, waits in its Library window without taking focus or speaking.
- A book opened from Finder opens once it is in the library and its questions are answered.
- The progress overlay's Cancel button also withdraws the questions of the imports started before it was pressed, those waiting and any still to come: a duplicate's new copy is discarded, an original file is kept, a ZIP's books stay where they are, and an offer to transcribe is dropped.
- Importing audio that TextMouth converts (Ogg, AC-3, and the other formats listed in [What TextMouth reads](what-textmouth-reads.md)) adds a step, Converting its audio, after the archive is extracted and its manifest checked; the overlay counts the tracks, as in "converting its audio: 12 of 176 tracks". The archive, folder, or file you import from is never changed. A track that can't be converted stops the import, and nothing is added; the alert says which track and why, as in "Could not import “My Tracks.zip”. Converting its audio failed: Converting 01.ogg was stopped because it used more than 960 seconds of processor time." That number is four times the converter's time limit, a minute plus a tenth of the track's length, here for a track of 30 minutes. [Where TextMouth keeps your library](where-your-library-lives.md) lists what else stops the converter. Cancel kills the conversions at once, and the import ends as a cancelled one. The reasons, with X the track's file name:
  - "The audio file X could not be read for converting." The Mac's tool could not read the file as audio, or the file's header claims a length that its size cannot hold, or more than a year.
  - "The audio converted from X failed its check: ..." and why: the converted file would not play, or lasts a different time from its source, as in "it lasts 12.0 seconds, not 600.0".
  - "The audio converted from X could not be given its name."
  - "Converting X was stopped because ..." and the watchdog's reason: "it ran longer than N seconds", "it held more than N MB of memory", "its output did not grow for N seconds", "it used more than N seconds of processor time", or "its output passed N MB", which is more than four times what the track should come to, and 16 MB more.
  - "Converting X failed (the converter ended with code N)."
  - "There is not enough free disk space to convert X: it needs N GB free." This is said before anything is converted, for audio of more than two channels, which is mixed to stereo through a hidden file of uncompressed sound that must fit on the disk.
  - "The audio file X has N channels but does not say which is which, so TextMouth cannot mix it to stereo."
