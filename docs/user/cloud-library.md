# Keeping your library in the cloud

Part of [TextMouth's documentation](../../README.md).

A data directory in iCloud Drive, Dropbox, Google Drive (streaming), or another cloud drive that macOS keeps in ~/Library/CloudStorage works as any other, and lets the sync service keep books only in the cloud to free space on this Mac: macOS removes the downloads of files it can fetch again when it needs space, and you can remove a book's download yourself. TextMouth recognizes such a folder from its path, tells each book's state from file-system metadata without downloading anything, and downloads a book when you open it. To put your library there, choose a folder in the drive with Change Location… and then Move Library Here; on another Mac signed in to the same drive, choose that folder and Use This Library (see [Where TextMouth keeps your library](where-your-library-lives.md)). CLOUD-STORAGE-RESEARCH-2026-10-03.md and CLOUD-STORAGE-PLAN-2026-10-03.md, in the same folder as this file, explain the design.

- How each drive keeps a book: iCloud Drive syncs a book's package, its .tmb folder, as one item, while Google Drive and Dropbox sync each file in it. TextMouth tells which from the package's own sync flags and acts on what the drive syncs. On iCloud Drive it reads a book's state, and whether its changes have uploaded, from the package, and Download Now, opening a book, and Remove Download ask for the whole package, which comes to this Mac, or leaves it, all at once; on the other drives it does each of these file by file.
- In the Library window:
  - Each book's row shows and speaks its state after the New or Now Reading badge: Downloaded, In Cloud, Downloading 40%, Download Failed, or Waiting for Sync, which means the book's package hasn't arrived on this Mac yet. While a row speaks a download's percentage, it speaks the reading progress as "42 percent read", so the two never sound alike. A book kept on this Mac (below) shows and speaks "Kept on this Mac" after its state. A library on this Mac or on another drive looks and reads as before.
  - The summary line adds how many of the books shown are in the cloud, as in "3 books in the cloud": those not wholly on this Mac; and how many are kept on this Mac, as in "2 books kept on this Mac".
  - The states are read again when a Library window opens, when TextMouth becomes the active app, after books are added, moved, or removed, and every minute while a Library window is open. While any book downloads, even one Finder started, the downloading books are read every 2 seconds; a download that starts meanwhile shows when every book is next read, within a minute.
  - A book's context menu, and its actions in VoiceOver's Actions menu (VO-Command-Space), offer Download Now for a book in the cloud or one whose download failed, Remove Download for a downloaded book, Keep on This Mac, or Stop Keeping on This Mac for a book kept already (below), and Show in Finder, which selects the book's package. Each cloud service also has its own command for keeping a book on this Mac, in Finder: Keep Downloaded for iCloud Drive, Offline Access for Google Drive, and Make available offline for Dropbox.
  - With several books selected, these commands act on the selection and count the books they act on: "Download 3 Books", "Remove Downloads of 3 Books", "Keep 3 Books on This Mac", "Show 3 Books in Finder".
  - Download Now downloads the books one at a time, each showing Downloading 0% until its turn. It announces when it starts, and gives one summary when every book has ended, naming any book that wasn't downloaded and why.
  - Remove Download frees the space a downloaded book takes on this Mac, leaving it in the cloud. It deletes nothing from the cloud, so it doesn't ask first. It refuses a book open in a reader, a book kept on this Mac, and one with changes not yet uploaded. When it keeps any download, an alert says what was removed, what stayed, and why; VoiceOver reads the alert, and nothing repeats it. When every download is removed, one announcement says so.
  - Book Info never waits for a download. For a book only in the cloud, it shows the details the library keeps, with "Some details appear once the book is downloaded.", and refuses to write changes into the book's EPUB file until the book is downloaded.
- Keep on This Mac:
  - A book's context menu, and its VoiceOver actions, offer Keep on This Mac, or Stop Keeping on This Mac for a book kept already, for any book in a library in the cloud, even one whose package hasn't arrived yet. With several books selected, each counts the books it acts on, as in "Keep 3 Books on This Mac". The Library menu has both commands too, for the books selected in the Library window in front; when nothing would change, VoiceOver says why, as in "No books are selected."
  - A kept book stays downloaded. One only in the cloud, or whose download failed, downloads at once, as Download Now downloads it, and VoiceOver hears "Keeping Moby-Dick on this Mac. Downloading it now", then the summary when the downloads end. One whose download the sync service removes, while TextMouth runs or before it started, downloads again, without an announcement, when the books' states are next read, and one whose download failed then waits five minutes before it is tried again.
  - Remove Download refuses a kept book: "The book is kept on this Mac, so its download can't be removed. Choose Stop Keeping on This Mac first." Stop Keeping on This Mac removes nothing: the download stays until the sync service or Remove Download removes it.
  - Keeping is this Mac's own choice, as Finder's Keep Downloaded is: another Mac that opens the same library keeps only the books chosen there. The choice is saved in this Mac's own Kept Books.json (see [Where TextMouth keeps your library](where-your-library-lives.md)), never in the library.
  - The reading list's books are kept too, in a library in the cloud, while the checkbox "Keep these books on this Mac" in the Reading List's options bar is checked, which it is until you clear it. The checkbox is not there for a library on this Mac or another drive. A book on the list shows and speaks "Kept on this Mac" like any kept book, downloads at once when it is only in the cloud, downloads again when the sync service removes it, and counts in the summary. When you add a book with Add to Reading List, VoiceOver hears the add, then, after it has finished, "Downloading Moby-Dick, a reading list book" (or "Downloading 3 books"), and the summary as Download Now says it. Books that arrive on the list from another Mac's sync, a first start after an update, and checking the checkbox download with one notice, once, such as "Downloading 7 reading list books". TextMouth first checks that the books fit in the free space on this Mac, less the 1 GB it always leaves free, and starts only those that do; if some don't, the notice says so, as in "Downloading 4 reading list books. There isn't enough free space for 3 more books", and they download at a later refresh once there is room. A book whose size TextMouth cannot learn, such as an iCloud Drive book that syncs as one item and is only in the cloud, takes no room in that check, so books of unknown size download one at a time: TextMouth starts the first, and when it has downloaded, reads the free space again and plans the books after it. A book you took off the list, or stopped keeping, while it waited is left out. If a later pass finds that the room has gone, it says once, as in "There isn't enough free space to download 3 reading list books", counting only the books it leaves out. One huge book of unknown size can still fill the disk once it has started, since nothing can weigh it before it downloads. A book left out for room, a book you kept yourself included, is written once to the debug log as DOWNLOAD_SKIPPED_NO_ROOM; VoiceOver hears only of the reading list's books, so a book you kept yourself waits for a later refresh with no notice, and the log alone tells of it.
  - Remove Download refuses a book kept only for the reading list: "The book is on the reading list, which this Mac keeps downloaded, so its download can't be removed. Take it off the reading list, or clear Keep these books on this Mac in the Reading List's options first." A book you kept yourself that is on the list too is refused with both reasons named, and the advice in order. Stop Keeping on This Mac is offered only for a book you kept yourself; it says the reading list still keeps the book when it does, and, from the Library menu on a book only the list keeps, VoiceOver says the book is kept for the reading list and how to let it go. A book you kept stays kept after it leaves the list. Book Information says "Kept on this Mac for the reading list" for a book the list alone keeps.
  - A book that leaves the list (taken off it, finished with Remove books when finished checked, or removed from the library) stops being kept for it, and nothing is removed from this Mac: its download stays until the sync service or Remove Download removes it. Clearing the checkbox keeps none of the list's books for the list and removes nothing. The choice is this Mac's own, saved in its Keep Reading List Books.json beside Kept Books.json, never in the library or the list, so another Mac that opens the library decides for itself.
- Opening a book:
  - A downloaded book opens at once. A book with files only in the cloud downloads first, in its reader window: "Downloading" and the book's title, the sync service's name, and a progress bar that VoiceOver moves to and reads as "2 of 3 files, 40 percent". While a single file is left and nothing has been counted yet, the bar gives that file's size and the time waited instead. Where the sync service reports how much of a file, or of a package iCloud Drive downloads whole, has arrived, the percentage counts that part too, never going back, so a book of one large file shows how far it has got.
  - VoiceOver hears the download start, then 25, 50, and 75 percent (or, while there is no percentage, the time waited, every 30 seconds), then "Downloaded. Loading."
  - Cancel, which Escape also presses, stops waiting, and the window then says the book isn't downloaded, with two buttons: Download, which Return presses, and Close.
  - A failure shows the reason with Try Again, which Return presses, and Close. Offline, the download fails at once: "This Mac is offline, so the book can't be downloaded from Dropbox. Connect to the internet and try again." A sync service that downloads nothing for 60 seconds is reported as perhaps paused, signed out, or not running. A book whose package hasn't arrived on this Mac yet says so.
  - The book is then read without ever waiting on the network. A file that went back to the cloud meanwhile is downloaded once more; if it has gone again, the reader says that part of the book isn't on this Mac.
  - A book that another book continues to, from its folder or through the reading list, starts playing once it has downloaded and loaded, however long the download takes. If the download fails or you cancel it, the book doesn't start by itself later, and once you close its window, it starts by itself only if it opens again within about 30 seconds of the hand-over. While the library is moving or isn't available, opening such a book, or a book from the Reading List, is refused as before, and nothing of the refused open is left waiting: when the book is opened later, it is neither started nor read from the reading list.
- Playing an audiobook:
  - An open audiobook plays from a working copy: a copy of its package in this Mac's Working Copies folder, which on the same disk takes almost no extra space. So it keeps playing offline, or after the sync service removes the book's download. The copy is deleted when the reader window closes, and positions and bookmarks still save to the library.
  - When no copy can be made, a chapter whose file is only in the cloud downloads before it plays, in the same view, while the reader shows Playing. Pausing, with Play/Pause or when the sleep timer runs out, stops waiting, so the chapter doesn't start by itself later; it downloads again when you next play it, if it still has to. A second Play while the audiobook waits for its chapter's download does nothing, with no second play sound. A failure stops at that chapter with a Chapter Not Downloaded alert offering Try Again.
  - A text book is read into memory when it opens, so it needs no copy.
- Background maintenance never downloads a book. The startup repair, the metadata refresh, the text cache and statistics passes, and Redo Text Extraction leave a book whose files are in the cloud as it is, decide nothing from what only the cloud knows, and catch the book up once its files are on this Mac; opening a book also rebuilds its text cache when that is out of date. Each pass that skipped books writes one MAINTENANCE_SKIPPED_IN_CLOUD line in the debug log, saying how many, and Redo Text Extraction says so in Storage settings too, as in "Done. 12 books in the cloud were skipped."
- Logs: they live in the library's Logs folder and sync with it, each kept to 2 MB with one older generation, so the uploads stay small, and TextMouth never downloads a log to write to it. To keep them off the cloud, choose In this Mac's Logs folder in Storage settings (see [Where TextMouth keeps your library](where-your-library-lives.md)).
- Several Macs:
  - Use a library on one Mac at a time. While a library on another drive or in a cloud folder is open, TextMouth keeps a file for this Mac in its Sessions folder. When another Mac's file was refreshed in the last three minutes, TextMouth warns, once a session: "TextMouth is also open on “Study iMac” (active 2 minutes ago). Using one library on two Macs at the same time can lose reading positions and changes." Continue, which Return presses, keeps the library open here, and Quit TextMouth quits. It is only a warning: nothing is locked. A sync service's conflict copy of this Mac's own file never counts as another Mac. The file is written and read away from the main thread, so a Sessions folder that hasn't synced yet never stalls TextMouth; at quit, removing the file is given up to two seconds.
  - config.json travels with the library, so a dataDirectoryPath that another Mac wrote is ignored when it names a folder this Mac doesn't have (see [Editing settings in config.json](config-json.md)).
  - Update TextMouth on every Mac that opens the library. A TextMouth built before October 18, 2026, such as 0.1.1, can't open a library that holds a book in a format added that day (rich text, rich text with attachments, Word 97-2003, OpenDocument, Word 2003 XML, web archive, or SSML), and one built before October 20, 2026 can't open a library that holds a braille book (BRF, BRL, or PEF), the format added that day: it finds the index unreadable and leaves it as it is, writing no index, but it still writes each book's record, which loses 0.2.0's records of edits and pages. It offers Rebuild Library Index; never choose it there (see library.json.unreadable-, under [Where TextMouth keeps your library](where-your-library-lives.md)). A TextMouth from 0.2.1 to 0.3.2 opens a library that holds a KFX book, a format added in 0.4.0, without that book (see the [changelog](changelog.md)).
  - TextMouth leaves alone the conflict copies a sync service makes of library.json, library-identity.json, config.json, reading_stats.json, substitutions.json, a feed's record, and a book's package and record, such as "library 2.json" or "library (1).json": it never reads one in place of the file it copies, nor adopts a copied package as a second book, and leaves each where it is. It doesn't merge what two Macs wrote.
  - While reading_stats.json or substitutions.json is only in the cloud, TextMouth neither waits for it nor saves over it, and asks the sync service for it. Meanwhile the statistics count only this session's listening, which is added to the file's totals once the file is on this Mac. The standard substitution rules stand in, and a change to them is reported as unsaved, with Retry; the file is read again whenever TextMouth becomes the active app and before each save, and once it is on this Mac its rules take the place of the standard ones, and that change is dropped. Where there is no substitutions.json at all, as on a Mac's first launch before the sync service has brought it down, the standard rules stand in without being written: the file is written only when a rule changes, so one that arrives later is adopted without a conflict copy.
  - When a library in the cloud opens, TextMouth gets its other few small files in the background if they're only in the cloud: config.json, reading_stats.json, substitutions.json, and the feeds' records. Never a book or an episode, and the library doesn't wait for them. Until config.json arrives, the settings already on this Mac stand, nothing is saved over it, and a setting you change meanwhile keeps your new value when it arrives.
  - Either file, when it can't be read, as a write cut short on another Mac can leave it, is kept beside itself before anything replaces it, its name followed by .unreadable- and the date and time, as an unreadable library.json is; the statistics then start afresh, and the standard rules stand in.
- Feeds: their records, and their folders of downloads with their indexes, sync with the library, and each Mac refreshes them on its own. A played episode's download is deleted, and a download beyond a feed's newest is removed under its List and download choice, only by a Mac that holds the whole book, as its cloud state says. Opening the library waits for every feed's index, as it waits for library.json (see When the library isn't available, under [Where TextMouth keeps your library](where-your-library-lives.md)), and a Mac marks an item downloaded again, after an older version of TextMouth marked it otherwise, only when its file is on that Mac. A feed whose record is missing when TextMouth opens, as one an earlier version unsubscribed from on another Mac, keeps its downloads in its folder until a later launch of this Mac finds the record missing again; only this Mac's own launches count (see Commands, under [Podcasts and article feeds](feeds.md)). Unsubscribing and Resubscribe live in the feed's record, which another Mac reads as it next opens the library.
- What was tested: the opt-in tests in [Testing on real cloud drives](../developer/testing.md#testing-on-real-cloud-drives), passed against Dropbox, Google Drive, and iCloud Drive, and CLOUD-STORAGE-MANUAL-TESTS-2026-10-03.md lists the checks, with VoiceOver steps, still to be made by hand on each drive.
