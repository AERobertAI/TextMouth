# Where TextMouth keeps your library

Part of [TextMouth's documentation](../../README.md).

TextMouth keeps everything in one data directory: .TextMouth in your home folder unless you chose another folder in Storage settings. Any folder can hold it, hidden or not: on this Mac, on an external or network drive, or in a cloud folder such as iCloud Drive, Dropbox, or Google Drive (see [Keeping your library in the cloud](cloud-library.md)). That choice itself is kept in TextMouth's preferences, with a bookmark of the folder and the identity of the library in it, because config.json lives inside the directory it names.

- Choosing a location:
  - Change Location… in Storage settings opens a folder chooser that shows hidden folders and can make a new folder; its button says Choose Location. The folder you choose becomes the data directory itself, with nothing added to its name.
  - TextMouth first looks at the folder, reading only what the file system says about it and downloading nothing, while the status line says "Checking" and the folder's path. Then it offers what the folder can hold, and VoiceOver announces each status line as it appears:
    - Move Library Here, for an empty folder, such as one just made in the chooser. The confirmation says that the library is copied there, checked, and used, with the current folder kept as recovery data, and what the place means: in a cloud folder, that the library, with its size, uploads in the background, and that a book only in the cloud needs an internet connection to open; on another drive, that the drive must be connected to open the library.
    - Use This Library, for a folder that holds a TextMouth library: its library-identity.json, or a library.json beside a Library folder. TextMouth switches to that library as it is, copying nothing, then quits and opens again on it. This is how another Mac restores a library from the cloud. The confirmation names both libraries, and says when the folder holds another copy of the library in use, such as the folder an earlier move left behind, which may lack the latest changes. Changes not yet saved are written first, and the switch is refused while some still can't be saved: choose Retry Saving, then try again. It is refused too while a move, Rebuild Directory, or a change that moves books between folders is under way, saying which, and while it runs those are refused in turn: "TextMouth is switching to another library and opening again on it."
    - For the folder the library is in already, the status line says it is the library TextMouth is using.
    - Anything else is refused, with the reason: a file rather than a folder, a folder holding other items, which it names, a folder inside the library, a folder in the Trash, one TextMouth can't read or isn't allowed to change, a cloud folder that isn't on this Mac yet, a missing folder whose enclosing folder is missing too, or another drive without room for the library.
  - Reset to Default moves a library in another folder back to ~/.TextMouth, the same way.
- Moving the library:
  - A move is refused while any book is open, naming the open books, and while books in a library in the cloud aren't downloaded: "3 books aren't downloaded. Download them first: select them in the library, then choose Download Now." It is refused too while another move, Rebuild Directory, or a change that moves books between folders is under way, saying which, as in "TextMouth is rebuilding its data directory. Try again when that finishes." A move from a current data directory that is not there, or is a file, says "The current data directory does not exist."
  - A book stored outside the data directory stops the move before anything is copied or published (0.4.3). The move cannot carry a file that is not in the data directory, and used to say the copy was missing the book's content. The alert now names the book and where it is, as in "The book Harbour Pilots is stored at /Volumes/Shelf/pilots.mp3, outside the data directory, so the move cannot carry it. Import it again, which asks about the duplicate, and choose Replace Existing so that the copy stored in the data directory takes its place, or remove it from the library, then move the data directory again." The title and path are the book's own.
    - Replace Existing puts the new copy, which is stored in the data directory, in place of the existing one, under the same ID, keeping its reading position, bookmarks, and settings (see [Adding books](adding-books.md)). Keep Both would leave the book outside the data directory, and the move would stop again.
  - An import, text extraction, or book analysis under way finishes first, and the move's progress says which it waits for; any that start meanwhile wait until the move is over. A move also waits for the feed rules' deletion of downloads under way, saying "Waiting for feed downloads to be deleted...", and a rule's deletion waits while a move copies the library.
  - Moving copies everything into a hidden folder beside the new location, a book at a time, checks the copy, then renames it into place in one step and switches to it. The new location must be an empty folder or one that does not exist yet. If anything else appears there, or the location is changed to lead somewhere else, while the copy is made, the move stops: TextMouth deletes only its own copy, leaves what appeared alone, keeps using the old folder, and says what appeared and where. A location that is a symbolic link counts as the folder it leads to, and messages name that folder too. The old folder is left where it was.
  - The hidden folder is gone when the move ends, however it ends: renamed into place when the move finishes, removed when it is cancelled or fails. When it can't be removed, because the new location's drive was unplugged during the copy or TextMouth was force-quit, it stays on that drive, and TextMouth removes it the next time it starts.
    - TextMouth notes each hidden folder in Move Leftovers.json, a file of this Mac's own (see below), before the move creates it, and a launch removes only the folders that list names. Even then it removes a folder only if its name is exactly .TextMouth-migration- followed by a UUID and it is a real folder, never a link.
    - A folder that can't be seen, because its drive is still away, stays on the list for 30 days, and each launch in that time tries again.
    - The debug log records MIGRATION_STAGING_REMOVED for each folder removed, and MIGRATION_STAGING_LEFT for each that could not be removed.
  - While the library moves, every Library window shows a sheet with its progress, as in "Moving the library… 40 percent", and Cancel, which Escape also presses; Storage settings show the same. VoiceOver moves to the progress bar, and announces what the move waits for, where the library is going as the copy starts, each quarter of the copy, and how the move ended. Books can't be opened or added meanwhile; a book opened from Finder is imported once the move is over.
  - Cancel deletes the partial copy and leaves the library where it was, with no setting changed, and the status then says so, as in "Move cancelled. The library is still at /Users/you/.TextMouth." Once every item is copied, the move can only finish.
  - Quitting during the copy stops the move first, as Cancel does, or lets it finish once every item is copied, and then quits. A move still waiting to start its copy doesn't hold up quitting.
- When the library isn't available:
  - TextMouth checks the data directory at launch, before it creates or loads anything, reading only metadata. It checks again when the drive holding it is unmounted, or when a save finds its folder gone.
  - The default location is always available: it is created when it is missing, as on a first launch. A folder you chose is never created, nor any folder above it: a missing one is an unplugged drive, a signed-out cloud service, or a folder that was moved or deleted, and creating it would start an empty library in its place. A folder that was renamed, or a drive that mounted under another name, is found again through its bookmark, unless that leads into the Trash or to another library.
  - Otherwise every Library window shows Library Not Available in place of the library: the reason, such as "The drive “Backup” isn't connected." or "The folder is there, but it holds a different TextMouth library.", then where to choose another folder instead, "To use another folder, open Settings, Storage, and choose Choose Another Library or Use Default Location.", the folder's full path, which you can select and copy, and two buttons, Try Again, which Return presses, and Quit TextMouth. VoiceOver moves to the reason and announces it once. Meanwhile the library index isn't saved, and no book can be opened or added.
  - When library.json, library-identity.json, the Feeds folder, a feed's folder, or a feed's index is only in the cloud, TextMouth gets it from the sync service itself and opens the library when it arrives, so you needn't do anything. Meanwhile every Library window shows Getting Your Library, with the reason "Some of the library's files are in Google Drive and aren't on this Mac yet. TextMouth is getting them now, and the library opens when they arrive.", naming your cloud service. It gets only these files, never a book or an episode, and TextMouth stays usable meanwhile. VoiceOver hears "The library is available." when the library opens, and every book you opened from Finder while waiting opens then.
    - A read that fails is tried again after 5, 15, and 30 seconds, since a cloud service may not be running yet just after a restart. TextMouth waits 60 seconds for a service that gives no answer at all, and at most eight files are read at once. If they still can't be had, the heading goes back to Library Not Available, the reason says that TextMouth couldn't get the files and what to check, and any books you opened from Finder are named as not opened. Try Again starts over, and a file that turns up late still opens the library.
  - Try Again opens the library once it is back. When the library went missing while TextMouth was open, library.json is read afresh, and the session's newer reading positions are carried into it.
  - Storage settings say Library Not Available, with the same reason, and offer the ways out: Choose Another Library…, for a folder that holds a TextMouth library, and Use Default Location…, which uses the library in ~/.TextMouth or starts a new, empty one there. Either quits and opens TextMouth again on that library, and the confirmation lists the changes that couldn't be saved, which switching loses. Nothing is created at the missing location.

The data directory holds:

- library.json: the library index. It lists every book of the library's own (title, author, format, folder, file path, reading position, bookmarks, and per-book settings), every folder, each location's sort (that of Feeds, and of a view of your own, under a key that begins with "/views/", as "/views/Feeds"), and the reading list, with its order and options, as compact JSON, without line breaks. Since October 10, 2026 it never holds a feed's downloaded episode or article, whose feed's own index lists it instead (see Feeds, below), and a row it holds is always a book of the library's own, whatever a hand edit of the file says. While a book plays, its reading position reaches the index within five minutes, or sooner when anything else in the library changes, when the book's reader closes, or when TextMouth quits; meanwhile the book's record in its package holds it (below). Each book's row also records which version of TextMouth's metadata reader last read its file for its title and author, and which of its details you edited by hand (see [The Library window](library-window.md), under [Finding your way around](../../README.md)). The first launch after an update that reads a format's metadata better reads every older row's file again, in the background before the text caches, and takes the author the file names where the row still says Unknown; an author you typed stays, and a file that still names no one leaves Unknown. It never replaces a field edited by hand. For a book imported from its own file since October 7, 2026, by Open Book, from Finder, in a ZIP of books, or with Import Folder…, whose record of hand edits begins at its import, it also brings up to date the title, author, publisher, and publication date the file names. For every other book, from before then, or made with New from Text, by a recording, from a feed's episode or article, or from a ZIP of audio tracks or a DAISY audio book's ZIP, whose names come from elsewhere than the file it reads, it replaces nothing but that Unknown author, and only with a name, so a title or an author you typed stays. It never reads an episode or article its feed lists, whose title and author come from the feed. A book whose files are only in the cloud waits for a launch that finds them on this Mac. The October 7, 2026 update does this once for every book. library.json is read one row at a time. A row this TextMouth cannot read, as a book that a later TextMouth added in a format this one does not know, is kept exactly as the file held it, written back at every save, and never shown, counted, opened, or searched. Storage settings say how many there are (see [Settings](settings.md)). The package such a row names is left alone by the library's repairs: no sweep for packages that no row lists adopts it as a second book, repairs it, or deletes it, though Delete Folder… still removes the packages of kept books filed in the folder it deletes, and Delete Feed… those of a feed's kept books. A sort that a later TextMouth saved by a field this one does not know reads as the default sort and is written back as it was until you choose another. A feed's index is read the same way. An index that is cut short or is not JSON at all, or whose folders, or whose list of books, are in a layout this TextMouth cannot read, is still unreadable as a whole (below).
- reading-checkpoints.json: present only while some books' records hold reading positions that library.json doesn't have yet. It names those books, so that a launch after a crash takes their newer positions from their records.
- library.json.unreadable- followed by a date and time: a preserved copy of an index that could not be read. When library.json cannot be read, TextMouth never overwrites it, and the Library window's Recovery Options… offer Try Again and Rebuild Library Index, which rebuilds the index from the books on disk. Rebuild Library Index keeps your reading list and the sort settings of your folders and views: those TextMouth held when the index became unreadable, or else those it can still read in the unreadable file itself, each on its own. When neither gives one, as when the file was cut short, the Rebuild choice says so, and so does its result, as in "TextMouth could not read the reading list or the sort settings in the previous index.", as does Try Again when the unreadable file has gone and it saves the rebuilt library instead; the preserved copy keeps them. A TextMouth built before October 18, 2026 finds the index unreadable whenever it holds a book in a format added that day, and one built before October 20, 2026 whenever it holds a braille book, a format added on that day: 0.1.1, built October 17, 2026, does for all eight (braille, rich text, rich text with attachments, Word 97-2003, OpenDocument, Word 2003 XML, Safari web archives, and SSML). The index names each book's format, and a TextMouth built before October 18 does not know the names rtf, rtfd, doc, odt, wordml, webarchive, and ssml, and one built before October 20 does not know braille. It leaves library.json as it is, saves this copy beside it, and writes no index, but it still writes each book's package record, and those records lose the fields it does not know: the record of an edit of the book's text and of the page reader that wrote it. A newer TextMouth then reads a book whose text you edited from its file again, keeping your edit beside it as content.md.edited- followed by a date and time (below). Nothing else is lost until someone chooses Rebuild Library Index there, which makes an index without the books in the formats it does not know, though their packages stay in the Library folder, and without the folders and the manual order that only the index held, which the preserved copy keeps. Never choose it. Open the library with a TextMouth built on or after the day its newest format was added instead. Rebuild Library Index refuses, and replaces nothing, when the index can be read again by the time you choose it, as when another Mac finished its save or you restored library.json from a backup: VoiceOver and the sheet's Last attempt row say "The library index was not rebuilt. It can be read again now. Choose Try Again to use it." A reading position saved while the index can't be read reaches the book's record, and is named in the checkpoint journal too, so the launch after you restore library.json takes it from the record instead of opening the book at the index's older place. At launch TextMouth gives each folder a book lies in, and the folders above it, a row in the index when it has none, so a library opened without its index, or with a book in a folder that has no row, keeps those folders.
- library-identity.json: which library this is, an identifier and the date the library was given it. It is written once, when TextMouth creates the library or first opens one an earlier version made, and never overwritten, so the library keeps its identity wherever its folder goes. TextMouth remembers the identifier it expects, so a folder that only has the right name, such as another drive called Backup, is never taken for your library.
- config.json: your settings, which you can edit by hand (see [Editing settings in config.json](config-json.md)).
- substitutions.json: the text substitution rules from the Text tab of Settings.
- audio-filters.json: the audio editor's filter presets. Until one is changed, the premade presets stand in and nothing is written. In a library in the cloud it is read and written as substitutions.json is (see [Keeping your library in the cloud](cloud-library.md)).
- transcript-cleanup.json: your own rules for Clean Up Transcript (Experimental)…, once Edit Rules… has made it from TextMouth's own (see [Transcribing an audiobook](transcribing.md)). TextMouth writes it only then, never over a copy of yours. It is read as substitutions.json is: one only in the cloud is asked for and waits there, and a copy of one that can't be used is kept beside it, its name followed by .unreadable- and a date and time; TextMouth's own rules stand in for either.
- reading_stats.json: listening statistics, kept by day, and the books finished, each with its kind once TextMouth began to record kinds.
- Sessions: in a library on another drive or in a cloud folder, a small file for each Mac that has the library open, holding the computer's name, when TextMouth was last active there, and its version. TextMouth writes this Mac's when the library opens, refreshes it every minute, and removes it at quit, and it removes any left untouched for 30 days (see [Keeping your library in the cloud](cloud-library.md)).
- Feeds: one file for each feed in the library, subscribed to or not, Feeds/ followed by the feed's identifier and .json, holding the feed's address, title, folder, and own settings, the date you unsubscribed, while you are, and the episodes and articles it keeps, with whether each is downloaded, in the library (Move to Library…), played, or deleted. It moves and syncs with the library. A file that can't be read is kept beside itself, its name followed by .unreadable- and a date and time, and its feed is left out until the file can be read; a file only in the cloud is read once it has arrived, at the next refresh of every feed; and a sync service's conflict copy is never read. Beside its file, a feed that has downloaded anything has a folder of its own, Feeds/ followed by the feed's identifier alone, holding a package for each episode or article it downloaded, laid out as a book's package is (Library, below), and the feed's own index of them, library.json, holding a row for each as the library's index holds a book's. A package whose download was deleted stays there without its file, holding its record, its content index, its content.md (an episode's transcript text, or an article's text unless Delete Download removed it), its transcript, and any copies Edit Text kept of an edited text, while it keeps your place, bookmarks, settings, details you edited by hand, transcript, or such a copy, and its row stays in the index, so downloading the item again restores the same book. A feed's folder can also hold, hidden, .replaced- followed by a package's name, a package a new download replaced, set aside when the two packages couldn't be swapped in one step, as on a drive that can't swap two folders, until the new one is in place, which the item's next download puts back or removes should TextMouth stop meanwhile; .removing- followed by the download's identifier and a name of its own, the folder an article's Delete Download moves its file and text into to remove them as one item, which, should a crash cut the deletion short, the next launch sends to the Trash under the article's own name, or deletes, as Removal Behavior says; should a refused Delete Download leave its files there, the next launch puts them back into the package; and, in a library in the cloud, empty .record-absent- files named after a Mac and one of its launches, each noting that the launch found the feed's record missing. Each save of the library writes a feed's index before the library's, and only when it changed or its file is gone, so listening to an episode rewrites its feed's small index and no other; a save stops before the library's index when a feed's can't be written. An index that can't be read is kept beside itself, its name followed by .unreadable- and a date and time, and its rows are read from its packages' records, as are those of a package its index doesn't list. An index only in the cloud, as when it went back to the cloud after the launch waited for it, or one a newer version of TextMouth wrote, is neither read nor written over while TextMouth runs: its rows are read from its packages' records meanwhile. Unsubscribing keeps this folder and its downloads, deleting only the packages kept for downloads you removed. Delete Feed… deletes the feed's packages, then this folder, then the feed's file, so no launch finds the folder without the file while a package is in it. Move to Library… moves an item's package out of it in one rename, and its row from this index into the library's. A launch that finds this folder while the feed's record is gone returns its downloads to the library, then deletes the kept packages and, once nothing else is in it, the folder.
- Library: your books. Its folders are the library's folders, and each book is a package: a folder named after the book's title, author, date added, and identifier, ending in .tmb. A package holds:
  - The book's own file, under its original name. An audiobook made of several tracks keeps them in a folder instead; one converted from a DAISY audio ZIP also has a manifest.json listing its sections and the stretches of audio each one plays.
  - .convertedOriginals: a hidden folder, present only in an audiobook that was imported while Keep originals of converted audio was on, and whose import converted audio. It holds each original as it was, under its path from the book's folder of tracks, or by its own name for a single file. Nothing in TextMouth opens these files; Export copies them out (see [Exporting books](exporting-books.md)).
  - bookInfo.json: the book's record, with its metadata (for an EPUB, its publisher, publication date, ISBN, language, identifier, and EPUB version, read at import or, for a book imported before TextMouth kept them, the first time a reader opens it; for a braille book, the braille table it is read with, such as en-ueb-g2.ctb, or "mac:" and the file name of one of this Mac's tables, such as mac:fr-bfu-g2.ctb, with the liblouis version of this Mac's tables, such as 3.34.0, when it is one of them, all of which its row in library.json holds too), which of its metadata fields you edited by hand, reading position, bookmarks, and per-book settings, written within half a second of each change, and every 30 seconds while the book plays. It can rebuild a book's library entry if library.json is lost. While a record is only in the cloud, TextMouth neither reads nor writes it, and the book's changes are saved in library.json alone, without waiting, until the record is on this Mac again. A downloaded episode's or article's record also names its feed and item, as its row in the feed's index does.
    - A plain text, Markdown, or HTML book whose encoding TextMouth guessed when it was added, or whose encoding you chose in Book Information (see [What TextMouth reads](what-textmouth-reads.md)), keeps it in its row and in its record, by name, such as windows-1251, koi8-r, macintosh, or utf-8, and every later reading of the book's text, a rebuild of content.md included, uses it. A choice is recorded as chosen, in a second key beside it, textEncodingSource, whose value is "chosen", or "automatic" when you chose Automatic. A chosen encoding is read whatever the file's bytes say of themselves, and a guessed one only where they name no encoding.
    - A BRF or BRL braille book keeps the braille file characters its file is read with in its row and in its record, as brailleFileCode, by the code's id: "ascii-na" for North American Braille ASCII, "ascii-eurobraille" for Eurobraille, six-dot, or "unicode" for Unicode braille patterns (see [What TextMouth reads](what-textmouth-reads.md)). An import records it explicitly, North American's too, and a read of the file again with other characters records the new ones; a PEF records none. The key is left out when there is none, and a book without it is read as North American Braille ASCII, or as Unicode braille patterns when its first character is a braille pattern. Every later reading of the book's text, a rebuild of content.md included, uses it. A TextMouth older than the one that records it ignores the key and drops it at its next save; when it rebuilds such a book's text, as Redo Text Extraction or a new cache version does, it reads a Eurobraille book as North American Braille ASCII, which gives wrong numbers and punctuation, or refuses a Unicode one and keeps its old text. Open a library that holds books you set to Eurobraille or Unicode braille patterns only with the TextMouth that set them, or a later one.
    - A TextMouth older than 0.2.2, 0.1.1 included, does not know the encoding's key or the note's, and drops both from the row and the record when it saves them. TextMouth 0.2.2 knows the encoding but not the note, and drops the note, so a choice becomes a guess of the same encoding: the book is read as before, unless the choice overrode valid UTF-8, a byte-order mark, or an HTML file's declaration, and Book Information says "guessed". Once the row and the record have both lost the encoding, nothing can bring it back, so the next time that book's text is rebuilt (content.md, below) it may be read as Windows-1252 again, as it was before TextMouth guessed. Open a library that holds such books with TextMouth 0.2.2 or later, and one that holds a book you chose an encoding for with TextMouth 0.2.3 or later.
  - contentIndex.json: the index of the book's chapters and headings, with their word counts and, for an audiobook, its timing, written when the book is imported or its content is analyzed again, so saving the book's place never rewrites it. Earlier versions of TextMouth kept the index inside bookInfo.json: TextMouth moves it out the next time it saves such a book, and an earlier version that opens a book saved since finds no index there and analyzes the book once more.
  - content.md: the text cache, the book's text as Markdown, so a text book opens without parsing its source again. TextMouth rebuilds it when the source file changes or when a newer version of TextMouth reads that format better, but these automatic rebuilds keep text you changed with Edit Text, and Redo Text Extraction, a button in the Storage tab of Settings, rebuilds it on request for every text book (see [Editing a book's text](editing-book-text.md) for what it does to that text), and a choice in a book's Text Encoding pop-up in Book Information rebuilds it for that book alone, in the encoding chosen (see [The Library window](library-window.md)). A line such as `<!-- page: 12 -->` in it marks where a page begins (see [Editing a book's text](editing-book-text.md)). Books already in your library gain their pages at the next launch after an update gives their format pages: TextMouth reads each one's file again, once, and your places follow their words. Books open in a reader are read first, and each such reader then quietly shows the book's new text with its pages, its cursor on the same words; speech that was playing starts again from the cursor. An EPUB's page-break element keeps its words: its own text is skipped only when it is no more than its page's label, the page's number and perhaps a caption of up to 32 characters, and any longer or other text in it is read, after its page marker; an element with no aria-label or title that holds more than that begins no page. DAISY 2.02 follows the same rule for what a page entry points at. A Word 6 or Word 95 document, which textutil read until version 0.4.1, with a table of contents or a link got every page, with the words kept apart at each break, where it got only its first page before. First it compares the whole of the book's content.md with what the book's file gives. A book whose text you changed with Edit Text keeps that text, without pages, until Redo Text Extraction, and so does one whose content.md was changed in another editor since TextMouth last wrote it. Any other book whose content.md differs from what its file gives, even only in a heading, a heading's level, or a chapter's title, as an edit made before TextMouth began recording edits on October 21, 2026 may, or in a chapter that an EPUB lost by naming its file in another letter case than its ZIP spells it, is read again with its pages too, once TextMouth has kept a copy of its text beside it as content.md.edited- followed by a date and time (below); if no copy can be made, the book keeps its text, without pages, and every automatic rebuild keeps it, as it keeps text you changed with Edit Text. A book whose file is missing keeps its text without pages; one whose file can't be read is tried again at the next launch, then keeps its text without pages; and one whose files are only in the cloud gains its pages at a launch when they're on this Mac. A Word document older than Word 6, which textutil reads, whose pages textutil couldn't read is tried again at the next launch, then keeps its text without pages until Redo Text Extraction. The debug log records a PAGES_REPLACED_TEXT line naming each copy kept, a PAGES_SKIPPED_CHANGED_TEXT line for each book that keeps its text, and one PAGES_UPGRADE_SUMMARY line counting the books given pages, replaced keeping a copy, kept as changed, skipped, and failed. A rich text, rich text with attachments, or Word 97-2003 book was read again once at the first launch of version 0.3.1, when TextMouth's own reader replaced textutil for it, and gained the headings and pages that reader finds. At the first launch of version 0.4.0, every rich text, rich text with attachments, Word 97-2003, Word, OpenDocument text, and Word 2003 XML book is read again once more, for what the readers now find: hidden text and tracked deletions left out, footnotes, endnotes, and text boxes read, and, for an OpenDocument or Word 2003 XML book, the document's own headings and its pages. Each is kept or replaced by the rules above, so your place follows its words and text you changed with Edit Text is kept. At the first launch of version 0.4.1, every .doc book is read again once more (its page reader line is 1.3.0), for Word 6 and Word 95 documents, which TextMouth now reads itself, and for the symbols of Word documents, and every .docx and .wordml book is read again once more (1.2.0), for the hidden text it now finds: a table style's and the document defaults' hiding in a .docx, and the words of a hidden row in Word 2003 XML. Each is kept or replaced by the same rules, so your place follows its words and text you changed with Edit Text is kept. A book you add, or whose text is rebuilt for another reason, gains its pages as its text is read. Edit Text opens it in your own editor, and TextMouth takes what you save while it's open (see [Editing a book's text](editing-book-text.md)). A transcribed audiobook's content.md holds its transcript's text instead (see transcript.json, below).
    - The first launch after the update of October 24, 2026 reads every braille, plain text, EPUB, and HTML book again, once, in the way just described. Braille and plain text books gain their pages, an EPUB or HTML book loses the number of a page break from the name of any heading that held one, and a braille book is read with the update's better reading of emphasis and of some words (see [What TextMouth reads](what-textmouth-reads.md) and [Reader windows](reader-windows.md)). A braille book whose new reading differs from its text, by its words or by its emphasis alone, as one whose braille holds emphasis signs may, keeps a copy of its old text beside it, as any book whose content.md differs from what its file gives does. An EPUB or HTML book that has its pages already is read again without that comparison, and keeps no copy. A book's places follow its words in every case.
  - content.md.edited- followed by a date and time: a copy of text in content.md that Edit Text couldn't take, or that TextMouth replaced, reading the text again from the book's own file (Redo Text Extraction and a choice in a book's Text Encoding pop-up do this over text you changed with Edit Text, after keeping it here, and so does the launch that gives books their pages, over text that differs from the book's file but that no record of Edit Text names) or, for a transcribed audiobook, writing it again from the transcript. TextMouth never reads these copies, and Delete Transcript leaves them; delete them when you no longer need them.
  - transcript.json: an audiobook's transcript, present once the book has been transcribed: the language, the recognizer and its model, the version of TextMouth, the date, the date of your last edit of it, once you have edited it, its last cleanup, once it has been cleaned up (when, whose rules, their version and date, and how many corrections), and, for each audio file, its fingerprint (its size, modification time, and digest) and every sentence heard in it, with each word's start and end in milliseconds and the recognizer's confidence. TextMouth writes the book's content.md from it, a heading for each chapter and a paragraph for every few sentences, and writes content.md again from it when the book next opens if content.md is missing or holds text TextMouth didn't write or take, which it first keeps beside content.md as content.md.edited- followed by a date and time, or if a newer version of TextMouth writes it differently. The transcript itself changes only when the book is transcribed again, Edit Text takes an edit of its text, or a cleanup is applied or undone, and Delete Transcript deletes it. One whose audio file has changed since it was made is kept, but its text is no longer shown; one written by a later version of TextMouth, as on another Mac sharing the library, is left as it is, unread; and one that can't be read is kept beside itself as transcript.json.unreadable- followed by a date and time.
  - transcript.json.before-cleanup: the transcript as it was before its last cleanup, which Undo Cleanup puts back and removes. The next cleanup replaces it, and Delete Transcript deletes it.
  - origin.json: only in a recording's package: when the recording started, how long it lasts, the microphone it was recorded from, and, until the book's audio is first edited, whether its original take is kept, with when the book's audio was last made from it, which the original audio policy counts from; after that, audioEdits/edits.json (below) records the take instead. Earlier versions of TextMouth leave it alone.
  - original-take.caf: a recording's original take, lossless, for as long as the original audio policy keeps it (see [Editing audio](editing-audio.md)).
  - audioEdits: present once a book's audio has been edited, or a marker dropped in its editor: edits.json, the edit history of each of its audio files, with the editor's markers, and the book's own original policy; originals, the original audio of an imported book's files, for as long as the policy keeps it; and takes, the new takes of punch-ins and the audio pasted or recorded at the cursor, as Apple Lossless when that loses nothing. A history that can't be read is kept beside itself as edits.json.unreadable- followed by a date and time; one written by a later version of TextMouth is left alone. Earlier versions of TextMouth leave the folder alone.
  - removedFromLibrary.json: present only when you chose Remove from Library Only. It keeps the package on disk without the book returning to the library. For a braille book it also keeps its braille table, and the liblouis version of this Mac's tables when it is one of them, so the book reads as before when it is added back. A text book whose encoding was guessed or chosen keeps that encoding, and who decided it, too, for the same reason, and a BRF or BRL book keeps its braille file characters. A book added back from such a package keeps the text its package holds: when reading the book's file would write other text over content.md, TextMouth first keeps content.md as content.md.edited- followed by a date and time, and says "The text of Harbour Pilots was read again from its own file. The text content.md held before was kept as content.md.edited-20261004T123012Z, in the book's package." A marker written before markers carried an edit record gets the same, and a package of a book edited with Edit Text imports with its edit kept. When no copy can be kept, adding the book back stops with "Harbour Pilots was not added back: no copy of the text its package held could be kept first, so TextMouth left the text as it was."
  - A folder whose name starts with .import- is an import in progress. Imports build their packages here only while the data directory is on another drive than this Mac's own folders (below), and otherwise in this Mac's Import Staging folder. Nothing else in TextMouth treats such a folder as a book. The next import into the same library folder removes one that an interrupted import, or an earlier version, left behind, and each import that builds in this Mac's folder clears what interrupted imports left there.
  - A hidden file named .awaitingDuplicateAnswer marks the package of a duplicate's new copy while its question, Keep Both or Replace Existing, waits for an answer (see [Adding books](adding-books.md)). Keep Both and Replace Existing take it off, and no walk of the library adopts a package that holds it; a package copied into the library with the mark still on is imported without it.
- Archive Extraction: the working folder of ZIP imports while the data directory is on another drive than this Mac's own folders; otherwise ZIPs are extracted in this Mac's Archive Extraction folder (below). Each import removes its own folder when it ends. At startup TextMouth removes any left over, here and in this Mac's folder, and, while this Mac's folder is the one in use, removes this one once it is empty.
- Logs: the diagnostic logs, which TextMouth writes here unless Storage settings put them on this Mac, so they sit beside your books, move with the library, and sync with it when it is in the cloud. They never hold your substitution rules, and they name files by their place inside the data directory or this Mac's TextMouth folder. They hold none of your books' text either: a CONTENT_INDEX_REJECTED line, written when a book's saved index is set aside and rebuilt, names a heading that changed by where it changed, never by its words. A transcript is a book's text too: the TRANSCRIPT_FILE, TRANSCRIPT_STALE, and TRANSCRIPT_TEXT_REBUILT lines name a book's files by their place in the book, and never quote what was heard, a transcription's TRANSCRIPTION_STARTED line names the book and the language, and the line that ends it, TRANSCRIPTION_FINISHED, TRANSCRIPTION_CANCELLED, or TRANSCRIPTION_FAILED, the seconds it took and the words it found, or why it failed, never a word heard, the TRANSCRIPT_CLEANUP_RULES, TRANSCRIPT_CLEANED_UP, and TRANSCRIPT_CLEANUP_UNDONE lines of a cleanup give counts and file names, never the words it changed or its rules, an AUDIO_EDITS_FILE line, for an audio edit history that can't be used, never quotes the history, which can hold chapter titles, and an AUDIO_EDITOR line, for an editor that couldn't open a book or finish a save or an export, names the error by its kind, never by a file's path. A feed is named by its host, never by its whole address, which can carry a private feed's token.
  - textmouth_debug.log, the main log. Its PLAYBACK_STOPPED_AFTER_REFUSAL line tells of a reader that stopped at a passage the speech engine refused, its PLAYBACK_PAUSED_AFTER_START_STALLS line of a reader that paused where the voice did not start, its WHERE_AM_I_CANCEL_UNEXPECTED line of a Where Am I? announcement the system cut short, and its WHERE_AM_I_RESUME_REJECTED line of a book Where Am I? paused that would not resume as the announcement ended, which is left paused. Its BOOK_FINISHED line marks each end of a book but a loop's, naming the book by the start of its identifier and saying whether Books Finished counted it then, had counted it already, or heard a rewind replay its end; and one FINISHED_BOOKS_AT_END line counts the finished books the one-time move put at their ends, those waiting for a later launch, and those it could not place. Every ZIP import of several books ends with a ZIP_IMPORT_FINISHED line naming the archive, with the books imported, skipped as duplicates, failed, and imported without all their text, whether Cancel stopped it, and the files it passed over by kind, as in "notBooks=176 (wma 176)". Its MOVE_SHEET_SHOWN line tells of the Move to Folder or Move to Library sheet appearing, with how many places it lists and how many items it moves, as in "MOVE_SHEET_SHOWN: Move to Folder lists 5 place(s) for 2 item(s)", never a title or a path. Its LIBRARY_ROWS_KEPT line tells, when library.json is read, how many of its rows need a newer TextMouth and are kept as they are, and its ASYNC_TIME_LIMIT line of an audio read that passed its limit and was abandoned, naming no file or title.
  - textmouth_timer.log, the sleep timer's log.
  - textmouth_transition.log, the speech engine's log. Its DIRECT_CANCEL_UNEXPECTED, DIRECT_RETRY_ENGINE, DIRECT_RETRY_ENGINE_FAILED, DIRECT_RETRY, DIRECT_RETRY_AT_RESUME, SLEEP_FADE_DIRECT_SEGMENT_REFUSED, DIRECT_RETRY_FAILED, RENDER_REFUSED, and RENDER_RETRY_RENDERED lines tell of a passage the speech engine refused and what TextMouth did then; its DIRECT_WATCHDOG_RECOVERY, DIRECT_START_WATCHDOG_RECOVERY, DIRECT_START_STALLED, and DIRECT_IDLE_STALLED lines of speech that stalled or never started, and how it went on or where it paused; its SEEK_ENGINE_FAILED, DIRECT_WATCHDOG_ENGINE_FAILED, and DIRECT_START_WATCHDOG_ENGINE_FAILED lines of prepared audio that could not play, after which speech went on from the voice; its AUDIO_ENGINE_START_FAILED lines of a play or a resume that could not start the audio engine, with the system's words for why; and its DIRECT_SYNTH_REPLACED lines of each fresh start of the voice and why; all by offsets and lengths, never the passage's words. Its SPEECH_REFUSAL_REPORTED line tells of the report shown when speech stopped, with how many times that place was refused and whether VoiceOver was told.
  - Routine trace lines are written only while tracing is on: set the TEXTMOUTH_TRACE_LOG environment variable for one launch, or run `defaults write com.textmouth.TextMouth diagnosticTraceLogging -bool YES` until you turn it off again with `-bool NO`.
  - A log that reaches 2 MB is renamed with .previous added to its name, replacing the older one in the same step, and a fresh one starts, so each log keeps at most two generations and a cloud drive uploads little. When the rename is refused twice, as a cloud drive can refuse one while it uploads the file, the log starts over instead, beginning with a LOG_ROTATION line saying why. TextMouth never downloads a log to add a line to it: one whose content is only in the cloud becomes the .previous generation, and a fresh one starts.
  - The Logs group in Storage settings chooses where they go: Log location offers Inside the data directory, the default, and In this Mac's Logs folder (~/Library/Logs/TextMouth). A change applies from the next line written; logs already written stay where they are. The line under the picker names the folder in use, and why while the logs can't go where it asks, and Show Logs in Finder opens that folder, saying so, aloud too, when Finder can't.
  - While the library isn't available, or the data directory or its Logs folder is missing, the logs go to ~/Library/Logs/TextMouth, and back to the data directory once it can take them. Each time they change place, the debug log they arrive in says why in a LOG_LOCATION line. TextMouth never creates a folder in the data directory to write a log: the Logs folder is made with the data directory's other folders.

TextMouth also keeps folders of this Mac's own, which never sync and keep working while the data directory isn't available:

- ~/Library/Logs/TextMouth: the diagnostic logs (see Logs, above), when Storage settings put them on this Mac, and while the data directory can't take them. Logs that earlier builds wrote only here stay here.
- ~/Library/Application Support/com.textmouth.TextMouth:
  - Working Copies: the copies that open audiobooks in a library in the cloud play from. Each is deleted when its reader window closes, and any that a crash left behind are removed the next time a copy is made.
  - Import Staging: the packages imports are building, while the data directory is on the same disk as this folder: the startup disk, which also holds the folders of iCloud Drive and other cloud drives. A data directory on another drive keeps them in its own library folders instead, so a new book is always put in place with one rename on one disk.
  - Archive Extraction: the working folders of ZIP imports, under the same condition.
  - Recordings: the takes being recorded, and any not yet saved as a book, each a CAF file named for when it started, as in "Take 2026-10-04 06.30.12 1A2B3C4D.caf". A take leaves once its book, with the original the original audio policy keeps, is in the library, or when Discard Recording deletes it. A take cut off by a crash or a forced quit, or whose save failed after its window closed, stays here, still readable, and the New Recording window lists it under Recovered recordings until it is saved or discarded (see [Recording from a microphone](recording.md)). A punch-in's take, recorded in the audio editor, leaves once its edit holds it, or when it is discarded.
  - Feed Downloads: episodes downloaded and not yet imported, for a moment each. Whatever an interrupted download left here is removed at the next launch.
  - Kept Books.json: the books kept on this Mac (see Keep on This Mac, in [Keeping your library in the cloud](cloud-library.md)), a choice another Mac sharing the library never reads.
  - Keep Reading List Books.json, beside it: whether this Mac keeps the reading list's books downloaded (the checkbox "Keep these books on this Mac" in the Reading List's options), also this Mac's own choice, which another Mac never reads.
  - Move Leftovers.json: the hidden folders that moves of the library began and have not yet cleaned up (see Moving the library, above), which the next launch removes. It is kept here because those folders are on the new location's drive, which may be away. The file is there only while it lists a folder.
- ~/Library/Caches/com.textmouth.TextMouth/Audio Edits: one folder for each book being edited, with the filtered stretches and the silence its preview and saves read, removed when the edits are saved or the editing session ends, or, after TextMouth quit or crashed with an editor open, at its next launch. macOS may empty it, and everything in it can be made again from the book's package: a filtered stretch macOS removed is made again when the editor next needs it.
- ~/Library/Caches/com.textmouth.TextMouth/Audio Editor Clips: a folder for each open editor window, holding the audio Copy or Cut keeps for Paste, removed when the window closes, or, after TextMouth quit or crashed with the window open, at its next launch.
- ~/Library/Caches/com.textmouth.TextMouth/Feeds: how this Mac last checked each feed (Fetch State), which lets a refresh skip a feed that hasn't changed, and the partial downloads a stopped download resumes from (Resume Data, kept a week), with the list of downloads under way or waiting when TextMouth last quit (Downloads at Quit.json), which the next launch asks for again and removes. macOS may empty it; the next refresh then reads each feed whole once.
- ~/Library/Caches/com.textmouth.TextMouth/Reading Text: the reading text of the large books this Mac opened lately, those whose content.md is a megabyte or more, so that opening one again reads it from here instead of re-reading the book's Markdown. The largest anthology reopens in about a tenth of a second instead of three quarters of one, and a 20 MB book in one chapter in about 50 ms instead of a second or more. Nothing about speech is kept here, so changing substitution rules or speech settings never makes it wrong. A book's file is removed a day after the book was last opened, at once when its text is extracted again or the book is deleted, and whenever its content.md or title changes or a new version of TextMouth is installed. Time Machine leaves it out of backups, and macOS may empty it when the disk runs low; the next open simply reads the book again.
- memory-quit.json: present only after TextMouth quit to protect your Mac; the next launch reads it, tells you, and removes it.
- The debug log names these playback events: AUDIO_PLAYBACK_STALLED (a player whose time stopped moving), AUDIO_MEMORY_RUNAWAY (the memory guard stopping playback or quitting), and SOUND_EFFECT_STUCK (sounds dropped behind one that didn't start).
- Once for each library, TextMouth converts the Ogg audio of the books already in it, one book at a time, while the Library window shows "Converting audio: 12 of 176 tracks of “Title”". Bookmarks and positions stay where they were. A book needs room for its converted copy plus TextMouth's one-gigabyte reserve; one that doesn't fit waits, and an alert says how much space it needs. A book whose files are only in the cloud waits until they are on this Mac. The debug log records OGG_CONVERTED for each book converted and OGG_CONVERSION_WAITS for each that waits.
- TextMouth converts Ogg audio, and the other audio its import converts (see [What TextMouth reads](what-textmouth-reads.md)), to AAC, or to Apple Lossless when the source is lossless, with Apple's own afconvert tool, run as a separate process that TextMouth stops when it runs longer than a minute plus a tenth of the track's length, grows past 1 GB, stops writing for 20 seconds, or writes more than four times what the track should come to and 16 MB more, and that the Mac itself ends when it has used more than four times that many seconds of processor time or tries to write past that amount. An import that can't convert a track stops (see [Adding books](adding-books.md)). A library book whose Ogg conversion fails is left exactly as it was and tried again at the next launch; Play says so. The debug log records AUDIO_CONVERSION_KILLED for each conversion stopped, as OGG_CONVERSION_KILLED did before October 18, 2026.
- The converter ends with TextMouth: when TextMouth quits, when it is force-quit, and when it quits to protect your Mac. At each launch TextMouth also stops any converter an earlier run left behind, touching only one that is writing one of TextMouth's own hidden conversion files. The debug log records OGG_ORPHAN_SWEPT, with how many it stopped, when it stopped any.
- Before it converts a file other than Ogg, and when a file's first bytes don't settle whether to convert it (an MPEG-4 or QuickTime file), TextMouth asks Apple's afinfo tool what the file holds, also as a separate process that TextMouth watches. TextMouth stops it when it runs longer than 30 seconds plus one more for each 20 MB of the file, holds more than 512 MB of memory, or prints more than 1 MB. afinfo prints into a hidden file in the Mac's temporary folder, named with a dot, an ID, and .watched-output, which is removed when afinfo ends. The debug log records AUDIO_INFO_KILLED, with the file's name and the reason, for each afinfo stopped, and AUDIO_INFO_IMPLAUSIBLE, with the file's name and the length it claimed, for a file whose header claims a length that its size cannot hold.
- afinfo ends with TextMouth in the same three cases as the Ogg converter. At each launch TextMouth also stops any afinfo an earlier run left behind, touching only one that is printing into one of those hidden files, and removes those files from the temporary folder when they are more than an hour old. The debug log records AFINFO_LEFTOVERS_SWEPT, with how many processes it stopped and how many files it removed, when it did either.
- TextMouth reads, on the Mac only, a Word document older than Word 6 with Apple's own textutil tool, run as a separate process that TextMouth watches (see [What TextMouth reads](what-textmouth-reads.md)). Every other kind of document, Word 6 and Word 95 documents since version 0.4.1 and OpenDocument text and Word 2003 XML since version 0.4.0 among them, is read inside TextMouth by its own code, which starts no process and is never stopped this way. TextMouth stops it when it runs longer than 30 seconds plus one more for each million bytes of the document, grows past 1 GB of memory, or uses more than four times the time allowed in processor time, which the Mac itself enforces. A document it stopped fails to import with "TextMouth stopped reading this document because ...", and the debug log records TEXTUTIL_KILLED, with the file's name and the reason. When textutil fails by itself, because it could not start, ended with an error, or ended without writing anything, which is what it does when it cannot read a file, the debug log records TEXTUTIL_FAILED, with the file's name and which of those happened. Cancel in the import overlay stops it at once, and for any import that Cancel stops the debug log records IMPORT_CANCELLED, with the file's name and where the import stopped, as in "while reading its text", "after 3 of 10 books", or "before it started".
- While an import runs, textutil writes its output as a hidden file in the package the import is building, which goes with that package should the import fail or be cancelled. When TextMouth reads again the text of a book already in the library, it writes it in a new folder named TextMouth-textutil- followed by an ID, in the Mac's temporary folder, and removes the folder when the conversion ends.
- textutil ends with TextMouth in the same three cases as the Ogg converter. At each launch TextMouth also stops any textutil an earlier run left behind, touching only one that is writing one of TextMouth's own hidden output files, and removes the TextMouth-textutil- folders in the temporary folder that are more than an hour old. The debug log records TEXTUTIL_LEFTOVERS_SWEPT, with how many processes it stopped and how many folders it removed, when it did either.
- TextMouth translates between print and braille with liblouis, which runs in TextMouthBraille, a helper program of TextMouth's own inside the app, also as a separate process that TextMouth watches (see [What TextMouth reads](what-textmouth-reads.md)). TextMouth stops it when it runs longer than 10 seconds plus a quarter of a second for each million bytes of braille it is given to read, or 6 seconds for each million bytes of print it is given to write as braille; when its output does not grow for as long; when it holds more than 16 MB of memory; or when it writes more than 10 times its input, 32 times when it writes braille, and 1 MB more. The Mac itself ends it when it has used more than four times the time allowed in processor time. For one of this Mac's tables that has passed its check (see [Settings](settings.md)), the limits on time and on memory are raised to four times the time and twice the memory its check measured, and a limit is never lowered. A book the helper stopped fails to import with "TextMouth stopped the braille translation because ...", and an export of braille fails the same way (see [Adding books](adding-books.md) and [Exporting books](exporting-books.md)). The debug log records BRAILLE_HELPER_KILLED, with what the helper was doing (back for braille to print, forward for print to braille), the table, and the reason. When the helper fails by itself, because it is missing, could not start, ended with an error, or wrote output that does not match its input, the debug log records BRAILLE_HELPER_FAILED, with the same and what happened. Neither line holds any text of a book. The debug log also records BRAILLE_MAC_TABLE_REFUSED when the check of one of this Mac's tables refuses it, with the table's name, as "mac:" and its file name, and the reason in the refusal's words (see [Settings](settings.md)); a check that could not run is not logged so, and the line holds no text of a book. Cancel in the import overlay stops it at once.
- The helper reads a hidden file and writes another, named with a dot, an ID, and .braille-in.txt or .braille-out.txt, in the places textutil's output goes: in the package an import is building, and, when TextMouth reads again the text of a braille book already in the library, in a TextMouth-textutil- folder in the Mac's temporary folder. An export's are in its scratch folder, and the check of one of this Mac's tables chosen in Settings or in Export's braille options makes its files in a TextMouth-textutil- folder too. They are removed however the translation ends.
