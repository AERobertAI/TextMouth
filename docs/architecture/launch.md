# Launch

Part of [TextMouth's architecture](../../ARCHITECTURE.md).

- TextMouthApp's initializer installs the real cloud services (CloudServices.installSystemServices) before anything else runs: SwiftUI creates LibraryViewModel before applicationWillFinishLaunching, and the library's launch check uses them.
- AppDelegate.applicationWillFinishLaunching starts the router before any window exists, so a book Finder hands over waits for the first Library window instead of opening a second.
- The data directory's first location is decided when anything first asks for it (StorageBoundary.shared): TextMouthPaths.root(for:) names the folder the preferences hold, or the default location. When a custom location is missing but its bookmark leads to a folder holding this library under another path, as after a rename or a remount under another name, that folder is the data directory, and the preferences name it from then on.
- LibraryViewModel's initializer copies a sandboxed release's data on first launch (through DataDirectoryMigrator, keeping the original), starts listening for the data directory's loss, and checks the data directory (checkDataDirectory), reading metadata only. Nothing is created or loaded until the check finds the library: then startLibrary creates the data directory's folders, records the library's identity, removes leftover archive extraction folders, loads the library index (loadLibraryIndex), sweeps away the originals of recordings and edited audiobooks whose time is up (sweepAudioOriginalsInBackground), clears what the audio editor left in this Mac's caches when TextMouth last ended with editors open (removeStaleAudioEditCachesInBackground), starts the background work below, and begins the session lease. Otherwise every Library window shows Library Not Available, and the Try Again that first finds the library runs startLibrary.
- Loading reads library.json and every feed's own index, the feeds' rows onto the library's feed shelf (feed items, below), and repairs the index against the disk (migrateOldBooksIfNeeded): every feed item's row waits on the shelf meanwhile, books removed with Remove from Library Only stay out, the books the checkpoint journal names take the newer reading positions their records hold (adoptNewerRecordedPositions), equivalent folder rows merge, stale file paths are fixed, legacy books move into packages, packages that two books shared are separated, misplaced packages move into their folders, packages missing from the index are adopted, the feed items whose files are here join the books (joinFeedItems), and the result is saved. Every check and read of the repair leaves dataless files in the cloud, and nothing is moved, rewritten, adopted, separated, relocated, or taken out on the strength of a check that met a dataless folder or a read that was refused; one MAINTENANCE_SKIPPED_IN_CLOUD line counts the books left as they were. The look for a removal marker, which is almost always absent, stops at the first folder above it that is there and not dataless, the package itself, rather than asking every folder up to the data directory. An unreadable index skips all of this and enters recovery instead (below).
- LibraryViewModel then brings every book up to date in the background (updateContentCachesAndStatistics): after the metadata refresh, the words of places saved before anchors (captureMissingTextAnchors, T06's branch B), then every book's text cache, and after that its statistics, leaving books whose files are in the cloud as they are. The batch finds the books whose caches need work off the main thread (booksNeedingCacheUpdate, on a utility queue), and starts on the main actor once it has them. Once that maintenance has ended, and only when the statistics were read from their file (ReadingStatsService.statsReadFromFile; over stand-ins for a missing, unreadable, cloud-only, or unavailable file nothing is moved, recorded, or logged, and a later launch makes the move), the library puts each book Books Finished counts whose row reads 100 percent (99.5 or more, rowsHundredPercent) exactly at its end, once on each Mac (moveFinishedBooksToTheirEndsOnce, P07; the preference library.finishedBooksAtEndVersion, kept on this Mac alone): it reads each book's content index off the main thread, with dataless files left in the cloud, and saves the end through persistReadingPosition(bookID:position:markingOpened: false), as a reader saves a place but keeping the book's lastOpened in its row and record (Library.updateReadingPosition(bookID:position:markingOpened:), whose default dates a reader's save as an opening). A book whose record or index is only in the cloud, or that a reader has open or opens meanwhile, keeps its place, and the move is recorded as made only once none waits, so a later launch makes it then; a book whose index disagrees with its row's measure is left. One FINISHED_BOOKS_AT_END line counts what it did. First, once for each library on this Mac, keepHandEditedTitlesInManifestsOnce writes each book of tracks' hand-edited title and author into its manifest where the manifest gives another, on the manifest sessions' queue, before any look; until it is recorded (library.manifestHandEditsKeptVersion, keyed by the library's identity), each look keeps its book's hand edits first. Before the metadata refresh, it takes the edits of audiobooks' manifests made while TextMouth was closed or on another Mac (takeOutsideManifestEdits, FR18), one book at a time on a utility queue, leaving books whose files are in the cloud as they are.
- startLibrary also starts the feed engine in the background (startFeeds, FeedCenter.start(library:)): it moves the feed settings that the List and download choice retired to the choice, once, before anything reads it (FeedSettings.moveToItemPolicyIfNeeded(in:)), reads every feed's record off the main thread, moving a feed's retired kept-entries number to a choice of its own (moveKeptEntriesOverrides()), reads this Mac's fetch details, and sweeps away what interrupted downloads left; then, outside a process hosting tests, it sends the hidden .removing- folders a Delete Download cut short left in the feeds' own folders to the Trash, or deletes them, as Removal Behavior says (sweepRemovalHolders(), through FeedItemPackage.removalHolders(in:); it runs only while feedLibraryIsComplete, so never while the library index is recovered; FeedItemPackage.removalHolder(for:beside:) names holders .removing-<book ID>-<UUID>, and sweepHolder(_:puttingBackInto:remove:) puts back what a still-downloaded row's package lacks (packageWaitingForItsFiles) and sends the rest through FeedEnvironment.removeItem folder by folder (HolderSweep); FEED_HELD_ASIDE_SWEPT, or FEED_HELD_ASIDE_LEFT for one left for the next launch), asks again for the downloads under way or waiting when TextMouth last quit (resumeDownloadsSavedAtQuit), deletes the played downloads that are due, runs the newest-N rule's first pass over every feed (the List and download choice, under Feeds, below), watches feedItems and feedNewestCount for the rule (itemPolicyChanged(for:)), refreshes every feed when feedRefreshAtLaunch is on, and refreshes them again every feedRefreshIntervalHours, never holding the library back. Once the records have loaded, the library moves the downloads made before FR11 into their feeds' own folders, returns to the library, as books, the downloads of each feed whose folder is here while its record is gone, and marks downloaded again the items an older TextMouth marked otherwise whose files are on this Mac (moveFeedDownloadsOnceRecordsLoad(); feed items, below).
- SettingsViewModel's initializer applies config.json, reconciles it with the preferences, and starts ConfigService watching the file. Before it applies the file (applyFileAtLaunch), the first launch whose preferences hold no record of the shortcuts the user edited makes one from the shortcuts saved before (KeyboardShortcutManager.moveSavedShortcutsIfNeeded; keyboard shortcuts, below). While the data directory is unavailable, ConfigService reads, writes, and watches nothing, and it reconciles the file once the library is back.
- applicationDidFinishLaunching tells of a quit to protect the Mac (PlaybackMemoryGuard.tellOfAQuitToProtectTheMac), begins the memory guard's readings (PlaybackMemoryGuard.shared.beginWatching()), and sweeps in the background the converters an earlier TextMouth left running (OrphanedConversionSweep.sweepInBackground(), REV17a; see [Imports](state/imports.md)). applicationShouldTerminate lets the guard's quit through with no questions (B07), and applicationWillTerminate ends every converting child (WatchedProcess.terminateAll()).
- convertOggAudioOnce runs beside the launch passes, once per library (preference library.oggAudioConvertedVersion.<identity>), a book at a time through OggConversionProgress.enqueue, each committed on the manifest sessions' queue (B06).
