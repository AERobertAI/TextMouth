# Launch

Part of [TextMouth's architecture](../../ARCHITECTURE.md).

- TextMouthApp's initializer installs the real cloud services (CloudServices.installSystemServices) before anything else runs: SwiftUI creates LibraryViewModel before applicationWillFinishLaunching, and the library's launch check uses them.
- AppDelegate.applicationWillFinishLaunching starts the router before any window exists, so a book Finder hands over waits for the first Library window instead of opening a second.
- The data directory's first location is decided when anything first asks for it (StorageBoundary.shared): TextMouthPaths.root(for:) names the folder the preferences hold, or the default location. When a custom location is missing but its bookmark leads to a folder holding this library under another path, as after a rename or a remount under another name, that folder is the data directory, and the preferences name it from then on.
- LibraryViewModel's initializer copies a sandboxed release's data on first launch (through DataDirectoryMigrator, keeping the original), starts listening for the data directory's loss, and checks the data directory (checkDataDirectory), reading metadata only. Nothing is created or loaded until the check finds the library: then startLibrary creates the data directory's folders, records the library's identity, removes leftover archive extraction folders, loads the library index (loadLibraryIndex), sweeps away the originals of recordings and edited audiobooks whose time is up (sweepAudioOriginalsInBackground), clears what the audio editor left in this Mac's caches when TextMouth last ended with editors open (removeStaleAudioEditCachesInBackground), starts the background work below, and begins the session lease. Otherwise every Library window shows Library Not Available, and the Try Again that first finds the library runs startLibrary.
- Loading reads library.json and every feed's own index, the feeds' rows onto the library's feed shelf (feed items, below), and repairs the index against the disk (migrateOldBooksIfNeeded): every feed item's row waits on the shelf meanwhile, books removed with Remove from Library Only stay out, the books the checkpoint journal names take the newer reading positions their records hold (adoptNewerRecordedPositions), equivalent folder rows merge, stale file paths are fixed, legacy books move into packages, packages that two books shared are separated, misplaced packages move into their folders, packages missing from the index are adopted (one whose record names the ID of a book the library lists is left as it is, unadopted and unwritten, as the old copy Replace Existing sent to the Trash is once Finder puts it back, with one ORPHAN_ID_LISTED line: ST04, in [Imports](state/imports.md)), the feed items whose files are here join the books (joinFeedItems), and the result is saved. Every check and read of the repair leaves dataless files in the cloud, and nothing is moved, rewritten, adopted, separated, relocated, or taken out on the strength of a check that met a dataless folder or a read that was refused; one MAINTENANCE_SKIPPED_IN_CLOUD line counts the books left as they were. The look for a removal marker, which is almost always absent, stops at the first folder above it that is there and not dataless, the package itself, rather than asking every folder up to the data directory. An unreadable index skips all of this and enters recovery instead (below).
- LibraryViewModel then brings every book up to date in the background (updateContentCachesAndStatistics): after the metadata refresh, the words of places saved before anchors (captureMissingTextAnchors, T06's branch B), then every book's text cache, and after that its statistics, leaving books whose files are in the cloud as they are. The batch finds the books whose caches need work off the main thread (booksNeedingCacheUpdate, on a utility queue), and starts on the main actor once it has them. Once that maintenance has ended, and only when the statistics were read from their file (ReadingStatsService.statsReadFromFile; over stand-ins for a missing, unreadable, cloud-only, or unavailable file nothing is moved, recorded, or logged, and a later launch makes the move), the library puts each book Books Finished counts whose row reads 100 percent (99.5 or more, rowsHundredPercent) exactly at its end, once on each Mac (moveFinishedBooksToTheirEndsOnce, P07; the preference library.finishedBooksAtEndVersion, kept on this Mac alone): it reads each book's content index off the main thread, with dataless files left in the cloud, and saves the end through persistReadingPosition(bookID:position:markingOpened: false), as a reader saves a place but keeping the book's lastOpened in its row and record (Library.updateReadingPosition(bookID:position:markingOpened:), whose default dates a reader's save as an opening). A book whose record or index is only in the cloud, or that a reader has open or opens meanwhile, keeps its place, and the move is recorded as made only once none waits, so a later launch makes it then; a book whose index disagrees with its row's measure is left. One FINISHED_BOOKS_AT_END line counts what it did. First, once for each library on this Mac, keepHandEditedTitlesInManifestsOnce writes each book of tracks' hand-edited title and author into its manifest where the manifest gives another, on the manifest sessions' queue, before any look; until it is recorded (library.manifestHandEditsKeptVersion, keyed by the library's identity), each look keeps its book's hand edits first. Each look then writes what its manifest is owed (BookManifestEditSessions.settleOwedFields(of:adding:isDataless:), ManifestOwedFields; package records) before it compares, so a title or author the manifest could not take stands over its stale value. Before the metadata refresh, it takes the edits of audiobooks' manifests made while TextMouth was closed or on another Mac (takeOutsideManifestEdits, FR18), one book at a time on a utility queue, leaving books whose files are in the cloud as they are.
- startLibrary also starts the feed engine in the background (startFeeds, FeedCenter.start(library:)): it moves the feed settings that the List and download choice retired to the choice, once, before anything reads it (FeedSettings.moveToItemPolicyIfNeeded(in:)), reads every feed's record off the main thread, moving a feed's retired kept-entries number to a choice of its own (moveKeptEntriesOverrides()), reads this Mac's fetch details, and sweeps away what interrupted downloads left; then, outside a process hosting tests, it sends the hidden .removing- folders a Delete Download cut short left in the feeds' own folders to the Trash, or deletes them, as Removal Behavior says (sweepRemovalHolders(), through FeedItemPackage.removalHolders(in:); it runs only while feedLibraryIsComplete, so never while the library index is recovered; FeedItemPackage.removalHolder(for:beside:) names holders .removing-<book ID>-<UUID>, and sweepHolder(_:puttingBackInto:remove:) puts back what a still-downloaded row's package lacks (packageWaitingForItsFiles) and sends the rest through FeedEnvironment.removeItem folder by folder (HolderSweep); FEED_HELD_ASIDE_SWEPT, or FEED_HELD_ASIDE_LEFT for one left for the next launch), asks again for the downloads under way or waiting when TextMouth last quit (resumeDownloadsSavedAtQuit), deletes the played downloads that are due, runs the newest-N rule's first pass over every feed (the List and download choice, under Feeds, below), watches feedItems and feedNewestCount for the rule (itemPolicyChanged(for:)), refreshes every feed when feedRefreshAtLaunch is on, and refreshes them again every feedRefreshIntervalHours, never holding the library back. Once the records have loaded, the library moves the downloads made before FR11 into their feeds' own folders, returns to the library, as books, the downloads of each feed whose folder is here while its record is gone, and marks downloaded again the items an older TextMouth marked otherwise whose files are on this Mac (moveFeedDownloadsOnceRecordsLoad(); feed items, below).
- SettingsViewModel's initializer applies config.json, reconciles it with the preferences, and starts ConfigService watching the file. Before it applies the file (applyFileAtLaunch), the first launch whose preferences hold no record of the shortcuts the user edited makes one from the shortcuts saved before (KeyboardShortcutManager.moveSavedShortcutsIfNeeded; keyboard shortcuts, below). A config.json with no "default…" entry and no object is in the old form, and is read after the move as the move reads it: a list equal to its action's default edits nothing (KeyboardShortcutManager.adopt(_:in:)); a hand-written file of only lists is read the same way. While the data directory is unavailable, ConfigService reads, writes, and watches nothing, and it reconciles the file once the library is back.
- applicationDidFinishLaunching tells of a quit to protect the Mac (PlaybackMemoryGuard.tellOfAQuitToProtectTheMac), begins the memory guard's readings (PlaybackMemoryGuard.shared.beginWatching()), and sweeps in the background the converters an earlier TextMouth left running (OrphanedConversionSweep.sweepInBackground(), REV17a, for afconvert, and sweepTextutilInBackground(), FMT13, for textutil and its working folders, and sweepAfinfoInBackground(), FMT09, for afinfo and its captured-output files; see [Imports](state/imports.md)) and the hidden staging folders that moves of the data directory left (MigrationStagingLeftovers.sweepInBackground(); see [The data directory](state/data-directory.md)), and reads this Mac's braille tables in the background (BrailleTableCatalog.loadInBackground(); see Braille files, in [Imports](state/imports.md)). applicationShouldTerminate lets the guard's quit through with no questions (B07), and applicationWillTerminate ends every converting child (WatchedProcess.terminateAll()). The rest of a quit is in the next bullet.
- A quit (AppDelegate.applicationShouldTerminate; 0.4.4). It answers in this order, and the saved and unsaved questions it asks are in [Saving failures](state/saving-failures.md).
  - The memory guard's quit goes through at once, with no questions (PlaybackMemoryGuard.shared.isQuittingToProtectTheMac, B07).
  - The system ending the session comes next (QuitReason.currentRequestEndsTheSession). If work is already being finished for the person's quit, it is answered .terminateLater, says the same words again, and is replied to when that work ends (QuitFinisher.answerSessionEnd).
  - A request that comes while that work is being finished is cancelled and says the same words again (QuitFinisher.answerRepeatedRequest), so a second Command-Q or the Dock's Quit never cuts the work off and never goes unanswered.
  - Step 0 is next: a library move that is copying is stopped, the Record window asks about a take it holds, and each audio editor with unsaved edits asks Save, Discard, or Cancel. Each cancels this request and asks to quit again (QuitRequest.ask()) once it is answered. If the request that follows a wait is cancelled here, the Quit Anyway kept for it is forgotten (UnsavedChangesTerminationGuard.forgetQuitAnyway()).
  - Then the unsaved-changes guard flushes what is pending and, with nothing unsaved or Quit Anyway chosen, lets step 4 answer (UnsavedChangesTerminationGuard.reply(whenQuitting:)).
  - Step 4 is the work a quit must not cut off, which is one list of QuitHold.Work (AppDelegate.heldWork), each with a kind, a longest wait, and a phrase for what it is doing:
    - "feed downloads" keep their place, for 3 seconds at most (FeedQuitHold.longestWait), saying "keeping the place of your feed downloads for next time".
    - "text re-reads" finish a book's text read again in another encoding, for 10 seconds at most (TextRereads.longestQuitWait), saying "reading a book's text again in another encoding", or "reading the text of 3 books again in another encoding" when several run.
    - "speech exports" stop with their finished chapters kept, for 5 seconds at most (SpeechExportsUnderWay.longestQuitWait), saying "stopping a speech export with the chapters it finished kept", or "stopping 2 speech exports with the chapters they finished kept" when several run.
    - The phrase is read when the quit is asked, not when the work is made, so a count is right.
  - A quit the person asks for while any of that work runs is cancelled, not left pending (QuitFinisher.finish(_:) returns true, and the delegate answers .terminateCancel). TextMouth then says what it is finishing and that it will quit, ends each piece of work in turn, each for at most its longest wait (QuitHold.end(_:)), and asks to quit again (QuitRequest.ask()). Nothing here waits longer than the sum of the waits, 18 seconds, so work that cannot end never keeps TextMouth open.
  - The request that follows the work is told which kinds of work were waited for (QuitFinisher.takeFinished()), and goes ahead without waiting for those kinds again, even when the work gave up waiting, so it cannot loop. A kind that began while TextMouth was waiting is waited for, once.
  - The words are one sentence in two places, QuitHoldWording: the panel titled "Quitting TextMouth" (QuitNotice, ordered to the front without taking the keyboard from the window the person is in) and a VoiceOver announcement from that panel. They are "TextMouth is finishing up before it quits: " followed by the phrases, joined as "a", "a and b", or "a, b, and c", and then " It will quit as soon as that is done." The panel comes down before the quit is asked again.
  - With no such work running, step 4 answers .terminateNow and the quit goes ahead.
  - The system ending the session (log out, restart, or shut down) is never cancelled, since a cancel would stop it. It is answered .terminateLater with the same words, and the reply is given when each piece of work has ended or had its longest wait (QuitHold.hold(_:reply:)). Step 0's questions and the unsaved-changes prompt still meet it, and cancel it, which stops the log out.
  - QuitReason (App/QuitReason.swift) tells the two apart. It reads the quit Apple event under the SDK's own keyword, AEKeyword(kAEQuitReason), which is 'why?' (0x7768793F), as an attribute or as a parameter, since AERegistry.h does not say which loginwindow uses. The reasons that end the session are kAELogOut, kAEReallyLogOut, kAERestart, and kAEShutDown.
  - A shut down or restart also posts NSWorkspace.willPowerOffNotification, which AppDelegate starts watching at launch (QuitReason.startWatchingForPowerOff()). A quit within 120 seconds of it (QuitReason.powerOffWindow) counts as the system's too, in case the event names no reason. A person who cancels the shut down and presses Command-Q within those 120 seconds is held with .terminateLater instead of cancelled, and still quits.
  - Command-Q, the Quit menu item, and a call to terminate carry no Apple event. The Dock's Quit carries one without a session-ending reason, so it is the person's quit.
  - Every ask to quit again goes through QuitRequest.ask() (App/QuitRequest.swift): Quit Anyway, Retry, the editors' and the Record window's answers, the end of a library move, Quit in the data-directory screens, the session lease, a relaunch, and the finisher's own. It schedules terminate(_:) on the main run loop as a timer in the common modes, and under hosted tests it only counts the request (QuitRequest.heldBackUnderTest) and quits nothing. The memory guard keeps its direct call, since the delegate answers it at once.
  - A source scan keeps it so. Any line that calls terminate(, names terminate in a #selector, or calls exit( or _exit( fails the scan unless that same line contains quit-ok: and a reason after it, in a comment, as the helper's own call does. The mark exempts that line only, never a whole file, and a mark anywhere on the line counts. The scan runs in QuitWhileHeldTests.testNoSourceAsksAppKitToQuitExceptTheHelperAndTheMemoryGuard and in Scripts/test/quit-while-held.py (see [Testing TextMouth](../developer/testing.md)). Only TextMouth/ is scanned, and it does not find forceTerminate(), a Selector("terminate:") built from a string, abort(), or kill(.
  - Two AppKit facts, shown by probes in real AppKit (Scripts/test/quit-while-held.py), are why it is built this way:
    - A quit asked again from a main-queue block or a main-actor Task while a reply is pending never ends: AppKit waits for the reply inside the main queue's drain, which runs no main-queue work, so the hold's own Task never starts. A run-loop timer fires outside the drain, which is why QuitRequest.ask() uses one.
    - A second terminate while a reply is pending quits at once, without asking the delegate, so a person's second Command-Q or the Dock's Quit would cut the work off. A cancelled quit does ask the delegate again, which is why the person's quit is cancelled while the work is finished.
- convertOggBooksOnce runs beside the launch passes, once per library (preference library.oggAudioConvertedVersion.<identity>), a book at a time through OggConversionProgress.enqueue, each committed on the manifest sessions' queue (B06).
