# Reading a book: the path from library row to spoken audio

Part of [TextMouth's architecture](../../ARCHITECTURE.md).

A book opens from its row in the Library window: VoiceOver's default action on the row, the row's Open command, or the Open Selected Book shortcut calls LibraryView.openBook(_:), which, at the Reading List, first asks the book's reader to read it from the list (reading from the reading list, above), and then ContentView's onOpenBook, which asks SwiftUI for the reader window whose value is the book's ID. A book already open comes forward instead of opening twice. Requests from elsewhere, such as Finder or a finished book continuing to the next, go through LibraryWindowRouter to the same scene. The scene builds a BookReaderWindowView, which looks the book up in LibraryViewModel and creates the window's ReaderViewModel with a copy of it. When the view appears it marks the book opened, and its window accessor gives the reader its window and registers the window with the router.

The new reader loads at once, on a background queue. It first asks the book storage where the library lives. Anywhere but a cloud location it reads the book in the same step, as it always has. In a cloud location it reads the book's cloud state too, and a book with files only in the cloud downloads first, in the reader window; the book is then read with dataless files left in the cloud, an audiobook after it is cloned into its working copy (getting a book from the cloud, above). A book being edited in the user's own editor, a text book or a transcribed audiobook, first has any edit saved there checked (settlePendingEdit(of:): edited text, above): one taken is read as the book's text, and one that can't be taken stops a text book's load, which says why, and leaves out an audiobook's transcript text. Reading calls BookContentAnalysisService.load, asking for a fresh text cache when the book records an older cache format than MarkdownCacheService.currentCacheVersion, and passes this Mac's ReadingTextCache: a large book whose kept text matches is read from it instead of content.md, and a parsed one is kept in the background. For a text book, loading writes content.md if it is missing; otherwise it checks the cache against its fingerprints, rebuilding it when the source or the cache has changed, reads it, and uses the content index saved in bookInfo.json when that index validates and lines up with the chapters, or indexes the chapters afresh. For an audiobook, loading uses a validated saved index, or else reads the audio through AudioBookParser, waiting for it through AsyncBridge, into chapters whose placeholder text stands for time at ten characters a second. A transcribed audiobook then has its transcript text laid over those chapters, for the text area to show while the audio plays (TranscriptTextLoader.load: transcripts, above). An audiobook's tags are read as well, but not an EPUB's package metadata: showEPUBMetadata() shows it from the book's row (Book.keptEPUBMetadata) when the row keeps every field, and otherwise reads it off the main thread once the book shows, through LibraryBookInfoReader.system's read, which never downloads, laying the book's edits over it as the book is when the read ends, and keeps it on the row and in the book's record (Book.keepEPUBMetadata(readFromFile:)), giving only the fields the row lacks the file's values, so an edit stands and later opens read nothing. Back on the main actor, the reader publishes the content and its headings, lays the book's own metadata edits over what the files hold, taking them from its copy of the book as it is by then, brings the saved position into range, commits a new or changed index through LibraryViewModel.updateContentIndex, saves the position, and claims a waiting autoplay request, if one is there. If the library moved the book while it loaded, the reader finds its chapter files at the new place, and a load that failed because of the move starts again from there. After claiming a waiting autoplay request, the reader prepares the opened chapter's speech off the main thread (prepareOpenedChapterSpeech).

Play starts nothing while the book is loading or while Where Am I? is speaking. For a text book, the reader first prepares what it will say, or takes what it prepared before from the same inputs (prepared speech, above). The chapter's text goes through the playback pipeline (ChapterSpeechInputs.prepare()): skipped sections are removed, runs of a repeated symbol are rewritten (RepeatedSymbolRule, which runs before the pauses because their periods and commas would lengthen runs of those symbols), punctuation pauses are added, and the substitution rules are applied, while a ComposedOffsetMap keeps track of where every spoken character came from. A position anywhere inside a rewritten run maps into the words that replaced it, and back. When nothing speakable remains, the book ends at once through its end-of-book behavior. Otherwise the reader claims the media controls through its NowPlayingSession, plays the play sound, records when playback started (for rewind on resume), starts a listening session in ReadingStatsService, resumes the sleep timer's countdown if this reader owns a paused one, and starts speaking.

Speaking begins a new play of the chapter (ChapterPlay), which gives the speech service a finish callback made for that play, and hands the spoken text and the starting offset to SpeechService.speak, which starts the synthesizer speaking directly at once, from a short first chunk, and renders the same text into an AudioEngineService in the background, through SpeechRenderCoordinator, for the next natural break. The reader then pre-renders the next speakable chapter, recording what that render was asked for as its signature and carrying that chapter's speech to its start; a chapter too long to render ahead is not rendered, and only its speech is prepared, off the main actor. As each word is spoken, onWordSpoken moves the cursor back through the offset map to the original text. The reader refreshes its view at most every 0.12 seconds, gives the library's rows and summary bar its cursor about once a second, through LiveReadingPositions, and saves a durable checkpoint every 30 seconds, into the book's record at once and into library.json within five minutes.

When a chapter's speech finishes, the callback made for its play ignores the end of a play the reader has already left, a later play having begun. Otherwise it saves the position and starts the next speakable chapter after the one that played, as a new play, unless the reader's own sleep timer stops playback at this chapter's end, where the next chapter begins the next heading, or the book ends (expireAtChapterEnd(endingTheHeading:endingTheBook:by:)): then the reader stops there instead, its cursor waiting at the next chapter's start. If the look-ahead holds that chapter's audio, rendered with the signature its speech has now, the engine plays it at once and the chapter after it is pre-rendered; otherwise the chapter is spoken from its current text. When no speakable chapter remains, handleEndOfBook stops, starts the book again, or continues to the next book in the folder or feed, as the book's end-of-book rule says (EndOfBookRule: its own choice, else its feed's or folder's, else the global setting) and the reader's sleep timer allows, or, for a book read from the reading list, goes where the list's options say (finishBookReadFromReadingList). Every end but a loop's calls finishAtTheEnd(replayingAFinishedEnd:) (P07), which tells ReadingStatsService.markBookFinished, unless the end replayed a finished end, writes one BOOK_FINISHED event line, counted, counted already, or a replay, and calls restAtEnd(), which saves the cursor at endOfBookPlace, the last chapter at its full length, so the place's global offset is the book's total, beginning a new playback generation only when that moves it to another chapter. Book.restsAtEnd, a saved place at or past the book's total, with no field of its own, and the reader's cursorRestsAtEnd, its live counterpart, then read the book as finished. A book that neither loops back to its beginning nor hands over to the next book rests finished at its end (hasFinishedBook) and keeps its Now Playing session, so a backward skip that reaches its reader, from the AirPods, the media keys, or the keyboard, plays it again from where the skip lands, while no other book plays (Now Playing and media keys, above); performSkip marks that play replaysFinishedEnd, which the end it reaches takes and a jump or a stop clears, and a forward skip from the end stays there. play() on a book whose cursor rests at its end calls playFromTheEnd(), which repeats the end's choice without playing the end: Stop says EndOfBookWording.finished(_:notes:sleepTimerExpired:) alone, EndOfBookBehavior.stopAndPlayStartsOver, which stops at the end as Stop does, and loop play the book from its beginning through playFromTheBeginning(announcing:) ("Starting again: Dune", or "Restarting: Dune"), and Continue to Next Book and the reading list go on through continueToNextBookInFolder and followReadingListPastThisBook, which both end in goOnPastThisBook (see [The reader](state/reader.md)). An audiobook's finished play reports no position (AudioPositionObserverPolicy's hasFinished, from AudioPlaybackService.finishedPlayGeneration), so the player's last tick never moves the cursor off the end.

An audiobook takes the other branch at Play: playAudioChapter begins a new play and loads the chapter's file into AudioPlaybackService, from the book's working copy when the reader has one, playing it from the cursor's time, counted from the chapter's start within the file when the chapter is a time range, at the book's speed. A segmented chapter plays its clips as one chain instead, from the clip that holds the cursor's time. In a cloud location without a working copy, a chapter whose file is only in the cloud downloads first (chapterFilesReadyToPlay), and plays once it is here. The service reports the end of each play once, and the reader moves on from the chapter that played, as it does for speech. A file that cannot be played stops playback where it was, and the reader shows an alert with Retry.

Pausing first ends a Where Am I? announcement, leaving its book paused, then records when playback stopped, pauses the sleep timer's countdown if this reader owns the timer, ends the listening session (crediting its last slice), and saves the position. Closing the window unregisters it from the router and closes the reader, which stops waiting for any download, stops playback, saves the position, releases its Now Playing session, stops the sleep timer if this reader owns it, deletes its working copy off the main thread, stops watching the library's updates to its book, and lets go of everything that grows with the book (a closed reader, above). The book's library row and its bookInfo.json then hold the last checkpoint, and LibraryPersistenceService writes both within half a second, library.json too, since unregistering the book brought its write forward from the checkpoint's deadline, or at the latest when the app quits.

When a multi-file audiobook's chapter ends and a pause follows it (chapterPauses), audioDidFinish, after the sleep timer's check, moves the cursor to the next chapter's start, lets go of the player at its volume, and starts the chapter from a cancellable work item once the pause has passed (startCursorChapter(afterPause:)). isPlaybackUnderWay counts the wait. stopAudioWaitingToPlay, stop() and so closing, a package move, and playAudioChapter() cancel it; a jump moves only the cursor. fileAfterCurrentChapter names no file after a chapter a pause follows; without a pause, playback rolls on gaplessly as before.
A reader of an audiobook of tracks looks at its manifest before it reads the book (readContent, LoadedContent.manifestLook) and whenever TextMouth becomes active (lookForOutsideManifestEdit, with its chapterPauses). What it finds goes to BookManifestEditor.handle(_:for:in:), which commits it through the library as a session's edit is committed (FR18).
