# Exports

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- An export (FR05): what the Export dialog offers, what is checked, where it goes, and how far it has got.
  - Owner: BookExportModel, one for each Export dialog, on the main actor: the books, what they offer (BookExportOffer), a choice for each kind any of them holds (BookExportChoice), the kinds checked, the destination, and the phase (listing, ready, exporting, or finished). The destination starts at the folder last exported to this session, kept only in memory, or else at Documents, in the home TextMouthRuntime names, so a test exports into its sandbox.
  - Who may write it: the dialog's controls, and BookExportService, which never downloads (MaintenanceFileAccess). offer(for:access:) lists, off the main thread, what a book's package holds, from what the file system says: for a folder of tracks it also reads the saved content index (audioFileOrder(listed:index:): the files in the order the chapters and their clips play them, then any others in Finder's order), and for a DAISY book kept as loose files its inventory (DAISYPackageInventory). It lists, too, the originals the audio editor keeps in the package's audioEdits/originals folder (AudioEditPackage.folder, originalsFolderName) as BookExportKind.originalAudio: one file as "<title> - Original Audio" with its own extension, or a book's tracks' originals in a folder of that name, each under its path in the book's audio folder, copied as they are; Export never makes one, and a recording's take stays its Original recording (originalRecording). plan(_:kinds:conversions:in:fileExists:) names every file: one book's items go in the destination, its tracks and a loose DAISY book's files in a folder named after it; several books get a folder each; and a name already taken is followed by a number (UniqueNames, compared without case), so nothing is replaced. When Export is pressed, the model lists the books again as the library holds them, and runs export(_:kinds:conversions:to:access:cancellation:progress:) off the main thread. It leaves out books and items only in the cloud, copies each file with dataless files left in the cloud, and writes the plain text (plainText(fromMarkdown:at:title:): the chapters as the reader parses them). The Text as Markdown item, and the Markdown of a transcribed audiobook's Transcript, are made from content.md, not copied: markdownFile(of:from:as:) lists each as a .converted source by BookExportConversion.markdown, with content.md's size as the offer's, and only transcript.json is copied byte for byte. Every file, whether copied, plain text, or converted (text export, below), is made at a scratch URL in a new scratch folder (writeThroughScratchFile): the system's item-replacement folder on the volume of the nearest existing folder that holds the target (makeScratchFolder(near:)), or, when the system makes none, a new "TextMouth Export <UUID>" folder in the temporary directory. When the file is whole and Stop has not been pressed, moveExclusively moves it to its target, and the target's folder is made only then. The move is an exclusive rename (renamex_np with RENAME_EXCL, which the file system makes atomic: FileManager.moveItem checks and then renames, so a file made between the two would be replaced) or, where the volume cannot do that (EXDEV, ENOTSUP, or EINVAL), an exclusive copy (copyfile with COPYFILE_EXCL) and then the removal of the source. A target that exists, even one made an instant ago, fails that file with fileWriteFileExists and is left as it was, and the scratch folder is removed in every case. So an export never replaces a file in the chosen folder, removes none that was there before it began, and leaves no half-written file after a Stop or a failure. The one thing it removes in the folder is the partial file that copyExclusively created itself, when an exclusive copy fails for a reason other than an existing target (an open follow-up in the TODO, from team export, October 19). Stop (BookExportCancellation) is read before each file and, through checkCancelled(), between a conversion's steps and a writer's blocks, so a conversion ends partway; a copy already begun finishes in the scratch folder, and writeThroughScratchFile, checking once more before the move, does not move it. Either way the file is neither exported nor a failure, and the files after it are not started. A destination inside the data directory is refused (BookExportModel.isInsideDataDirectory).
  - How others observe it: BookExportSheet shows the model, VoiceOver's focus on its first checkbox. LibraryExportSupport presents it on a Library window, for the selection File > Export… finds or the books a row's context menu acts on, and ReaderBookCommandsSupport on a reader, for its book, from File > Export… or the toolbar's Export button. The end is announced once (BookExportWording.finished); the dialog closes when everything was exported (didEverything), and keeps its summary otherwise. Each export writes one BOOK_EXPORT line, and each file that couldn't be written a BOOK_EXPORT_FAILED line.
  - Files: Services/BookExportService.swift, ViewModels/BookExportModel.swift, Models/BookExportWording.swift, Models/LibraryCloudWording.swift, Views/Export/BookExportSheet.swift, Views/Export/BookExportPresentation.swift, Views/Reader/ReaderBookCommands.swift, Views/Library/LibraryView.swift, Views/Library/LibrarySubviews.swift, App/MenuCommands.swift.
- Text export (FMT18, FMT19, FMT22): what the Convert to picker, beside Text as Markdown, makes of a text book's content.md in place of its Markdown (T3, October 23, 2026: Markdown is written too, and no export copies content.md). What each format keeps and leaves out is in [Exporting books](../../user/exporting-books.md).
  - Owner: BookExportModel keeps the Convert to choice of each kind whose text a writer can convert (conversionIDs: a writer's id, or TextExportWriters.markdownID until another is chosen; BookExportKind.convertsText is true for .markdown alone) and each writer's options (optionsStates, one TextExportOptionsState for each writer chosen, kept for the dialog's life), and BookExportSheet draws the picker beside the checked checkbox, with the chosen writer's options view under it. TextMouth/Services/Export/ holds the writers and what they read:
    - ExportDocument, the model every writer reads. For a writer that asks (EPUB, since 0.4.1) it also says where each chapter begins (chapterStarts, ExportChapterStart), where each page begins (ExportPageBreak: the block case .pageBreak between blocks, ExportRun.pageBreak inside text, and ExportTable.cellPages for a page that starts in a table cell, ExportCellPage), and the places the book's contents point at (ExportNavigationTarget: .navigationTarget between blocks and ExportRun.navigationTarget inside text, a heading annotation of content.md that a converted book carries for a contents entry naming a styled paragraph, an anchor, or a deeper entry of a Kindle book; ExportContentsItem is one entry of the contents, a heading or a target), all read where the reader reads them.
    - ExportDocumentWalker, the one swift-markdown walk of content.md, since Markdown stays the base. It splits the text into chapters at the markers exactly as the reader does, so text before the first marker is left out, as the reader leaves it out. ExportWalkOptions says what the walk keeps besides the words: keepsChapters and keepsPageMarkers, off in .plain (HTML, RTF, Word, and braille get the document they always did) and on in .bookStructure, which a writer asks for in TextExportWriter.walkOptions. The decoding of a marker line is MarkdownMarker (Parsers/MarkdownMarker.swift), moved out of the reader unchanged and shared with the exporters; one effect reaches every writer: the walk no longer drops the words that follow a marker on the same line. A target in a table cell is a place before the table; a page that starts in a cell stays in it.
    - TextExportWriter, the writer protocol, with the TextExportWriters.all registry, the TextExportConversion erasure, and the dialog's options state (TextExportOptionsState).
    - HTMLExportWriter with XMLEscaping, RTFExportWriter, and WordDocExportWriter, which is Apple's .docFormat from TextMouth's RTF. HTMLExportWriter and EPUBExportWriter write their blocks through XHTMLMarkup (Services/Export/XHTMLMarkup.swift), so a heading, a list, or a table is written once, and their contents lists through ExportContentsList (the same file): one list for each item, a heading that rises out of a skipped level joining its sibling's list and an entry above the outermost level lowering it, where the HTML writer used to put two lists in one item. ExportBookDetails.languageTag accepts a language only if it is a well-formed BCP 47 tag, for HTML, PEF, and EPUB.
    - EPUBExportWriter (FMT28, 0.4.1), registered after WordDocExportWriter and before BRFExportWriter in TextExportWriters.all. An existing test pins the first choices. The order is html, rtf, doc, epub, brf, pef, and without the Word writer, which iOS lacks, html, rtf, epub, brf, pef. It asks for .bookStructure and writes the package through EPUBPackageBuilder:
      - `mimetype`, stored and first, and META-INF/container.xml.
      - OEBPS/chapter-N.xhtml for each chapter:
        - A long chapter continues in another file past maximumFileBytes, 256,000 by default, ending the file where a heading begins when it can, else past four times that.
        - A chapter of only page markers joins the next file, or the previous one at the end.
      - OEBPS/nav.xhtml: the contents nested by level from ExportContentsList, and the hidden page list.
      - OEBPS/content.opf:
        - The identifier: urn:uuid and the book's library identity in lower case, or a new UUID for a book without one.
        - The title and creator.
        - The language: "und" and dir="auto" on every block when the book names none or says "und".
        - The modified date.
        - The accessibility metadata, which the summary follows by the entries written.
        - page-progression-direction="rtl" with dir="rtl" for a right-to-left language or script (EPUBPackageBuilder.isWrittenRightToLeft: the script subtag when there is one, else the language, ku, sd, ks, and ug being assumed neither way).
    - EPUBExportWriter, links and targets:
      - EPUBLinkAddress.url(from:) percent-encodes a link's address for EPUBCheck's RSC-020: ASCII hexadecimal digits only, a port up to 65535, a host of letters, digits, dots, and hyphens.
      - It answers nil for an address that is not a URL, when the link's words are written without the link.
      - A navigation target becomes an empty target with an id and a contents entry at its level. The reader reads that entry back at its depth in the contents, so levels 3 to 6 alone under a chapter come back as 2, and one in a table cell comes back a few words early.
      - A chapter that opens with text gets an entry named for the chapter or the book.
      - A heading of only forbidden or zero-width characters is a target, named "Untitled".
    - EPUBExportWriter, writing and checking:
      - write(_:options:to:cancellation:) refuses a file already there, writes the package, and opens it again in verify(_:holds:).
      - verify checks the entries and their order, and each entry's checksum, which ZIPFoundation's extract returns and leaves its caller to compare. Any failure removes the file.
      - Archive.ArchiveError and Data.DataError become "The EPUB file could not be written." or, from writeFailureSentence(errno:), a sentence naming a full disk or the system's own words for a read-only volume or a missing permission.
      - `afterEachFile` exists only so a test can stop or fail the export after a given file.
      - Nothing is checked in Apple Books or by VoiceOver. EPUBCheck 5.2.1 reports nothing on the exports of the test books.
    - MarkdownExportWriter, the Markdown choice, listed first by TextExportWriters.markdownID and not in TextExportWriters.all (its id is "md"): headings, paragraphs, lists, quotes, code, breaks, and tables, with emphasis (MarkdownEmphasis.markdown(_:styles:literal:), given MarkdownLiteral.minimallyEscaped as its literal writer) and web and mail links, and no title heading, so the file is the book's text as content.md holds it, without its marker lines. It writes only the backslashes Markdown needs (MarkdownLiteral.minimallyEscaped, and guardingLineStart for each line's start, which also guards a line that would read as a table's delimiter row, and an exclamation mark that ends the words before a link is escaped). content.md, TextMouth's own cache, escapes every ASCII punctuation character so that its reader reads exactly a book's characters, and stays as it is: no export copies it.
  - Adding a writer: one new file plus one line in TextExportWriters.all, where the picker's order is the array's order. Scripts/agents/briefs/2026-10-19/export/interface-for-braille.md describes the interface.
  - Braille (FMT22): BRFExportWriter and PEFExportWriter (Services/Export/BrailleExportWriters.swift), last in TextExportWriters.all, write a book as braille. What the files hold and the layout's rules are in [Exporting books](../../user/exporting-books.md); the translator, its helper, and the table catalog are under Braille files in [Imports](imports.md).
    - Blocks: BrailleExportBlocks.blocks(of:) turns an ExportDocument into BrailleBlocks, and printBlocks(of:) gives each its emphasis (BraillePrintBlock): a block's print keeps its runs' italic (isEmphasis) and bold (isStrong) as flags on each scalar (EmphasizedText(runs:)), and a link's address is not written. The text of a table's cells, a code block's lines, an ordered item's number, and the title carries no emphasis. The title heading comes first, as level 1, when the document has one; a heading keeps its level; a paragraph is a paragraph; a list item is a list item at its depth, an ordered list's beginning with its number and a period; a quote is the text of its blocks; a code block is a paragraph for each of its lines that has text; a table is a paragraph for each row, its cells joined by semicolons; a thematic break is nothing.
    - Writing: BrailleExportWriting.write checks the cancellation, binds BookExportCancellation.childProcesses, the ImportCancellation that Stop sets with the export's own flag, as ImportCancellation.current around the translation, so Stop kills the braille helper at once instead of waiting for a translation that can run for up to a minute on a long book (TODO 3985), asks BrailleDocumentWriter for the file's bytes (its translator's hidden files go in the scratch folder that holds the target), checks again, and writes them with .withoutOverwriting; a BrailleTranslator.Failure becomes a TextExportError with its sentence. BrailleDocumentWriter translates the blocks' text, with its emphasis, to braille (BrailleTranslator, print to braille, with the options' table; liblouis writes the table's emphasis indicators for the classes the helper finds liblouis reads back exactly (the helper, in [Imports](imports.md)), UEB's; EBAE's italic and bold, which liblouis misreads, and most of this Mac's tables write plain braille, byte for byte as without emphasis, although the helper reads EBAE's signs in a braille book), lays the cells out with BrailleLayout.pages(of:format:), and frames the pages with BrailleFileWriter: brf(pages:lineEnd:code:), each row's cells written in the options' braille file code (BrailleFileCode: a byte of North American Braille ASCII or of Eurobraille, which are ASCII only, or Unicode braille patterns in UTF-8 with no byte order mark and the blank cell as U+2800), with the line end after each row and one form feed between pages, or pef(pages:metadata:format:), PEF 2008-1 XML in one volume of the options' cells and lines (PEFExportWriter.metadata(of:): the title, the author or none, the language or "en", a urn:uuid identifier, and the day). Both write six-dot cells only (sixDotCells(of:)), so the eight-dot cell liblouis writes for the backslash of an escape becomes ⠳ and TextMouth reads its own files. Any other eight-dot cell is refused, never written as its six-dot part: sixDotCell(of:) throws EightDotCell, whose sentence names the print character the table writes with it (BrailleDocumentWriter finds it by translating each distinct character of the block alone), and BrailleExportWriting turns it into a TextExportError. No table writes an emphasis indicator in eight dots (all 328 of macOS 26's were measured on October 21, 2026), so emphasis adds no such failure. Before translating, BrailleDocumentWriter.printForBraille(_:) writes an eight-dot braille pattern already in the print as its six-dot part and removes Unicode's noncharacters. The PEF escapes its head's text with an escaped(_:) of its own (see [Known duplication](../known-duplication.md)).
    - Layout: BrailleLayout is pure Swift over translated cells: BANA's margins, each list set apart by blank lines (setListsApart), pagination (Paginator), and the cuts of a word too long for a line (cutLength(of:room:)).
    - Options: BrailleExportOptions (a BraillePageFormat with the cells per line, 18 to 80, the lines per page, 4 to 50, and whether pages are numbered; the table; the BRF's BrailleLineEnd, and the BRF's fileCode, a BrailleFileCode) is the two writers' Options, started by BrailleExportOptions.standard() from BraillePreferences.importTable() and, for the file code, the Braille setting's, BraillePreferences.importFileCode() (never Unicode braille patterns, which the Export dialog offers but the setting does not), or from the default table, with replacedTable set, when that is one of this Mac's tables that this Mac does not offer or that a kept verdict refused this session (isUnusableMacTable; a too-slow refusal and a check that could not be made are not kept); the options view then says BrailleExportWording.startsFromDefault(replacing:) until another table is chosen. BrailleExportOptionsView draws them under the picker, with the words in BrailleExportWording and no line ends or braille file characters for a PEF; a BRF's two own pop-ups, drawn by one menuPopUp builder, come last, the braille file characters (BrailleFileCode.all) after the line ends, so every other control keeps its place in the reading order; its language, code, and contraction pop-ups are BrailleTablePickers, which the Braille tab of Settings draws too, each with hints of its own (see [Preferences](preferences.md)). A Mac table chosen there is checked off the main thread (The check of this Mac's tables, in [Imports](imports.md)) through BrailleTableChoiceChecks.shared, which BookExportModel.export waits on in its exporting phase (finished(unless:), ended at once by Stop or the dialog closing), so the export writes with the table the pop-ups show; BookExportSheet gives the Export button BookExportWording.exportWaitsHint meanwhile.
  - Who may write it: BookExportService, as above, off the main thread and one book at a time. plan(_:kinds:conversions:in:fileExists:) plans a converted kind's files as .converted sources (BookExportFile.Source), each named with the writer's extension in place of the Markdown's and made unique like any other name. BookExportConversion is the job runner's conversion, text now and audio later: it gives the extension, the kinds it applies to, and the name the picker says; BookExportConversion.markdown, the Markdown writer with no options, is what the offer's Markdown files are converted by, and files(of:for:conversions:) converts a copied or an already converted file, so that choosing another writer replaces the Markdown the offer lists. writeConverted reads content.md as the reader does (MarkdownCacheService.cacheText), walks it, and has the writer write it to a scratch file, which is moved into place as above. A writer that cannot write a book throws a TextExportError, whose sentence the export names after the file, as in "Couldn't export <file name>: <sentence>" (BookExportWording.failureSentence), and the other books still export; WordDocExportWriter.failureSentence is the Word writer's, for a book Apple's reader or writer refuses.

The picker lists BookExportConversionChoice values: Markdown (BookExportWording.markdownChoiceName and markdownChoiceHint, which is also the Text as Markdown checkbox's hint while Markdown is chosen: hint(for:)), then each writer's name and hint.

- Transcripts as captions (FMT23; 0.4.2).
  - Owner: BookExportModel offers the Convert transcript to picker beside the Transcript checkbox (transcriptConversionChoices): JSON and Markdown (TranscriptExportFormat.jsonAndMarkdownChoiceID, the default), each text writer, then each TranscriptExportFormat (webVTT, subRip). EPUB stays among the text writers, since it writes the transcript's text as every other text writer does.
  - Who may write it: TimedTextWriters (Services/Export/TimedTextWriters.swift). WebVTTWriter escapes a cue's text as XML does and writes a cue ending where it begins as ending a millisecond later. SubRipWriter ends lines with CR LF, starts the file with the UTF-8 byte-order mark (TranscriptExportFormat.fileBytes), and writes as character references what a reader would take for structure: the ">" of "-->", a "<" with a ">" after it, "{" before a backslash, and an "&" that begins a reference TimedTextMarkup decodes. A cue left with no text is passed over, and SubRip numbers count only the cues written.
  - A Transcript item that holds Markdown and no transcript.json is a failure the export reads out: BookExportWording.noTimedTranscriptReason. A transcript only in the cloud is noted, with the book named, as any cloud kind is.
  - Files: Services/Export/TimedTextWriters.swift, ViewModels/BookExportModel.swift, Models/BookExportWording.swift.
- Spoken audio (FMT43; 0.4.2): a text book, or a range of its headings, spoken by its voice into one M4B, M4A, or MP3 with a chapter for each heading.
  - Owner: BookExportKind.spokenAudio ("Text as spoken audio"). BookExportModel holds the speech options (SpeechOptionsMaking), which it makes the first time the kind is checked and not when the dialog opens, so the dialog opens without reading the book's text; Export waits for them, and the dialog says "Reading the book's headings…" meanwhile. SpeechExportText.headingPlaces works the range's headings out once, for the text and for the options. SpeechExportStore holds the kept chapters and allows one export at a time (claim()).
  - Who may write it: SpeechExportJob speaks the chapters one by one through SpeechChapterRenderer, which writes buffers from AVSpeechSynthesizer behind SpeechBufferWriting (AVSpeechBufferWriter in the app, a scripted writer in tests) and so can be tested. A chapter's loudest sample must rise above silenceCeiling, 0.001 (-60 dBFS), or the chapter fails. Waits are bounded by StallLimits: the first buffer gets 2 ms for each UTF-16 unit of the utterance and never less than 3 minutes, and the gap between buffers is 60 seconds. SpeechExportEncoder writes M4B, M4A, and MP3 (MP3Tag.maximumChapters is 255; the range's headings beyond it have no chapter). The file is moved into the chosen folder as the job's last step, so the chapters stay until it is in place. copyExclusively fails, removing what it made, when close() fails.
  - The kept chapters: one file for each chapter in this Mac's Caches folder, in Speech Export, matched by the book's text, voice, rate, and pitch, so a stale chapter is never used. They end when TextMouth quits, a different export starts, or the book's voice, text, substitution rules, or pauses change, and SpeechExportStore.sweep empties the folder at the Mac's launch. iOS does not sweep yet. Export refuses a destination in this folder, for any kind of export.
  - A quit: SpeechExportsUnderWay is a QuitHold.Work (kind "speech exports") in AppDelegate's held work, beside feed downloads and re-reads. The whole quit is in [Launch](../launch.md).
    - It stops every export as Stop does, with the chapters it finished kept, and waits at most 5 seconds (SpeechExportsUnderWay.longestQuitWait).
    - A quit the person asks for is cancelled while it does, and TextMouth asks to quit again afterwards (0.4.4). It says "TextMouth is finishing up before it quits: stopping a speech export with the chapters it finished kept. It will quit as soon as that is done." in a panel and through VoiceOver. With several exports under way it says "stopping 2 speech exports with the chapters they finished kept", counting them.
    - A second Command-Q or the Dock's Quit meanwhile is cancelled too and says the same words again, so it no longer quits at once and cuts the export off.
    - The system ending the session is answered later with the same words, and replied to when the exports have stopped or after 5 seconds.
  - How others observe it: a power assertion (SpeechExportPower) holds the Mac awake while it runs, and holds nothing on iOS, which has no IOKit. The debug log records a SPEECH_EXPORT line when it ends (finished, stopped, or failed), with the chapters done and kept. The model's progress is "Speaking chapter N of M…" and "Encoding the audio file…". Every sentence is in SpeechExportWording.
  - The render coordinator is not used: measured, overlapping writes of different and of the same voices wrote the same samples as each alone. A speech export's writes beside the reader speaking aloud in direct mode were not measured, and on March 23, 2026 (62fc142e) a background render of a very long chapter made speak() loop back to text it had spoken.
  - Not done: encoding each chapter while the next is spoken; resuming per heading; WAV, AIFF, CAF, Apple Lossless, FLAC, time ranges, and a selection (FMT44).
