# Exports

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- An export (FR05): what the Export dialog offers, what is checked, where it goes, and how far it has got.
  - Owner: BookExportModel, one for each Export dialog, on the main actor: the books, what they offer (BookExportOffer), a choice for each kind any of them holds (BookExportChoice), the kinds checked, the destination, and the phase (listing, ready, exporting, or finished). The destination starts at the folder last exported to this session, kept only in memory, or else at Documents, in the home TextMouthRuntime names, so a test exports into its sandbox.
  - Who may write it: the dialog's controls, and BookExportService, which never downloads (MaintenanceFileAccess). offer(for:access:) lists, off the main thread, what a book's package holds, from what the file system says: for a folder of tracks it also reads the saved content index (audioFileOrder(listed:index:): the files in the order the chapters and their clips play them, then any others in Finder's order), and for a DAISY book kept as loose files its inventory (DAISYPackageInventory). It lists, too, the originals the audio editor keeps in the package's audioEdits/originals folder (AudioEditPackage.folder, originalsFolderName) as BookExportKind.originalAudio: one file as "<title> - Original Audio" with its own extension, or a book's tracks' originals in a folder of that name, each under its path in the book's audio folder, copied as they are; Export never makes one, and a recording's take stays its Original recording (originalRecording). plan(_:kinds:conversions:in:fileExists:) names every file: one book's items go in the destination, its tracks and a loose DAISY book's files in a folder named after it; several books get a folder each; and a name already taken is followed by a number (UniqueNames, compared without case), so nothing is replaced. When Export is pressed, the model lists the books again as the library holds them, and runs export(_:kinds:conversions:to:access:cancellation:progress:) off the main thread. It leaves out books and items only in the cloud, copies each file with dataless files left in the cloud, and writes the plain text (plainText(fromMarkdown:at:title:): the chapters as the reader parses them). Every file, whether copied, plain text, or converted (text export, below), is made at a scratch URL in a new scratch folder (writeThroughScratchFile): the system's item-replacement folder on the volume of the nearest existing folder that holds the target (makeScratchFolder(near:)), or, when the system makes none, a new "TextMouth Export <UUID>" folder in the temporary directory. When the file is whole and Stop has not been pressed, moveExclusively moves it to its target, and the target's folder is made only then. The move is an exclusive rename (renamex_np with RENAME_EXCL, which the file system makes atomic: FileManager.moveItem checks and then renames, so a file made between the two would be replaced) or, where the volume cannot do that (EXDEV, ENOTSUP, or EINVAL), an exclusive copy (copyfile with COPYFILE_EXCL) and then the removal of the source. A target that exists, even one made an instant ago, fails that file with fileWriteFileExists and is left as it was, and the scratch folder is removed in every case. So an export never replaces a file in the chosen folder, removes none that was there before it began, and leaves no half-written file after a Stop or a failure. The one thing it removes in the folder is the partial file that copyExclusively created itself, when an exclusive copy fails for a reason other than an existing target (an open follow-up in the TODO, from team export, October 19). Stop (BookExportCancellation) is read before each file and, through checkCancelled(), between a conversion's steps and a writer's blocks, so a conversion ends partway; a copy already begun finishes in the scratch folder, and writeThroughScratchFile, checking once more before the move, does not move it. Either way the file is neither exported nor a failure, and the files after it are not started. A destination inside the data directory is refused (BookExportModel.isInsideDataDirectory).
  - How others observe it: BookExportSheet shows the model, VoiceOver's focus on its first checkbox. LibraryExportSupport presents it on a Library window, for the selection File > Export… finds or the books a row's context menu acts on, and ReaderBookCommandsSupport on a reader, for its book, from File > Export… or the toolbar's Export button. The end is announced once (BookExportWording.finished); the dialog closes when everything was exported (didEverything), and keeps its summary otherwise. Each export writes one BOOK_EXPORT line, and each file that couldn't be written a BOOK_EXPORT_FAILED line.
  - Files: Services/BookExportService.swift, ViewModels/BookExportModel.swift, Models/BookExportWording.swift, Models/LibraryCloudWording.swift, Views/Export/BookExportSheet.swift, Views/Export/BookExportPresentation.swift, Views/Reader/ReaderBookCommands.swift, Views/Library/LibraryView.swift, Views/Library/LibrarySubviews.swift, App/MenuCommands.swift.
- Text export (FMT18, FMT19): what the Convert to picker, beside Text as Markdown, makes of a text book's content.md in place of a copy. What each format keeps and leaves out is in [Exporting books](../../user/exporting-books.md).
  - Owner: BookExportModel keeps the Convert to choice of each kind whose text a writer can convert (conversionIDs: a writer's id, or TextExportWriters.markdownID until another is chosen; BookExportKind.convertsText is true for .markdown alone) and each writer's options (optionsStates, one TextExportOptionsState for each writer chosen, kept for the dialog's life), and BookExportSheet draws the picker beside the checked checkbox, with the chosen writer's options view under it. TextMouth/Services/Export/ holds the writers and what they read:
    - ExportDocument, the model every writer reads.
    - ExportDocumentWalker, the one swift-markdown walk of content.md, since Markdown stays the base. It splits the text into chapters at the markers exactly as the reader does, so text before the first marker is left out, as the reader leaves it out.
    - TextExportWriter, the writer protocol, with the TextExportWriters.all registry, the TextExportConversion erasure, and the dialog's options state (TextExportOptionsState).
    - HTMLExportWriter with XMLEscaping, RTFExportWriter, and WordDocExportWriter, which is Apple's .docFormat from TextMouth's RTF.
  - Adding a writer: one new file plus one line in TextExportWriters.all, where the picker's order is the array's order. Scripts/agents/briefs/2026-10-19/export/interface-for-braille.md describes the interface.
  - Who may write it: BookExportService, as above, off the main thread and one book at a time. plan(_:kinds:conversions:in:fileExists:) plans a converted kind's files as .converted sources (BookExportFile.Source), each named with the writer's extension in place of the Markdown's and made unique like any other name. BookExportConversion is the job runner's conversion, text now and audio later: it gives the extension, the kinds it applies to, and the name the picker says. writeConverted reads content.md as the reader does (MarkdownCacheService.cacheText), walks it, and has the writer write it to a scratch file, which is moved into place as above. A writer that cannot write a book throws a TextExportError, whose sentence the export names after the file, as in "Couldn't export <file name>: <sentence>" (BookExportWording.failureSentence), and the other books still export; WordDocExportWriter.failureSentence is the Word writer's, for a book Apple's reader or writer refuses.
  - How others observe it: the checkbox's words follow the picker (BookExportWording.name(of:convertedTo:), hint(for:convertedTo:), and choiceLabel(kind:bookCount:availableItemCount:fileCount:byteCount:inCloudCount:convertedTo:), which gives no size while a writer is chosen, since a converted file's size is known only once it is written). The picker lists BookExportConversionChoice values: Markdown (BookExportWording.markdownChoiceName and markdownChoiceHint), then each writer's name and hint.
  - Files: Services/Export/ExportDocument.swift, Services/Export/ExportDocumentWalker.swift, Services/Export/TextExportWriter.swift, Services/Export/HTMLExportWriter.swift, Services/Export/XMLEscaping.swift, Services/Export/RTFExportWriter.swift, Services/Export/WordDocExportWriter.swift, and, from the export above, Services/BookExportService.swift (BookExportConversion), ViewModels/BookExportModel.swift, Models/BookExportWording.swift, Views/Export/BookExportSheet.swift.
  - Tests: the export area of Scripts/test/areas.conf (`python3 Scripts/test/run-area.py export`), with the dialog's sheet in the sheets area.
