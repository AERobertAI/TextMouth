# Exports

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- An export (FR05): what the Export dialog offers, what is checked, where it goes, and how far it has got.
  - Owner: BookExportModel, one for each Export dialog, on the main actor: the books, what they offer (BookExportOffer), a choice for each kind any of them holds (BookExportChoice), the kinds checked, the destination, and the phase (listing, ready, exporting, or finished). The destination starts at the folder last exported to this session, kept only in memory, or else at Documents, in the home TextMouthRuntime names, so a test exports into its sandbox.
  - Who may write it: the dialog's controls, and BookExportService, which never downloads (MaintenanceFileAccess). offer(for:access:) lists, off the main thread, what a book's package holds, from what the file system says: for a folder of tracks it also reads the saved content index (audioFileOrder(listed:index:): the files in the order the chapters and their clips play them, then any others in Finder's order), and for a DAISY book kept as loose files its inventory (DAISYPackageInventory). It lists, too, the originals the audio editor keeps in the package's audioEdits/originals folder (AudioEditPackage.folder, originalsFolderName) as BookExportKind.originalAudio: one file as "<title> - Original Audio" with its own extension, or a book's tracks' originals in a folder of that name, each under its path in the book's audio folder, copied as they are; Export never makes one, and a recording's take stays its Original recording (originalRecording). plan(_:kinds:in:fileExists:) names every file: one book's items go in the destination, its tracks and a loose DAISY book's files in a folder named after it; several books get a folder each; and a name already taken is followed by a number (UniqueNames, compared without case), so nothing is replaced. When Export is pressed, the model lists the books again as the library holds them, and runs export(_:kinds:to:access:cancellation:progress:) off the main thread. It leaves out books and items only in the cloud, copies each file with dataless files left in the cloud, and writes the plain text (plainText(fromMarkdown:at:title:): the chapters as the reader parses them) without replacing anything. It removes any partial file it made, and stops before its next file once Stop is pressed (BookExportCancellation). A destination inside the data directory is refused (BookExportModel.isInsideDataDirectory).
  - How others observe it: BookExportSheet shows the model, VoiceOver's focus on its first checkbox. LibraryExportSupport presents it on a Library window, for the selection File > Export… finds or the books a row's context menu acts on, and ReaderBookCommandsSupport on a reader, for its book, from File > Export… or the toolbar's Export button. The end is announced once (BookExportWording.finished); the dialog closes when everything was exported (didEverything), and keeps its summary otherwise. Each export writes one BOOK_EXPORT line, and each file that couldn't be written a BOOK_EXPORT_FAILED line.
  - Files: Services/BookExportService.swift, ViewModels/BookExportModel.swift, Models/BookExportWording.swift, Models/LibraryCloudWording.swift, Views/Export/BookExportSheet.swift, Views/Export/BookExportPresentation.swift, Views/Reader/ReaderBookCommands.swift, Views/Library/LibraryView.swift, Views/Library/LibrarySubviews.swift, App/MenuCommands.swift.
