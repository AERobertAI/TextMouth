# Text caches and content indexes

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- content.md: each text book's text cache, its text as Markdown. A transcribed audiobook's content.md is its transcript's text instead (transcripts, above).
  - Owner: MarkdownCacheService. The format's version is MarkdownCacheService.currentCacheVersion ("3.0.7"), and a book whose recorded cacheFormatVersion is older (SemanticVersion.isOutdated, which judges the metadata reader's version, above, the same way) is extracted again.
  - Who may write it: MarkdownCacheService, which writes a new cache only after extraction succeeds and replaces the old one atomically (writeCache), and, through Edit Text, the user's own editor (edited text, below). Before it replaces the content.md of a book being edited, writeCache asks BookTextEditSessions (permitTextRebuild(of:writing:)), and afterwards tells it what it wrote (textRebuilt(_:writing:fingerprint:)). generateCacheContent runs inside BookContentAnalysisService.load: when an import reads its new book, when a reader opens a book whose cache is missing or outdated, and when a stale cache is rebuilt. generateCacheAnalyzeAndStamp runs for startup maintenance (extractMissingContentCaches, through TextCacheUpdateQueue, which runs ordinary EPUBs on two utility workers and everything else one at a time), for Redo Text Extraction in Storage settings, and for the legacy migration. Maintenance leaves a book whose files are in the cloud as it is (maintenance in a cloud library, below). The extraction a cache is written from parses each EPUB document once: EPUBParser converts a document to Markdown from the DOM its contents scan parsed, and again only when a contents page later in the book names a new destination in it, and asks whether an element is hidden only in markup that holds the word (PublicationSemantics.mayCarryHiddenAttribute(_:)). HTMLToMarkdownConverter wraps emphasis and links in time that grows with what they wrap, not with what was converted before them.
  - How others observe it: BookContentAnalysisService.load reads it and parses it into DocumentContent, splitting it into chapters over Substrings of the cache, one copy per chapter (MarkdownCacheService.splitChapters(_:)).
  - Files: Services/MarkdownCacheService.swift, Services/TextCacheUpdateQueue.swift, Services/BookContentAnalysisService.swift, ViewModels/LibraryViewModel+Migration.swift, Parsers/EPUBParser.swift, Parsers/EPUBParser+Navigation.swift, Parsers/PublicationSemantics.swift, Parsers/HTMLToMarkdownConverter.swift.
- Page markers in content.md (PG01): `<!-- page: LABEL -->`, an inert HTML comment that names a page of the book and adds no reading text, so writing, moving, or deleting one moves no saved place.
  - Owner: content.md, in the one form of MarkdownPageMarker (Parsers/MarkdownPageMarker.swift). Its label is the page's name as its source gives it, trimmed, with each inner run of white space made one space and cut to maximumLabelLength (32) Characters; a label left empty takes the page's 1-based ordinal. markdown writes each %, <, >, control, line separator, and paragraph separator as % and two uppercase hexadecimal digits, and the second of two hyphens too, since CommonMark ends or refuses a comment at "--". decode accepts only that exact form and refuses a comment with a raw <, >, or -- in its label, so a comment the source itself carried stays invisible (PAGES-RESEARCH-2026-10-21.md, section 2.2). MarkdownPageMarker.isNoMoreThanLabel(_:label:) is the one rule for whether text found where a page begins is no more than that page's label, so that the marker stands in for it (ST02): empty, or at most maximumLabelLength Characters and, when there is a label, containing it or contained in it ignoring case, or only a page number in another numbering (looksLikeAPageNumber: numbers, Roman numeral letters, white space, and punctuation, as "V" under the label "5"); longer or other text is words, never dropped. EPUB's page-break elements (HTMLToMarkdownConverter.readsOwnText(ofPageBreak:page:)) and DAISY 2.02's page fragments (DAISY202PageMarker.isNumber(in:)) both ask it, and an element with no aria-label or title is a page by its text only when the text could be a label. A heading that holds such an element leaves its number out of its label as the body text does: HTMLToMarkdownConverter.destinationMarkers(inside:) returns the page-break elements whose text is not read (EnclosedDestinations.unreadPageBreaks) with the markers it writes before the heading, and HTMLReadingText.label(of:leavingOut:) skips them, so "Part <page 9>Two" is the heading "Part Two" with page 9 written before it. An element that holds words other than its page's number keeps them, and a read without pages (includesPages: false) writes the label as cache format 3.0.7 did. A PDF's label is the one PDFKit gives, except that PDFTextParser.plainNumberLabel(_:ordinal:) writes a page's own number as plain digits when PDFKit grouped it for the locale, as it does for a PDF that names no labels ("1,000", "1.000", "1 000"), so that the N of "Page 1000 of N" counts it; any other label stays, and so does "1.100" on page 100, which only looks grouped.
  - Who may write it: the converters, only through MarkdownMarkerWriter.write (Parsers/MarkdownMarkerWriter.swift), which places heading annotations too. CommonMark opens an HTML block at "<!--", in a list item or quote too, and the block swallows the rest of the line, so a marker never begins a line that words follow: inside running text it stands where the page begins; at a block boundary it is a block of its own; at the opening of a list item or quote it is a block of its own inside it; at the opening of a heading it is written in the heading; after a hard break it is written at the end of the line before; and on a line indented four columns or more it is a block of its own at the margin. EPUBParser (the page list, else the page-break elements), HTMLToMarkdownConverter, PDFTextParser, DOCXParser (DOCXPageTracker), DAISYParser, TextutilDocumentReader (a second textutil run, TextutilPageBreaks), BrailleBookReader (a BRF's and a PEF's braille pages, BrailleBookReader+Pages.swift, PG12: Braille files, in [Imports](imports.md)), and PlainTextParser (the pages of form feeds, PG13) write them. PlainTextParser.pagedBlocks(in:) finds a form feed's page: a form feed (U+000C) ends a line as it always did, so the reading text is the same with pages and without them, and begins a page at the first line after it that is read, a heading or a paragraph's line, not an empty line and not the underline a setext heading took. Several form feeds before one line begin a page each there, a blank page kept in its order; one with no words before it or none after it begins none. Page 1 stands at the book's start and the markers are labelled 1, 2, 3 on from it, a block of their own before the block a page begins and, inside a paragraph, at the end of the line before; a text whose form feeds begin no page, and a read without pages (includesPages: false; the direct parse reads no pages either), write what cache format 3.0.7 wrote. Every extraction takes includesPages: true for every cache the app writes (MarkdownCacheService.writeCache); false writes what cache format 3.0.7 wrote, which the tests that pin a parser's exact Markdown read with, and which PG09 compares a content.md with to find text changed by hand (MarkdownCacheService.readingTextsWithoutPages). The user's editor may delete, rename, or add one (edited text, below).
  - How others observe it: MarkdownParser turns each marker into a PageBreak in Chapter.pages, at the first whole word it stands before or in (PageBreak.firstWordStart: white space moves it forward to the next word, the middle of a word back to its start), and DocumentContent gathers the chapters' into BookPages (a book's pages, in [The reader](reader.md)). The exports leave markers out (ExportDocumentWalker, which every export writer reads, the Markdown writer included). An HTML block that begins with one or more complete markers of ours and then holds words (CommonMark swallows the rest of such a line, and an Edit Text change can make one) is read as its markers followed by the Markdown of the rest, whose words, emphasis, and offsets are read in place (PlainTextExtractor.visitHTMLBlock, ST05; isReadingRestOfMarkerLine bounds it to one level, so a second marker-led block inside the rest reads as before). MarkdownCacheService.splitChapters does the same for a chapter line with words after it (chapterMarkerFollowedByWords, ST05b): the marker begins its chapter and the words are the chapter's first line.
  - Files: Parsers/MarkdownPageMarker.swift, Parsers/MarkdownMarkerWriter.swift, Parsers/MarkdownParser.swift, Models/BookPages.swift, Models/DocumentContent.swift, Parsers/EPUBParser.swift, Parsers/EPUBParser+Navigation.swift, Parsers/HTMLToMarkdownConverter.swift, Parsers/HTMLReadingText.swift, Parsers/PDFTextParser.swift, Parsers/DOCXParser+Converter.swift, Parsers/DOCXParser+Sections.swift, Parsers/DAISYParser.swift, Parsers/DAISYParser+TextExtraction.swift, Parsers/TextutilDocumentReader.swift, Parsers/TextutilPageBreaks.swift, Parsers/BraillePageAnalyzer.swift, Parsers/BrailleBookReader+Pages.swift, Parsers/PlainTextParser.swift, Services/Export/ExportDocumentWalker.swift.
- The page reader's version (PG09): which page reader wrote a book's content.md.
  - Owner: the package record and the library row, as Book.pageReaderVersion (BookInfo.state.pageReaderVersion), an analysis-owned field (Book.ContentAnalysisFields, in [Package records](package-records.md)) that is nil until a generation stamps it. PageReaderVersions.current(for:) gives each format's version, "1.0.1" for EPUB and HTML, whose shared converter no longer reads a page break's number into a heading's label, which changes the reading text of the books that have such a heading and of no others, "1.0.0" for PDF (whose changed labels leave its reading text alone, so a PDF already in the library keeps its old labels until Redo Text Extraction), DOCX, DAISY, RTF, RTFD, DOC, ODT, WordML, braille, and plain text, and nil for a format without pages, which is never read again for them; a format that gains pages later adds a case of its own, which reads again only its own books (V07), as braille did (PG12), whose BRL books have no pages and are read again once with the rest and stamped, and plain text did for its form feeds (PG13), whose books with no form feed between words, most of them, are read again once, their content.md byte for byte as before, and stamped. A web archive's text page writes no pages (WebArchiveReader.MainPage.markdown() asks PlainTextParser for none), since a web archive has no page reader line of its own (PageReaderVersions.current(for:) is nil for it) and no book of it is read again for pages, so its books would differ by when they were read.
  - Who may write it: every generation records its format's current version (MarkdownCacheService.GeneratedCache.pageReaderVersion, committed with the analysis through LibraryPersistenceService.saveContentAnalysis(…pageReaderVersion:)), since every generation writes pages. When textutil's run for the pages failed or timed out, the generation records a note after the version instead (PageReaderVersions.stamp(for:pageRunFailed:previous:), PG16): "1.0.0+failed-once", which the next launch reads again, then "1.0.0+failed", which no launch reads again. The launch's batch also stamps a book whose content.md it keeps, through BookTextEditSessions.settleKeptText: the format's version, "+failed" (PageReaderVersions.failedStamp(for:)) for a book whose file is missing, or "+failed-once" and then "+failed" (PageReaderVersions.failureStamp(for:previous:)) for one whose file could not be read. An analysis that carries none leaves the record's own (Book.applyContentAnalysis): an analysis says nothing about which page reader wrote content.md.
  - How others observe it: PageReaderVersions.isDueForPages(_:) is true for a book whose version is behind its format's (PageReaderVersions.isOutdated, which reads a note apart from its version and takes "+failed-once" as behind) while the launch re-read is on, as it is since PG16 (PageReaderVersions.launchRereadIsOn). Then booksNeedingCacheUpdate chooses the book, and BookContentAnalysisService.recoveredTextCache does not recover a record that predates its format's page reader. A book whose stamp notes success (PageReaderVersions.notesSuccess: an earlier page reader read its pages) and whose content.md is as its record describes it is read again without the compare below (V05): a build that records every edit wrote it, and compared, it would differ from what the newer reader writes, so the first bump of a format's page reader would keep a copy of every book of the format (EPUB and HTML at 1.0.1 keep none). A book with no stamp, as every braille and plain text book has when its format gains its reader (V07), or whose stamp notes a failure, is compared as ever, so a braille book whose reading changed meanwhile keeps a copy. For a book behind only in its pages (isBehindOnlyInPages) that holds no edit taken, the batch compares the whole content.md, byte for byte, with the book's file read again (pageUpgradeCheck), before it looks for an edit saved while TextMouth was closed: content.md that is the file's text without pages is read again with them; the file's text with pages, which a batch stopped before its commit leaves, only has its record stamped; any other text, which nothing can tell from an edit made before B12, is copied beside content.md as content.md.edited-<UTC time> (PageUpgradeCopies, through BookTextEditSessions.keepCopy), logging PAGES_REPLACED_TEXT, and read again with pages, its places relocated, or, when no copy can be made, kept, recorded as edited (Book.editedText, B12) and stamped, logging PAGES_SKIPPED_CHANGED_TEXT; a book whose file is missing is stamped "+failed", and one whose file could not be read, with pages or without, "+failed-once" and then "+failed" (PageReaderVersions.failureStamp), logging PAGES_SKIPPED_UNREADABLE. A read with pages whose textutil run failed never matches: a content.md changed since its record is then left unstamped for the next launch (PAGES_DEFERRED). A changed source, or a content.md changed since its record that is not the text with pages, is left to the stale-cache and FR05 checks. A book a reader has open gets its new text handed over (ST01): the batch reads open books first (LibraryViewModel.openBooksFirst(_:open:)), updateTextCache returns a TextCacheUpdate, its summary and, for a book open in a reader (asked of the worker through AudioEditActivity.isOpenInReader), its textForOpenReader, the text parsed and indexed as it was written, and updateProgress applies the analysis to the row on the main actor and calls LibraryBookUpdates.textReplaced, so the reader shows the text with its pages in place of the one it loaded, its cursor on the same words (the edited-text path, ReaderViewModel+EditedText); every other book's update keeps no text. pageUpgradeCheck rebases the book to the data directory's current place itself (StorageBoundary.rebasedToCurrent), as the queue does for each book it hands over, so the check is right for any caller. The batch ends with one PAGES_UPGRADE_SUMMARY line counting the books given pages, replaced keeping a copy, kept as changed, skipped (in the cloud, missing), and failed. TextPipelineGoldenTests pins that includesPages: false still writes the content.md recorded before pages for the golden books that gained them. The October 21, 2026 review that kept the re-read off until PG16 is restated in the comment on launchRereadIsOn; the re-read's tests switch it off with _setLaunchRereadForTesting(_:) to check that the batch then chooses nothing.
  - Files: Models/PageReaderVersions.swift, Models/Book.swift, Models/BookInfo.swift, Services/MarkdownCacheService.swift, Services/LibraryPersistenceService.swift, Services/BookContentAnalysisService.swift, ViewModels/LibraryViewModel+Migration.swift.
- The content index (BookContentIndex): chapter starts and lengths, word counts, headings with their offsets, totals, and, for audiobooks, the media layout and timing, with every clip of a chapter that plays several, and, for a transcribed audiobook, its transcript text's layer (BookContentIndex.transcript: transcripts, above).
  - Owner: the package record, as its contentIndex.json (BookInfo.contentIndex), beside bookInfo.json. Its version is BookContentIndex.currentVersion ("1.0.0"). library.json keeps only the totals and contentIndexVersion, so launch never decodes every heading in the library.
  - Who may write it: BookContentAnalysisService builds it (BookContentIndex.build) from parsed content, its word counts counted as the runs of Characters that are not whitespace (Chapter.wordCount(of:), which reads a Character whole only around non-ASCII bytes and makes no substring per word), and it is saved only through LibraryPersistenceService (saveContentAnalysis or saveBookInfo(for:contentIndex:)).
  - How others observe it: BookContentAnalysisService.load uses a saved index only when it passes validationFailure(for:audioBaseURL:) and, for a text book, alignmentFailure(with:countingWords:) against the parsed chapters. One that fails is logged as CONTENT_INDEX_REJECTED and replaced by a fresh index. The reader takes headings, chapter offsets, and totals from the index inside its DocumentContent.
  - Which version to change: a change to source extraction changes MarkdownCacheService.currentCacheVersion. A change only to how the reading text or the index is derived changes BookContentIndex.currentVersion instead, so existing Markdown is indexed again without converting every source. Reading Markdown tables a row at a time (each row a paragraph, its cells one space apart, the table set apart from the text around it, as HTMLReadingText reads an HTML table) changed neither version: content.md is unchanged, and the change only adds breaks and spaces, so the saved index of every book it affects, a DOCX or Markdown book holding a Markdown table, no longer lines up with its reading text, fails the alignment check once (CONTENT_INDEX_REJECTED), and is rebuilt from the cache.
  - What guards the output: TextPipelineGoldenTests hold the digests of what the text pipeline produced on main before the performance work of October 3, for TestData's books (its two untracked DAISY audio ZIPs only where a checkout has them), synthetic books, and generated EPUBs: every content.md an import writes, the reading each book opens to (titles, text, headings, and word counts), and the converters' own output. A change meant to keep the output must leave them passing. A deliberate change of output, which changes one of the versions above, records the new digests, which each failure names, once the new output has been checked. TextPipelineBefore (TextMouthProductionTests/TextPipelineFixtures.swift) keeps the code each change replaced, for these tests and the benchmarks to compare with.
  - Files: Models/BookContentIndex.swift, Models/DocumentContent.swift, Services/BookContentAnalysisService.swift, TextMouthProductionTests/TextPipelineGoldenTests.swift, TextMouthProductionTests/TextPipelineFixtures.swift.
- Text cache fingerprints (TextCacheFingerprint): for the source and for content.md, the size, the modification time, and the MD5 digest, as they were when the cache was written. Times are kept in nanoseconds but compared to the microsecond (FileStamp.hasSameModificationTime(as:)), since a sync service can give a file back with its time moved by a fraction of a microsecond. An RTFD, being a folder, is stamped by the regular files in it (FileStamp(of:): their total size and latest modification time) and digested by its checksum (FileImportService.contentChecksum(of:format:)), both from the walk its import used (regularFilePaths(in:)), which passes over hidden items and symbolic links: browsing the folder changes neither, and changing, adding, or removing a file in it changes both.
  - Owner: the package record (state.textCacheFingerprint, also copied into the index), mirrored on the library row.
  - Who may write it: MarkdownCacheService records them when it writes a cache, and BookTextEditSessions when it takes an edit. BookContentAnalysisService fingerprints a current cache written before fingerprints existed, once, the first time the cache passes every check; that result is saved by the usual save.
  - How others observe it: BookContentAnalysisService.loadExistingCache compares the files' sizes and dates with the record before it trusts the cache or its index, and reads a file for its digest only when the size is unchanged but the date is not. A changed file is logged as CACHE_STALE and the cache is rebuilt from the source. Startup maintenance compares the sizes the library row recorded with the files, two stat calls a book, to find stale caches without reading anything, and reads for its digest only a content.md of the recorded size with another date (hasRedatedTextCache), which may hold an edit saved while TextMouth was closed (edited text, below): one only touched keeps its digest, and the row records its new stamps, so the next launch reads nothing. completedTextCacheIndex checks a package's record when recovering an interrupted batch. A dataless file, whose content is only in the cloud, is never judged by the size and date it reports, since an evicted iCloud Drive file can report 0 bytes, and never read for its digest (FileStampComparison.dataless).
  - Files: Models/TextCacheFingerprint.swift, Services/BookContentAnalysisService.swift, Services/MarkdownCacheService.swift, ViewModels/LibraryViewModel+Migration.swift.
- Kept reading text (ReadingTextCache, PERF22): this Mac's copy of a large text book's reading text (each chapter's title, text, and headings as parsed), at MachineLocalPaths.readingTextCache/<book ID>.readingtext, for a content.md of at least 1 MiB. The file is a prefix ("TMRT", the layout version, the header length), a JSON header (the producer, the ReadingTextKey, the chapter entries, each with its title, UTF-8 length, headings, and pages), then the UTF-8 chapter texts. The layout is ReadingTextCache.formatVersion, 2 since each chapter's pages (PG01); a file of layout 1 is never read, and is removed as unusable.
  - Who may write it: BookContentAnalysisService.loadExistingCache, only when given the cache (only ReaderViewModel.readContent passes it), after parsing a content.md its record vouches for, in the background (storeInBackground: a partial file renamed into place). MarkdownCacheService.writeCache, LibraryViewModel.removeDeletedBook, BookTextEditSessions, when it takes an edit, and LibraryViewModel.settleFeedFileRemovals(_:failures:), with which every removal of a feed item's file ends (FR11's branches A2 and B), remove a book's file; removeExpired removes files unused for a day (by modification time, which each use refreshes), at startLibrary and after each store.
  - How others observe it: used instead of parsing when the fingerprints verify, the saved index validates and was measured from the same content.md, and the key matches (the record's content.md digest, its ContentFileIdentity of size, modification time, inode, and status-change time, and the book title), together with the producer (BookContentIndex.currentVersion and the build identity) and the layout. The chapters must pass alignmentFailure(with:countingWords: false). Otherwise the book is parsed; a damaged or mismatched file is logged as READING_TEXT_CACHE_REJECTED and removed. content.md is read only for a digest or a parse.
  - Files: Services/ReadingTextCache.swift, Services/BookContentAnalysisService.swift, Services/MarkdownCacheService.swift, ViewModels/ReaderViewModel.swift, ViewModels/LibraryViewModel.swift, ViewModels/LibraryViewModel+BookOperations.swift.
- Edited text (FR05): a text book's content.md, or a transcribed audiobook's, an episode's in its feed included, since a transcript is the listener's own work and stays in the episode's package when its download goes (October 23, 2026), never a feed article's (BookTextEditor.canEditText(of:isTranscribed:), FR11), as the user edits it in an editor of their own (Edit Text in Default Editor and Edit Text With…).
  - Owner: BookTextEditSessions.shared, one session for each book being edited: its baseline (BookTextBaseline: the fingerprints of the source, a text book's own file or a transcribed audiobook's transcript.json, as BookTextEditSessions.sourceURL(of:) names it, and of content.md, taken when the edit began, or when TextMouth last took or rebuilt the text), the edit the last check refused, and a copy a rebuild under way kept. BookTextEditor.shared, on the main actor, starts sessions, for a text book or an audiobook whose package holds a transcript (looked for off the main thread), watches each content.md (ContentFileWatcher, which checks 0.75 seconds after the last change and follows a file an editor's save replaces), and says what happened. A session ends when its book leaves the library (a check that finds no row, as for a feed episode whose download was deleted, announces BookTextEditWording.stoppedBookGone once: endBecauseBookIsGone), when its transcript is replaced or deleted (BookTextEditor.pauseEditing(of:), which lets a check running finish, takes an edit saved but not yet checked through BookTextEditSessions.settlePendingEdit(of:), and ends the session; a change that fails calls resumeEditing(of:), which begins it again from a fresh baseline), or when TextMouth quits. The record of an edit taken, for a text book, is Book.editedText (B12): an EditedText, the digest of the content.md the edit left and when it was taken. The check that takes the edit sets it (LibraryPersistenceService.saveContentAnalysis(…editedText:)); the package record keeps it (BookInfo.state.editedText), so a library rebuilt from its records still keeps the user's text; and it is an analysis-owned field, which Book.applyContentAnalysis drops once an analysis records a content.md digest other than the edit's, as when Redo Text Extraction wrote the source's text or another edit was taken.
  - Who may write it: the user's editor. Checks run on the sessions' serial queue, as storage work (StorageBoundary.perform(.contentAnalysis)): when content.md settles, when TextMouth becomes active, and before a reader reads the book. A check takes an edit when content.md changed and the source did not: it parses it, saves the new index with new fingerprints at the current cache format (LibraryPersistenceService.saveContentAnalysis), and drops the book's kept reading text. A transcribed audiobook's edit is taken into its transcript instead (TranscriptStore.takeEdit): TranscriptEditing.apply lays the parsed chapters over the transcript's sentences (TranscriptEditAlignment), each sentence taking the words that stand for it and keeping its time, a changed one dropping its words' timings (TranscriptSentence.rewrite(as:)), and one whose every word went being removed; transcript.json is written with editedAt, and the audio index's layer is saved with that transcript.json as its source and the user's content.md, unchanged, as its cache, so no load writes the text again over the edit. A layer the index or the record refuses puts transcript.json back as it was. Before any sentence is aligned, TranscriptEditing.checkOutsideSentences refuses what the transcript has nowhere to keep: a chapter heading that is not the one the text builder writes from the audio's chapter title (TranscriptTextBuilder.headingTitle(of:number:)), renamed, removed, or added (TranscriptEditError.headingChanged), and words besides the heading in a chapter without sentences (wordsWithoutSentences). An edit it can't take (BookTextEditRefusal: notText, noChapters, sourceChanged, transcriptChanged, chaptersChanged(found:expected:), headingChanged, wordsWithoutSentences, or failed, which covers an audiobook whose audio changed since it was transcribed) is first kept beside content.md as content.md.edited- and the time (keepCopy(of:bytes:), through SavedFile.preserveUnusable and LibraryIndexQuarantine under TextMouthPaths.keptTextCopyMarker; an earlier copy of the same bytes is used again).
    - While an edit not taken stands beside an unchanged source, nothing replaces content.md. ReaderViewModel.readContent asks settlePendingEdit(of:), which answers readTaken, readAsUsual, or hold; hold throws BookTextEditPending for a text book, which the reader shows in place of the book (loadHeldByTextEdit) until an edit is taken, and leaves out only an audiobook's transcript text, its audio loading and playing as ever. For an audiobook the reader keeps the reason (ReaderViewModel.transcriptWithheld, TranscriptTextWithheld.editHeld(_:keptCopy:)), which Search in Book says (see [The reader](reader.md); BookTextEditWording.heldReason(_:forAudiobook:)).
    - MarkdownCacheService.writeCache, the one path every rebuild of a text book's content.md takes, calls permitTextRebuild(of:writing:) before it replaces the file. That keeps any other text it would replace (TEXT_EDIT_KEPT) and refuses over an edit not taken (TEXT_EDIT_HELD), so the cache batch and Redo Text Extraction skip that book; Redo counts the books it left so (HeldTextEditTally), and Storage settings say how many (textReextractionOutcome(skippedInCloud:heldByEdits:)). textRebuilt(_:writing:fingerprint:) then makes the written text the session's baseline. TranscriptTextLoader.writeText calls it too, for the text of a transcript it writes again (its sessions argument: the app's for the loader's rebuild, none for an install, which pauses the session first), so TextMouth's own rewrite is never taken for the listener's edit. For a book no session watches, it keeps the text content.md holds, when that isn't what the book's record says TextMouth last wrote or took there, and also when it is an edit taken (Book.editedText, B12), which only Redo Text Extraction replaces, beside it before the rebuild (keepTextSavedWithoutSession(of:replacedBy:), TEXT_EDIT_KEPT), and refuses the rebuild when no copy can be made.
    - A finished edit is kept by automatic re-reads (B12): BookTextEditSessions.holdsTakenEdit(_:access:) is true when the book records an edit taken (Book.editedText) and content.md still has exactly that edit's digest; it reads nothing of a book that records no edit, and counts a content.md only in the cloud, missing, or unreadable as not matching. Then no automatic generation replaces the text: MarkdownCacheService.writeCache throws EditedTextKept before it reads the source, and logs one TEXT_EDIT_KEPT line naming the title only, unless replacingEditedText is set, which only Redo Text Extraction sets (updateTextCache's force). The launch batch's committedTextCache indexes the text as it is and commits it with the current cache format once (keptText), so the batch does not visit the book at every launch, and a reader that meets EditedTextKept reads content.md as it is. Redo Text Extraction reads the file over the edit after keepTextSavedWithoutSession has kept the text as content.md.edited- and the time, and refuses the rebuild when no copy can be made; TextMouth deletes no copy itself.
    - Launch's cache batch takes an edit saved while no session watched, as while TextMouth was closed: for a book whose content.md no longer matches its row's fingerprints, and which no earlier run committed, it checks content.md as a session's save is checked, against the fingerprints the book's record keeps (BookTextEditSessions.settleEditSavedWhileClosed, recordedTextCacheFingerprint(of:access:)). An edit beside an unchanged source is taken when it parses, logged as TEXT_EDIT_ADOPTED and announced to no one; any other is kept beside content.md, and the cache is rebuilt from the source.
    - The statistics pass skips books being edited (commitStatistics).
    - FileImportService.isPackageContentName (TextMouthPaths.isKeptTextCopy) keeps the copies out of the candidates for the book's own file.
