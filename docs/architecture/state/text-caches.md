# Text caches and content indexes

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- content.md: each text book's text cache, its text as Markdown. A transcribed audiobook's content.md is its transcript's text instead (transcripts, above).
  - Owner: MarkdownCacheService. The format's version is MarkdownCacheService.currentCacheVersion ("3.0.7"), and a book whose recorded cacheFormatVersion is older (SemanticVersion.isOutdated, which judges the metadata reader's version, above, the same way) is extracted again.
  - Who may write it: MarkdownCacheService, which writes a new cache only after extraction succeeds and replaces the old one atomically (writeCache), and, through Edit Text, the user's own editor (edited text, below). Before it replaces the content.md of a book being edited, writeCache asks BookTextEditSessions (permitTextRebuild(of:writing:)), and afterwards tells it what it wrote (textRebuilt(_:writing:fingerprint:)). generateCacheContent runs inside BookContentAnalysisService.load: when an import reads its new book, when a reader opens a book whose cache is missing or outdated, and when a stale cache is rebuilt. generateCacheAnalyzeAndStamp runs for startup maintenance (extractMissingContentCaches, through TextCacheUpdateQueue, which runs ordinary EPUBs on two utility workers and everything else one at a time), for Redo Text Extraction in Storage settings, and for the legacy migration. Maintenance leaves a book whose files are in the cloud as it is (maintenance in a cloud library, below). The extraction a cache is written from parses each EPUB document once: EPUBParser converts a document to Markdown from the DOM its contents scan parsed, and again only when a contents page later in the book names a new destination in it, and asks whether an element is hidden only in markup that holds the word (PublicationSemantics.mayCarryHiddenAttribute(_:)). HTMLToMarkdownConverter wraps emphasis and links in time that grows with what they wrap, not with what was converted before them.
  - How others observe it: BookContentAnalysisService.load reads it and parses it into DocumentContent, splitting it into chapters over Substrings of the cache, one copy per chapter (MarkdownCacheService.splitChapters(_:)).
  - Files: Services/MarkdownCacheService.swift, Services/TextCacheUpdateQueue.swift, Services/BookContentAnalysisService.swift, ViewModels/LibraryViewModel+Migration.swift, Parsers/EPUBParser.swift, Parsers/EPUBParser+Navigation.swift, Parsers/PublicationSemantics.swift, Parsers/HTMLToMarkdownConverter.swift.
- The encoding a text file is read in (FMT16): a plain text, Markdown, or HTML book's content.md is built from its file, whose bytes may name no encoding, and every build of it reads the file in the encoding the book recorded when it was imported, or that the listener chose (encodingchoice), so a rebuild never moves the text under the book's saved places (the guess and the choice, in [Imports](imports.md)).
  - Owner: the book, as Book.textEncodingRecord on its row (Book.textEncoding and textEncodingSource: the encoding, and who decided it) and BookMetadata.textEncodingRecord in its package record (Book.recordedTextEncodingRecord() gives the row's, else the record's), set by the import that guessed it, and again by the listener's re-read in another encoding. It is empty (TextEncodingRecord.unrecorded) for a book whose bytes named their encoding or that Windows-1252 reads right, and for every book imported before guesses were recorded.
  - Who may write it: MarkdownCacheService.generateReportedCacheAnalyzeAndStamp, from the guess an import with guessingEncoding made (GeneratedCache.guessedEncoding) or, for a row that lost the encoding, from the record; and LibraryViewModel.readTextAgain, which records the listener's choice, or the guess Automatic makes, with the text it reads (Reading a book again in another encoding, below). No rebuild or migration guesses.
  - How others observe it: MarkdownCacheService.encodingPolicy(of:guessingEncoding:) turns the book into the policy of a read: .guess for an import or an Automatic re-read (guessingEncoding set and no encoding or decision on the row), otherwise book.recordedTextEncodingRecord().policy, which is .chosen(identifier) for an encoding the listener chose, the recorded encoding (TextFileDecoder.EncodingPolicy.forBook(recording:)) for a guess, or the Windows-1252 fallback for a book with none. The two places that read a text file for a book both ask it: writeCache, which every generation passes through (the import, startup maintenance, Redo Text Extraction, the legacy migration, and the reader's regeneration), and extractedText(for:includesPages:), which the launch's re-read for pages compares content.md with, so the compare reads the file as the generation that wrote content.md did. When BookContentAnalysisService.load cannot write a cache for a book that has none, it parses the file straight (BookParser.parse(url:format:...encodingPolicy:)) with the same recorded policy, so the direct parse and the cache never start from different text. A book with no recorded encoding is read by the fallback, as every book was before guesses, so no rebuild changes a book already in the library. A recorded encoding that the bytes are not valid in, as a file changed since is, leaves them to the fallback too, and so does a book that lost the encoding from its row and its record both, as an older TextMouth's saves leave it: its next rebuild reads Windows-1252. A chosen encoding that the bytes are not valid in, as a file changed since is, is refused instead (TextEncodingError.invalidForChosenEncoding), never read by the fallback.
  - Files: Services/MarkdownCacheService.swift, Services/BookContentAnalysisService.swift, Parsers/BookParser.swift, Parsers/TextFileDecoder.swift, Models/Book.swift, Models/TextEncodingRecord.swift.
- Reading a book again in another encoding (encodingchoice): the one-book form of Redo Text Extraction that the listener asks for from Book Information's Text Encoding pop-up (the sheet and its model, in [Windows](windows.md); the decoding, in [Imports](imports.md)).
  - Owner: LibraryViewModel.booksBeingReadAgain (ViewModels/LibraryViewModel.swift), a Set of book IDs on the main actor, not published: the books whose text is being read again, from the moment the listener confirms until the library row has the new reading.
  - Who may write it: LibraryViewModel.readTextAgain(bookID:as:access:) (ViewModels/LibraryViewModel+TextEncoding.swift), on the main actor, in this order.
    1. It refuses a book that has left the library (TextEncodingWording.bookGoneRefusal) and one that no longer offers the choice (failedRefusal), then whatever textEncodingChangeRefusal(of:) says, which the pop-up asked too before it confirmed: another operation holding the storage work (StorageBoundary.shared.heldFor, worded by StorageBusyError, as Replace Existing words it), the library's text being read again (isExtracting: the launch's batch, Redo Text Extraction), the book being read again already, and the book being exported (BookExportModel.booksBeingExported).
    2. It adds the book to booksBeingReadAgain, which a defer removes again however the work ends.
    3. A book being edited with Edit Text is no refusal. BookTextEditor.pauseEditing(of:) lets a check running finish, takes an edit saved and not yet checked, and ends the session, since the session watches the content.md that is about to be replaced and would take the new reading for an edit. A re-read that is refused afterwards begins the session again from a fresh baseline (resumeEditing(of:)), so the listener's later saves are still taken; one that goes ahead leaves it ended, and the one announcement says so (BookTextEditWording.stoppedBookReadAgain).
    4. rereadText(of:as:access:isOpenInReader:) does the work off the main actor (OffMainWork), in one piece of storage work (StorageBoundary.shared.perform(.textExtraction)), so a folder edit or a data-directory move that begins meanwhile waits for it, and the book's package never moves between content.md's write and the record's commit. It rebases the book to the data directory in use now, refuses a book with a file only in the cloud (LibraryCloudWording.notDownloaded(titles:)) before it reads anything, and reads through the access, so nothing is downloaded.
    5. rereadFiles(of:as:access:isOpenInReader:) goes in this order: (a) for a choice, validatedChoice(of:for:) reads the file strictly in each identifier of the option's name before anything is written, and gives the record of the first that reads every byte, as chosen, or the not-valid refusal naming the encoding, "Nothing was changed."; (b) keptUnwrittenText(of:access:) keeps content.md beside the new text when it holds text TextMouth did not write, an edit on record (Book.editedText) or a save no edit took (DuplicateReplacement.holdsUnwrittenText(_:of:hasher:), which Replace Existing asks too), named as BookTextEditSessions.keepCopy(of:bytes:) names the copies Edit Text keeps, and throws UnwrittenTextNotKept when it can't; (c) MarkdownCacheService.generateReportedCacheAnalyzeAndStamp(for:replacingEditedText: true, guessingEncoding:) reads the file again with the record set on the book, a choice's, or an empty one with guessing on for Automatic, and moves the book's places with the text (T06, in [Package records](package-records.md)); (d) the record Automatic keeps is the guess it made, if any, with the source automatic (TextEncodingRecord(identifier: updated.textEncoding, source: .automatic)), so a choice made before it leaves the row and the record alike; (e) after access.requireOnThisMac(book, reading: .all) has checked that no file went to the cloud meanwhile, LibraryPersistenceService.saveContentAnalysis(…textEncoding:) commits the analysis, the moved places, and the encoding in one write of the book's record, as a decision that replaces the record's (Book.bookInfo(replacing:contentIndex:revisionFloor:decidingTextEncoding:), in [Package records](package-records.md)).
    6. If anything after content.md's write throws, or the record takes nothing (CommitDropped: its file was replaced or moved), PackageFileBeforeInstall (Services/TranscriptInstallation.swift, which a transcript's install uses to put back what it wrote) puts the old content.md back, its bytes and its dates, since the record still describes it and no later load should take the new reading for text changed by hand; committing the record first would not do, because the record's fingerprint of content.md exists only after the write. A put-back that fails logs a line with the tag TEXT_ENCODING_CHANGED.
    7. The result, a TextEncodingReread (readAgain, with a TextCacheUpdate, the reading for VoiceOver, and the copy kept, or refused, with the sentence), returns to the main actor. applyTextCacheUpdate(_:atOnce: true) gives the row the analysis whether or not a reader has the book open, after flushing the summaries waiting for it (analysisSummaries.flush()) so none lands over it, and tells a reader that has the book open through LibraryBookUpdates.textReplaced; which readers have it open is asked at the commit, from the work's thread (audioEditActivity.isOpenInReader, as the batch asks it), so a reader opened during the read is given the new text too. The batch's updateProgress calls the same method without atOnce.
    8. The announcement (TextEncodingWording.readAgainAnnouncement(bookTitle:reading:keptCopy:stoppedEditing:)) is spoken once for the whole, and returned as the outcome, which the pop-up's sheet shows only when it is a failure. One TEXT_ENCODING_CHANGED line goes to the storage log (textEncodingLogLine(title:record:keptCopy:)): the title, then "read again as <identifier>, chosen", "read again automatically, as <identifier>, guessed", or "read again automatically, with no encoding to record", and "; its earlier text was kept as <copy name>" when a copy was kept. It holds no text of the book.
  - How others observe it: readingAgainRefusal(of:) says "TextMouth is reading “<title>” again in another encoding. Try again when that finishes." (TextEncodingWording.readingAgainRefusal(bookTitle:)) for a book in booksBeingReadAgain, or, with no ID, for any, and four entry points ask it, so each waits in the same words and none leaves a content.md from one run beside the record of another (review of October 24, finding 3): a second re-read (textEncodingChangeRefusal(of:)); Edit Text (BookTextEditor.edit(_:choosingApp:in:from:), which announces it and opens nothing, before it looks at the book and again after its dialogs, since a re-read may begin while they are open); Redo Text Extraction (redoAllTextExtraction starts no pass, and redoAllTextExtractionReturningOutcome returns the failure, which Storage settings' status line shows and VoiceOver announces; it said nothing before); and Replace Existing (replacementRefusal(of:), asked last, since a re-read ends by itself in a moment, as DuplicateReplacement.Refusal.readingAgain, whose sentence is said as it is).
  - A quit (0.4.4): TextRereads.quitWork is a QuitHold.Work (kind "text re-reads") that a quit waits for, until every re-read has written its text and its record, for 10 seconds at most (TextRereads.longestQuitWait). The whole quit is in [Launch](../launch.md).
    - A quit the person asks for is cancelled while it waits, and TextMouth asks to quit again afterwards. It says "TextMouth is finishing up before it quits: reading a book's text again in another encoding. It will quit as soon as that is done." in a panel and through VoiceOver, or "reading the text of 3 books again in another encoding" when several run.
    - A second Command-Q or the Dock's Quit meanwhile is cancelled too and says the same words again, so it no longer quits at once and cuts the re-read off.
  - Files: ViewModels/LibraryViewModel+TextEncoding.swift, ViewModels/LibraryViewModel.swift, ViewModels/LibraryViewModel+Migration.swift, ViewModels/LibraryViewModel+Duplicates.swift, Platform/macOS/Services/BookTextEditor.swift, Services/DuplicateReplacement.swift, Services/TranscriptInstallation.swift, Services/MarkdownCacheService.swift, Services/LibraryPersistenceService.swift, Models/LibraryInfoWording.swift, Models/BookTextEditWording.swift, Views/Settings/StorageSettingsView.swift.
- Page markers in content.md (PG01): `<!-- page: LABEL -->`, an inert HTML comment that names a page of the book and adds no reading text, so writing, moving, or deleting one moves no saved place.
  - Owner: content.md, in the one form of MarkdownPageMarker (Parsers/MarkdownPageMarker.swift). Its label is the page's name as its source gives it, trimmed, with each inner run of white space made one space and cut to maximumLabelLength (32) Characters; a leading word "Page" is taken off when a name follows it (MarkdownPageMarker.withoutPagePrefix: "Page 12", "page xii", "PAGE: 3", and "Page12" are the pages 12, xii, 3, and 12, since the reader says "Page" itself; "Pages 4" and "Pageant" stay), in decode as in the writer, so a content.md written with "Page 12" reads as page 12; and a label that names no page (MarkdownPageMarker.namesNoPage, asked after the word is taken off: nothing left, a lone period, or only the word "Page" in any capitals, which a generator writes as aria-label="Page " when it has no number for the page) takes the page's 1-based ordinal. markdown writes each %, <, >, control, line separator, and paragraph separator as % and two uppercase hexadecimal digits, and the second of two hyphens too, since CommonMark ends or refuses a comment at "--". decode accepts only that exact form and refuses a comment with a raw <, >, or -- in its label, so a comment the source itself carried stays invisible (PAGES-RESEARCH-2026-10-21.md, section 2.2). MarkdownPageMarker.isNoMoreThanLabel(_:label:) is the one rule for whether text found where a page begins is no more than that page's label, so that the marker stands in for it (ST02): empty, or at most maximumLabelLength Characters and, when there is a label, containing it or contained in it ignoring case, or only a page number in another numbering (looksLikeAPageNumber: numbers, Roman numeral letters, white space, and punctuation, as "V" under the label "5"); longer or other text is words, never dropped. EPUB's page-break elements (HTMLToMarkdownConverter.readsOwnText(ofPageBreak:page:)) and DAISY 2.02's page fragments (DAISY202PageMarker.isNumber(in:)) both ask it, and an element with no aria-label or title is a page by its text only when the text could be a label. An aria-label or title that names no page is passed over for the next one (HTMLToMarkdownConverter.attributeLabel), and an element whose attributes say only "Page" is a page by its text only when the text is a page number (MarkdownPageMarker.isPageNumber: ASCII digits or a canonical Roman numeral); its other words stay words, since readsOwnText compares them with the attributes' own text (attributeText), so "Page " over "Chapter One" begins no page and is read. The converter keeps each page's label as its source spelled it (HTMLToMarkdownConverter.PageStart, and HTMLPageTargets.sourceLabels for a page list's), and an element's text that is no more than either form is not read: "Page 12" under "Page 12" stays unread, a number under "Page 12" is the page's own and is not read, and a caption "Page 12" under a label of "12" alone is read (stable020's rule). A heading that holds such an element leaves its number out of its label as the body text does: HTMLToMarkdownConverter.destinationMarkers(inside:) returns the page-break elements whose text is not read (EnclosedDestinations.unreadPageBreaks) with the markers it writes before the heading, and HTMLReadingText.label(of:leavingOut:) skips them, so "Part <page 9>Two" is the heading "Part Two" with page 9 written before it. An element that holds words other than its page's number keeps them, and a read without pages (includesPages: false) writes the label as cache format 3.0.7 did. A PDF's label is the one PDFKit gives, except that PDFTextParser.plainNumberLabel(_:ordinal:) writes a page's own number as plain digits when PDFKit grouped it for the locale, as it does for a PDF that names no labels ("1,000", "1.000", "1 000"), so that the N of "Page 1000 of N" counts it; any other label stays, and so does "1.100" on page 100, which only looks grouped.
  - Who may write it: the converters, only through MarkdownMarkerWriter.write (Parsers/MarkdownMarkerWriter.swift), which places heading annotations too. A caller that writes many markers in a row (the DTBook converter, and the HTML converter for the trailing markers of a run) passes a MarkdownMarkerWriter.RunMemo, remembering: &memo, which keeps where the last marker went, so the next goes just after it while nothing else has been written (the Markdown's length is the memo's, and the marker before the offset is the one remembered); anything else is placed from the line as ever and forgets the memo. Placing from the line is linear in the line, so 5,000 markers after a 2 MB line took 15.7 seconds and 80 seconds or more in a DTBook; with the memo the same take under half a second, and the scan back to the line's last line feed stops at the first scalar only a word can hold, which the marker just written supplies. The output is byte for byte the writer's without a memo (compared on millions of random sequences). CommonMark opens an HTML block at "<!--", in a list item or quote too, and the block swallows the rest of the line, so a marker never begins a line that words follow: inside running text it stands where the page begins; at a block boundary it is a block of its own; at the opening of a list item or quote it is a block of its own inside it; at the opening of a heading it is written in the heading; after a hard break it is written at the end of the line before; and on a line indented four columns or more it is a block of its own at the margin. EPUBParser (the page list, else the page-break elements; a page list entry whose text is only the id it links to or carries gives no label unless the id is a page number, an NCX pageTarget's value standing in, and a list that labels none of its pages is passed over, for the NCX's and then the page-break elements, EPUBParser.readPageList and givenPageLabel), HTMLToMarkdownConverter, PDFTextParser, DOCXParser (DOCXPageTracker), DAISYParser, TextutilDocumentReader (a second textutil run, TextutilPageBreaks, now only for a compound-file Word document older than Word 6, the one thing textutil still reads), RTFDocumentReader and WordDocumentReader (the page-break spans of their own HTML; see Own readers of rich text and Word 97-2003, in [Imports](imports.md)), BrailleBookReader (the braille pages of a file that marks them, a PEF's or a BRF's, BrailleBookReader+Pages.swift, PG12: Braille files, in [Imports](imports.md)), and PlainTextParser (the pages of form feeds, PG13) write them. PlainTextParser.pagedBlocks(in:) finds a form feed's page: a form feed (U+000C) ends a line as it always did, so the reading text is the same with pages and without them, and begins a page at the first line after it that is read, a heading or a paragraph's line, not an empty line and not the underline a setext heading took. Several form feeds before one line begin a page each there, a blank page kept in its order; one with no words before it or none after it begins none. A book has at most MarkdownPageMarker.maximumPagesPerBook (100,000) pages, page 1 among them, the limit textutil's reader keeps (TextutilPageBreaks.maximumPages): past it a form feed begins no page, though it still ends its line, so the text is unchanged, and a megabyte of form feeds between two words cannot write a million pages. Page 1 stands at the book's start and the markers are labelled 1, 2, 3 on from it, a block of their own before the block a page begins and, inside a paragraph, at the end of the line before; a text whose form feeds begin no page, and a read without pages (includesPages: false; the direct parse reads no pages either), write what cache format 3.0.7 wrote. Every extraction takes includesPages: true for every cache the app writes (MarkdownCacheService.writeCache); false writes what cache format 3.0.7 wrote, which the tests that pin a parser's exact Markdown read with, and which PG09 compares a content.md with to find text changed by hand (MarkdownCacheService.readingTextsWithoutPages). The user's editor may delete, rename, or add one (edited text, below).
  - How others observe it: MarkdownParser turns each marker into a PageBreak in Chapter.pages, at the first whole word it stands before or in (PageBreak.firstWordStart: white space moves it forward to the next word, the middle of a word back to its start), and DocumentContent gathers the chapters' into BookPages (a book's pages, in [The reader](reader.md)). The exports leave markers out (ExportDocumentWalker, which every export writer reads, the Markdown writer included). An HTML block that begins with one or more complete markers of ours and then holds words (CommonMark swallows the rest of such a line, and an Edit Text change can make one) is read as its markers followed by the Markdown of the rest, whose words, emphasis, and offsets are read in place (PlainTextExtractor.visitHTMLBlock, ST05; isReadingRestOfMarkerLine bounds it to one level, so a second marker-led block inside the rest reads as before). MarkdownCacheService.splitChapters does the same for a chapter line with words after it (chapterMarkerFollowedByWords, ST05b): the marker begins its chapter and the words are the chapter's first line.
  - Files: Parsers/MarkdownPageMarker.swift, Parsers/MarkdownMarkerWriter.swift, Parsers/MarkdownParser.swift, Models/BookPages.swift, Models/DocumentContent.swift, Parsers/EPUBParser.swift, Parsers/EPUBParser+Navigation.swift, Parsers/HTMLToMarkdownConverter.swift, Parsers/HTMLReadingText.swift, Parsers/PDFTextParser.swift, Parsers/DOCXParser+Converter.swift, Parsers/DOCXParser+Sections.swift, Parsers/DAISYParser.swift, Parsers/DAISYParser+TextExtraction.swift, Parsers/TextutilDocumentReader.swift, Parsers/TextutilPageBreaks.swift, Parsers/BraillePageAnalyzer.swift, Parsers/BrailleBookReader+Pages.swift, Parsers/PlainTextParser.swift, Services/Export/ExportDocumentWalker.swift.
- The page reader's version (PG09): which page reader wrote a book's content.md.
  - Owner: the package record and the library row, as Book.pageReaderVersion (BookInfo.state.pageReaderVersion), an analysis-owned field (Book.ContentAnalysisFields, in [Package records](package-records.md)) that is nil until a generation stamps it. PageReaderVersions.current(for:) gives each format's version, "1.0.3" for EPUB and "1.0.4" for HTML: at 1.0.1 their shared converter stopped reading a page break's number into a heading's label, which changed the reading text of the books that have such a heading and of no others, and at 1.0.2 a label of only the word "Page" names no page and an EPUB page list that labels none of its pages is passed over, which changes those books' pages, and their text only where a page-break element holds its page's number, which is then the page's label and no longer read; and at 1.0.3 a label's leading "Page" is taken off, which changes the text only where a number stands under a label such as "Page 12" (every format's content.md loses the word as it is read, so no other format's books are read again); and at HTML's 1.0.4 the text decoder reads unmarked UTF-16 and UTF-32 in every script and an HTML file that declares ISO-2022-JP, unless the book recorded its encoding (TextFileDecoder.unmarkedUnicode(in:latinOnly:) and Evidence), which changes the text of the HTML books that have such a file and of no EPUB, so HTML was split from EPUB; "1.2.0" for RTF, RTFD, and DOC ("1.1.0" from 0.3.1, when TextMouth's own readers replaced textutil for them, FMT47: their headings come from the document's styles and outline levels and their pages from \pagebb, \sect, and a paragraph set to start a page, so each such book was read again once; "1.2.0" from 0.4.0, when the one reading policy of the document readers began: for RTF and RTFD, tracked deletions left out, notes read after the text, and a shape's text box after its paragraph; for DOC, hidden text left out, the piece modifiers of fast-saved files, Word's list tables, and text boxes after the notes; every such book is read again once more), "1.1.0" for DOCX (hidden text and deletions left out, notes after the text, a text box read once and after its paragraph, no emphasis mark spoken), ODT, and WordML (from 0.4.0, when their own readers replaced textutil: their own headings, pages from style breaks, master pages, and soft page breaks, hidden text left out, and notes after the text), "1.0.0" for KFX (from 0.4.0, a case of its own: pages only from a print page list) and for PDF (whose changed labels leave its reading text alone, so a PDF already in the library keeps its old labels until Redo Text Extraction), DAISY, and braille, "1.0.1" for plain text (the same decoder rules as HTML's 1.0.4: every plain text book is read again once more, its content.md byte for byte as before unless its file is one of those; Markdown has no page reader and no version, so its books read the new way whenever their text is built again), and nil for a format without pages, which is never read again for them; a format that gains pages later adds a case of its own, which reads again only its own books (V07), as braille did (PG12), whose BRL books have no pages and are read again once with the rest and stamped, and plain text did for its form feeds (PG13), whose books with no form feed between words, most of them, are read again once, their content.md byte for byte as before, and stamped. A web archive's text page writes no pages (WebArchiveReader.MainPage.markdown() asks PlainTextParser for none), since a web archive has no page reader line of its own (PageReaderVersions.current(for:) is nil for it) and no book of it is read again for pages, so its books would differ by when they were read.
  - Who may write it: every generation records its format's current version (MarkdownCacheService.GeneratedCache.pageReaderVersion, committed with the analysis through LibraryPersistenceService.saveContentAnalysis(…pageReaderVersion:)), since every generation writes pages. When textutil's run for the pages failed or timed out (only for a compound-file Word document older than Word 6, the one thing textutil still reads since 0.4.1; an own reading makes no second run, so its book is never noted this way), the generation records a note after the version instead (PageReaderVersions.stamp(for:pageRunFailed:previous:), PG16): "1.0.0+failed-once", which the next launch reads again, then "1.0.0+failed", which no launch reads again. The launch's batch also stamps a book whose content.md it keeps, through BookTextEditSessions.settleKeptText: the format's version, "+failed" (PageReaderVersions.failedStamp(for:)) for a book whose file is missing, or "+failed-once" and then "+failed" (PageReaderVersions.failureStamp(for:previous:)) for one whose file could not be read. An analysis that carries none leaves the record's own (Book.applyContentAnalysis): an analysis says nothing about which page reader wrote content.md.
  - How others observe it: PageReaderVersions.isDueForPages(_:) is true for a book whose version is behind its format's (PageReaderVersions.isOutdated, which reads a note apart from its version and takes "+failed-once" as behind) while the launch re-read is on, as it is since PG16 (PageReaderVersions.launchRereadIsOn). Then booksNeedingCacheUpdate chooses the book, and BookContentAnalysisService.recoveredTextCache does not recover a record that predates its format's page reader. A book whose stamp notes success (PageReaderVersions.notesSuccess: an earlier page reader read its pages) and whose content.md is as its record describes it is read again without the compare below (V05): a build that records every edit wrote it, and compared, it would differ from what the newer reader writes, so the first bump of a format's page reader would keep a copy of every book of the format (EPUB at 1.0.1, 1.0.2, and 1.0.3, and HTML at those and 1.0.4, keep none). A book with no stamp, as every braille and plain text book has when its format gains its reader (V07), or whose stamp notes a failure, is compared as ever, so a braille book whose reading changed meanwhile keeps a copy. For a book behind only in its pages (isBehindOnlyInPages) that holds no edit taken, the batch compares the whole content.md, byte for byte, with the book's file read again (pageUpgradeCheck), before it looks for an edit saved while TextMouth was closed: content.md that is the file's text without pages is read again with them; the file's text with pages, which a batch stopped before its commit leaves, only has its record stamped; any other text, which nothing can tell from an edit made before B12, is copied beside content.md as content.md.edited-<UTC time> (PageUpgradeCopies, through BookTextEditSessions.keepCopy), logging PAGES_REPLACED_TEXT, and read again with pages, its places relocated, or, when no copy can be made, kept, recorded as edited (Book.editedText, B12) and stamped, logging PAGES_SKIPPED_CHANGED_TEXT; a book whose file is missing is stamped "+failed", and one whose file could not be read, with pages or without, "+failed-once" and then "+failed" (PageReaderVersions.failureStamp), logging PAGES_SKIPPED_UNREADABLE.
