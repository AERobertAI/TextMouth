# Imports

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- An import in progress.
  - Owner: LibraryViewModel's SerialImportQueue, which runs one import at a time off the main thread, each as storage work that a data-directory move waits for or holds back (StorageBoundary.perform), and reports activity on the main queue, and ImportCancellation, which the queued imports share and the progress overlay's Cancel button sets.
  - Who may write it: FileImportService does the work. Open Book offers the types it reads (FileImportService.supportedTypes), video among them, since an audiobook may be an MPEG-4, M4V, or QuickTime file whose sound alone plays (BookFormat.audio's mp4, m4v, and mov; public.mpeg-4, com.apple.m4v-video, and com.apple.quicktime-movie), so a video episode's package imports again too, as does the audio the import converts (BookFormat.audio's ogg, oga, and opus, with org.xiph.ogg-audio, also declared in Info.plist, and ImportAudioConverter.coreAudioExtensions, which the list ends with, each offered by its system type where it has one) and an M3U playlist (public.m3u-playlist); ArchiveEntryLimits.audioExtensions is the same list; a feed still tells a video enclosure from audio for itself (FeedMediaKind, whose audioExtensions leave video's out). It identifies the source, builds the package under a hidden staging name (ImportStaging, .import- followed by a UUID and .tmb), in this Mac's Import Staging folder while the data directory is on its volume and beside the package's destination otherwise (ImportScratchSpace), copies the content, reads the book as the reader will, writes bookInfo.json and reads it back, and only then publishes the package with one rename. A TextMouth package is staged as every import is (REV13): ImportStaging.makeEmpty makes the staged package, then the .copying step copies the source package's items into it (copyContents(of:)), so the import overlay names the copy, and a package whose own folder is read-only imports, since the staged folder is TextMouth's own. A failure removes whatever was staged and throws an ImportFailure naming the file and the step, and the original file is never touched after a failure. A ZIP is inspected and extracted within an ArchiveBudget into an Archive Extraction folder on the same condition, this Mac's or the data directory's (ArchiveExtraction), and every format reader takes entries out of archives through ArchiveEntryReader, which holds each entry to its limits. A reader that looks up more than a member or two, as the EPUB, Word, and DAISY readers do, finds them in an IndexedArchive, the archive's entries read into an index by path once, since ZIPFoundation finds each by reading the archive's central directory from its start; the index answers exactly as the archive would, the first entry at a path winning. DAISY audio conversion copies each audio file through DAISYFileProvider.copyFile(at:to:): out of a ZIP a megabyte at a time (ArchiveEntryReader.stream), never whole, and from a folder as a clone. A ZIP batch reads each book's checksum once, for its duplicate check, and hands it to the book's import (importFileWithReport(from:checksum:toFolder:observer:)).
  - How others observe it: LibraryViewModel adds the published book to the library, unless the library already holds a copy, and the overlay shows how far the import has got (import progress, below); every question an import raises waits its turn in one queue (import questions, below).
  - The manifest's check (FR15): an archive whose manifest.json is found (AudioManifestLocation.find(in:)) is checked in a step of its own, Reading its manifest (ImportStep.readingManifest), after extraction and before the book is read. AudioManifestCheck.checkedManifest(at:audioFolder:) stops at the first problem, in the order a person fixes them, with an AudioManifestProblem whose sentence begins "manifest.json". Only the import checks; every later read is lenient (AudioManifest.read(inAudioFolder:)).
  - Files: Services/FileImportService.swift, Services/FileImportService+Packages.swift, Services/ImportStaging.swift, Services/ImportScratchSpace.swift, Services/ImportFailure.swift, Services/ArchiveBudget.swift, Services/ArchiveExtraction.swift, Parsers/ArchiveEntryReader.swift, Parsers/DAISYParser.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/LibraryViewModel+Duplicates.swift, Parsers/AudioManifest.swift, Parsers/AudioManifestCheck.swift.
- Import progress (FR10): what the import overlay shows, and what VoiceOver hears of an import.
  - Owner: LibraryViewModel.importProgress, an ImportProgress (ViewModels/ImportProgress.swift) on the main actor, whose state is an ImportProgressState: a notice, the books done of the total, the book under way (its name, its number in a batch, its ImportStep, when it began, and, for an archive holding one audiobook, how far its extraction has got, BookUnderWay.extraction, which its line says while it extracts), what the books done took (timing, a WorkTiming), the sizes the batch's books are timed by (bookSizes), the time left, whether Cancel was pressed, and the imports waiting behind the one shown (waitingImports), which a new import's state keeps. The duplicates a batch skipped are counted once, in its ZipImportResult (skippedDuplicates). Whether the overlay shows at all is still the model's isImporting.
  - Who may write it: the imports, on the main queue. ArchiveExtractor reports an archive's extraction as an ArchiveExtractionProgress, its entries and the bytes they declare, both totals from the archive's central directory, which the budget reads anyway: at the start, and whenever the whole percentage of either changes, between the chunks of a large entry as well as between entries. A ZIP batch reports ZipImportProgress.extracting, then .importingBook as each book begins and as each step of it begins (through the importer's ImportStepObserver), and .importing(done:total:skippedDuplicate:) as each book is imported, fails, or is skipped as a duplicate; a batch also reports .foundBooks(sizes:) once, before its first book, each size from FileImportService.timedSize(of:): a text book's file size (an EPUB, PDF, Word document, rich text, Word 97-2003, OpenDocument, Word 2003 XML, web archive, SSML, or plain text, Markdown, or HTML file), and nil for an audiobook's file, whose import reads its chapters rather than its every byte, for a DAISY book, a DTBook on its own included, and for an RTFD, which is a folder. A single file, or an archive holding one book, reports through ImportProgress.observeBook(_:startingAt:then:), which tells the overlay of each step before the queue's test hook, and so do a TextMouth package opened from the Finder (openTMBPackage(from:), from .checkingPackage), New from Text (createBookFromText, from .preparingPackage, by its title), and a recording's save (LibraryViewModel.saveRecording, from .preparingPackage, by its title, REV13), whose line is cleared (clear()) rather than ended, so it announces nothing, since the New Recording window says how the save ended; an archive holding one audiobook reports its extraction through observeExtraction(). TimeLeftEstimate (Models/TimeLeftEstimate.swift, shared with the feed downloads' progress) gives the time left from the WorkTiming of the books imported or failed, duplicates not timed: each book still to come of known size takes its bytes at the rate the sized books took theirs, and any other the average time of the books timed without a size, or of every book timed before any of those, less the time it has run; TimeLeftEstimate.rounded(_:) rounds it to the minute under 10 minutes, to 5 minutes under an hour, and to 15 beyond. The library follows the import queue's count of imports queued or running (importActivityChanged(to:), which observeImportActivity() starts, and which assigns isImporting only when it changes, so the library model publishes as imports start and end and not with each import queued or done, REV13), and the progress counts those behind the one shown as waiting (noteImportsQueued(_:)). Cancel calls cancel(), and end(_:) ends the import shown.
  - How others observe it: only ProgressObserver, a generic view in Views/ContentView.swift, observes it, as it observes the text cache's progress (PERF12, #1461), drawing the overlay in a TimelineView that ticks every 5 seconds from the book's start, so the time on a book keeps up between reports while the library model is never republished. ProgressOverlay takes detail lines and a spoken summary from its caller; the text cache overlay keeps its own. ImportProgressWording words every line, the overlay's VoiceOver label, the announcements, and Speak Import Progress, the imports waiting included (waiting(_:), "2 more imports waiting", left out once Cancel is pressed, since queued ZIP archives never start). An import that has run 10 seconds (ImportProgress.announcedAfter) announces each quarter of a batch's books once, at medium priority, and its end, unless Cancel was pressed, when its alert says where it stopped; Cancel is announced at once. A batch that found no new book and in which nothing failed (ZipImportResult.foundNoNewBook) is not announced: LibraryViewModel.completeZIPImport raises the library's alert instead, which waits on screen and which VoiceOver reads, since an announcement made while TextMouth has no window in front is never spoken (October 13, 2026). The alert is titled ImportProgressWording.nothingImportedTitle ("Nothing Imported", set in LibraryViewModel.errorTitle, which goes back to nil, "Error", whenever showError turns false) and says nothingImported(from:result:): the duplicates sentence, noNewBooks(in:alreadyInLibrary:), or, for an archive with no book, noBooksFound(in:holding:), which names what it held by kind from ZipImportResult.nonBookFiles, a NonBookFiles that FileImportService.importCandidates counts by extension for every file it passes over, those in archives inside included. Every batch also ends with one ZIP_IMPORT_FINISHED event line in the debug log (ZipImportResult.logLine(archiveName:)). The reading list's join after an import made at the Reading List is announced at medium priority (addImportedBooksToReadingList(_:request:)), after the import's own words rather than over them. ShortcutAction.speakImportProgress, under Information with no default key, and Library > Speak Import Progress post speakImportProgress, which the library model hears from any window (observeImportProgressRequests()) and answers through VoiceOver.
  - Files: ViewModels/ImportProgress.swift, Models/ImportProgressWording.swift, Models/TimeLeftEstimate.swift, Services/ArchiveExtraction.swift, Services/FileImportService.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/LibraryViewModel.swift, Views/ContentView.swift, Models/CountWording.swift, Models/KeyboardShortcut.swift, App/MenuCommands.swift.
- Import questions.
  - Owner: LibraryViewModel.importDecisions, an ImportDecisionQueue of the questions imports are waiting to ask (whether to replace or keep a duplicate, whether to delete an original file, whether to put a ZIP archive's books in a new folder, and whether to transcribe an audiobook just imported), asked one at a time in the order they arose. Each ImportDecision holds everything its answer acts on, captured when its import finished (a duplicate's new copy and the copy it matched, an original file, a ZIP archive's books and folder, or an audiobook's ID, title, and length), and the ImportRequest its import was made with: the Library window it started in (ImportOrigin), whether to open the book afterwards, and the cancellation its batch shares.
  - Who may write it: LibraryViewModel+Import and LibraryViewModel+Duplicates. ask(_:) queues a question behind those waiting, and a question an answer raises about the same file, such as whether to delete the original of a duplicate just kept, is asked next. An offer to transcribe (ImportDecision.Kind.transcriptionOffer, FR05) is queued after an import's own questions, for each audiobook it added, when TranscriptionOffers.offersTranscription(of:) allows it: an audiobook in a package of its own, Offer to transcribe after importing an audiobook on, and a Mac that can transcribe. Its Transcribe sends LibraryViewModel.acceptedTranscriptionOffers to the Library window that asked (LibraryTranscriptionSupport), which opens the Transcribe Audio sheet, starting at once when it can. answerImportDecision(_:with:) acts only on the question being asked, named by its ID, so a second press can never answer the next one; an answer that fails, such as a folder name the library refuses, keeps the question open with the reason. While the data directory moves (dataDirectoryMove is set), it refuses every answer with DataDirectoryMoveWording.importAnswerRefusal, shown in the sheet and spoken, and the question stays until the move ends, since a window asking one when a move begins keeps that sheet instead of the move's. cancelImports(), the progress overlay's Cancel, withdraws the questions of its batch, those waiting and those raised later: a duplicate's new copy is discarded, an original file is kept, a ZIP archive's books stay where they are, and an offer to transcribe is dropped.
  - How others observe it: each Library window's ImportDecisionPresenter watches the queue, and exactly one window asks the question at its front (ImportDecisionQueue.askingWindow): the window its import started in while that is open, or else the first open Library window, the question waiting while none is open. That window shows ImportDecisionSheet, whose words, the screen's and VoiceOver's alike, come from ImportDecisionWording, with a title that gives the question's place when there is more than one, as in "Duplicate Book Found, 2 of 5". The choice that removes nothing comes first; Return and Escape press the marked choices, and Replace Existing and deleting an original file are never on a key. A question that appears while the user is in another window waits without taking focus or being announced. A book whose import asked to open it, as one opened from Finder does, opens through LibraryViewModel.readerOpener once it is in the library and its questions are answered.
  - Files: Models/ImportDecision.swift, Models/ImportDecisionQueue.swift, ViewModels/TranscriptionOffers.swift, ViewModels/LibraryViewModel+Duplicates.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/DataDirectoryMoveProgress.swift, Views/Library/ImportDecisionPresenter.swift, Views/Library/ImportDecisionSheet.swift, Views/ContentView.swift.
- A folder of tracks (FR17): importFileWithReport sends a folder of tracks that no format reads to importAudioFolderWithReport, which shares publishTracks with the ZIP import. A folder with neither a DAISY book nor tracks throws FolderWithoutBookError.
- A folder with a DAISY book in a folder beneath it, at any depth, is no folder of tracks either, and throws FolderWithoutBookError too: isFolderOfTracks is false when holdsDAISYBookBeneath finds a folder holding a DAISY book at its top level (DAISYParser.isDAISYDirectory), searched only once the folder is known to hold audio and passing over hidden items, Finder's __MACOSX folder, and symbolic links, since such a folder is no book and its tracks belong to the books beneath it; the error's words (ImportProgressWording.noBookInFolder) list the files the folder holds at any depth, and do not say the books are inside it.
- A folder's original is never deleted: ImportedBook.isFromFolder (once isFromPackageFolder, set only for a DAISY book copied from its folder) is set for both folder branches, the DAISY book's and importAudioFolderWithReport's, so mayDeleteOriginal is false for a folder of tracks too: it holds files the import did not copy (a cover, lyrics, a Bonus folder), and is never deleted or offered for deletion. FileImportService.deleteOriginalFile(at:) refuses a folder too, or a link to one (fileExists(atPath:isDirectory:) follows links), whatever its caller decided: it removes nothing, sends nothing to the Trash, and does not throw, since nothing failed; it writes one ORIGINAL_KEPT line.
- A file with no text to read: FileImportError.noTextToRead ("This file has no text to read.") is thrown by FileImportService.readableContent(of:run:refusingBlankText:) when refusingBlankText is set, the book's format is one of plainTextFormats (txt, markdown, and html), and no chapter of the generated content holds a character that is not white space, so the .readingText step fails and no silent, empty book is published. Only importFileWithReport sets it, through publishReadableBook(_:from:run:feedLink:replacing:refusingBlankText:publish:), so Open Book, Finder, and the members of a ZIP (importSupportedFiles imports each through importFileWithReport) are refused, while New from Text, a feed's download, and every rebuild of an existing book's text are not. The check is in readableContent and not in MarkdownCacheService, because every rebuild of an existing book's text goes through that, and a book already in the library must never become unreadable. A Markdown file that is only a heading still imports. ImportFuzzTests.knownIssues, which held the empty Markdown file the first sweep found, is empty.
- A full disk: ImportFailure.isOutOfSpace(_:) says a volume is full when an error, or one it wraps under NSUnderlyingErrorKey at any depth, is Cocoa's NSFileWriteOutOfSpaceError or POSIX ENOSPC, and ImportFailure.outOfSpaceDescription ("There isn’t enough free space on the disk.") is then the failed step's reason in place of the system's own sentence, which names the hidden staged package (.import- followed by an ID and .tmb). reason and reason(for:) both word an error this way, so an alert, a ZIP batch's list of failures, the IMPORT_FAILED line, and a feed download's failure (FeedDownloadError.importFailed) say it alike.
- A manifest's title and author (FR17): publishTracks and AudioBookParser take them through AudioManifest.bookTitle and bookAuthor, which read one that is empty or only whitespace as none, so the name of the ZIP or folder, or Unknown, stands as for a missing one; the manifest's stored title and author keep every byte.
- Audio the import converts (B06, FMT09): FileImportService.publishReadableBook converts a staged book's audio first (convertImportedAudio(of:in:keepingOriginals:run:), in FileImportService+AudioConversion.swift; step .convertingImportedAudio(done:of:)), before anything reads it as a book, so a ZIP of tracks, a folder, a single file, a playlist, and a feed's episode are converted in one place, each converted file renamed in the manifest through BookManifestFile.change. ImportAudioConverter.tracksNeedingConversion(in:) (a folder) and needsConversion(among:) (files) choose the tracks, by what each holds: verdict(for:) takes the extension (convertedExtensions: oggExtensions and coreAudioExtensions) and then AudioContentSniffer.kind(of:), which reads a file's first 64 KB by hand with no Apple audio API. Ogg, AC-3 and E-AC-3, CAF, AIFC, AU, Wave64, AMR, 3GPP audio, and MPEG layers I and II convert; WAVE (RIFF, RF64, BW64), AIFF, FLAC, MP3, and ADTS AAC are left; MPEG-4, QuickTime, and anything unrecognized go to afinfo, whose codec decides (playsAsIs(formatID:fileType:): AAC, Apple Lossless, and MP3 in them stay). So an Ogg file named .m4a, or an MP2 feed episode named .mp3, is converted.
- ImportAudioConverter reads a source's facts from OggHeaderReader for Ogg (Vorbis, Opus, or FLAC), and from AudioFileInfo for the rest: afinfo -x -r, run by WatchedProcess.runCapturingOutput, gives the container, codec, channels, sample rate, bit depth, length, and whether it names a channel layout. No Apple audio API opens the source in TextMouth's process. plan(for:info:) is leaveAsItIs, convertToAAC, or convertToAppleLossless when the codec keeps every bit (SourceInfo.isLossless: lpcm, alac, flac). target(for:bytes:) gives AAC the source's average bit rate (bytes × 8 ÷ duration) rounded up to the next standard rate (bitRate(averaging:channels:accepted:), 64 to 192 kbit/s for stereo, half for mono) at its own sample rate where AAC takes it (sampleRate(for:)), and Apple Lossless the smallest of 16, 20, 24, or 32 bits that holds the source's samples (24 when the depth is unknown or the samples are floating-point). afconvertArguments(from:to:info:target:) never passes -c, since afconvert refuses it for AAC above stereo. AudioMediaProbe, AudioEditBase.load, and the transcriber refuse every format the import converts by ImportAudioConverter.isNeverDecodedInApp(_:), a converted extension other than TextMouth's own CAF or a file that begins with OggS (AudioContentSniffer.isOgg(at:)); AudioPlaybackService.metadataAsset(for:) asks isConvertedAtImport, by extension alone, since an import reads a source before it converts it. OggConversionProgress.markFailed keeps a failed book from being tried again before the next launch (B09).
- Audio of more than two channels (maximumChannels is 2) takes two steps (write(_:to:info:target:using:)): downmixArguments writes a hidden stereo CAF (".<UUID>.audio-downmix.caf", linear PCM, 16 bits for AAC and the lossless depth, 24 for 20, with -c 2 --mix, because without --mix afconvert drops channels by position and a PCM source's centre came out silent), and afconvertArguments encodes that file, which is removed as soon as the second step ends. Before the first step the volume's free space must hold the PCM file and a 512 MB reserve (downmixBytesNeeded(duration:target:), Failure.notEnoughSpace), and a source of more than two channels that names no layout is refused (Failure.unlabelledChannels). Apple's normalized mix puts the centre in both channels about 10.7 dB down for PCM and 13.7 dB down for AC-3, measured on macOS 26.3.1.
- What watches a conversion: afconvert gets 60 seconds plus a tenth of the track's length, 1 GiB, a stall allowance of 20 seconds, the default processor-time allowance, and an output cap of four times what it should write and 16 MB more (outputCap(of:duration:target:); the expected output is the AAC rate times the length, 320 kbit/s where the encoder chooses, or for Apple Lossless and the downmix's PCM the length times rate, channels, and bytes a sample), set as Limits.maximumOutputBytes. AudioFileInfo.read(_:using:) gets 30 seconds plus one for each 20 MB, 512 MiB, and a cap of 1 MiB on what afinfo prints, and believes a length only up to a year and only as far as the file's bits at the codec's lowest bit rate allow (isPlausible(inFileOfBytes:), logged as AUDIO_INFO_IMPLAUSIBLE; a 136 KB CAF once claimed 25 billion seconds), so a lying header cannot lift the time limit or the cap; a file it cannot read is Failure.unreadable. AUDIO_CONVERSION_KILLED (in place of OGG_CONVERSION_KILLED) and AUDIO_INFO_KILLED are storage events. The converted file is written under ".<UUID>.audio-conversion.m4a", checked by AudioMediaProbe (it plays, and lasts as long as its source to within allowedLengthError(for:), a second and half a percent), and only then named.
- Kept originals: with the setting on (ConfigService's keepsOriginalOfConvertedAudio, read by keepsOriginalsOfConvertedAudio(feedLink:), and never for a feed's episode), convertImportedAudio moves each source into the package's hidden .convertedOriginals folder (ImportAudioConverter.keepSources(of:from:inPackage:): under its path from the book's folder of tracks, or by its own name for a single file) in place of removing it (removeSources(of:)). The folder is hidden so that every track scan passes it by and FileImportService.isPackageContentName refuses it; a kept Ogg file is never opened, and BookExportService.convertedOriginalItem copies the files out as Export's Original file. ConvertedOriginalWording holds the setting's words.
- Package track scans: AudioBookParser.audioFiles(in:scan:) takes a TrackScan. The import's scans (.importing) take every audio format (BookFormat.audio.fileExtensions, which ends with coreAudioExtensions), since they run before the conversion. A package's scans (.package: loading the reader, re-analysis, a manifest edit, the library's checks) take BookFormat.packageTrackExtensions, which leaves out the formats added on October 18, 2026, so a stray .aifc, .au, or .ac3 left in a package is neither played nor counted as a chapter; Ogg stays, since the library converts the Ogg books it holds and that conversion needs their tracks found, and TextMouth's own CAF is taken by its name and place (isOwnCAF(atPath:)).
- Chapters: AudioPlaybackService.extractChapters(from:) reads a Nero chapter list by hand when AVFoundation finds no chapter in an M4A, M4B, MP4, M4V, or MOV file (NeroChapterReader.mayHoldChapterList(_:); read(at:) walks the box headers of the file to the chpl atom under moov and udta on a FileHandle, never reading the media, with every size checked and every level capped; bookChapters(from:fileDuration:) sorts the chapters, drops one at or past the end of the file, and names an untitled one "Chapter N").
- Playlists (FMT10): importFileWithReport sends an M3U or M3U8 file (M3UPlaylist.isPlaylist, by extension) to importPlaylistWithReport, which builds a folder book through publishTracks as importAudioFolderWithReport does. M3UPlaylist.read(at:) takes at most 4 MiB (an .m3u8 as UTF-8, an .m3u through TextFileDecoder) and parse reads #PLAYLIST, #EXTINF, and #EXT-X- lines; a stream is PlaylistImportError.streaming, and a list of only web addresses PlaylistImportError.onlyWebAddresses. resolve(inFolder:) uses only a file that realpath(3) puts strictly inside the playlist's own folder, and skips a web address, a Windows drive, a path outside, a missing entry, a folder, a file that is not one of BookFormat.audio's extensions, anything hidden or not a regular file, and a repeat (distinctTracks(of:) counts a second spelling of one file as a repeat), each as a Skipped with a SkipReason whose words the notice quotes; with no track left it throws PlaylistImportError.noTrack. Each track is copied to the same path in the staged audio folder, with an AudioManifest built in memory from the playlist's order and titles and written there (BookManifestFile.encoded), so the manifest check and the conversion treat the book as any folder of tracks; the book is known by folderHash over the tracks' paths and the playlist's own file name, each with the MD5 of its bytes, so the same playlist imported twice is a duplicate. ImportedBook.isFromFolder is set, so mayDeleteOriginal is false, and ImportedBook.notice holds PlaylistImportWording.notice(playlistName:skipped:) (at most 10 entries named within 600 characters, each location at most 60 characters, a file name of more than 40 shortened in its middle), which ImportedBook.announcement(warning:) joins to the warning; the library presents it under ImportProgressWording.bookImportedTitle ("Book Imported", where a failure's alert says "Error") and does not open the book.
- OggHeaderReader (Services/OggHeaderReader.swift, REV17a) reads an Ogg file's codec (Vorbis, Opus, or, since FMT09, FLAC), channels, sample rate, bit depth (FLAC), length, and tags from the file's own bytes. Ogg FLAC's first packet (identifyFLAC) is the mapping header, "fLaC", and the STREAMINFO block, which gives the rate, channels, bits a sample, and total samples; the length is the last granule position, refused when STREAMINFO's total differs from it by more than a second; its tags are the VORBIS_COMMENT block among the header packets (flacTags). read(at:) takes the first 256 KB (headLength) and the last 70,000 bytes (tailLength) and hands them to parse(head:tail:), which is pure and bounded whatever the bytes are: a page counts only when it lies wholly inside the bytes and its CRC-32 checks (crc(of:)), so a stray "OggS" in audio data costs nothing, and at most 256 rejected candidates are tried in the tail. It takes the identification packet of the Vorbis, Opus, or FLAC stream among the leading start-of-stream pages (audioStream(in:): a multiplexed file begins with one such page for each stream, and an Ogg Skeleton stream's fishead may come first, so the walk goes on while pages have the start flag, a page that fails its checks ends it, and the first serial whose first packet identify accepts is the stream; Speex, Theora, or an unknown codec gives nil), the length from the last page of that same stream in the tail (a page of another stream, as in a multiplexed file, is passed over, so a chained file whose tail holds only another stream's pages gives nil) less the granule position the stream starts at (StreamStart.startOffset: 0 for a stream that begins at the start of its recording, more for one cut from a longer stream, as a live broadcast joined an hour in), and the tags from its comment packet (title; artist, else performer; album; genre; date; a comment packet over 256 KB, cover art say, gives empty tags). A length over a year (maximumDuration) gives nil, so no later Int(seconds) can overflow, and Opus always reports 48,000 Hz. The start offset is found as libvorbisfile and opusfile find a stream's first sample (startOffset(of:codec:)): lead(of:headerCount:in:) gathers the stream's packets from its first page through its first audio page, the first page after the header packets (3 for Vorbis, 2 for Opus) that completes an audio packet and has a granule position of 0 or more, passing over up to maxAudioPagesWithoutGranule (16) pages that complete one without a granule and stopping, keeping what it has, at the first page that fails its checks; the offset is that page's granule less the samples its packets produce, never below 0 (Opus: each packet's frames from its TOC byte, RFC 6716, a packet over maxOpusPacketSamples, 5,760, being invalid; Vorbis: a quarter of each packet's block size plus a quarter of the previous packet's, the first packet giving none, from the identification packet's block sizes and the setup packet's modes). It is 0 when anything cannot be read, and an offset past the last granule is ignored. streamStartOffset(inHead:) gives tests the offset. The metadata readers use it too, through AudioPlaybackService.metadataAsset(for:) ([media playback](media-playback.md)).
- WatchedProcess starts a tool as /bin/sh, which sets the kernel's processor-time limit (ulimit -t, from Limits.effectiveMaximumCPUSeconds: maximumCPUSeconds, else four times maximumSeconds) and then replaces itself with the tool (exec), so the pid it watches, measures, and kills is the tool's own; a child the kernel ends at that limit (SIGXCPU) is reported as KillReason.usedTooMuchProcessorTime. The same shell also sets the kernel's file-size limit (ulimit -f, whole kilobytes: fileSizeLimitForShell(_:)) from Limits.maximumOutputBytes, and the watchdog kills a child whose watched file passes that cap (KillReason.wroteTooMuch, "its output passed N MB"); a child the kernel ends at the limit (SIGXFSZ) is reported the same way, since a check once a second let a fast writer put hundreds of megabytes on the disk between two looks. runCapturingOutput(_:arguments:limits:maximumOutputBytes:...) keeps what a child prints (afinfo's): its standard output goes to a new hidden .<UUID>.watched-output file in the temporary directory, which is the watched file, capped at maximumOutputBytes (1 MiB unless asked otherwise) and removed however the run ends, by an exit, a kill, a failure to start, or a cancellation; there output is not progress, so the stall clock runs from the child's start, and a child that prints without end still ends at its time limit while one that prints only when it ends (afinfo) is not killed for being silent. A reason's words (KillReason.words) count its seconds with CountWording.seconds, so a limit of one second reads "1 second". The watchdog's clock is ProcessInfo.systemUptime, which never runs backwards, so a sleep or a change of the wall clock never ages a healthy child. ChildGate holds the child's pid and whether its task was cancelled under one lock, so a cancellation and the child's start meet in either order and the child is killed all the same, and a task already cancelled starts no child. Every running child is in a registry that terminateAll() kills with SIGKILL, taking a short lock and never waiting for a child; applicationWillTerminate and PlaybackMemoryGuard.quitAtOnce() call it. startReaper(watching:parent:) starts a /bin/sh loop that checks each second and kills the child once TextMouth's own pid is gone, however TextMouth went (quit, force-quit, or the memory guard's _exit), and ends by itself when the child does; a reaper that cannot start is not an error for the run.
