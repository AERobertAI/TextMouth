# Imports

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- An import in progress.
  - Owner: LibraryViewModel's SerialImportQueue, which runs one import at a time off the main thread, each as storage work that a data-directory move waits for or holds back (StorageBoundary.perform), and reports activity on the main queue, and ImportCancellation, which the queued imports share and the progress overlay's Cancel button sets.
  - Who may write it: FileImportService does the work. Open Book offers the types it reads (FileImportService.supportedTypes), video among them, since an audiobook may be an MPEG-4, M4V, or QuickTime file whose sound alone plays (BookFormat.audio's mp4, m4v, and mov; public.mpeg-4, com.apple.m4v-video, and com.apple.quicktime-movie), so a video episode's package imports again too, as does the audio the import converts (BookFormat.audio's ogg, oga, and opus, with org.xiph.ogg-audio, also declared in Info.plist, and ImportAudioConverter.coreAudioExtensions, which the list ends with, each offered by its system type where it has one) and an M3U playlist (public.m3u-playlist); ArchiveEntryLimits.audioExtensions is the same list; a feed still tells a video enclosure from audio for itself (FeedMediaKind, whose audioExtensions leave video's out). It identifies the source, builds the package under a hidden staging name (ImportStaging, .import- followed by a UUID and .tmb), in this Mac's Import Staging folder while the data directory is on its volume and beside the package's destination otherwise (ImportScratchSpace), copies the content, reads the book as the reader will, writes bookInfo.json and reads it back, and only then publishes the package with one rename. A TextMouth package is staged as every import is (REV13): ImportStaging.makeEmpty makes the staged package, then the .copying step copies the source package's items into it (copyContents(of:)), so the import overlay names the copy, and a package whose own folder is read-only imports, since the staged folder is TextMouth's own. A failure removes whatever was staged and throws an ImportFailure naming the file and the step, and the original file is never touched after a failure. A ZIP is inspected and extracted within an ArchiveBudget into an Archive Extraction folder on the same condition, this Mac's or the data directory's (ArchiveExtraction), and every format reader takes entries out of archives through ArchiveEntryReader, which holds each entry to its limits. A reader that looks up more than a member or two, as the EPUB, Word, and DAISY readers do, finds them in an IndexedArchive, the archive's entries read into an index by path once, since ZIPFoundation finds each by reading the archive's central directory from its start; the index answers exactly as the archive would, the first entry at a path winning. IndexedArchive.file(at:) finds the entry at exactly a path, else the first file entry whose path matches it without regard to case (ST09; Archive.file(at:) is the same rule for an archive not indexed), which the EPUB reader's lookups and the DAISY reader's use, since a badly made book may name a member in another case than its ZIP spells it; the exact spelling always wins. DAISY audio conversion copies each audio file through DAISYFileProvider.copyFile(at:to:): out of a ZIP a megabyte at a time (ArchiveEntryReader.stream), never whole, and from a folder as a clone. A ZIP batch reads each book's checksum once, for its duplicate check, and hands it to the book's import (importFileWithReport(from:checksum:toFolder:observer:)).
  - How others observe it: LibraryViewModel adds the published book to the library, unless the library already holds a copy, and the overlay shows how far the import has got (import progress, below); every question an import raises waits its turn in one queue (import questions, below).
  - The manifest's check (FR15): an archive whose manifest.json is found (AudioManifestLocation.find(in:)) is checked in a step of its own, Reading its manifest (ImportStep.readingManifest), after extraction and before the book is read. AudioManifestCheck.checkedManifest(at:audioFolder:) stops at the first problem, in the order a person fixes them, with an AudioManifestProblem whose sentence begins "manifest.json". Only the import checks; every later read is lenient (AudioManifest.read(inAudioFolder:)).
  - Files: Services/FileImportService.swift, Services/FileImportService+Packages.swift, Services/ImportStaging.swift, Services/ImportScratchSpace.swift, Services/ImportFailure.swift, Services/ArchiveBudget.swift, Services/ArchiveExtraction.swift, Parsers/ArchiveEntryReader.swift, Parsers/DAISYParser.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/LibraryViewModel+Duplicates.swift, Parsers/AudioManifest.swift, Parsers/AudioManifestCheck.swift.
- Import progress (FR10): what the import overlay shows, and what VoiceOver hears of an import.
  - Owner: LibraryViewModel.importProgress, an ImportProgress (ViewModels/ImportProgress.swift) on the main actor, whose state is an ImportProgressState: a notice, the books done of the total, the book under way (its name, its number in a batch, its ImportStep, when it began, and, for an archive holding one audiobook, how far its extraction has got, BookUnderWay.extraction, which its line says while it extracts), what the books done took (timing, a WorkTiming), the sizes the batch's books are timed by (bookSizes), the time left, whether Cancel was pressed, and the imports waiting behind the one shown (waitingImports), which a new import's state keeps. The duplicates a batch skipped are counted once, in its ZipImportResult (skippedDuplicates). Whether the overlay shows at all is still the model's isImporting.
  - Who may write it: the imports, on the main queue. ArchiveExtractor reports an archive's extraction as an ArchiveExtractionProgress, its entries and the bytes they declare, both totals from the archive's central directory, which the budget reads anyway: at the start, and whenever the whole percentage of either changes, between the chunks of a large entry as well as between entries. A ZIP batch reports ZipImportProgress.extracting, then .importingBook as each book begins and as each step of it begins (through the importer's ImportStepObserver), and .importing(done:total:skippedDuplicate:) as each book is imported, fails, or is skipped as a duplicate; a batch also reports .foundBooks(sizes:) once, before its first book, each size from FileImportService.timedSize(of:): a text book's file size (an EPUB, PDF, Word document, rich text, Word 97-2003, OpenDocument, Word 2003 XML, web archive, SSML, or plain text, Markdown, or HTML file), and nil for an audiobook's file, whose import reads its chapters rather than its every byte, for a DAISY book, a DTBook on its own included, and for an RTFD, which is a folder. A single file, or an archive holding one book, reports through ImportProgress.observeBook(_:startingAt:then:), which tells the overlay of each step before the queue's test hook, and so do a TextMouth package opened from the Finder (openTMBPackage(from:), from .checkingPackage), New from Text (createBookFromText, from .preparingPackage, by its title), and a recording's save (LibraryViewModel.saveRecording, from .preparingPackage, by its title, REV13), whose line is cleared (clear()) rather than ended, so it announces nothing, since the New Recording window says how the save ended; an archive holding one audiobook reports its extraction through observeExtraction(). TimeLeftEstimate (Models/TimeLeftEstimate.swift, shared with the feed downloads' progress) gives the time left from the WorkTiming of the books imported or failed, duplicates not timed: each book still to come of known size takes its bytes at the rate the sized books took theirs, and any other the average time of the books timed without a size, or of every book timed before any of those, less the time it has run; TimeLeftEstimate.rounded(_:) rounds it to the minute under 10 minutes, to 5 minutes under an hour, and to 15 beyond. The library follows the import queue's count of imports queued or running (importActivityChanged(to:), which observeImportActivity() starts, and which assigns isImporting only when it changes, so the library model publishes as imports start and end and not with each import queued or done, REV13), and the progress counts those behind the one shown as waiting (noteImportsQueued(_:)). Cancel calls cancel(), and end(_:) ends the import shown.
  - How others observe it: only ProgressObserver, a generic view in Views/ContentView.swift, observes it, as it observes the text cache's progress (PERF12, #1461), drawing the overlay in a TimelineView that ticks every 5 seconds from the book's start, so the time on a book keeps up between reports while the library model is never republished. ProgressOverlay takes detail lines and a spoken summary from its caller; the text cache overlay keeps its own. ImportProgressWording words every line, the overlay's VoiceOver label, the announcements, and Speak Import Progress, the imports waiting included (waiting(_:), "2 more imports waiting", left out once Cancel is pressed, since queued ZIP archives never start). An import that has run 10 seconds (ImportProgress.announcedAfter) announces each quarter of a batch's books once, at medium priority, and its end, unless Cancel was pressed, when its alert says where it stopped; Cancel is announced at once. A batch that found no new book and in which nothing failed (ZipImportResult.foundNoNewBook) is not announced: LibraryViewModel.completeZIPImport raises the library's alert instead, which waits on screen and which VoiceOver reads, since an announcement made while TextMouth has no window in front is never spoken (October 13, 2026). The alert is titled ImportProgressWording.nothingImportedTitle ("Nothing Imported", set in LibraryViewModel.errorTitle, which goes back to nil, "Error", whenever showError turns false) and says nothingImported(from:result:): the duplicates sentence, noNewBooks(in:alreadyInLibrary:), or, for an archive with no book, noBooksFound(in:holding:), which names what it held by kind from ZipImportResult.nonBookFiles, a NonBookFiles that FileImportService.importCandidates counts by extension for every file it passes over, those in archives inside included. Every batch also ends with one ZIP_IMPORT_FINISHED event line in the debug log (ZipImportResult.logLine(archiveName:)). The reading list's join after an import made at the Reading List is announced at medium priority (addImportedBooksToReadingList(_:request:)), after the import's own words rather than over them. ShortcutAction.speakImportProgress, under Information with no default key, and Library > Speak Import Progress post speakImportProgress, which the library model hears from any window (observeImportProgressRequests()) and answers through VoiceOver.
  - Files: ViewModels/ImportProgress.swift, Models/ImportProgressWording.swift, Models/TimeLeftEstimate.swift, Services/ArchiveExtraction.swift, Services/FileImportService.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/LibraryViewModel.swift, Views/ContentView.swift, Models/CountWording.swift, Models/KeyboardShortcut.swift, App/MenuCommands.swift.
- Import questions.
  - Owner: LibraryViewModel.importDecisions, an ImportDecisionQueue of the questions imports are waiting to ask (whether to replace or keep a duplicate, whether to delete an original file, whether to put a ZIP archive's books in a new folder, and whether to transcribe an audiobook just imported), asked one at a time in the order they arose. Each ImportDecision holds everything its answer acts on, captured when its import finished (a duplicate's new copy and the copy it matched, an original file, a ZIP archive's books and folder, or an audiobook's ID, title, and length), and the ImportRequest its import was made with: the Library window it started in (ImportOrigin), whether to open the book afterwards, and the cancellation its batch shares.
  - Who may write it: LibraryViewModel+Import and LibraryViewModel+Duplicates. ask(_:) queues a question behind those waiting, and a question an answer raises about the same file, such as whether to delete the original of a duplicate just kept, is asked next. An offer to transcribe (ImportDecision.Kind.transcriptionOffer, FR05) is queued after an import's own questions, for each audiobook it added, when TranscriptionOffers.offersTranscription(of:) allows it: an audiobook in a package of its own, Offer to transcribe after importing an audiobook on, and a Mac that can transcribe. Its Transcribe sends LibraryViewModel.acceptedTranscriptionOffers to the Library window that asked (LibraryTranscriptionSupport), which opens the Transcribe Audio sheet, starting at once when it can. answerImportDecision(_:with:) acts only on the question being asked, named by its ID, so a second press can never answer the next one; an answer that fails, such as a folder name the library refuses, keeps the question open with the reason. While the data directory moves (dataDirectoryMove is set), it refuses every answer with DataDirectoryMoveWording.importAnswerRefusal, shown in the sheet and spoken, and the question stays until the move ends, since a window asking one when a move begins keeps that sheet instead of the move's. cancelImports(), the progress overlay's Cancel, withdraws the questions of its batch, those waiting and those raised later: a duplicate's new copy is discarded, an original file is kept, a ZIP archive's books stay where they are, and an offer to transcribe is dropped.
  - How others observe it: each Library window's ImportDecisionPresenter watches the queue, and exactly one window asks the question at its front (ImportDecisionQueue.askingWindow): the window its import started in while that is open, or else the first open Library window, the question waiting while none is open. That window shows ImportDecisionSheet, whose words, the screen's and VoiceOver's alike, come from ImportDecisionWording, with a title that gives the question's place when there is more than one, as in "Duplicate Book Found, 2 of 5". The choice that removes nothing comes first; Return and Escape press the marked choices, and Replace Existing and deleting an original file are never on a key. A duplicate's question says what Replace Existing keeps (ST04): ImportDecisionWording.duplicateMessage adds, after the choice, replacingKeepsSentence(existing:new:), which chooses from both copies' kinds and never promises what DuplicateReplacement.carriedBook drops: replacingKeepsTextSentence or replacingKeepsAudioSentence for two copies of one kind, and replacingAcrossKindsSentence when one is an audiobook (BookFormat.isAudio) and the other is not, which says "played from its recording" and "read aloud from its text" rather than "not an audiobook", so that it is true of a DAISY book too. Then replacedCopySentence(movesToTrash:) follows the Trash setting (RemovalPreferences.movesToTrash): with the Trash on it says that the files go to the Trash but putting them back won't return that copy to the library, since the package's record names the book the new copy now is, which no launch adopts a second time (adoptOrphanedTMBPackages); with it off it is RemovalMode.deletePermanently's files clause. The choice's hint is ImportDecisionChoiceWording.replaceExisting(acrossKinds:), which across kinds promises only the folder and the place on the reading list. The words say what Replace Existing does (replacing a duplicate, below). A question that appears while the user is in another window waits without taking focus or being announced. A book whose import asked to open it, as one opened from Finder does, opens through LibraryViewModel.readerOpener once it is in the library and its questions are answered.
  - Files: Models/ImportDecision.swift, Models/ImportDecisionQueue.swift, ViewModels/TranscriptionOffers.swift, ViewModels/LibraryViewModel+Duplicates.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/DataDirectoryMoveProgress.swift, Views/Library/ImportDecisionPresenter.swift, Views/Library/ImportDecisionSheet.swift, Views/ContentView.swift.
- Replacing a duplicate (ST04): what Replace Existing does with the two copies of a duplicate's question. The new copy, which its import has already published in a package of its own, takes the place in the library of the copy the library holds, as that same book.
  - Owner: the library's row of the replaced copy, which the new copy takes over under the same ID. DuplicateReplacement (Services/DuplicateReplacement.swift) decides what the new copy keeps (carriedBook(replacing:with:places:location:)): the ID, so that what the app keeps by ID stays, such as the place on the reading list; the folder, the place in the folder's manual order, the date added, and when it was last opened and played; the metadata the user edited by hand (Book.HandEdits, keepHandEditedMetadata(of:)); and, for two books of one kind (areSameKind: both audiobooks, or both read from their text, a DAISY book among them, since BookFormat.isAudio tells them apart), the book's own settings (Book.hasOwnSettings, takeOwnSettings(of:): voice, speed, pitch, what happens at its end, and the units of its skips) and its places (carriedPlaces). A text book's places are moved from the old text to the new one by the words they were saved by where the two texts differ (PlaceRelocator.relocate(_:from:to:movedAt:)), but only from an old text that is the text they were saved in, the content.md TextMouth last wrote or took, whose digest the record keeps (holdsTextOfPlaces, as Edit Text moves places only then); from a save no edit took, or when the old text cannot be read, they are found in the new text by their words alone (PlaceRelocator.relocate(_:within:movedAt:)), and a place nothing finds stays as it was saved; PLACES_RELOCATED is logged when any moved. An audiobook's places count time in its recording (P08) and follow the new chapter list (movedAudioPlaces(_:from:to:at:)): the same list leaves them; a book of tracks, one track to a chapter with every old track among the new copy's, moves each place to its track at the same time into it, a skipped heading with it (TrackPlaces.moved); any other list moves each place through time on the recording (PlaceClock) to the new chapter that holds the time where its old chapter starts plus its offset's time, never held to that chapter's end, and its skipped headings wait, naming no heading, since another chapter list does not keep them. A copy of the other kind keeps only the ID, the place in the library, and the hand-edited metadata, since a text's places and speed mean nothing to a recording. Everything else is the new copy's: its file and text, what reading them measured, its title and author where the user edited neither, and where it came from. The new copy's package record keeps the import's own ID until the library commits the new row, so a stop before then never leaves two records naming one book.
  - Who may write it: LibraryViewModel.replaceExisting(with:of:), which answerImportDecision(_:with:) reaches for Replace Existing, on the main actor, in this order. It finds the library's copy that matches now (duplicateMatch(for:)), which an earlier answer may have changed since the question arose, and adds the new copy as Keep Both does (keep(_:of:)) when none matches. It refuses (replacementRefusal(of:), a DuplicateReplacement.Refusal) while another operation holds the library's storage work (StorageBoundary.shared.heldFor: .storageBusy, as a folder edit does while it moves packages off the main thread, when the replacement would carry nothing from a package moved meanwhile and write its record into the old package's new place); while the copy is open in a reader, being transcribed, or being exported, the uses a deletion of a feed's download refuses (.inUse, FeedBookUse.refusal(of:doing:retry:), whose clause names the action); while its audio is edited in the audio editor or saved from it (.audioBeingEdited, AudioEditActivity.isBeingEdited); and when the old package or a file carried over is only in the cloud (.filesInCloud), which a replacement never downloads. It flushes the analyses of the old copy that wait in the buffer (analysisSummaries.flush()); one still on its way names the old package, which the new row's is not, so it never lands on the new row (applyAnalysisSummaries). DuplicateReplacement.prepare(replacing:with:) then reads everything carried over before it writes anything, and writes it into the new copy's package, which it moves into the old copy's folder: the copies Edit Text kept (TextMouthPaths.isKeptTextCopy); the old text, kept beside the new text as content.md.edited- (BookTextEditSessions.keepCopy(of:bytes:)) when the two differ and it holds text TextMouth did not write, an edit on record (Book.editedText) or a content.md whose digest is not the one written, or, for an audiobook, a save its transcript's layer does not account for or the text of an edited transcript that stays behind, with TextNotKept thrown when no copy can be made; the transcript, with the one kept before its cleanup; and the places. The transcript is kept only when the new copy's audio is proven to be the audio transcribed (fitted(_:to:index:sourceMatches:access:)), and nothing is hashed, since this runs on the main thread: a book of one file whose content hash (Book.md5Hash) is the digest the transcript recorded for its file, whatever its name (the transcript's file is then renamed to the new copy's); the same source imported again (the two copies' content hashes equal, an archive's own or a folder's), with every file the transcript names at the same path and of the same size, since extracting an archive gives every file a new date; or each file the same by path, size, and date (TranscriptTextLoader.audioCheck with no hasher). A file only in the cloud proves nothing, and a transcript of a later layout goes into the new package as it is. A failure while writing undoes what was written (Preparation.undo()), putting the package back as the import published it. commitReplacement(of:by:) then commits the new copy, each step on disk before the next: whatever waits to be written for the old copy goes into its own package (LibraryPersistenceService.writePendingBookInfoNow(bookID:)), then the new row's record under the kept ID (saveBookInfoThrowing()), then the library's index naming it (LibraryPersistenceService.saveAndWait(_:)); a failure of the last throws IndexNotSaved, and the caller undoes the preparation and writes the new copy's record under the import's own ID again. Only then does the library hold the new row, at the old row's place; the old row's queued writes are forgotten (LibraryPersistenceService.forgetDeletedBook) with the reading text this Mac kept for it (ReadingTextCache); the old copy's Edit Text session ends saying so (endEditingSessions(of:): BookTextEditor.endBecauseBookWasReplaced(_:title:), BookTextEditWording.stoppedBookReplaced) and its Edit Manifest session ends quietly; the transcript is noted (TranscribedBooks); and DUPLICATE_REPLACED is logged. removeReplacedPackage(of:) then removes the old package (DuplicateReplacement.removeReplacedPackage(of:movesToTrash:)): to the Trash in one move under its own name, or, with the Trash off, renamed first to a staged package's hidden name in its own folder (ImportStaging.freshName()) and deleted with everything in it (ImportStaging.removeStagedPackage(at:), which gives back the write permission a read-only item took away), since a deletion can stop partway and a half-deleted package under its own name would be a broken book; what cannot be deleted stays hidden, and the next import into that folder removes it (ImportStaging.removeAbandoned(in:)). The replacement stands whatever happens then: a package that cannot be removed stays in its folder, and the library's alert says so (DuplicateReplacement.oldCopyLeftMessage). When the old text was kept, VoiceOver says where, after the answer's own words (DuplicateReplacement.keptTextAnnouncement(title:copy:)). The new row then finishes as a kept book does (finishKeeping(_:from:of:offeringTranscription:)): a book already on the reading list keeps its place there, and an audiobook is offered for transcription only when its transcript was not kept. A refusal, or a failure before the commit ("Could not replace duplicate" and the reason, or TextNotKept's or IndexNotSaved's sentence), is an OperationOutcome.failure: the question stays open and the library's copy is as it was.
  - How others observe it: the question's sheet shows a refusal or failure above its buttons (OperationFailureNotice, which VoiceOver reads as "Error: " and the sentence, and announces once). ReadingList.replace(_:with:) is no longer called by the app, since the new row keeps the old row's ID and so its place on the list. The old package's record names a listed book, so the launch's repair that adopts packages missing from the index (FileImportService.adoptOrphanedTMBPackages(library:libraryDirectory:access:skips:)) leaves it as it is, unadopted and unwritten, with one ORPHAN_ID_LISTED line, whether Finder put it back from the Trash, a stop left it beside its replacement, or a failed removal kept it: no two rows share an ID, no index recovery rewrites a record, and in a cloud library whose library.json arrives after its packages no new ID is written over the index's. Of two such packages that no row listed before the walk, as an index rebuilt from the packages finds an old copy put back beside its replacement, the one whose record was written later becomes the book, whichever the folder lists first: the replacement, whose record Replace Existing wrote after the old copy's last one. Folder-path fixes wait for the walk's end, so the other package is never written.

- A file with no text to read: FileImportError.noTextToRead ("This file has no text to read.") is thrown by FileImportService.readableContent(of:run:refusingBlankText:) when refusingBlankText is set, the book's format is one of plainTextFormats (txt, markdown, and html), and no chapter of the generated content holds a character that is not white space, so the .readingText step fails and no silent, empty book is published. Only importFileWithReport sets it, through publishReadableBook(_:from:run:feedLink:replacing:refusingBlankText:publish:), so Open Book, Finder, and the members of a ZIP (importSupportedFiles imports each through importFileWithReport) are refused, while New from Text, a feed's download, and every rebuild of an existing book's text are not. A Markdown file that is only a heading still imports. ImportFuzzTests.knownIssues, which held the empty Markdown file the first sweep found, is empty.
- A full disk: ImportFailure.isOutOfSpace(_:) says a volume is full when an error, or one it wraps under NSUnderlyingErrorKey at any depth, is Cocoa's NSFileWriteOutOfSpaceError or POSIX ENOSPC, and ImportFailure.outOfSpaceDescription ("There isn’t enough free space on the disk.") is then the failed step's reason in place of the system's own sentence, which names the hidden staged package (.import- followed by an ID and .tmb). reason and reason(for:) both word an error this way, so an alert, a ZIP batch's list of failures, the IMPORT_FAILED line, and a feed download's failure (FeedDownloadError.importFailed) say it alike.
- A manifest's title and author (FR17): publishTracks and AudioBookParser take them through AudioManifest.bookTitle and bookAuthor, which read one that is empty or only whitespace as none, so the name of the ZIP or folder, or Unknown, stands as for a missing one; the manifest's stored title and author keep every byte.
- Audio the import converts (B06, FMT09): FileImportService.publishReadableBook converts a staged book's audio first (convertImportedAudio(of:in:keepingOriginals:run:), in FileImportService+AudioConversion.swift; step .convertingImportedAudio(done:of:)), before anything reads it as a book, so a ZIP of tracks, a folder, a single file, a playlist, and a feed's episode are converted in one place, each converted file renamed in the manifest through BookManifestFile.change. ImportAudioConverter.tracksNeedingConversion(in:) (a folder) and needsConversion(among:) (files) choose the tracks, by what each holds: verdict(for:) takes the extension (convertedExtensions: oggExtensions and coreAudioExtensions) and then AudioContentSniffer.kind(of:), which reads a file's first 64 KB by hand with no Apple audio API. Ogg, AC-3 and E-AC-3, CAF, AIFC, AU, Wave64, AMR, 3GPP audio, and MPEG layers I and II convert; WAVE (RIFF, RF64, BW64), AIFF, FLAC, MP3, and ADTS AAC are left; MPEG-4, QuickTime, and anything unrecognized go to afinfo, whose codec decides (playsAsIs(formatID:fileType:): AAC, Apple Lossless, and MP3 in them stay). So an Ogg file named .m4a, or an MP2 feed episode named .mp3, is converted.
- ImportAudioConverter reads a source's facts from OggHeaderReader for Ogg (Vorbis, Opus, or FLAC), and from AudioFileInfo for the rest: afinfo -x -r, run by WatchedProcess.runCapturingOutput, gives the container, codec, channels, sample rate, bit depth, length, and whether it names a channel layout. No Apple audio API opens the source in TextMouth's process. plan(for:info:) is leaveAsItIs, convertToAAC, or convertToAppleLossless when the codec keeps every bit (SourceInfo.isLossless: lpcm, alac, flac). target(for:bytes:) gives AAC the source's average bit rate (bytes × 8 ÷ duration) rounded up to the next standard rate (bitRate(averaging:channels:accepted:), 64 to 192 kbit/s for stereo, half for mono) at its own sample rate where AAC takes it (sampleRate(for:)), and Apple Lossless the smallest of 16, 20, 24, or 32 bits that holds the source's samples (24 when the depth is unknown or the samples are floating-point). afconvertArguments(from:to:info:target:) never passes -c, since afconvert refuses it for AAC above stereo. AudioMediaProbe, AudioEditBase.load, and the transcriber refuse every format the import converts by ImportAudioConverter.isNeverDecodedInApp(_:), a converted extension other than TextMouth's own CAF or a file that begins with OggS (AudioContentSniffer.isOgg(at:)); AudioPlaybackService.metadataAsset(for:) asks isConvertedAtImport, by extension alone, since an import reads a source before it converts it. Only its pass for UEB's emphasis terminators changes words, where liblouis misread them, so a book's text can change with the better reading, by its emphasis or, in contracted UEB, by a word. No cache version was raised: a braille book imported before keeps its content.md until something rebuilds it, which braille's page reader line does once at the next launch (V07, in [Text caches](text-caches.md)); PG16's compare then keeps a copy of the old text of a book whose new reading differs, even by emphasis alone, and its saved places move with the text. A book with no blocks or no print text throws FileImportError.noTextToRead.

With includesPages, which only MarkdownCacheService asks for (it is false otherwise, so the direct parse reads the text alone), each braille page of a file that marks its pages is a page marker (BrailleBookReader+Pages.swift, PG12). marksItsPages(_:_:) says which files do: a PEF by its page elements, a BRF by the form feeds between its braille text, or, in a BRF with none, braille page numbers that end more than half of its 25-row pieces, which shows the cut matches its layout, since the pieces are otherwise no pages an embosser counts and naming them would invent pages; a BRL has none. pageStarts(of:) leaves out a page with neither text nor a braille page number, such as the blank back of a two-sided page or the empty page a form feed leaves at a file's start or end, and labels the others by braillePageLabel or, without one, by their place among the pages kept, so a book without numbers reads 1 to N. PagedTranslation puts the markers between block lines, never inside one, writing the markers that share a place at once and looking each page's cut up, so many pages cost linear time: a page that begins a block, or begins inside a heading, is a marker of its own before it, and one that begins inside a paragraph splits the paragraph's Markdown into lines there, each its own literal with its own emphasis, the marker after the words of the line before, so the lines read as one paragraph. Every block is still translated whole, so pages change no word; each paragraph a page begins inside is also sent in pieces cut at those pages' first cells, in the same run of the helper, and places(ofCutsIn:pieces:) finds each page in the whole paragraph's print, from the start and then from the end, or else places it at the last place found before it, never after its first word, as when an indicator's passage goes on over the page and only the piece that holds the indicator reads it; nothing is logged then. A BRL has no pages, and its book is read again with the other braille books when braille gains its page reader (PageReaderVersions, in [Text caches](text-caches.md)).

    - The protocol: TextMouthBraille/include/TextMouthBrailleProtocol.h defines it once. The helper's main.c includes it, and the app imports it as the Clang module TextMouthBrailleProtocol (TextMouthBraille/include/module.modulemap, found through SWIFT_INCLUDE_PATHS), in BrailleEmphasis.swift alone, so the two cannot disagree about its version, its emphasis flags, or how they are written. Protocol 2 (October 21, 2026): each input and output file is UTF-8 and begins with TMB_PROTOCOL_HEADER, "TextMouthBraille 2", on a line of its own; then comes a record for each paragraph, in the same order in both files, of two lines, the paragraph's text and its emphasis codes, one printable ASCII byte for each Unicode scalar ("@" for none, "A" for italic, "B" for bold, "C" for both, up to "_" for every flag: BrailleEmphasis.code), or an empty line when no scalar has any. The helper refuses an input without the header (exit status 7), and the app an output without it, so a helper and an app built from different sources fail by name, never by misreading. Protocol 1 was one line for each paragraph, with no header and no emphasis.
    - Outcomes: exit 0 is success, and exit 2 is Failure.unknownTable. Any other status (7 is an input without the protocol's header), a failure to start, a missing helper, or output whose records do not match is Failure.failed, logged as BRAILLE_HELPER_FAILED; a kill is Failure.stopped, logged as BRAILLE_HELPER_KILLED with the mode, the table, and the reason. Both are import events, and neither holds any book text. Failure.uncheckedTable is a Mac table whose check could not be made, not kept, so the next use checks again, and Failure.changedTable is above; each has its sentence in errorDescription. A check that refuses a table logs BRAILLE_MAC_TABLE_REFUSED, an import event beside those, with the stored value and the reason.
    - The helper has three modes: `check` compiles a table with every table it includes (the tests and MacBrailleTableCheck call BrailleTranslator.check), and `forward` (print to braille) and `back` (braille to print) translate a file of records, one for each paragraph (the protocol, above), into a file of records of the same kind, in Unicode braille patterns, with a blank cell and never a space between words. forward reads each print paragraph's emphasis codes and writes braille whose cells hold the table's emphasis indicators, with an empty code line; back reads braille with an empty code line and writes the print with the codes of the emphasis read from its cells (read_braille, below). Both carry only the classes that read back exactly with the table (italic, bold, underline, script, and trans1 to trans5 as one flag), which the helper measures on each run, never by the table's name (check_readable: a sample of plain words is translated forward with each class the table has on marked stretches, then back by liblouis alone, and the class passes when the words come back exactly and the class lies on exactly the marked letters). UEB's pass, and so does liblouis's own EBAE underline, which is written and read as liblouis has it; EBAE's italic and bold, which liblouis misreads, and the classes of most of this Mac's tables do not, so those write plain braille, and an EBAE export is byte for byte what it was before the reading passes. back reports the readable classes and the classes the EBAE pass reads (flags_for_typeform), so an EBAE book read in TextMouth has the italic and bold the pass found, while an export writes none. It changes into the tables folder it is given, the bundle's or, for a "mac:" table, the Mac's own (a run reads one folder, never both, so a Mac table's includes come from the Mac's own liblouis), sets LOUIS_TABLEPATH to ".", loads the table by its bare name, and then changes into /var/empty, so a comma in the app's path is harmless and no table elsewhere on the Mac is read. Back mode passes a typeform buffer, or liblouis writes UEB's italic indicator as an escape such as "\46/", which a listener would hear, and the buffer is where it returns the emphasis it read. A translation counts only when at least 16 cells of room are left over, else it is retried with more room, since liblouis reports success when its output fills on an escape.
    - The reading passes (October 24, 2026): read_braille reads a record's braille through the pass of the code the table writes its emphasis in (uses_code, found by translating a probe as the writing side finds it, never by the table's name), and through liblouis alone for any other table. Braille with no sign of the code reads byte for byte as liblouis alone reads it. A pass gives each character the emphasis of the cell it came from (give_cells_emphasis, by liblouis's input and output positions, then read_kept_cells, the end the two passes share); where one rule read cells of different emphasis together, split_rule translates the cells of the word up to the change again and gives the rule's characters after the place the emphasis ends the emphasis after it, so "can" in "can't", which contracted EBAE reads as one rule from ⠉⠄⠞, is italic and "'t" is not.
      - read_ebae reads EBAE's italic and bold only where the sign is certain, and every word it reads is liblouis's own. liblouis 3.39.0 reads EBAE's ⠨ before a word as a period before a to j (".cat"), as "=" before k, and as "µ" before m, drops it silently before the other letters, which loses the emphasis, drops bold's ⠸⠨ with its emphasis, writes ">" for the sign it writes again after a passage, and lets a passage run to the end of the paragraph. Its own EBAE writes a period before a word, "=", ">", and "µ" with those same cells, so the braille cannot tell them from a sign. strip_ebae_signs finds the signs as BANA writes them (the NLS Instruction Manual for Braille Transcribing, lesson 15): ⠨ before a word, ⠨⠨ before a passage with ⠨ before its last word, bold's ⠸⠨ and ⠸⠨⠨, the signs after opening punctuation, a dash, a slash, or a joined "to", "into", or "by", the termination sign ⠠⠄, and liblouis's own end signs. may_strip leaves a sign out only where liblouis drops it anyway (find_strippable_signs: liblouis reads the sign and the cell after it, standing alone, exactly as it reads that cell alone), so the words stay those liblouis read before the pass and only emphasis is added: a sign before a to j, k, or m is left, and is the period, the "=", or the "µ" it always was, though a passage's last sign there still ends the passage. BANA's EBAE has no sign for bold italic, and liblouis's, bold's sign before italic's, is not read: more ⠨ after a word's sign than a passage's is left to liblouis. A bold passage is counted in print's words (print_words_in), since contracted EBAE joins "to", "into", and "by" to the word after them, and "and", "for", "of", "the", "with", and "a" to one another. It leaves to liblouis a ⠨ inside a number (the decimal point) or a contraction, ⠨⠅ or ⠨⠂ standing alone (liblouis's "=" and ">"; but in contracted EBAE ⠨⠅ ends an open italic passage as its last word, "knowledge"), and computer braille between ⠸⠬ and ⠸⠱ (a web or mail address, whose ⠨ is a period). It runs only for a table that reads ⠨ alone as punctuation (reads_cell_as_punctuation, in detect_codes): the Bharati tables, which also write italic as ⠨ before a word but read it as a letter, are read as before.
      - The safety net (keep_liblouis_words): leaving a sign out can still change how liblouis reads the cells around it, as "(" ⠶ and "be" ⠆ read together as "}" once the sign between them was gone ("(before" came back "}from"). A record the pass left a cell out of is therefore also read by liblouis alone, and wherever the two readings differ in any character, liblouis's is the record's, with only its own emphasis: the words are liblouis's by construction, and a paragraph where the net fires has no emphasis from the pass. Double capitals are found anywhere in a word, and the termination sign is kept for liblouis, which reads it as nothing and keeps a word's parts apart.
      - read_ueb: liblouis reads UEB's indicators and their emphasis, but reads the cells just before a terminator (an indicator's prefix and ⠄, as ⠨⠄ for italic, after a cell that is not blank) as if they could not end a word, so a whole-word contraction there came back as the letter or sign its cell also is: "people" (⠏) as "p", "Knowledge" as "K", "can" as "c", "his" (⠦) as a double quotation mark, "were" as a prime, and "enough" as "en" (review E1, October 21, 2026). Braille that holds a terminator is read twice: as it is, for the emphasis liblouis reads, and without its terminators, for the words, each cell taking the emphasis of the first character of its rule in the first reading and each character of the second reading the emphasis of its cell (give_cells_emphasis), split where the emphasis ends inside one rule ("people's" is one). The indicators that begin emphasis stay for the second reading, which takes them as indicators as the first did.
      - Measured with random sentences read back from the braille liblouis wrote: contracted UEB changed words in 25 of 549 emphasized sentences before its pass and in none after it. The EBAE pass gave liblouis's own words in every one of 153,000 seeded sentences, 60,000 plain sentences, and 360,000 random paragraphs, run under memory and undefined-behaviour checkers, and read italic and bold in 79 percent (uncontracted) and 81 percent (contracted) of its seeded BANA-style sentences, where liblouis alone reads none; the net fired in 13 of 9,000.
      - Limits: an emphasized word that starts with a to j, k, or m keeps liblouis's period, "=", or "µ" and loses its emphasis; liblouis writes a period before a word as ⠨ wherever the word begins and reads it back as nothing before a capital or a letter past j, as it reads a sign there, so such a period is read as a sign (".NET" is italic "NET", the words being liblouis's, which lose the period too); liblouis's own readings of EBAE that are no emphasis sign are kept with their faults, such as "3.e" for 3.5; and a passage that crosses the 4,000-scalar cut still comes back plain after it (above).
