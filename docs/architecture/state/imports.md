## An import in progress
<!-- id: import-in-progress; keys: ; src: TextMouth/Services/FileImportService.swift, TextMouth/Services/FileImportService+Packages.swift, TextMouth/Services/ImportStaging.swift, TextMouth/Services/ImportScratchSpace.swift, TextMouth/Services/ImportFailure.swift, TextMouth/Services/ArchiveBudget.swift, TextMouth/Services/ArchiveExtraction.swift, TextMouth/Parsers/ArchiveEntryReader.swift, TextMouth/Parsers/DAISYParser.swift, TextMouth/ViewModels/LibraryViewModel+Import.swift, TextMouth/ViewModels/LibraryViewModel+Duplicates.swift, TextMouth/Parsers/AudioManifest.swift, TextMouth/Parsers/AudioManifestCheck.swift, Scripts/test/kf8-fuzz/Stubs.swift, TextMouth/ViewModels/LibraryViewModel.swift, TextMouth/Models/Book.swift, TextMouth/Services/StorageGeneration.swift, TextMouth/Services/ImportAudioConverter.swift -->

An import in progress.

- Owner: LibraryViewModel's SerialImportQueue, which runs one import at a time off the main thread, each as storage work that a data-directory move waits for or holds back (StorageBoundary.perform), and reports activity on the main queue, and ImportCancellation, which the queued imports share and the progress overlay's Cancel button sets.
- Who may write it: FileImportService does the work.
  Open Book offers the types it reads (FileImportService.supportedTypes), video among them, since an audiobook may be an MPEG-4, M4V, or QuickTime file whose sound alone plays (BookFormat.audio's mp4, m4v, and mov; public.mpeg-4, com.apple.m4v-video, and com.apple.quicktime-movie), so a video episode's package imports again too, as does the audio the import converts (BookFormat.audio's ogg, oga, and opus, with org.xiph.ogg-audio, also declared in Info.plist, and ImportAudioConverter.coreAudioExtensions, which the list ends with, each offered by its system type where it has one) and an M3U playlist (public.m3u-playlist); ArchiveEntryLimits.audioExtensions is the same list; a feed still tells a video enclosure from audio for itself (FeedMediaKind, whose audioExtensions leave video's out).
  It identifies the source, builds the package under a hidden staging name (ImportStaging, .import- followed by a UUID and .tmb), in this Mac's Import Staging folder while the data directory is on its volume and beside the package's destination otherwise (ImportScratchSpace), copies the content, reads the book as the reader will, writes bookInfo.json and reads it back, and only then publishes the package with one rename.
  A TextMouth package is staged as every import is (REV13): ImportStaging.makeEmpty makes the staged package, then the .copying step copies the source package's items into it (copyContents(of:)), so the import overlay names the copy, and a package whose own folder is read-only imports, since the staged folder is TextMouth's own.
  A failure removes whatever was staged and throws an ImportFailure naming the file and the step, and the original file is never touched after a failure.
  A ZIP is inspected and extracted within an ArchiveBudget into an Archive Extraction folder on the same condition, this Mac's or the data directory's (ArchiveExtraction), and every format reader takes entries out of archives through ArchiveEntryReader, which holds each entry to its limits.
  A reader that looks up more than a member or two, as the EPUB, Word, and DAISY readers do, finds them in an IndexedArchive, the archive's entries read into an index by path once, since ZIPFoundation finds each by reading the archive's central directory from its start; the index answers exactly as the archive would, the first entry at a path winning.
  IndexedArchive.file(at:) finds the entry at exactly a path, else the first file entry whose path matches it without regard to case (ST09; Archive.file(at:) is the same rule for an archive not indexed), which the EPUB reader's lookups and the DAISY reader's use, since a badly made book may name a member in another case than its ZIP spells it; the exact spelling always wins.
  DAISY audio conversion copies each audio file through DAISYFileProvider.copyFile(at:to:): out of a ZIP a megabyte at a time (ArchiveEntryReader.stream), never whole, and from a folder as a clone.
  A ZIP batch reads each book's checksum once, for its duplicate check, and hands it to the book's import (importFileWithReport(from:checksum:toFolder:observer:)).
- How others observe it: LibraryViewModel adds the published book to the library, unless the library already holds a copy, and the overlay shows how far the import has got (import progress, below); every question an import raises waits its turn in one queue (import questions, below).
- The manifest's check (FR15): an archive whose manifest.json is found (AudioManifestLocation.find(in:)) is checked in a step of its own, Reading its manifest (ImportStep.readingManifest), after extraction and before the book is read.
  AudioManifestCheck.checkedManifest(at:audioFolder:) stops at the first problem, in the order a person fixes them, with an AudioManifestProblem whose sentence begins "manifest.json".
  Only the import checks; every later read is lenient (AudioManifest.read(inAudioFolder:)).
- Files: Services/FileImportService.swift, Services/FileImportService+Packages.swift, Services/ImportStaging.swift, Services/ImportScratchSpace.swift, Services/ImportFailure.swift, Services/ArchiveBudget.swift, Services/ArchiveExtraction.swift, Parsers/ArchiveEntryReader.swift, Parsers/DAISYParser.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/LibraryViewModel+Duplicates.swift, Parsers/AudioManifest.swift, Parsers/AudioManifestCheck.swift.

## Import progress
<!-- id: imports-import-progress; keys: ; src: TextMouth/ViewModels/ImportProgress.swift, TextMouth/Models/ImportProgressWording.swift, TextMouth/Models/TimeLeftEstimate.swift, TextMouth/Services/ArchiveExtraction.swift, TextMouth/Services/FileImportService.swift, TextMouth/ViewModels/LibraryViewModel+Import.swift, TextMouth/ViewModels/LibraryViewModel.swift, TextMouth/Views/ContentView.swift, TextMouth/Models/CountWording.swift, TextMouth/Models/KeyboardShortcut.swift, TextMouth/App/MenuCommands.swift, TextMouth/Services/ImportFailure.swift, Scripts/test/kf8-fuzz/Stubs.swift -->

Import progress (FR10): what the import overlay shows, and what VoiceOver hears of an import.

- Owner: LibraryViewModel.importProgress, an ImportProgress (ViewModels/ImportProgress.swift) on the main actor, whose state is an ImportProgressState: a notice, the books done of the total, the book under way (its name, its number in a batch, its ImportStep, when it began, and, for an archive holding one audiobook, how far its extraction has got, BookUnderWay.extraction, which its line says while it extracts), what the books done took (timing, a WorkTiming), the sizes the batch's books are timed by (bookSizes), the time left, whether Cancel was pressed, and the imports waiting behind the one shown (waitingImports), which a new import's state keeps.
  The duplicates a batch skipped are counted once, in its ZipImportResult (skippedDuplicates).
  Whether the overlay shows at all is still the model's isImporting.
- Who may write it: the imports, on the main queue.
  ArchiveExtractor reports an archive's extraction as an ArchiveExtractionProgress, its entries and the bytes they declare, both totals from the archive's central directory, which the budget reads anyway: at the start, and whenever the whole percentage of either changes, between the chunks of a large entry as well as between entries.
  A ZIP batch reports ZipImportProgress.extracting, then .importingBook as each book begins and as each step of it begins (through the importer's ImportStepObserver), and .importing(done:total:skippedDuplicate:) as each book is imported, fails, or is skipped as a duplicate; a batch also reports .foundBooks(sizes:) once, before its first book, each size from FileImportService.timedSize(of:): a text book's file size (an EPUB, PDF, Word document, rich text, Word 97-2003, OpenDocument, Word 2003 XML, web archive, SSML, or plain text, Markdown, or HTML file), and nil for an audiobook's file, whose import reads its chapters rather than its every byte, for a DAISY book, a DTBook on its own included, and for an RTFD, which is a folder.
  A single file, or an archive holding one book, reports through ImportProgress.observeBook(_:startingAt:then:), which tells the overlay of each step before the queue's test hook, and so do a TextMouth package opened from the Finder (openTMBPackage(from:), from .checkingPackage), New from Text (createBookFromText, from .preparingPackage, by its title), and a recording's save (LibraryViewModel.saveRecording, from .preparingPackage, by its title, REV13), whose line is cleared (clear()) rather than ended, so it announces nothing, since the New Recording window says how the save ended; an archive holding one audiobook reports its extraction through observeExtraction().
  TimeLeftEstimate (Models/TimeLeftEstimate.swift, shared with the feed downloads' progress) gives the time left from the WorkTiming of the books imported or failed, duplicates not timed: each book still to come of known size takes its bytes at the rate the sized books took theirs, and any other the average time of the books timed without a size, or of every book timed before any of those, less the time it has run; TimeLeftEstimate.rounded(_:) rounds it to the minute under 10 minutes, to 5 minutes under an hour, and to 15 beyond.
  The library follows the import queue's count of imports queued or running (importActivityChanged(to:), which observeImportActivity() starts, and which assigns isImporting only when it changes, so the library model publishes as imports start and end and not with each import queued or done, REV13), and the progress counts those behind the one shown as waiting (noteImportsQueued(_:)).
  Cancel calls cancel(), and end(_:) ends the import shown.
- How others observe it: only ProgressObserver, a generic view in Views/ContentView.swift, observes it, as it observes the text cache's progress (PERF12, #1461), drawing the overlay in a TimelineView that ticks every 5 seconds from the book's start, so the time on a book keeps up between reports while the library model is never republished.
  ProgressOverlay takes detail lines and a spoken summary from its caller; the text cache overlay keeps its own.
  ImportProgressWording words every line, the overlay's VoiceOver label, the announcements, and Speak Import Progress, the imports waiting included (waiting(_:), "2 more imports waiting", left out once Cancel is pressed, since queued ZIP archives never start).
  An import that has run 10 seconds (ImportProgress.announcedAfter) announces each quarter of a batch's books once, at medium priority, and its end, unless Cancel was pressed, when its alert says where it stopped; Cancel is announced at once.
  A batch that found no new book and in which nothing failed (ZipImportResult.foundNoNewBook) is not announced: LibraryViewModel.completeZIPImport raises the library's alert instead, which waits on screen and which VoiceOver reads, since an announcement made while TextMouth has no window in front is never spoken (October 13, 2026).
  The alert is titled ImportProgressWording.nothingImportedTitle ("Nothing Imported", set in LibraryViewModel.errorTitle, which goes back to nil, "Error", whenever showError turns false) and says nothingImported(from:result:): the duplicates sentence, noNewBooks(in:alreadyInLibrary:), or, for an archive with no book, noBooksFound(in:holding:), which names what it held by kind from ZipImportResult.nonBookFiles, a NonBookFiles that FileImportService.importCandidates counts by extension for every file it passes over, those in archives inside included.
  A batch with failures or an incomplete book raises the alert under ImportProgressWording.zipAlertTitle(for:addedBooks:), set through presentImportMessage(_:title:), where addedBooks counts the books the library took (completeZIPImport's acceptedBooks, not result.books): nothingImportedTitle when the batch found no book, alreadyInLibraryTitle ("Already in Library") when it found books and the library took none, someFilesNotImportedTitle ("Some Files Not Imported") when books came in but a file failed or the batch was cancelled, and otherwise bookImportedTitle or, for more than one book, booksImportedTitle ("Books Imported"), so that title never reads "Error" over books that came in.
  Every batch also ends with one ZIP_IMPORT_FINISHED event line in the debug log (ZipImportResult.logLine(archiveName:)).
  The reading list's join after an import made at the Reading List is announced at medium priority (addImportedBooksToReadingList(_:request:)), after the import's own words rather than over them.
  ShortcutAction.speakImportProgress, under Information with no default key, and Library > Speak Import Progress post speakImportProgress, which the library model hears from any window (observeImportProgressRequests()) and answers through VoiceOver.
- Files: ViewModels/ImportProgress.swift, Models/ImportProgressWording.swift, Models/TimeLeftEstimate.swift, Services/ArchiveExtraction.swift, Services/FileImportService.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/LibraryViewModel.swift, Views/ContentView.swift, Models/CountWording.swift, Models/KeyboardShortcut.swift, App/MenuCommands.swift.

## Import questions
<!-- id: import-questions; keys: ; src: TextMouth/Models/ImportDecision.swift, TextMouth/Models/ImportDecisionQueue.swift, TextMouth/ViewModels/TranscriptionOffers.swift, TextMouth/ViewModels/LibraryViewModel+Duplicates.swift, TextMouth/ViewModels/LibraryViewModel+Import.swift, TextMouth/ViewModels/DataDirectoryMoveProgress.swift, TextMouth/Views/Library/ImportDecisionPresenter.swift, TextMouth/Views/Library/ImportDecisionSheet.swift, TextMouth/Views/ContentView.swift, TextMouth/ViewModels/LibraryViewModel.swift, TextMouth/Models/RemovalWording.swift, TextMouth/Views/Transcription/TranscriptionPresentation.swift, TextMouth/Services/DuplicateReplacement.swift, Scripts/test/kf8-fuzz/Stubs.swift -->

Import questions.

- Owner: LibraryViewModel.importDecisions, an ImportDecisionQueue of the questions imports are waiting to ask (whether to replace or keep a duplicate, whether to delete an original file, whether to put a ZIP archive's books in a new folder, and whether to transcribe an audiobook just imported), asked one at a time in the order they arose.
  Each ImportDecision holds everything its answer acts on, captured when its import finished (a duplicate's new copy and the copy it matched, an original file, a ZIP archive's books and folder, or an audiobook's ID, title, and length), and the ImportRequest its import was made with: the Library window it started in (ImportOrigin), whether to open the book afterwards, and the cancellation its batch shares.
- Who may write it: LibraryViewModel+Import and LibraryViewModel+Duplicates. ask(_:) queues a question behind those waiting, and a question an answer raises about the same file, such as whether to delete the original of a duplicate just kept, is asked next.
  An offer to transcribe (ImportDecision.Kind.transcriptionOffer, FR05) is queued after an import's own questions, for each audiobook it added, when TranscriptionOffers.offersTranscription(of:) allows it: an audiobook in a package of its own, Offer to transcribe after importing an audiobook on, and a Mac that can transcribe.
  Its Transcribe sends LibraryViewModel.acceptedTranscriptionOffers to the Library window that asked (LibraryTranscriptionSupport), which opens the Transcribe Audio sheet, starting at once when it can. answerImportDecision(_:with:) acts only on the question being asked, named by its ID, so a second press can never answer the next one; an answer that fails, such as a folder name the library refuses, keeps the question open with the reason.
  While the data directory moves (dataDirectoryMove is set), it refuses every answer with DataDirectoryMoveWording.importAnswerRefusal, shown in the sheet and spoken, and the question stays until the move ends, since a window asking one when a move begins keeps that sheet instead of the move's. cancelImports(), the progress overlay's Cancel, withdraws the questions of its batch, those waiting and those raised later: a duplicate's new copy is discarded, an original file is kept, a ZIP archive's books stay where they are, and an offer to transcribe is dropped.
- How others observe it: each Library window's ImportDecisionPresenter watches the queue, and exactly one window asks the question at its front (ImportDecisionQueue.askingWindow): the window its import started in while that is open, or else the first open Library window, the question waiting while none is open.
  That window shows ImportDecisionSheet, whose words, the screen's and VoiceOver's alike, come from ImportDecisionWording, with a title that gives the question's place when there is more than one, as in "Duplicate Book Found, 2 of 5".
  The choice that removes nothing comes first; Return and Escape press the marked choices, and Replace Existing and deleting an original file are never on a key.
  A duplicate's question says what Replace Existing keeps (ST04): ImportDecisionWording.duplicateMessage adds, after the choice, replacingKeepsSentence(existing:new:), which chooses from both copies' kinds and never promises what DuplicateReplacement.carriedBook drops: replacingKeepsTextSentence or replacingKeepsAudioSentence for two copies of one kind, and replacingAcrossKindsSentence when one is an audiobook (BookFormat.isAudio) and the other is not, which says "played from its recording" and "read aloud from its text" rather than "not an audiobook", so that it is true of a DAISY book too.
  Then replacedCopySentence(movesToTrash:) follows the Trash setting (RemovalPreferences.movesToTrash): with the Trash on it says that the files go to the Trash but putting them back won't return that copy to the library, since the package's record names the book the new copy now is, which no launch adopts a second time (adoptOrphanedTMBPackages); with it off it is RemovalMode.deletePermanently's files clause.
  The choice's hint is ImportDecisionChoiceWording.replaceExisting(acrossKinds:), which across kinds promises only the folder and the place on the reading list.
  The words say what Replace Existing does (replacing a duplicate, below).
  A question that appears while the user is in another window waits without taking focus or being announced.
  A book whose import asked to open it, as one opened from Finder does, opens through LibraryViewModel.readerOpener once it is in the library and its questions are answered.
- Files: Models/ImportDecision.swift, Models/ImportDecisionQueue.swift, ViewModels/TranscriptionOffers.swift, ViewModels/LibraryViewModel+Duplicates.swift, ViewModels/LibraryViewModel+Import.swift, ViewModels/DataDirectoryMoveProgress.swift, Views/Library/ImportDecisionPresenter.swift, Views/Library/ImportDecisionSheet.swift, Views/ContentView.swift.

## Limits of what a file claims

Limits of what a file claims (October 31, 2026): EPUBParser.readingXML(_:_:) is the one way EPUB XML is read, with .nodeLoadExternalEntitiesNever, as the feed and OPML readers do, so an entity naming a local file reads as nothing; the NCX is read through withNCX, which hands its document to the navigation and page-list readers the same way.

## Copying tracks, and room for them
<!-- id: copying-tracks-room-them; keys: ; src: TextMouth/Services/ArchiveBudget.swift, Scripts/test/kf8-fuzz/Stubs.swift, TextMouth/Services/FileImportService.swift, TextMouth/Services/ImportFailure.swift, TextMouth/Services/SpeechExport/SpeechExportSpace.swift -->

A folder of tracks and a playlist copy their tracks through FileImportService.copyTracks(_:into:), which first asks requireRoom(forCopying:onVolumeOf:): the rule of the archives (ArchiveLimits.current, so its freeSpace and freeSpaceReserve, which tests replace), applied to the sum of the tracks' sizes (the reserve is 1 GB) before the first byte is copied, throwing CocoaError.fileWriteOutOfSpace, which ImportFailure words as a full disk.
A track the copy will clone counts as empty (ArchiveLimits.copyIsClone, from volumeClonesCopy(from:to:): the source and the destination on one volume that supports cloning, and the source not still in the cloud), a file whose size cannot be read counts as empty, and a disk whose free space cannot be told is not checked.
The manifest and a later Ogg conversion's output are not counted, so the check is a lower bound, and the space is measured where the package is staged, not where it publishes.
The same rule is written out again in ArchiveBudget's admission of an archive, SpeechExportSpace, and LibraryViewModel+OggConversion's check, and a shared helper is a known follow-up.

## A folder with a DAISY book beneath it
<!-- id: folder-daisy-book-beneath-it; keys: ; src: TextMouth/Services/FileImportService.swift, TextMouth/Parsers/DAISYParser.swift, TextMouth/Parsers/AudioBookParser.swift, TextMouth/Services/MaintenanceFileAccess.swift, TextMouth/Models/ImportProgressWording.swift -->

A folder with a DAISY book in a folder beneath it, at any depth, is no folder of tracks either, and throws FolderWithoutBookError too: isFolderOfTracks is false when holdsDAISYBookBeneath finds a folder holding a DAISY book at its top level (DAISYParser.isDAISYDirectory), searched only once the folder is known to hold audio and passing over hidden items, Finder's __MACOSX folder, and symbolic links, since such a folder is no book and its tracks belong to the books beneath it (every walk of tracks, AudioBookParser.audioFiles, filesHeld, and holdsDAISYBookBeneath, calls skipFinderMetadataFolder, which skips only a real folder of that name: NSDirectoryEnumerator.skipDescendants() on a file or a symbolic link skips the contents of the next folder listed beside it, which lost the tracks of a book whose folder listed a link right before a folder, and MaintenanceFileAccess's walk of a package skips only folders for the same reason; a book folder that is itself a symbolic link still scans as an error, isFolderOfTracks is false and filesHeld is 0); the error's words (ImportProgressWording.noBookInFolder) list the files the folder holds at any depth, and do not say the books are inside it.

## A folder's original is never deleted
<!-- id: folder-original-never-deleted; keys: ; src: TextMouth/Services/FileImportService.swift, Scripts/test/kf8-fuzz/Stubs.swift -->

A folder's original is never deleted: ImportedBook.isFromFolder (once isFromPackageFolder, set only for a DAISY book copied from its folder) is set for both folder branches, the DAISY book's and importAudioFolderWithReport's, so mayDeleteOriginal is false for a folder of tracks too: it holds files the import did not copy (a cover, lyrics, a Bonus folder), and is never deleted or offered for deletion.
FileImportService.deleteOriginalFile(at:) refuses a folder too, or a link to one (fileExists(atPath:isDirectory:) follows links), whatever its caller decided: it removes nothing, sends nothing to the Trash, and does not throw, since nothing failed; it writes one ORIGINAL_KEPT line.

## A file with no text to read
<!-- id: file-no-text-read; keys: ; src: Scripts/test/kf8-fuzz/Stubs.swift, TextMouth/Services/FileImportService.swift, TextMouth/Services/MarkdownCacheService.swift, TextMouthProductionTests/ImportFuzzTests.swift -->

A file with no text to read: FileImportError.noTextToRead ("This file has no text to read.") is thrown by FileImportService.readableContent(of:run:refusingBlankText:) when refusingBlankText is set, refusesBlankText(_:) holds for the book (formatsRefusedWhenBlank, under Refusals below, which the Word documents joined on November 13, 2026), and no chapter of the generated content holds a character that is not white space, so the .readingText step fails and no silent, empty book is published.
Only importFileWithReport sets it, through publishReadableBook(_:from:run:feedLink:replacing:refusingBlankText:publish:), so Open Book, Finder, and the members of a ZIP (importSupportedFiles imports each through importFileWithReport) are refused, while New from Text, a feed's download, and every rebuild of an existing book's text are not.
The check is in readableContent and not in MarkdownCacheService, because every rebuild of an existing book's text goes through that, and a book already in the library must never become unreadable.
A Markdown file that is only a heading still imports.
ImportFuzzTests.knownIssues, which held the empty Markdown file the first sweep found, is empty.

## A full disk
<!-- id: full-disk; keys: ; src: TextMouth/Services/ImportFailure.swift, TextMouth/Services/Feeds/FeedDownloadManager.swift -->

A full disk: ImportFailure.isOutOfSpace(_:) says a volume is full when an error, or one it wraps under NSUnderlyingErrorKey at any depth, is Cocoa's NSFileWriteOutOfSpaceError or POSIX ENOSPC, and ImportFailure.outOfSpaceDescription ("There isn’t enough free space on the disk.") is then the failed step's reason in place of the system's own sentence, which names the hidden staged package (.import- followed by an ID and .tmb). reason and reason(for:) both word an error this way, so an alert, a ZIP batch's list of failures, the IMPORT_FAILED line, and a feed download's failure (FeedDownloadError.importFailed) say it alike.
