# Package records

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- bookInfo.json and contentIndex.json: each package's record of its book (BookInfo), in two files. bookInfo.json holds the metadata, the reading state, and the bookmarks, about a kilobyte, pretty-printed with sorted keys; contentIndex.json, beside it, holds the content index alone, compact with sorted keys, since it can run to hundreds of kilobytes and changes only when the book is imported or analyzed.
  - Owner: LibraryPersistenceService's metadata queue, for every save the running library makes. The record is built from a Book by Book.bookInfo(replacing:contentIndex:revisionFloor:). A braille book's table (BookMetadata.brailleTable, FMT21) and, for a Mac table, the liblouis version of this Mac's tables it was read with (BookMetadata.brailleTableVersion) are the row's, else the stored record's, so a row that lost either never erases it. Who chose the table (BookMetadata.brailleTableOrigin, brfguess, "guessed" or absent, an @LenientOptional) goes with it, but by the row's table: the row's origin when the row holds a table, so a choice in Book Information, which clears the origin, replaces a guess the record holds, and the stored record's only when the row holds none (The guess of English Braille, American Edition, in [Imports](imports.md)). A text book's guessed or chosen encoding (BookMetadata.textEncoding, FMT16) and who decided it (BookMetadata.textEncodingSource, encodingchoice) are kept as one (TextEncodingRecord), by a rule of their own. A decision the stored record holds is a re-read's, which LibraryViewModel.readTextAgain writes with the new text, through saveContentAnalysis(…textEncoding:), before the library row takes it, so only a write that decides anew (decidingTextEncoding, which only that save passes) replaces it. Any other save, a reading checkpoint among them, whether the row it writes lags behind the re-read or not and with or without a content index, writes the stored record's encoding and source back as they are, and never the old encoding beside the new text (review of October 24, finding 5); crash recovery followed the same rule already (ContentAnalysisSummary.apply(to:), below). Over a stored record that names no decision, only a guess or nothing, a row that holds either writes its own, its nil encoding included, and only a row that holds neither takes the stored record's. Both are @LenientOptionals (Models/LenientFields.swift): a value that cannot be read decodes as none, logged as a repair, without failing the record around it, and a nil one is left out of the file, so the record of a book with neither is exactly as it was (Text files in other encodings, in [Imports](imports.md)).
  - Who may write it: saveBookInfo(for:) and saveBookInfo(for:contentIndex:), which hold each book's newest snapshot for half a second and write only it; saveContentAnalysis (below); and flushPendingSave(). A save of a book's state writes over the package's record (BookInfo.saveRecord(to:)): a record carrying an index writes contentIndex.json first, so bookInfo.json never names an index that is not on disk yet, and one without leaves contentIndex.json as it is, so a reading checkpoint writes about a kilobyte. The record such a save replaces is read as a StoredBookRecord, bookInfo.json and whether the package keeps an index, never reading contentIndex.json. A package written whole, by an import or a repair that separates a shared package, replaces both files (BookInfo.save(to:)), removing contentIndex.json when the record has no index; an import writes its new package's record so and reads it back (FileImportService.writeVerifiedRecord). Folder moves, migrations, and data-directory moves write records directly with Book.saveBookInfoThrowing, under the same revision rules but outside the queue's order; a move writes each staged copy's record as a save of its book does (saveBookInfoThrowing(contentIndex:inPackageAt:)), so the contentIndex.json it copied stays as it was, byte for byte. A record that is only in the cloud, or whose package or removal marker is, is neither read nor written by the queue, since reading it would download it: the book's saves go to library.json alone until the record is on this Mac again, with one BOOK_RECORD_IN_CLOUD line, and an analysis result for it is dropped.
  - How others observe it: BookInfo.load(from:) reads bookInfo.json with the index from contentIndex.json. An index an older version kept inside bookInfo.json wins, and the next save moves it into its own file, while an older version reading a record written since finds no index and builds one once. A missing or damaged contentIndex.json leaves the record without an index, which the book's next load builds afresh, and a read refused because either file is only in the cloud is passed up rather than downloading it. Content analysis reads the saved index and fingerprints from the record (Book.storedBookInfo()), and saveContentAnalysis reads it back as a Book (Book(record:filePath:folderPath:tmbDirectoryName:)) to merge an analysis into. Orphan adoption, which also builds the provisional library while the index cannot be read, and importing a .tmb package (FileImportService.bookFromPackageInfo) rebuild library rows from records with that initializer too, each without the feed link its record may hold (Book.placedInLibraryFolder(), FR11), since a package in the Library folder is a book of the library's own; a feed's index rebuilds its rows the same way, keeping the link (feed items, above).
  - Files: Models/BookInfo.swift, Models/Book.swift, Models/TextEncodingRecord.swift, Models/LenientFields.swift, Services/LibraryPersistenceService.swift, Services/TextMouthPaths.swift.
- Revisions.
  - Owner: BookState.revision, in each record.
  - Who may write it: every write stores one more than the record it replaces, and never less than one more than the highest revision this process has written for the book, so a book's revisions only rise, across restarts too.
  - How others observe it: no decision rests on a revision. Whether an analysis still applies is decided by the book's content (below).
  - Files: Models/BookInfo.swift, Models/Book.swift, Services/LibraryPersistenceService.swift.
- Analysis-owned fields.
  - Owner: the content analysis. Book.ContentAnalysisFields (the word and character counts, the audio duration, the content index version, the cache format version, the text cache fingerprint, the record of an edit taken, Book.editedText (B12), and the page reader that wrote content.md, Book.pageReaderVersion (PG09); both are described in [Text caches and content indexes](text-caches.md)) travel together with the content index. Book.applyContentAnalysis drops editedText once an analysis records a content.md digest other than the edit's, and leaves pageReaderVersion as it is, since only a generation says which page reader wrote the text.
  - Who may write it: LibraryPersistenceService.saveContentAnalysis merges a finished analysis into the book's latest durable state, on the metadata queue: the snapshot still waiting there, or else the record on disk. Only the analysis fields and the index change, and, when the caller passes one (textEncoding, which a re-read in another encoding does), the book's encoding and who decided it. A result is dropped, with one CONTENT_ANALYSIS_DROPPED log line, when that state describes other content: another MD5 hash, format, or file path, or another book's record. A save that carries no index keeps the stored index and its fields, so neither kind of write undoes the other. The reader commits a fresh index of its own through LibraryViewModel.updateContentIndex.
  - How others observe it: a library row takes the committed fields and keeps its own reading state, settings, and metadata. The text cache batch and the statistics pass hand each finished book's fields to LibraryViewModel.analysisSummaries (ContentAnalysisSummaryBuffer), which gives the rows all that arrived in one change of library and one save, at most half a second after the first of them (flushInterval), when a pass ends, and when TextMouth quits; a summary a crash loses is recovered from the book's record by the next launch's batch. A summary also carries the encoding the book's record keeps for a text file, and who decided it (ContentAnalysisSummary.textEncoding and textEncodingSource, FMT16 and encodingchoice), which a row that holds no encoding and no decision takes, and so does a row whose record holds the listener's own decision: a re-read writes it into the record with its new text before the row takes it, so a row a stop left behind catches up when its analysis is recovered. A row that holds a guess of its own otherwise keeps it; a recovered summary takes the pair only from the book's own record (Text files in other encodings, in [Imports](imports.md)). The batch's progress is an object of its own, LibraryViewModel.textExtraction (TextExtractionProgress), which only the Library windows' overlay and Storage settings observe (ProgressObserver, the generic observer the import overlay uses too), so a finished book redraws only them.
  - Files: Models/Book.swift, Models/TextEncodingRecord.swift, Services/LibraryPersistenceService.swift, ViewModels/LibraryViewModel+BookOperations.swift, ViewModels/LibraryViewModel+Migration.swift, ViewModels/ContentAnalysisSummaryBuffer.swift, ViewModels/TextExtractionProgress.swift.
- The metadata reader's version: which reader last read a book's file for its title and author.
  - Owner: ImportedFileMetadata.readerVersion ("1.0.0"), the version of the reader every import uses (ImportedFileMetadata.read, which opens EPUB, Word, PDF, DAISY, and audio files, and rich text, RTFD, Word 6 to Word 2003, OpenDocument, and Word 2003 XML documents and KFX books through TextMouth's own readers, and, on the Mac, a compound-file Word document older than Word 6 through textutil (an import leaves the textutil run out and takes their names from the conversion that reads their text; see [Imports](imports.md)), and a PEF braille file's head (BrailleFileReader.pefMetadata(of:); a BRF or BRL names neither title nor author, so it is read for nothing), and never a plain text, Markdown, HTML, web archive, or SSML file: readsFile(of:)), stamped on the row as Book.metadataReaderVersion and, with the book's next save, in its record (BookMetadata.metadataReaderVersion), so a library rebuilt from its records reads again only the books saved before that. SemanticVersion.isOutdated(stored:current:) judges it as it judges the text cache's format version, so a stamp a newer TextMouth left in a shared library is never undone. An EPUB's author is EPUBParser.authorName(in:): the dc:creator with the author role (EPUB 2 opf:role, EPUB 3 a meta refining it), else the first dc:creator naming anyone, else a dcterms:creator meta element, else a dc:contributor with the author role, the name trimmed, and an element holding only the placeholder Book.unknownAuthor naming no one; parseOPF, readMetadata, and the editor's write (updateOPFMetadata, which writes into that creator or adds one) share the choice.
  - Who may write it: an import stamps the row it makes (importFileWithReport). The launch's metadata refresh (LibraryViewModel.refreshOutdatedMetadata, in LibraryViewModel+MetadataRefresh.swift) reads the file of every row an older reader stamped, or none, but a feed item's (FR11), whose title and author come from its feed, off the main thread with the same reader, each read as storage work a data-directory move waits for (StorageWork.metadataRefresh), and stamps every row read. Each file is read with an empty fallback title (ImportedFileMetadata.read(from:format:fallbackTitle:)), so a file that names no title names none, into a MetadataReading of the values it names for the fields the refresh may replace (Book.MetadataField.refreshable: the title, the author, and an EPUB's publisher and publication date), an author only when it names someone. refreshedValues(of:from:), asked on the main actor of each row as it is then, so a field edited by hand while the pass ran stays, decides what the row takes: never a field its record of hand edits names (hand edits, below); every other refreshable field whose value differs, for a row whose record has been kept since its import (Book.HandEdits.sinceImport); and for any other row, whose unrecorded fields may hold edits nothing recorded, only an author still at the placeholder, and only with a name. Since October 7, 2026, FileImportService.importFileWithReport begins such a record on every book it makes (hand edits, below); every other row can take nothing but an author in the placeholder's place. The refresh records no edit of its own, and a row with a field replaced has its record written as any edit of it would. A book whose files are in the cloud is left unstamped and counted in the pass's CloudSkips (MaintenancePass.metadataRefresh; maintenance in a cloud library, below); a book whose format keeps no metadata in its file, or whose content is a folder (of tracks, or an RTFD), is stamped without a look.
  - How others observe it: updateContentCachesAndStatistics runs the refresh first, then the text cache batch, then the statistics; the rows take what was read in one change of the library and one save (applyMetadataReadings), and one METADATA_REFRESH line in the debug log counts the books read, the fields replaced, and the rows they were replaced on (metadataRefreshLogLine(read:replaced:rows:)). A reader follows a new author as it follows any edit (ReaderViewModel+LibraryUpdates).
  - Files: Services/FileImportService.swift, Models/Book.swift, Models/SemanticVersion.swift, Parsers/EPUBParser.swift, ViewModels/LibraryViewModel+MetadataRefresh.swift, ViewModels/LibraryViewModel+Migration.swift, Services/StorageGeneration.swift, Services/MaintenanceFileAccess.swift.
- Hand edits (FR06): which of a book's metadata fields the user edited by hand.
  - Owner: Book.handEdits, a Book.HandEdits (Models/Book.swift, under Hand Edits), on the row and, as BookMetadata.handEdits, in bookInfo.json: the Book.MetadataFields edited (title, author, publisher, publicationDate, audioAlbum, audioGenre, and audioYear), kept in MetadataField.allCases order, each once, so a record is always written as the same bytes, and sinceImport, whether the record has been kept since the book's import, so that it names every hand edit. nil means nothing was recorded: every row saved before October 7, 2026, and every book since that the file import did not make, until an editor's save begins its record. library.json decodes it leniently (LenientFields.optionalValue), a record that can't be read counting as none; a field name a later TextMouth writes is dropped, and a record without sinceImport reads as begun by an edit. makeBookInfo() and Book(record:filePath:folderPath:tmbDirectoryName:) carry it both ways, and Book.EditableMetadata carries it, so a reader's copy takes the row's through libraryFields.
  - Who may write it: LibraryViewModel.updateBookMetadata(_:of:contentHash:), the one save every metadata editor goes through: the Book Info sheet of a plain text, Markdown, or HTML book (LibraryBookInfoSheet); the EPUB editor, the library's and the reader's (ReaderViewModel.saveEPUBMetadata(_:openedAs:writeToFile:writer:)), through LibraryViewModel.saveEPUBMetadata(_:openedAs:for:writingToFile:writer:); and the audio editor, the library's directly and the reader's through saveAudioMetadata(_:openedAs:). It takes a Book.MetadataEdit: the values of the fields the editor shows, as it opened with them and as they were saved. Its changes (MetadataEdit.changes) are the fields saved with a value other than the one the editor opened with, a field it opened without counting as opened empty, and each is saved without the blanks and line breaks around it: a field is a change only when the typed text differs from what the editor opened with and so does the trimmed text, so blanks over an empty field are no change and mark nothing, "Press " saves as "Press", and a value an older version saved with blanks, left alone, is not rewritten (the trimming is in changes and not in the edit's init, which would have made every such untouched field a change). An editor shows a value nothing knew as empty (Book.storedEPUBMetadata and storedAudioMetadata, which Book Info shows for a book only in the cloud), so such a field saved empty is no change and stays nil, and the book's file gives its value once the book is downloaded. Book.applyMetadataEdit(_:) applies the changes alone to the row as it is at the save, and marks exactly those through Book.markEditedByHand(_:), which begins a record with sinceImport false on a row without one; nothing removes a field. Every other field keeps the row's value, so a change another window or the launch metadata refresh made while the editor was open is neither put back nor marked, and the row's record keeps every field it gained meanwhile. A save with no change and no new content hash writes nothing. Every editor keeps what it opened with in @State, since whoever shows it may make it again with newer values, as the reader's Book Info does when the library changes the book: MetadataEditorView hands openedEPUBMetadata or openedAudioMetadata to its save beside the edits, and LibraryBookInfoSheet keeps its title and author trimmed as Save trims them (values(title:author:)), from which edit(from:title:author:) makes its edit, or nil for a blank title. LibraryViewModel.saveEPUBMetadata, asked to write the library's copy of the EPUB file, writes it with the row as the edit leaves it laid over the editor's metadata (mergingEditableEPUBMetadata(_:)), and passes the written file's hash as contentHash. The save returns the row as saved, whose record the reader's copy takes; the reader's saves then show the saved row over the edit, and its audio save of a book no longer in the library changes nothing and says so (MetadataEditorWording.notInLibrary(title:), the sentence every metadata editor's save says when the book has left the library). HandEdits.noneSinceImport is the record FileImportService.importFileWithReport begins on every book it makes (each single-file format, a DAISY book's folder, package file, or navigation file, a text-only DAISY archive, and each book of a ZIP batch), beside the metadata reader version it stamps, since that reader read its title and author in the very file the launch refresh reads again. New from Text (importText), recordings (importRecording), a feed's downloads (FeedEpisodeImporter), and archives of audio tracks or of a DAISY audio book (stagedAudioBook) begin none, and a package keeps what its record carries (bookFromPackageInfo, orphan adoption; reconstructedBook has none). An episode's or article's Book Info while it is in its feed (Book.hasReadOnlyBookInfo, FR11's branch C) has no editor and saves nothing: LibraryView.bookInfoSheet(for:) and the reader's ReaderBookInfoSheet show FeedItemBookInfoSheet (Views/Library/FeedItemBookInfoSheet.swift), whose details (FeedItemBookInfoWording.details(of:info:feedTitle:), each a BookInfoDetail) FeedInfoValue draws as one element whose value can be selected, with a spoken value where it differs, as a duration does; LibraryViewModel.feedTitle(of:) names the feed, for Book Info and Speak Info, and the reader's Book Info button is labelled by readerButtonLabel(readOnly:).
  - How others observe it: the launch metadata refresh never replaces a recorded field (the metadata reader's version, above). MetadataEditorWording.fieldLabel(_:for:in:) (Views/Reader/MetadataEditorView.swift) adds MetadataEditorWording.editedByHand, "edited by hand", to the accessibility label of a recorded field's control, as in "Book title, edited by hand", in MetadataEditorView, which takes handEdits:, and in LibraryBookInfoSheet, which reads its book's. The Library window passes handEdits: to both of its editors, and so does the reader's Book Info, ReaderBookInfoSheet (Views/Reader/ReaderView.swift), which observes the reader and passes its copy's record, which every save of the row, the reader's own included, brings up to date; for an episode or article in its feed (Book.hasReadOnlyBookInfo) it shows the read-only FeedItemBookInfoSheet, and for any other plain text, Markdown, or HTML book LibraryBookInfoSheet, which reads the reader's copy.
  - Files: Models/Book.swift, Models/BookInfo.swift, Services/FileImportService.swift, ViewModels/LibraryViewModel+BookOperations.swift, ViewModels/LibraryViewModel+MetadataRefresh.swift, ViewModels/ReaderViewModel+Bookmarks.swift, Views/Reader/MetadataEditorView.swift, Views/Reader/ReaderView.swift, Views/Library/LibrarySheetViews.swift, Views/Library/LibraryView.swift, Views/Library/LibraryBookInfoLoader.swift, Views/Library/FeedItemBookInfoSheet.swift.
- Saved places' text anchors (T06, branches A to E): what a reading position, a bookmark, and a skipped heading keep of the text around them, so a place can be found again by its words when the book's text is read anew, and how the places follow their text: at every rebuild of it, every load of it, and every Edit Text edit.
  - Owner: the library row and the package record. ReadingPosition.anchor and Bookmark.anchor are each a TextAnchor (Models/TextAnchor.swift): up to quoteLength, 64, UTF-16 units of the chapter's reading text before and after the place, cut on composed-character boundaries, a place inside a composed character counting as at its start; the place's share of the book, counted as Book.restsAtEnd counts a place, so an anchor captured at or past the book's total marks its end; the text cache's and content index's versions it was measured in (currentMeasure, as "3.0.7/1.0.0"), which nothing decides by; and its format version. Book.skippedHeadings, and BookState.skippedHeadings in the record, hold a SkippedHeading for each skipped heading: its level, label, chapter, offset, and the anchor at its start. Every field is read leniently, an anchor that can't be read counting as none, and written only when set, so a book with neither writes exactly what it wrote before.
  - Who may write it: ReaderViewModel.makeCurrentReadingPosition() gives every position its anchor (anchorToSave(at:)), keeping the opened place's saved anchor (openedPlaceAnchor) until the cursor moves; both bookmark adds pass one to LibraryViewModel.addBookmark and Library.addBookmark; toggleHeadingSkip saves SkippedHeadings with anchors through updateSkippedHeadings(bookID:headings:) and Book.setSkippedHeadings(_:), which writes skippedHeadingIDs from them. Book.skippedHeadings is kept in step with skippedHeadingIDs, which older builds read: made from the IDs where a row or record has none, and following every change to them, keeping each still-named heading's anchor (SkippedHeading.inStep(with:keeping:)). Places saved before anchors take theirs at load (captureMissingAnchorsAtLoad()) and in the launch pass captureMissingTextAnchors(access:then:), run by updateContentCachesAndStatistics after the metadata refresh and before the cache batch (TEXT_ANCHORS_BACKFILLED); both use CapturedPlaceAnchors.capturing and Book.adoptCapturedAnchors(_:), which gives words only to places still saved where they were read. The pass reads each book's content.md off the main thread, writes nothing else, skips books only in the cloud, held by an Edit Text session, or open in a reader (they wait for a later launch), and changes no place's date and no lastOpened. A place still saved past its chapter's end is quoted at that end; a place in a chapter the book lacks, and a skipped heading whose ID names no current heading, get no words, since quoting where a skip's old place falls now could make it skip the wrong section. measuredIn is TextAnchor.measure(ofTextCachedBy:) of the content.md's recorded cache version, nil when the book records none. DAISY text books (.daisy) take words like any text book; DAISY books with audio are audiobooks and keep places in time.
  - How others observe it: TextAnchor.stands(at:in:) is the direct check, the anchor's text standing exactly around the saved numbers, compared unit for unit. TextAnchorFinder (Models/TextAnchorFinder.swift), a pure Sendable value built once per book's text, off the main thread and only when a direct check fails, finds a place again by its words, read as fine words (FineWords and BookWords, Models/FineWords.swift: runs of letters or digits, ending where letters meet digits and where a small letter meets a capital, compared in lower case, each keyed by a 64-bit FNV-1a hash, the one word rule every way of finding a place shares). The end of the book stays the end; then the direct check; then every spot where the first four words after the place, or the last four before it, stand, scored 2 for each word after that agrees, in order, and 1 for each word before, a candidate needing 8; equal best spots are settled by nearness to where the place was, and a best spot far from it (more than 5% of the book, and more than 3,000 units) yields to a near one scoring 8 or more, both silent best guesses; then a tolerant second search, lining the quote's words up with the book's around every spot where three of them stand together; and last the same share of the place's chapter, at a word start, when the chapter's old length is known, or else its saved offset held within the chapter (for a chapter the book no longer has, its share of the whole book). findHeading names a skipped heading only by the direct check, or when all the skip's saved words after the heading match from a heading's first word, within its chapter, with at least sectionProofWords (four) of them past the label, ties settled by the skip's label (REV16 F1); otherwise it returns nil so the skip waits. Each result says how the place was found (TextAnchorFinder.Finding: unchanged, found, or guessed, with its reason).
  - Moving them across a rebuilt text (T06, branch C): PlaceRelocator (pure, Sendable) moves a book's reading position, bookmarks, and skipped headings from its old text (the old content.md as this build reads it) to its new one. It lines the two texts' fine words up once by a patience diff (PatienceDiff). For each place it: keeps it when its anchor still stands or marks the end of the book (TextAnchorFinder.settled); finds it in the old text, at its numbers or else by its words; carries it by the diff's rules (solid matches, a place keeping the words that follow it, like-for-like stretches, removals slid back, moved text followed into text the diff found put in, the end to the end); else asks the saved-words search, then guesses silently. A place goes to the new text's end only when it was at the old text's end (TextPlace.restsAtEnd, which Book.restsAtEnd also uses); a place at its chapter's end stays at that chapter's end; a place in a chapter without words goes to the matching chapter without words between its neighbours; a reading position at the very start of the book stays at the start; a place saved without words in a lost chapter is held as the reader opens it (TextPlace.opening, which ReaderViewModel.openingPlace also uses). A skipped heading is found first in the old text: by the heading its ID names, else by its level and label when one old heading has them (of several, the one its saved words find for certain), else at its place where its saved words still stand exactly; never by saved words alone or at stale numbers. That heading's start is carried like a place, and a new heading there takes the skip only on the diff's proof: no rival old heading that lent it words, or whose section continues in it, has a label more like it (or as like, with its own section continuing there instead), and its label is the skip's, or the skipped section continues in it, or most of the skipped heading's words went into it. Among several, the label decides, then the level, so a re-levelled heading keeps its skip. Failing that, the one new heading of its level with its label takes the skip unless the diff makes it another section; otherwise the skip waits, unchanged. The relocator takes both texts' headings together, or neither (the initializers for places alone let every skip wait). relocate(_:movedAt:) takes the time of the move, which a moved position takes as its date, and returns the places to save (anchors captured anew), how each was found, and the counts for the PLACES_RELOCATED line (Counts.logLine(title:)); the findings and counts cover only the skips kept. It shares BookWords.landing and TextAnchorFinder.settled and onlyBestSpot with the finder.
  - Moving them when a rebuild writes the text (T06, branch D): MarkdownCacheService.writeCache(for:) copies the old content.md and the book's places aside before it writes (PlaceSnapshot.keep, in MachineLocalPaths.placeSnapshots), and after writing moves the places with PlaceSnapshot.movePlaces(to:at:), through PlaceRelocator.relocate(_:from:to:movedAt:), which builds a relocator only when some place does not stand. Nothing is copied for a book with no places, one in an Edit Text session, one whose content.md is only in the cloud, or one whose new text is unchanged. The moved places travel in GeneratedCache.movedPlaces and BookContentAnalysisService.Result.movedPlaces. The batch, Redo Text Extraction, the statistics pass, a re-read in another encoding (readTextAgain, in [Text caches](text-caches.md)), and the reader commit them with LibraryPersistenceService.saveContentAnalysis(…movedPlaces:), guarded by Book.takeMovedPlaces(original:moved:), which compares each place as stored (the record and the row keep dates to the second, so a place saved during the session would otherwise never equal its stored copy and silently not move) and guards each place on its own, except the skip lists, which move as one because the relocator merges skips; that save deletes the copy. Library rows take them through ContentAnalysisSummary, which narrows them with MovedPlaces.taken(by:), and the reader in showLoadedContent by takeMovedPlaces(_:), in order with the moves of the next bullet. The launch's recovery, finishLeftoverPlaceMoves, runs first in updateContentCachesAndStatistics and commits through saveMovedPlaces; PlaceSnapshot lists the copies this run is still using, and the recovery skips them, so it never sweeps or takes one a reader's rebuild is still using (the test seam forgetCopiesInUse() empties the list, as a quit does). A skipped heading the new text no longer has waits: Book.waitingSkippedHeadings and BookState.waitingSkippedHeadings hold it, a list of its own that no reader of skippedHeadingIDs sees, so it skips nothing (older builds drop the list, so for them the section plays), and it names a heading again only where that heading stands exactly as it was skipped, with saved words. Waiting skips are not a book's own settings (Book.hasOwnSettings). The debug log's lines are PLACES_NOT_KEPT, PLACES_NOT_MOVED, PLACES_RECOVERED, and PLACES_RELOCATED. The recovery's finishPlaceMove gives the row moved.taken(by: committed), so a place the row changed meanwhile is kept (REV16 C1). The next launch's recovery of a committed text cache (committedTextCache) reads the book's record once (BookContentAnalysisService.recoveredTextCache) and brings its moved places to the row through ContentAnalysisSummary(recovered:record:): the position only when the record's is at least as new, a bookmark only when nothing but its place and words differ, and the skips as one (REV16 C5).
  - Moving them at every load and at every Edit Text edit (T06, branch E): PlaceRelocator.relocate(_:within:movedAt:) checks the places at every load, with no old text, and returns nil when every place stands, by direct checks only; places nothing finds stay exactly as saved, numbers and words, so a later text that has the words again can find them (keepingPlacesNothingFound), and a skip with no saved words whose heading no longer exists waits, as it does at a rebuild. ReaderViewModel.readContent runs the check off the main thread. LoadedContent.movedPlaces is a list: the edit's moves, then a rebuild's, then the check's, which showLoadedContent takes in order through takeMovedPlaces(_:). The check saves nothing on its own: the reader takes the moves into the row, and updateBook writes the row and the record, as any change is saved. The row takes a move only as far as the record took it (MovedPlaces.taken(by:) puts each move the record refused back to its original, so a place another Mac or the listener saved meanwhile wins), and only where no reader is involved: the batch, the statistics pass, Edit Text's takes, and edits saved while closed. A reader re-dates its position at every open (savePosition()), so narrowing there would protect nothing.

- Transcripts (FR05): a transcribed audiobook's transcript.json, and the text written from it.
  - Owner: the package. transcript.json (Transcript, in layout Transcript.currentVersion, 1) is a record, not a cache: only transcribing the book again replaces it, only Edit Text and a cleanup or its undo change it, and only Delete Transcript removes it. It is compact JSON with sorted keys and ISO 8601 dates, written atomically (TranscriptStore): its layout version; the locale; the recognizer and its model (model: the engine, SpeechTranscriber, the asset status the system reported, and the macOS version); the build of TextMouth (app: its version, build number, and commit); when the transcription finished (createdAt, in whole seconds); when the user last edited it (editedAt, in whole seconds, left out until then, so an earlier TextMouth reads an edited transcript as any other); its last cleanup by rule (cleanedUp, a TranscriptCleanupNote: when, in whole seconds, the rules' version and date, whose rules they were, "built-in" or "user", kept as words so that a source a later TextMouth adds never keeps this one from reading the transcript, and how many corrections it made; left out until a cleanup); and files, one for each audio file in the order the book plays them, each with its path as the book's audio index names it, its fingerprint (FileFingerprint: size, modification time in nanoseconds, and MD5 digest) taken just before it was transcribed, its duration in milliseconds, and its sentences. A sentence holds its text, its start and end, and its words, each an array of [UTF-16 offset in the sentence, UTF-16 length, start, end, confidence], the confidence to three decimals and left out when the recognizer gives none. Times are whole milliseconds from the start of their own file, so the recognizer's 60-millisecond steps stay exact; none lies beyond Transcript.maximumMilliseconds, 100 hours, and a file that says so is refused as damaged (validationFailure), so that no sum of times can overflow (the text builder's arithmetic is clamped for the same reason, and a bad offset is worded, never added). The text derived from it is a cache: content.md, which TranscriptTextBuilder writes (each chapter's marker and heading, then paragraphs of at most four sentences or about 600 UTF-16 units, a pause of two seconds or more starting a new one; escaped only as TextMouth's reader needs, by MarkdownLiteral.minimallyEscaped with smartPunctuation and guardingLineStart, where a text book's content.md has a backslash before every ASCII punctuation character), and the transcript layer of the book's content index (BookContentIndex.transcript, a BookContentTranscriptIndex, version BookContentTranscriptIndex.currentVersion, "1.1.0", raised from "1.0.0" on October 23, 2026 with that escaping, so each transcribed book's text is written again once as it opens), which records the text's own index (as a text book's: chapters, headings, and counts), each chapter's sentences as [UTF-16 offset, length, start, end], in milliseconds of chapter time, the audio files' fingerprints, and a TextCacheFingerprint with transcript.json as the source and content.md as the cache. The audio index itself is unchanged, so BookContentIndex.currentVersion, and every position and bookmark, which count time, stay as they were. bookInfo.json notes the transcript (BookState.transcript, a TranscriptNote: the layout version, the locale, and the date); library.json does not. Beside it, transcript.json.before-cleanup (TextMouthPaths.transcriptBeforeCleanupPath(in:)) holds the bytes of the transcript as it was before its last cleanup, for Undo Cleanup.
  - Who may write it: TranscriptStore.install, which TranscriptionJobCenter runs off the main thread once the audio is transcribed (TranscriptionService.transcribeAndSave does both for the fixture tests), as storage work (StorageBoundary.perform(.textExtraction)): it checks that the book's audio is still the audio transcribed and that content.md is on this Mac (TranscriptTextLoader.requireTextOnThisMac: when it is only in the cloud, nothing is read, downloaded, or written, and TranscriptTextError.textOnlyInCloud is thrown, before transcript.json changes), reads the transcript the package holds (previous), writes transcript.json, writes content.md from it (TranscriptTextLoader.writeText), saves the index through LibraryPersistenceService.saveContentAnalysis, and drops the book's kept reading text. TranscriptTextLoader writes content.md and the layer again from transcript.json, as storage work, when either is missing, was changed, or was made by another version (TRANSCRIPT_TEXT_REBUILT), and tells the sessions of the text it wrote (BookTextEditSessions.textRebuilt). Before it replaces content.md, writeText(of:for:over:replacing:previous:hasher:isDataless:keepCopy:sessions:) keeps a content.md holding text TextMouth didn't write or take beside itself (BookTextEditSessions.keepCopy(of:bytes:), TEXT_EDIT_KEPT), and also one that TextMouth wrote from an edited transcript but that reads differently from the text written from that transcript (unwrittenTextNeedsKeeping, which compares reading text, so escapes and paragraph breaks alone keep nothing); when that copy cannot be made it throws TranscriptTextError.textNotKept and leaves content.md as it is, as it leaves one only in the cloud (a rewrite so left is logged and tried again at the book's next open). TranscriptStore.takeEdit writes an edit of the text into transcript.json (edited text, below). TranscriptStore.cleanUp(_:expecting:with:from:now:hasher:) and undoCleanup(of:hasher:) (Services/TranscriptCleanupStore.swift) clean a transcript up by rule, and undo that, as storage work, for the Clean Up sheet (a transcript's cleanup, below). A cleanup reads transcript.json with dataless files left in the cloud, and goes on only while it still holds the transcript the sheet previewed (TranscriptCleanupError.transcriptChanged) and the rules change something; it writes the bytes it read to transcript.json.before-cleanup, replacing an earlier copy, rewrites each sentence a rule changed (TranscriptCleanup, through TranscriptSentence.rewrite(as:), which TranscriptEditing.apply shares), records cleanedUp, and installs the result as a transcription installs one (install). A cleanup that fails while transcript.json still holds what it read puts the earlier copy back, or removes the new one. undoCleanup installs the copy again, when the transcript records a cleanup and the copy can be used, then removes it. TranscriptStore.delete(for:), as storage work, removes transcript.json first, so a deletion cut short leaves no transcript to show, then the copy kept before a cleanup, content.md, and the kept reading text, and saves the audio index without its layer, which drops the record's note; the copies kept beside the files stay. The record's note follows the index each write carries, an import's included (Book.bookInfo(replacing:contentIndex:revisionFloor:), FileImportService.writeVerifiedRecord), and every other save keeps it.

An audio file whose size or contents changed since transcription makes the transcript stale (TRANSCRIPT_STALE), and it shows no text; one only touched keeps it, its new stamp recorded.
