# Preferences

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- The preferences store.
  - Owner: TextMouthRuntime.current.preferences, which is UserDefaults.standard in the app and a sandboxed store under hosted tests. Each preference has one owner that reads and writes it:
    - SettingsViewModel: the Voice, Playback, and Miscellaneous settings, through properties backed by @AppStorage.
    - SoundEffectService: whether sounds play, their volume, and each event's sound.
    - TextSubstitutionService: whether the substitution rules apply, and the repeated-symbol style, threshold, and symbol set (repeatedSymbolStyle, repeatedSymbolThreshold, and repeatedSymbolSet), which that switch does not affect. It also owns the rules, kept in substitutions.json.
    - KeyboardShortcutManager: the record of the shortcuts the user edited, under keyboardShortcutEdits, from which every action's keys in force follow, no key in force for two actions in one kind of window (ShortcutScope: every window but an audio editor's, Library windows, reader windows, the audio editor's windows, or the Record window; keyboard shortcuts, below), and the double-press time, under shortcutDoublePressSeconds. The whole map of every action's keys that earlier releases saved, under customKeyboardBindings, is read once, at the first launch without a record, and never written again.
    - SleepTimerService: the last timer started, under sleepTimer.lastUsedDuration.
    - TextMouthPaths and the library model, through DataDirectoryPreferences: the data directory's location, a bookmark of its folder, and the identity of the library expected there, under textMouthDataDirectory, textMouthDataDirectoryBookmark, and textMouthLibraryIdentity.
    - LibrarySessionLease: this Mac's ID, which names its file in a library's Sessions folder and, in a library in the cloud, the notes a launch leaves in a feed's folder when it finds the feed's record missing (FeedRecordAbsence), under textMouthSessionMacID.
    - RecordingInputChoice: the microphone the Record window and the audio editor's punch-ins record from, under recordingInputDeviceID, empty until one is chosen.
    - RecordingLevelAnnouncements (Services/RecordingPreferences.swift): whether the Record window announces the level while recording, under recordingAnnouncesLevel, off until turned on, and how many seconds apart, under recordingLevelAnnouncementSeconds (SettingsPolicy.recordingLevelAnnouncementSeconds: 5 to 60, 10 until changed), read as the Record window opens and written as they change.
    - AudioOriginalPolicy: what happens to the original audio of recordings and edited audiobooks, under recordingOriginalPolicy and recordingOriginalDays, the names it had when only recordings kept an original, which Storage settings' Audio Editing group changes.
    - AudioFilterEngine.usePreference: whether an installed ffmpeg, when TextMouth finds one, runs the audio editor's filters, and writes MP3 should the LAME built in fail to start, under useInstalledFFmpeg, on until turned off, which the same group changes. SettingsViewModel mirrors the Record window's keys (RecordingPreferences.keys) and audio editing's (AudioEditingPreferences.keys) in config.json.
    - AudioEditorPreferences: whether the editor's Apply Filter previews a filter before applying it, and whether the editor plays half a second at the cursor after each move, under audioEditorPreviewsFilters and audioEditorPlaysAfterMoves, both on until turned off, which the same group changes; they are among AudioEditingPreferences.keys, so config.json mirrors them.
    - DiagnosticLog.TraceSwitch: the hidden trace-logging switch, diagnosticTraceLogging.
    - The log writer, through LogLocation.preference: where the logs are written, logLocation ("dataDirectory" or "machine"), which it reads for every line. Storage settings change it through SettingsViewModel.logLocation, and config.json mirrors it.
    - Export, through BookExportPreferences.showInReaderToolbar: whether reader toolbars show an Export button, under showExportInReaderToolbar. Playback settings change it through SettingsViewModel.showExportInReaderToolbar, as Storage settings change logLocation, and config.json mirrors it.
    - Braille, through BraillePreferences.table (Models/BrailleTableCatalog.swift): the braille table braille files are read and written with, by its stored value (BrailleTableSource: a bundled table's file name, or "mac:" and the file name of one of this Mac's tables), under brailleTable. It reads as the stored value when that is a bundled table or names a Mac table by a bare file name (BrailleTableCatalog.storableValue(_:)), a Mac table being kept even when this Mac no longer has it, so that an import or an export refuses it by name, and as BrailleTableCatalog.defaultTableID, "en-ueb-g2.ctb", Unified English Braille contracted, otherwise; reading it never reads the Mac's folder. The Braille tab (BrailleSettingsView, whose three pop-ups, language, code, and contraction, are BrailleTablePickers, the view Export's braille options share) changes it through SettingsViewModel.brailleTable, which writes only an offered table's value and only a change; the pop-ups set a Mac table only once its check passes. Imports and braille exports read it through BraillePreferences.importTable(), which a hosted test overrides with the task-local tableForImports (see Braille files, in [Imports](imports.md)). config.json mirrors it as brailleTable, an empty or invalid name there leaving the table as it is, and a "mac:" name taken as it is. BraillePreferences.fileCode, under brailleFileCode, is the braille file characters an import reads a BRF or BRL file with, by the code's id: it reads as the stored id when that is one of BrailleFileCode.importChoices (ascii-na or ascii-eurobraille) and as ascii-na otherwise, so a stored unicode or unknown id falls back to North American Braille ASCII, since Unicode braille patterns are recognized by a file's bytes and never taken from the setting; the Braille tab's fourth pop-up changes it through SettingsViewModel.brailleFileCode, Export's braille options start a BRF from it (BraillePreferences.importFileCode(), which a hosted test overrides with the task-local fileCodeForImports), and config.json mirrors it as brailleFileCode, an empty, Unicode, or unknown id there leaving the choice as it is. A book's own code is its row's (Book.brailleFileCode), never this preference. A book's own table is its row's (Book.brailleTable), never this preference.
    - BookTextEditor: whether Edit Text has explained itself on this Mac, under editTextExplained, which stays out of config.json.
    - The library model: whether this Mac has made the one-time move of finished books to their ends, under library.finishedBooksAtEndVersion (LibraryViewModel.finishedBooksAtEndKey, P07), which stays out of config.json too (ConfigService.AppConfig.Portability.localStoreKeys, since P08).
    - FeedSettings: the seven feed settings (feedRefreshAtLaunch, feedRefreshIntervalHours, the List and download choice under feedItems and feedNewestCount, read together as itemPolicy, feedDeleteDownloadsDaysAfterPlayed, feedRefreshAlert, and feedNotifications), which the feed engine reads, the Feeds tab of Settings (FeedSettingsView) changes through SettingsViewModel.feedSettings, and config.json mirrors. The two settings the choice retired, feedKeepEntries and feedAutoDownload, stay in the store as they were, read only by the move to the choice (FeedSettings.moveToItemPolicyIfNeeded(in:); the List and download choice, under Feeds, below), and listed as retired (FeedSettings.retiredPreferenceKeys, in the config.json mirror's retiredStoreKeys). FeedItemPolicyControls (Views/Feeds/FeedItemPolicyControls.swift) draws the List and download choice here and in Feed Info: a menu-style Picker labelled "List and download", whose titles and hints come from FeedWording.itemPolicyTitle and itemPolicyHint, with the feed's ItemNoun in Feed Info, and its number through FeedNumberField, the field and stepper every feed number shares, disabled while the choice downloads by hand. FeedThresholdControl draws the two that can be off, refreshing only at launch and when asked and never deleting a played download, the second in Feed Info too, each a FeedNumberField with a checkbox for its off value.
    - TranscriptionLanguage: the language transcription uses, under transcriptionLocale (TranscriptionLanguage.preference), which reads a value that can't be a language identifier, or none, as this Mac's English. Playback settings' Transcription group (TranscriptionSettingsSection) changes it through SettingsViewModel.transcriptionLanguage, and config.json mirrors it.
    - TranscriptionPreferences.offerAfterImport: whether an import offers to transcribe each audiobook it adds, under offerTranscriptionAfterImport, off until chosen, which the same group changes through SettingsViewModel.offerTranscriptionAfterImport; config.json mirrors it.
    - LibraryViewDefinitionStore (Models/LibraryViewDefinitionStore.swift, on the main actor, an ObservableObject; LibraryViewDefinitionStore.shared is the one on the app's preferences): the Library window's views, in order, under libraryViews (LibraryViewDefinitionList.fileKey), as one JSON array of the entries config.json holds, written as data with sorted keys, so that an older TextMouth that drops the key from config.json loses nothing here. LibraryViewDefinitionStore.preference, a StoredPreference<LibraryViewDefinitionList>, reads it as the shipped list while none is saved or what is saved is not a JSON array, and reading it logs nothing. config.json mirrors it as libraryViews (ConfigService.AppConfig.libraryViews, an optional array of JSONValue, listed in ConfigService.AppConfig.Portability.mirrored and among SettingsViewModel's service preference keys), which SettingsViewModel writes after each change and applies at launch and on an outside edit, the list reading each entry on its own and logging its repairs as config.json's; an empty list or none leaves the views alone. The Library tab of Settings (LibraryViewsSettingsView) and the Library windows (ContentView and LibraryView, which observe the store) read it; the views' sorts are not in it (see [The library index](library-index.md)).
    - LeadingArticles (Models/LeadingArticles.swift): what a title's leading article does in the Library's lists, under leadingArticles (November 13, 2026), "partOfTitle", "ignoredWhenTyping", or "ignoredWhenTypingAndSorting" (the library index, above, for what each does). LeadingArticles.preference is a StoredPreference<LeadingArticles> written as the case's raw value and read through SettingsPolicy.leadingArticles, an EnumSettingRule whose default is .partOfTitle, so a missing or unsupported value reads as the default and nothing changes until the listener chooses. The Library tab's Titles section (LeadingArticlesSettingsSection, whose words are LeadingArticleWording's, in Views/Settings/LibraryViewsSettingsView.swift's tab) changes it through SettingsViewModel.leadingArticles, which writes only a change. The Library windows read it from the store each time they draw or sort (LibraryViewModel.leadingArticles, from TextMouthRuntime.current.preferences, always .partOfTitle on the iPhone), so a change reaches every open window at once. config.json mirrors it as leadingArticles (ConfigService.AppConfig.leadingArticles, a String, in Portability.mirrored): syncToConfig writes the raw value, applying the file adopts SettingsPolicy.leadingArticles.requestedValue(fromConfig:), and an empty, unsupported, or differently cased name leaves the choice as it is; SettingsViewModel lists its key among the service preference keys it observes and announces (shownServicePreferenceKeys), so the pop-up follows a change made in config.json. The hosted tests' isolation check (HostedTestIsolationSupport.textMouthKeys) lists the key among those whose value in the user's real store it compares before and after a run.
  - Who may write it: each preference's owner, through its StoredPreference definition (the key, how the value is read, and how it is written, in one place) or its @AppStorage property. SettingsViewModel also applies config.json's values, using the services' own definitions for theirs.
  - How others observe it: SettingsViewModel publishes its own changes and increments a revision that open playback bars watch. PreferenceObserver (key-value observing) tells SettingsViewModel when a service-owned key changes, so config.json follows; a change of logLocation, of showExportInReaderToolbar, of a feed setting, or of a transcription setting is also announced, so the controls showing it, and the readers' toolbars, follow it. SpeechService reads the speed, pitch, and voice from its store through SettingsPolicy.
  - Files: Models/StoredPreference.swift, Models/LogLocation.swift, Models/TranscriptionLanguage.swift, Models/TranscriptionPreferences.swift, Models/LibraryViewDefinitionStore.swift, Models/LibraryViewDefinitionList.swift, Models/LibraryViewDefinition.swift, Views/Settings/LibraryViewsSettingsView.swift, Models/LeadingArticles.swift, Models/LeadingArticleWording.swift, Views/Settings/LeadingArticlesSettingsSection.swift, Views/Transcription/TranscriptionSettingsSection.swift, Models/AudioOriginalPolicy.swift, Services/AudioEditing/AudioEditingPreferences.swift, Services/AudioEditing/AudioEditorPreferences.swift, Services/AudioEditing/FFmpeg.swift, Models/FeedSettings.swift, Models/FeedItemPolicy.swift, Views/Feeds/FeedSettingsView.swift, Views/Feeds/FeedItemPolicyControls.swift, Views/Feeds/FeedThresholdControl.swift, Services/RecordingInputDevices.swift, Services/RecordingPreferences.swift, ViewModels/BookExportModel.swift, Platform/macOS/Services/BookTextEditor.swift, ViewModels/SettingsViewModel.swift, Services/SoundEffectService.swift, Services/TextSubstitutionService.swift, Services/KeyboardShortcutManager.swift, Services/SleepTimerService.swift, Services/DataDirectoryAvailability.swift, Services/LibrarySessionLease.swift, App/TextMouthRuntime.swift.
- The config.json mirror.
  - Owner: ConfigService.shared, on the main actor. Its config property holds the file's values. While TextMouth runs, the preferences store is the source of truth and config.json follows it; at launch, the file is applied first, because it can change while TextMouth is closed.
  - Who may write it: SettingsViewModel, after each settings change (syncToConfig) and when reconciling at launch, and the Storage settings for the three choices only the file holds. A change updates ConfigService.config at once, and scheduleSave() writes the file once changes pause for 250 ms (defaultSaveDelay), so a slider dragged through its steps writes it once; flushScheduledSave() writes a waiting save when TextMouth quits (UnsavedChangesTerminationGuard.flushPendingWrites()) and before the data directory moves, and in the hosted tests as each test ends (ConfigSaveFlush). ConfigService.saveToDisk, which writes at once, first merges any outside edit not yet handled, writes nothing when the file already holds the same bytes, and reports a failed save to PersistenceFailureCenter. Every read leaves dataless files in the cloud: a config.json only in the cloud is neither applied at launch nor written over, with one line in the debug log, until a save finds it on this Mac and merges it as an outside edit. While the data directory is unavailable, ConfigService neither reads, writes, nor watches the file; dataDirectoryBecameAvailable then merges it as an outside edit, keeping each setting changed meanwhile, saves it, and watches it again.
  - How others observe it: a file-system watcher notices saved edits, tells them from TextMouth's own saves by their bytes, and publishes each once through externalEdits, which SettingsViewModel.applyConfigChanges applies. A changed dataDirectoryPath posts dataDirectoryChangeRequested, and LibraryViewModel moves the data directory, unless DataDirectoryRequest finds the folder missing on this Mac or already holding a TextMouth library, as another Mac's path in a library in the cloud would: that edit is ignored with one CONFIG_FILE line.
  - Files: Services/ConfigService.swift, ViewModels/SettingsViewModel.swift, Models/LenientFields.swift, App/UnsavedChangesTermination.swift.
- The policy table.
  - Owner: SettingsPolicy, the single table of validated preferences. Each rule (NumericSettingRule, EnumSettingRule, KeyedSettingRule, ThresholdSettingRule, WholeNumberSettingRule, or CharacterSetSettingRule) states a key, the supported range, cases, or characters, the default, and, for speed and pitch, the value meaning "not chosen yet", or, for a threshold, the value at or below which it is off: -1 for the repeated-symbol threshold, for the feeds' days, and for their retired kept entries, which only the move to the List and download choice reads, and 0 for the feeds' refresh interval. A WholeNumberSettingRule has no off value and moves anything outside its range to the nearest bound, as the List and download choice's number does (1 to 2,000).
  - Who may write it: no one while the app runs; it is a static table whose ranges match the Settings controls.
  - How others observe it: decoding config.json (LenientFields), applying it, reading @AppStorage values, services reading the store directly, and decoding per-book speed and pitch from bookInfo.json and library.json all pass values through it. ConfigService.AppConfig.Portability lists which preferences config.json mirrors, which only it holds, which stay on this Mac, and which an earlier release wrote and none writes now (retiredStoreKeys: customKeyboardBindings, and FeedSettings.retiredPreferenceKeys, feedKeepEntries and feedAutoDownload); the tests take their expectations from those lists.
  - Files: Models/SettingsPolicy.swift, Models/LenientFields.swift, Services/ConfigService.swift.
- Keyboard shortcuts (FR12): the record of the shortcuts the user edited, every action's keys in force, and the double-press time.
  - Owner: KeyboardShortcutManager (Services/KeyboardShortcutManager.swift), the one the app makes and every window shares. Its edits, a ShortcutEdits (Models/ShortcutEdits.swift), hold each action the user edited, with its keys, and nothing else: an action is edited exactly while the record holds it, even with its default keys, and an edited action without a key holds an empty list. The preferences store keeps the record under keyboardShortcutEdits (editsPreference) as JSON keyed by the actions' names, the form the whole map had, an action working in a scope the user chose holding an object, {"keys": [...], "worksIn": "<the ShortcutScope's raw value>"}, written with sorted keys so one record is always the same bytes (storedData), and read entry by entry (ShortcutEdits.reading(_:)), so an entry naming no action this build knows, or whose keys can't be read, is left out with a STORED_VALUE_REPAIRED line while the rest load, and an entry naming a scope this build doesn't know, or one its action can't be given, keeps its keys at its default scope with such a line. Each action works in a scope (ShortcutScope: .app, every window but an audio editor's; .library; .reader; .audioEditor; .recording, the Record window), its defaultScope its group's or one of its own (ShortcutAction.defaultScopesOfTheirOwn: New from Text… and the Library menu's Import Folder… and Add Feed… in Library windows, Show Sleep Timer and the Playback menu's Copy Reading Position and Search in Book in reader windows), and the user may change it among availableScopes, which offer .app, .library, and .reader to the app's actions and the File menu's commands and fix every other's. The record keeps a chosen scope beside the action's keys only when it is not the default (scopesByEditedAction, setScope(_:for:keys:), cleared by Reset to Default). The Record window's buttons are the group ShortcutAction.recordingWindowCategory, "New Recording", the window's own title (RecordingWording.windowTitle), which begins their names, as in "New Recording: Stop", where the group was "Recording Window" before REV11. The menu commands' keys, and the Record window's buttons', are actions too (ShortcutAction.keyEquivalentActions): each is one press with Command or Control that no text field edits with (KeyBinding.canBeKeyEquivalent, TextEditingKeys), and claims its double press as well (KeyClaims.forms(of:for:)). ShortcutAction.refusal(ofKeys:holding:), the one refusal rule since REV11, refuses, among the keys a change adds to those the action holds, any other key for one of them and a key past the one its item may have, or past as many as it holds, and, for any action, a key in KeyBinding.systemCommands that is not the action's own default, with a ShortcutRefusal naming the first key at fault, and never a key the action holds already: the manager passes the action's keys in force (change(_:to:)), and config.json none (ShortcutListing.refusal(for:)), asking it only of the entries the record doesn't hold (ShortcutEdits.entriesLeftOut(of:)). Its bindings, every action's keys in force, are ShortcutEdits.effectiveBindings(defaults:) over this build's ShortcutAction.defaultBindings, a static let built once, as audioEditorDefaultBindings is: the edited actions claim their keys first, then every other action takes its defaults less any key that clashes with one already claimed in a kind of window where its keys act (KeyClaims, by ShortcutWindowKind), each group in ShortcutAction.allCases order, which since FR12's branch B is the order the Shortcuts tab lists the actions in, each group whole (#1528, pinned by ShortcutsSettingsTabTests), so no key is in force for two actions in one kind of window, and a default a later build adds or changes reaches every action the user never edited and none the user did. ShortcutScope.windowKinds(of:) gives the kinds of window where an action's keys act: its scope's, and, for a key equivalent, every kind its menu item acts in (admitsMenuCommand(in:)), an audio editor's included for a File menu command working in every window, so no editor action holds a key such a command answers there (REV11). ShortcutAction.sharesAWindow(in:with:in:) is the clash rule's overlap (ShortcutEdits.key(_:of:clashesWith:of:), and the move from the saved map), which KeyClaims, ShortcutPressDispatcher.Index, and the tests' ShortcutKeyOwners (keysOnTwoActions(in:scopes:) and actions(holding:in:sharingAWindowWith:scopes:), which took the place of KeyboardShortcutManager.action(holding:in:), used by tests alone) follow too. A KeyBinding can be a double press (isDoublePress, FR12's branch B): its stroke, the key with its modifiers, pressed twice within the double-press time. A key's single press and its double press are two keys, which two actions may hold, unless one of them is a key equivalent's, whose key claims both. KeyBinding's Codable is written by hand, so a binding saved without the flag, as every binding before it was, reads as a single press, and a single press is saved exactly as before, with no flag. The double-press time is SettingsPolicy.shortcutDoublePressSeconds (0.2 to 2 seconds, 0.5 by default), one time for every shortcut: the manager reads and writes it in tenths of a second (doublePressTimePreference, through SettingsPolicy.validatedDoublePressSeconds(_:)), correcting a stored value out of range or between tenths silently, with no log line, and publishes it as doublePressTime.
  - Who may write it: the manager, every change going through the record and saved at once. updateBindings(for:to:), addBinding(_:to:), and removeBinding(_:from:) make an action the user's through ShortcutEdits.setKeys(_:for:), which takes each of its keys from every other edited action that shares a kind of window with it (sharesAWindow(in:with:in:)), those keeping their other keys and staying edited; keys that leave an unedited action as it is change nothing, and a key the action can't take changes nothing and comes back as a ShortcutRefusal (ShortcutAction.refusal(ofKeys:holding:)). setScope(_:for:), from the tab's Works in, makes the action edited at its keys in force in the scope chosen, taking them from the actions whose scopes now overlap. resetToDefault(_:) takes one action out of the record (Reset to Default), and resetToDefaults() empties it (Reset to Defaults). The tab's Reset to Defaults asks first, then KeyboardShortcutsSettingsView.resetEveryShortcut(_:announce:) resets and announces ShortcutsSettingsWording.resetDone once the alert has closed (VoiceOverAnnouncer.announceAfterSheetCloses); the Sound Effects tab's, which asks nothing, runs SoundEffectsSettingsView.resetEverySound(_:announce:), which announces SoundEffectsSettingsWording.resetDone at once. At the first launch whose store holds no record, SettingsViewModel's applyFileAtLaunch calls moveSavedShortcutsIfNeeded(in:fileListings:) before it applies config.json. It reads, once, the whole map every earlier release saved under customKeyboardBindings, with config.json's lists in the old form, and makes the record (ShortcutEdits.migrating): an action takes the file's keys where they differ from the map's, an edit made while TextMouth was closed; an action whose keys are its default, today's or a former one (ShortcutAction.formerDefaultBindings: Move Book Up's and Move Book Down's Control-Option arrows before March 22, 2026, and Next Bookmark's Shift-Command-B before March 24), whole or less the keys other actions whose default scopes overlap its own hold, counts as unedited; and a key two edited actions then hold goes to the one the file edited, or, where the file edited both or neither, to the first in allCases order. It logs SHORTCUT_EDITS_MOVED with the actions edited, writes the record, and returns true, so applyFileAtLaunch leaves the file's shortcuts out of what that launch applies and the launch's own save writes config.json in the new form; nothing writes customKeyboardBindings again, so it stays as a copy to go back to. A config.json already in the new form, holding an entry that follows the defaults, moves nothing: an empty record is written and the file is applied over it. config.json's entries (SettingsPolicy.keyboardShortcuts, whose KeyedSettingRule reads an action's name in any letter case through ShortcutAction.named(_:), the exact spelling winning over another, and a name ending in an ellipsis read with three periods or none; a former name, as the Record window's buttons' "Recording Window: …" or the bookmark command's "Add Bookmark" (its case is still addBookmark, its name Toggle Bookmark), is read as its action's, here and in the stored record (ShortcutAction.formerNames, through named(_:) and exactlyNamed(_:), which ShortcutEdits.reading(_:) uses), and only the names in force are written) are ShortcutListing values (Models/KeyboardShortcut.swift): a list, an edited action's keys; an object (.object(keys:worksIn:)), an edited action's keys and the scope it works in, written with ShortcutScope.title and read by ShortcutScope.named(_:), its field names in any letter case (ShortcutJSONKey), and "keys" also as one shortcut written as text; or text beginning with "default", an action following the defaults, whose other words are never read, naming a Library or reader default after it ("default in reader windows: …", ShortcutScope.isSaidAsADefault); any other text is one shortcut. Each shortcut is written as KeyBinding.configText and read back by KeyBinding(configText:), which takes "twice" after a shortcut, or "double" before it, in any letter case and with or without spaces, as a double press, and a key by its name in KeyBinding.keyNames, such as pageDown or f5, or by its own character. applyConfigChanges puts them in place through KeyboardShortcutManager.adopt(_:in:) (ShortcutEdits.adopting(_:)): a list makes its action the user's in its default scope, an object in the scope it names, and "default" takes it out of the record, keys and scope; a file in the old form, which holds no entry in the record's form (no object and no text beginning with "default": ShortcutListing.isInTheRecordsForm), as a hand-written file of only lists does not, is read as the move reads it (listingsLeavingOutDefaults(of:skipping:)): a list whose keys are a default of its action by the move's own rule (ShortcutEdits.keysAreADefault, which steps 2 and 3 of migrating share, so the two cannot differ: today's default or a former one, whole or less the keys other actions' lists in the file hold, compared as sets) is left out and edits nothing, so an action edited in the app keeps its edit, an unedited one keeps following the defaults, and only a list that differs from every default makes its action the user's; in a file with any entry in the record's form, a list equal to its action's default still makes the action the user's, so an edited action set back to its default keys stays the user's; an entry ShortcutEdits.entriesLeftOut(of:) names (a scope its action can't have, or keys it refuses) is left out with a STORED_VALUE_REPAIRED line and adopt(_:in:) returns true, as it does when it left an old-form file's list out as a default (one trace line counts them, naming no key), so the file is saved again in the new form, which a second reading changes nothing in; and a key two edited actions then hold goes to the one whose entry changed the record, or, where both or neither did, to the first in allCases order (resolvingSharedKeys(favoring:)), with a STORED_VALUE_REPAIRED line naming the key and both actions; after either, applyConfigChanges saves config.json again (syncToConfig), so the file shows the keys in force. The double-press time is set by the Shortcuts tab's stepper (setDoublePressTime(_:)) and by config.json's shortcutDoublePressSeconds, which ConfigService reads moved into range and to the nearest tenth, logging the repair, and applyConfigChanges adopts through doublePressTimePreference, a file without it leaving the time alone; a change of either in the store reaches the manager through its PreferenceObserver.
  - How others observe it: the manager publishes once for each change of the record (take(_:)), a change another writer makes in the store included, such as applying config.json (PreferenceObserver), and once for each change of the double-press time, and key presses go by both at once (key presses, under Windows, below). syncToConfig lists every action in config.json (ShortcutEdits.listings(defaults:)): an edited action as the list of its keys in force, or, when it works in a scope the user chose, an object of them and the scope's ShortcutScope.title, and every other as "default: " and its keys in force, or "default: none", with "default in Library windows: " or "default in reader windows: " where ShortcutScope.isSaidAsADefault; it writes shortcutDoublePressSeconds beside them. The Shortcuts tab (KeyboardShortcutsSettingsView and ShortcutBindingRow, in Views/Settings/KeyboardShortcutsSettingsView.swift) shows "Edited" and Reset to Default on the row of an action isEdited(_:) names, Reset to Default as a button and as an accessibility action of the row, and its words are ShortcutsSettingsWording's, pinned by ShortcutsSettingsTabTests: the row's VoiceOver label (rowLabel(for:keys:isEdited:defaultsHeldElsewhere:worksIn:), which says where the action works when that is Library or reader windows or other than its default, and, for an unedited action that goes without a default key, which action has it, ShortcutsSettingsWording.defaultsHeldElsewhere(_:), from the manager's defaultKeysHeldElsewhere(for:), as the row shows it too); its keys in words through KeyBinding.accessibleDisplayString, from the one table of named keys, KeyBinding.keyNames (KeyName: the key as a binding holds it, its words, what the screen shows, config.json's name, and the key code of a key matched by its code), which holds the nine keys matched by their codes (Space, Tab, Return, Delete, Escape, and the arrows), every AppKit function key, held as its private-use character but named in words (Forward Delete, Home, End, Page Up, Page Down, the F keys, and the rest), the keypad's Enter, and the punctuation marks, named in words and shown as themselves, any other key being its character, a letter in capitals, and a double press ending in " twice"; the announcement of a key recorded, with every action that lost a key to it (actions(thatLostKeysSince:besides:)); and that of a reset, with the keys the action has then and, when the reset changed it, where it works (resetAnnouncement(for:keys:worksIn:)). ShortcutBindingRow adds a Works in Picker on each row whose action has more than one scope available, bound to the manager's scope(of:) and setScope(_:for:) and announced by scopeChanged(_:to:takenFrom:). A key from the private-use area that no name says can no longer be recorded or read (KeyBinding.isUnnamedPrivateUseCharacter(_:)). The tab opens with DoublePressTimeStepper (setDoublePressTime(_:), its value spoken through CountWording.secondsToTheTenth(_:), as the Miscellaneous tab's gesture time window is) and Try a Double Press (tryDoublePress(report:), over a DoublePressTrial, in Services/ShortcutPressDispatcher.swift, which takes the next two presses for five seconds as no shortcuts and reports a DoublePressTrial.Outcome). A key's button records through ShortcutRecorderEventHandler, whose local key monitor hands each press to a ShortcutRecording: a single press once the double-press time passes, a second press of the same key within it as a double press, another key ending the wait with the first recorded as a single press, a held key's repeats ignored, and Escape cancelling; for a key equivalent's row it takes the first press at once (takesDoublePresses false). DoublePressTrial and ShortcutRecording measure two presses through one TwoPresses, and Try a Double Press keeps its last outcome as text under the button (trialStatus, from the manager's lastDoublePressTrialOutcome, kept until TextMouth quits), and one more line of text under it says why a letter shortcut does nothing in a Library window (ShortcutsSettingsWording.letterNavigationNote, pinned by ShortcutsSettingsTabTests; the rule is under Key presses in [Windows](windows.md)). recordingStarted(by:) and recordingStopped(by:) tell the manager, which holds the recorders weakly and acts on no key while one records. Make Double Press and Make Single Press (ShortcutsSettingsWording.pressChange(for:)) are each key button's accessibility action and context menu item, but a key equivalent's, whose row holds one key. A key recorded is announced through ShortcutsSettingsWording.recorded(_:for:takenFrom:nowWaitsBefore:), which adds nowWaits(_:before:) when the manager's waitingAction(for:in:) newly names an action the key's single press waits before. An audio editor window's model reads the keys in force for its buttons' hints through bindingsPreference, a read-only StoredShortcutBindings over the record's key, says them in the same words (AudioEditorWording.shortcutSentence(_:)), and redraws as the record changes. The Record window does the same for its buttons (RecordingWindowView, through StoredKeyEquivalents): each hint ends with the button's key in force, in those words (RecordingWording.recordHint(device:key:), pauseHint(key:), resumeHint(key:), and stopHint(key:)), or with nothing while the button has no key, where it once named the default keys whatever was set. The Bookmarks menu (App/MenuCommands.swift) titles each of its items from its ShortcutAction raw value, so the menu, the Shortcuts tab, and config.json cannot name a command differently.
