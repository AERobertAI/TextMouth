# Audio edits

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- The edit history (FR04): an edited audiobook's audioEdits/edits.json, and a recording's original take until its first edit.
  - Owner: the package. edits.json (AudioEditHistory, in layout AudioEditHistory.currentVersion, 1) is a record, pretty-printed with sorted keys and ISO 8601 dates: the book's own original policy (policyOverride; none follows the global setting), and one AudioEditList for each audio file edited, named by its path inside the package. A list is the file's version control: its edits in order (AudioEditEntry: an identity, when it was made, and an AudioEdit, whose times are seconds on the audio as the edits before it left it), a cursor (how many are applied; the rest were undone and can be redone until a new edit discards them), renderedCursor (how many the book's file holds as last rendered), when it was last rendered, its original (AudioOriginal: its file, and when the audio was last edited from it), or when the policy deleted it, and the editor's markers (AudioEditMarker: an identity, a time on the audio as the applied edits leave it, and a name), written only when there are any, so a list without them is written as before; an earlier TextMouth reads such a list and drops the markers when it next writes it. While an original is kept the edits apply to it, so every edit can be undone; without one they apply to the file as last rendered, and undo stops there (undoLimit). The folder also holds originals, the originals of imported books' files, each at its file's own path, and takes, the takes of punch-ins and of audio inserted (AudioEdit.insert(at:with:), stored as "insert": a paste, or a recording made with nothing selected), as Apple Lossless when that loses nothing (AudioEditPackage).
  - Who may write it: only AudioEditHistoryStore, whose update reads, changes, and writes a history under one lock for the whole process, so an editing session, a render, and the original policy's sweep never write over one another, and then deletes the takes no edit can use any more. A recording's take stays recorded in its origin record, origin.json, as the Record window saved it, until the history holds more than it: the write that adds an edit, a marker, or a policy of the book's own, writes edits.json and strikes the take from origin.json, so exactly one record describes it. A history that can't be used is preserved beside itself (SavedFile.preserveUnusable, AUDIO_EDITS_FILE), and one of a later layout is left alone; neither is written over, and an editing session starts over only when asked to (startingOver).
  - A podcast episode's chapters beside a book of one file (podcastChapters.json) are set aside when edits are saved (0.4.3):
    - LibraryViewModel.setAsidePodcastChapters(of:in:) moves the file to the hidden .podcastChapters.unedited.json (TextMouthPaths.podcastChaptersSetAsideFileName) when the save applies at least one edit, and the content analysis of that save does not read the chapters. A PODCAST_CHAPTERS_SET_ASIDE line says so, and a PODCAST_CHAPTERS_LEFT line says a move that failed, the save going on.
    - restorePodcastChapters(of:in:) moves it back when a save applies no edit, so the original audio the chapters were timed to is back, and the analysis reads them (PODCAST_CHAPTERS_RESTORED). Chapters already in their place, as a new download's, are left, and the set-aside file with them.
    - AudioEditHistoryStore.update discards it (AudioEditPackage.discardSetAsidePodcastChapters, PODCAST_CHAPTERS_DISCARDED) when a history starts over after an unusable one, since the audio an undo of every edit reaches is no longer the one the chapters fit. The discard runs after the new history is written, so a failed write tries again.
    - It goes with its episode (it is not in staysWithoutTheFile, so FeedItemPackage.removeWhatTheFileMade and whole-package removal take it), and is never taken for content (FileImportService.isPackageContentName). It stays when the policy deletes the original (at most 1 MB). A history file deleted outside TextMouth reads as empty and not unusable, so no discard happens (a follow-up).
  - How others observe it: AudioEditHistoryStore.read never downloads: a history, or a recording's origin record, only in the cloud is reported as such (Lookup.inCloud, AudioEditError.historyInCloud): an edit or a save is refused until it is on this Mac, and a sweep leaves the book for later. A path a history records is used only while it stays inside the package (AudioEditPackage.url(of:in:)), however edits.json was edited. FileImportService.isPackageContentName passes over the folder by its one name.
  - Files: Models/AudioEdit.swift, Models/AudioEditList.swift, Services/AudioEditing/AudioEditHistoryStore.swift, Services/AudioEditing/AudioEditPackage.swift, Services/AudioEditing/AudioEditError.swift, Models/BookOrigin.swift, Services/FileImportService+Packages.swift.
- From the list to sound: previewing, saving, and exporting edited audio.
  - Owner: values made from the list, off the main thread. AudioEditTimeline is the edited audio laid out in whole sample frames at the rate of the audio the edits start from, so every edit lands on the same sample however often it is applied; it applies the edits that only rearrange sound itself, and its chapter markers follow the sound. A filter's or a gain change's stretch goes through an AudioEditProcessing: AudioFilterProcessor renders the stretch to float PCM, runs its chain on the engine chosen when the session or the save began (AudioFilterEngine: TextMouth's own filters through AudioFilterRunner, or the installed ffmpeg as a child process), and keeps the result in this Mac's Audio Edits folder (AudioEditScratch) under a digest of everything that decides it, so undo, redo, and a later render read it back; whatever writes there makes the book's folder again first (AudioEditScratch.make), since a save removes it while an editor edits on, and macOS may empty the Caches folder. A stretch of the edited audio whose file macOS removed is made again when next needed (AudioEditSession.restorePurgedStretches, before an edit, a preview, a stretch copied or cut, and an export): callers at once share one rebuild, one made for a list that changed meanwhile is not taken, and of two renders of one stretch at once, the result the first moved into place stands (AudioFilterProcessor). AudioEditComposition makes a timeline an AVMutableComposition, the preview, sample-exact; AudioEditRenderer writes it with AVAssetReader and AVAssetWriter in one pass, writing decoded audio no further than the edits' length, so a compressed take that ends them adds none of its last packet's padding, and MP3 with the LAME built in: the composition is decoded to floats and handed to MP3Encoder buffer by buffer (AudioEditRenderer.renderMP3, along an MP3Route), or, should LAME fail to start, rendered to float PCM and encoded by an installed ffmpeg (FFmpeg.encodeMP3). The AVAssetWriter path and LAME's share the reader and the loop that cuts decoded audio at the edits' end (makeReader, drain).
  - Who may write it: AudioEditSession, on the main actor, the edit session the editor window's model works through (the editor window, below), which changes the list only through the history store, off the main thread, checking each edit against the audio first (AudioEditError.invalidEdit, a sentence saying why), and holds a use of its book while it is open; and LibraryViewModel.saveAudioEdits, which refuses a book open in a reader and runs AudioEditBookRender as storage work (StorageWork.audioEditing) under a use of the book. Under the history's lock, an imported file never rendered into has its original kept first, a clone, unless the policy keeps none; the edits are rendered into a hidden file beside the book's file, in its own format where TextMouth can write it (AudioRenderFormat.inPlace), read back and checked for length, and put in the file's place in one step, or under a new name, the old file then deleted only once the book's record names the new one (LibraryPersistenceService.writePendingBookInfoNow); under the lock again, the list notes what the file holds. The book's audio is then analyzed afresh (BookContentAnalysisService.analyzeAudio), and its row, record, and index saved. Its bookmarks and saved reading position follow the sound (AudioEditPlaces.follow): the session keeps the route from the file as last saved to the audio edited now (AudioEditSession.savedFileRoute, an AudioEditorTimeMap.Route: each edit, undo, and redo a crossing with the audio's lengths around it, an undo of the newest crossing taking it back), works it out from the list as it opens, and knows none when the file holds edits the list no longer has; saveAudioEdits reads the chapters as the reader lays them over the file before the render (BookContentAnalysisService.load), and moves each place through that layout, along the route, and through the new one, as a time on the whole file in a book of one file, or on its track in a book of several, where only the saved track's places move. A moved position is dated at the save, so it wins over older copies of itself; without a route, nothing moves, and an AUDIO_EDITS_SAVED line says why. Everything here works without a window.
  - How others observe it: the book's row and record take its new file, fingerprint, length, chapters, and index, with an AUDIO_EDITS_SAVED line; the reading text kept for it is dropped, and a transcript made of the old audio no longer matches its fingerprints, so it is stale. AudioEditSession.export writes the edits as they stand, saved or not, to a new file in an AudioExportFormat, MP3 among them without ffmpeg, leaving the book's file alone.
  - Files: Models/AudioEditTimeline.swift, Models/AudioFilterChain.swift, Models/AudioBuiltInFilter.swift, Models/AudioEditWording.swift, Models/AudioEditPlaces.swift, Services/AudioEditing/AudioEditComposition.swift, Services/AudioEditing/AudioEditRenderer.swift, Services/AudioEditing/AudioEditRenderer+MP3.swift, Services/AudioEditing/AudioEditBookRender.swift, Services/AudioEditing/AudioFilterProcessor.swift, Services/AudioEditing/AudioFilterRunner.swift, Services/AudioEditing/FFmpeg.swift, Services/AudioEditing/AudioExportFormat.swift, ViewModels/AudioEditSession.swift, ViewModels/AudioEditorTimeMap.swift, ViewModels/LibraryViewModel+AudioEditing.swift.
- An MP3 file TextMouth writes (FR04): an MP3 book's save, or an export.
  - Owner: MP3Encoder, one for each file: LAME 3.100's encoder at a constant bit rate (MP3EncoderSettings: an MP3 book's own, or 64 kbit/s a channel for speech, LAME taking the nearest the sample rate allows), quality 2, mono or joint stereo. The file starts with MP3Tag's ID3v2.3 tag: the title (TIT2) and author (TPE1) in UTF-16; one top-level table of contents (CTOC) listing a chapter frame (CHAP) for each chapter marker, at most 255 (maximumChapters), since AVFoundation reads only a top-level table and a table counts its entries in one byte, the 255th then running to the end; and the iTunes gapless comment, iTunSMPB (MP3GaplessInfo), which AVFoundation honours, written at a fixed width first and again in place once finish() knows the numbers. LAME's own Info tag goes in the frame LAME leaves for it, when that frame has room. An encoder that doesn't finish removes its file.
  - Who may write it: AudioEditRenderer.renderMP3, for an MP3 book's save and for an export.
  - How others observe it: as any MP3, through AudioEditBase, AudioBookParser, and AudioMediaProbe.
  - The library: LAME 3.100 in Vendor/lame, built by project.yml as the static library target LAME (libmp3lame.a), optimized for size, its warnings hidden, DEBUG undefined, and linked without -ObjC (requiresObjCLinking: false). Swift imports it as the LAME module (Vendor/lame/include/module.modulemap), in MP3Encoder alone. README.md's Third-party code is its notice.
  - Files: Services/MP3/MP3Encoder.swift, Services/MP3/MP3Tag.swift, Services/AudioEditing/AudioEditRenderer+MP3.swift, Vendor/lame, project.yml.
- The originals, and the original policy.
  - Owner: AudioOriginalPolicy: keep, delete (edits then change the book's audio in place), or delete a number of days after the last edit, held globally in the preferences store under the names it had when only recordings kept an original, recordingOriginalPolicy and recordingOriginalDays (SettingsPolicy's rules: delete after 1 day until changed, from 1 to 365 days), and mirrored in config.json. A book's own policy, in its edit history or, for a recording never edited, beside its take in origin.json, wins. An original is a recording's take, original-take.caf, which a recording saved under delete never keeps, or the copy of an imported file kept as its edits are first rendered.
  - Who may write it: Storage settings' Audio Editing group (AudioEditingSettingsSection, whose AudioEditingSettingsModel follows the store through PreferenceObserver) and config.json, for the global policy; LibraryViewModel.setAudioOriginalPolicy(_:forBook:), for a book's own, which the editor's Audio Info calls (AudioEditSession.setPolicyOverride(_:)). Only AudioOriginalSweep deletes an original: at launch (startLibrary), after each recording or edit is saved, and after a book's own policy changes (sweepAudioOriginalsInBackground), off the main thread as storage work, and only when the policy says its time is up, the book's file holds exactly the applied edits (AudioEditList.canForgetOriginal), and AudioEditActivity says the book is neither open in a reader (mirrored from LibraryViewModel.openBookIDs) nor being edited or rendered. It asks under the history's lock, which a render takes only once its use has begun, so a render never loses the original it reads.
  - How others observe it: the list notes when its original was deleted, and undo stops at the audio as last rendered. A sweep never downloads: a package whose history is only in the cloud waits for a later sweep, on this Mac or another, deleting an original reads none of it, and a history it can't read is left alone. It writes AUDIO_ORIGINALS_SWEPT, and AUDIO_ORIGINAL_REMOVAL_FAILED for an original the next sweep tries again.
  - Files: Models/AudioOriginalPolicy.swift, Services/AudioEditing/AudioOriginalSweep.swift, Services/AudioEditing/AudioEditActivity.swift, Services/AudioEditing/AudioEditingPreferences.swift, ViewModels/LibraryViewModel+AudioEditing.swift, ViewModels/LibraryViewModel+Recording.swift, ViewModels/LibraryViewModel.swift, Views/Settings/AudioEditingSettingsSection.swift, Views/Settings/StorageSettingsView.swift.
- The filter presets.
  - Owner: AudioFilterPresetLibrary, on the main actor: the presets the editor offers (AudioFilterPreset: an identity, a name, and a chain in ffmpeg's syntax), kept in audio-filters.json in the data directory (TextMouthPaths.audioFiltersFile), beside substitutions.json. The twelve premade presets (AudioFilterPresetLibrary.standard), each with an identity made from its name, stand in, unsaved, while there is no file.
  - Who may write it: add, update, remove, move, and resetToDefaults, each saving the file whole. It is read and written as substitutions.json is: never read or written over while only in the cloud, the premade presets standing in and a save waiting; a file that can't be used is preserved beside itself; and one that arrives from another Mac while the premade presets stand in takes their place, the change made meanwhile refused (AudioFilterPresetError.fileArrived). The editor's Apply Filter (AudioEditorFilterSheet) and Storage settings' Filter Presets… (AudioFilterPresetsView) each make one, reading the file as they open.
  - How others observe it: the editor's filter chains; AUDIO_FILTERS_FILE lines tell of each wait and preserved copy.
  - Files: Services/AudioEditing/AudioFilterPresets.swift, Views/AudioEditor/AudioEditorFilterSheet.swift, Views/Settings/AudioFilterPresetsView.swift.
- The editor window (FR04): one audio file of a book, open for editing.
  - Owner: AudioEditorModel, on the main actor, one for each window, over one AudioEditSession, which it changes only through the session. It holds the cursor and the selection; the markers (AudioEditMarker), which follow the sound through edits and undo (AudioEditorTimeMap), come back from the file's edit list as the window opens, and are kept there after every change (AudioEditSession.keepMarkers: written off the main thread one at a time, a newer request taking the place of one waiting, and a save waiting first for those asked before it), Revert to Original deleting them; the audio a Cut or Copy keeps for Paste (AudioEditorClip: up to ten minutes, rendered losslessly by AudioEditSession.renderStretch(_:to:) into the window's own folder in this Mac's Audio Editor Clips, which AudioEditCaches.newClipFolder() names, and kept in the package as a take once pasted); the punch-in under way (AudioEditorPunchIn); and the levels and pauses (AudioEditorLevels: a level for every hundredth of a second, and a pause wherever they stay at least 0.4 seconds below 15 dB above the quietest tenth, kept between -60 and -30 dBFS), measured from the preview after each edit on a thread of its own (AudioEditorLevels.Reading, bridged to its task with a cancellation handler that only raises a flag, since a reader may not be cancelled while it is read), one measurement at a time, a newer one waiting for the older, cancelled one to stop. It plays through AudioEditorPlayback (AVAudioEditorPlayer, an AVPlayer over the session's composition, every seek exact, touching neither Now Playing nor the media keys), and records punch-ins through RecordingService with the Record window's capture backend and microphone choice (AudioEditorRecorder), after a count-in. Its sentences are AudioEditorWording's. Its views are AudioEditorView; its sheets, one at a time (AudioEditorSheet: a question with one field, the markers and pauses, Apply Filter, the progress of a save or an export, Export, and Audio Info); and AudioEditorWaveform, hidden from accessibility.
  - Who may write it: the window's commands, pressed as a button, a shortcut, or a VoiceOver action, which all reach AudioEditorModel.perform(_:); while a punch-in records, only Stop, Play / Pause, Punch In, Clear Selection, and Where Am I? act. AudioEditorLauncher opens the window, from the Book menu (editBookAudio) or a row's LibraryAudioCommand.editAudio(_:): it refuses a book that isn't an audiobook in a package of its own, or whose manifest plays sections (AudioEditorTracks.sections); asks which track of a book of several; closes the book's reader (closeReaderForAudioEditing), waiting up to three seconds for it; and opens the session, asking first when a history that can't be read would be started over. AudioEditorWindowController.shared keeps one window for each book, brings an open one forward, asks Save, Discard, or Cancel before a window closes over edits not saved, keeps it open while work is under way or a punch-in records, and opens the book's reader again once the window closes, when the launcher closed it. As TextMouth quits, the app delegate asks it after a library move (holdQuit): an editor still working or recording holds the quit, its window brought forward to say so; otherwise each editor with edits not saved is asked about in turn, by its book's title, in an alert over every window, each answer carried out as closing carries it out (carryOut), the markers still waiting are written, and one request to quit again goes through. Audio Info gives the book an original policy of its own (AudioEditSession.setPolicyOverride(_:), through LibraryViewModel.setAudioOriginalPolicy(_:forBook:)).
  - Keys: the Audio Editor group of ShortcutAction works in a scope of its own (ShortcutScope.audioEditor, its defaultScope), so its keys may be the reader's. KeyboardShortcutManager matches a press only against the actions whose scopes reach the key window's kind (windowKind(ofKeyWindow:)): the editor's alone in an editor window, none in a sheet over one, and elsewhere those of every scope that reaches that kind of window; a key moved in Settings or config.json leaves only the actions whose scopes overlap its own (KeyClaims). In an editor window a press with Shift matches only a binding with Shift, since none of the editor's actions takes Shift along (ShortcutAction.actionsTakingShiftAlong), so a Shift-R the user gave Release Media Controls never reaches the editor's R, Punch In. An editor key posts audioEditorShortcut with the action and the window it was pressed in, and only that window's model acts (WindowCommandRouting).
  - The Edit menu: AppKit's own, so a text field anywhere keeps its Undo Typing, its Cut, and the rest. An editor window's delegate, the editors' controller, gives the window its editor's stand-in undo manager (windowWillReturnUndoManager, AudioEditorUndoManager), whose titles and availability are the editor's Undo and Redo buttons' and which NSWindow's own undo: and redo: validate and call, and answers cut:, copy:, paste:, and selectAll: (NSMenuItemValidation) only while the editor's window is itself the key window, never in a sheet over it. Each sends the editor's command as its shortcut does (AudioEditorEditMenu.send, posting audioEditorShortcut), taken through WindowCommandRouting.
  - What it added to the session: AudioEditSession.insert(takeAt:at:using:), for a paste and for a recording made with nothing selected; makePreview(applying:), which Apply Filter's Preview plays; renderStretch(_:to:), for a clip; and saveFormat(), the format a save writes, for Audio Info and a save's first sentence.
  - The sheets: AudioEditorModel+Filters.swift's applyWouldPreview(_:on:) says whether Apply previews first (the setting on, and the preset not yet previewed on that target since Apply Filter opened, per previewedFilter, which openFilters clears); chooseApply reads it, and applyHint(for:on:) turns it into Apply's hint (AudioEditorWording.applyPreviewsFirstHint or applyHint), which AudioEditorFilterSheet gives the button. AudioEditorFilterSheet takes its AudioFilterPresetLibrary (the saved presets, unless a test gives others) and asks VoiceOver's start for Cancel when it lists no preset. In AudioEditorMarkersSheet.swift the marker, chapter marker, and pause rows share row(_:subject:commands:) over RowCommand (a title, whether it is destructive, and an action): one container labelled with the row's words, the drawn text hidden from VoiceOver, a button per command labelled rowButton(title, subject), the subjects being markerSubject, chapterSubject, and pauseSubject, and the commands as the row's actions by title; AudioEditorRenameRow is a row's rename state (the field, where the keyboard goes as the row opens, Save Name as the default button, and Cancel as the cancel button), and closeShortcut(whileRenaming:) gives Close the cancel key only while no name is typed. Tests: AudioEditorWindowTests hosts the prompt sheets and the rename row, puts the keyboard in the field (windowWithKeyboardInField), and sends keys through window.sendEvent (press), which includes AppKit's key-equivalent pass, proving that one Return runs a command once; testARowsWordsAreReadOnce skips without an assistive app.
  - How others observe it: the window shows and speaks its state: Position, Status, and Last message, which repeats the last announcement made through VoiceOverAnnouncer for a braille display. AUDIO_EDITOR lines tell of a book the editor couldn't open, of a save or an export it couldn't finish, and of markers it couldn't keep, naming an error by its kind, never by a path. The editor's two settings are AudioEditorPreferences (preferences, below). Its tests play through FakeAudioEditorPlayer, which only notes what it was asked, and record through FakeCaptureBackend, so they make no sound and need no microphone.
