# Transcription

Part of [TextMouth's architecture](../../../ARCHITECTURE.md).

- A transcription in progress (FR05).
  - Owner: TranscriptionService.shared, an actor that runs one transcription at a time: a second is refused with TranscriptionError.busy, naming the book under way. It checks the language and its model before reading any audio (TranscriptionEngine.prepare(locale:)), plans the book's audio off the main thread (TranscriptionPlan: each file once, in the order the book plays them, measured, refusing a book with a file only in the cloud before measuring any), and transcribes file by file, fingerprinting each file just before it is read, through a TranscriptionEngine. SystemTranscriptionEngine uses SpeechAnalyzer's SpeechTranscriber on macOS 26: each file handed over as an AVAudioFile, only final results asked for, with their time ranges and confidence, and the model kept loaded between files (lingering); a file refused because its language isn't reserved is tried once more after reserving it, which downloads nothing. On an earlier system it refuses, saying that transcription needs macOS 26. TranscriptSentenceBuilder turns the results into sentences with the system's sentence tokenizer. A language nobody chose, the system's English, gives way to US English when the recognizer doesn't support it (TranscriptionLanguage.languagesToTry(in:)); a chosen one never does.
  - Who may write it: the caller of transcribe(_:language:progress:), which returns the Transcript and writes nothing, or of transcribeAndSave(_:language:currentBook:progress:), which saves it (transcripts, above) into the book as the library holds it once the transcription is done, while the service still counts as busy. Cancelling the task that awaits either stops the recognizer within a moment (cancelAndFinishNow) and throws TranscriptionError.cancelled, and nothing is written before the transcript is saved. In the app the caller is TranscriptionJobCenter (below), which calls transcribe and saves the transcript itself; transcribeAndSave serves the fixture tests (TranscriptionFixtureTests).
  - How others observe it: TranscriptionProgress (the file's index and the count of files, the seconds done and in all, and the time elapsed) arrives on no particular thread as each file starts and as results arrive. TranscriptionAvailability answers what this Mac offers without downloading a model or reserving a language: whether the system can transcribe, the supported and installed languages, and each language's model status, deciding that a model is installed by the recognizer's own list. Every TranscriptionError has a sentence ready to show and speak. The language is TranscriptionLanguage.preference (transcriptionLocale), mirrored in config.json.
  - Files: Services/TranscriptionService.swift, Services/TranscriptionEngine.swift, Services/TranscriptionAvailability.swift, Services/TranscriptSentenceBuilder.swift, Models/TranscriptionLanguage.swift.
- The transcription the app runs, for every window (FR05).
  - Owner: TranscriptionJobCenter.shared, on the main actor: current, the TranscriptionJob under way (the book, its title, when it began, and its progress as last shown), and lastEnding, how the latest one ended (finished, with its word count and seconds; cancelled; or failed, with why).
  - Who may write it: start(_:language:library:window:), from a Transcribe Audio sheet, which starts nothing while a transcription is under way. It transcribes off the main thread (TranscriptionService.transcribe), then, with the book as the library holds it by then, pauses the book's Edit Text session (pauseTextEdit, BookTextEditor.pauseEditing(of:): a check running finishes, an edit saved but not yet checked is taken, and the session ends) and saves the transcript through TranscriptStore.install on a global queue (OffMainWork.runThrowing); an install that fails begins the session again (resumeTextEdit, BookTextEditor.resumeEditing(of:)), so the listener's later saves are still taken. cancel(), from the sheet's Cancel and from AppDelegate.applicationWillTerminate, stops it, leaving the book as it was unless its transcript was being saved already.
  - How others observe it: the sheets showing it observe current, which takes the progress at most every 250 milliseconds (progressInterval), and at once when it moves to another file or is done, and lastEnding. VoiceOver hears the start, each quarter it passes (TranscriptionWording.milestones), and the end, from the window that started it, and the debug log records its start, with the language, and its end, with the words found and the seconds taken, or why it failed (TranscriptionLog), naming the book by its title and never quoting a word heard. Once the transcript is saved, TranscribedBooks records the book, and LibraryBookUpdates.transcriptReplaced brings the text to its readers.
  - Files: ViewModels/TranscriptionJobCenter.swift, Models/TranscriptionWording.swift, Platform/macOS/App/AppDelegate.swift.
- The Transcribe Audio sheet, and each window's transcription dialogs.
  - Owner: TranscriptionPresenter, one for each Library window (LibraryTranscriptionSupport) and each reader (kept by ReaderView, which hands it to ReaderBookCommandsSupport and to SpeechRefusalReportPresenter, whose report waits while one of its dialogs shows, isShowingAny), which holds the Transcribe Audio sheet showing, the Clean Up sheet showing (a transcript's cleanup, below), the confirmation before Delete Transcript (TranscriptDeletionRequest), and a notice saying why a command did nothing, all shown by TranscriptionPresentation; and TranscriptionSheetModel, one for each sheet, in its phase (checking, unavailable, ready, transcribing, or failed): the book, the language resolved as TranscriptionService resolves it (TranscriptionLanguage.languagesToTry(in:)), its model's status, a download under way, the book's transcript as transcript.json holds it (existing, with when the listener last edited it and last cleaned it up; or unreadableExisting, .inCloud or .laterVersion for one a later TextMouth wrote, so that hasTranscript, true for any of them, decides the names Retranscribe Audio… and Retranscribe), whether the book's text, content.md, is only in iCloud (isTextInCloud, asked of TranscriptionSheetServices.isTextInCloud, one lstat that reads nothing), and another book being transcribed. isBookInCloud joins a transcript only in iCloud to a text only in iCloud: either makes canTranscribe false, before any audio is transcribed, and focusTarget Cancel. TranscriptionSheetServices is everything the sheet asks of the system and the app, which tests replace.
  - Who may write it: the commands. A library row offers LibraryAudioCommand.commands(for:isTranscribed:) in its context menu and as its VoiceOver actions: Edit Audio… first, for one audiobook in a package of its own alone, never a feed's episode (LibraryAudioCommand.isAudioEditable(_:), which AudioEditorLauncher asks too), which TranscriptionPresenter.perform(_:library:window:) hands to AudioEditorLauncher (the editor window, above); then, for one transcribed audiobook alone, Retranscribe Audio… (LibraryAudioCommand.retranscribe, which opens the sheet as transcribe does for one book), Clean Up Transcript (Experimental)…, and Delete Transcript…, a feed's episode included, since a transcript is the listener's own work (October 23, 2026; isTranscriptCleanable is gone), or else Transcribe Audio… when one of the books it acts on is an audiobook in a package of its own, which several books get even with a transcribed one among them; the reader enables the Book menu's Clean Up for every transcribed audiobook (canCleanUpBookTranscript). The Book menu's Transcribe Audio… (named Retranscribe Audio… by TranscriptionWording.transcribeCommandTitle(hasTranscript:) while canDeleteBookTranscript says the key reader's book has a transcript), Clean Up Transcript (Experimental)…, and Delete Transcript… post transcribeBookAudio, cleanUpBookTranscript, and deleteBookTranscript to the reader that takes them. An offer accepted after an import opens the sheet too (import questions, above). TranscriptionRequest refuses several books, or a book that isn't an audiobook, with a sentence. A model downloads only when Download is pressed, through TranscriptionModelInstalling (SystemTranscriptionModelInstaller, the asset inventory's installation request on macOS 26), and closing the sheet stops a download.
  - How others observe it: TranscriptionSheet shows the model, moving VoiceOver and keyboard focus to its first control (focusTarget, through focusing(_:first:_:)), then announcing its lines once for each phase; TranscriptionWording words everything shown and spoken. The ready sheet's lines are its heading (retranscribeSheetTitle once hasTranscript), the audio, the estimate, the language, and noticeLines, in order: existingLine (or the later-version line), editedLine, cleanedLine, bookInCloudLine (the transcript's sentence before the text's), busyLine, and the download's notice; transcribeTitle and transcribeHint follow hasTranscript. A deletion the user confirms pauses the book's Edit Text session (pauseEditing(of:)), runs TranscriptStore.delete(for:) on a global queue, begins the session again if the deletion fails (resumeEditing(of:)), then records the book as untranscribed and tells its readers (LibraryBookUpdates.transcriptReplaced, with no text); while the book is being transcribed, a notice says to cancel first.
  - Files: ViewModels/TranscriptionSheetModel.swift, Views/Transcription/TranscriptionSheet.swift, Views/Transcription/TranscriptionPresentation.swift, Services/TranscriptionModelInstaller.swift, Models/LibraryAudioCommand.swift, Models/TranscriptionWording.swift, Views/Reader/ReaderBookCommands.swift, Views/Library/LibraryView.swift, Views/Library/LibrarySubviews.swift, App/MenuCommands.swift.
- Which audiobooks are transcribed.
  - Owner: TranscribedBooks.shared, on the main actor: the books with a transcript (bookIDs), and the one being transcribed (transcribingBookID). A book's record notes its transcript in its package alone, never in library.json, so a library row can't carry it.
  - Who may write it: refresh(_:), which looks for each audiobook's transcript.json off the main thread, reading and downloading nothing, as a Library window appears, as the number of books changes, and as TextMouth becomes active (LibraryTranscriptionSupport), when another Mac sharing the library may have transcribed a book; record(_:isTranscribed:), when a transcription saves a transcript or a deletion removes one, which wins over a look begun before it; and setTranscribing(_:), from TranscriptionJobCenter.
  - How others observe it: each row's note (TranscriptionRowNote, Transcribed or Transcribing, drawn after the cloud notes by RowNoteBadge and spoken in the row's label), its transcription commands (Retranscribe Audio… in place of Transcribe Audio… for a transcribed one: LibraryAudioCommand.commands(for:isTranscribed:)), and whether Edit Text is offered for an audiobook, a feed's episode included (BookTextEditor.canEditText(of:)), in its row and in the Book menu.
  - Files: ViewModels/TranscribedBooks.swift, Views/Transcription/TranscriptionPresentation.swift, Views/Library/LibrarySubviews.swift, Views/Library/BookCloudNote.swift, Platform/macOS/Services/BookTextEditor.swift.
- A transcript's cleanup (FR05, experimental): the Clean Up sheet, and what it would change.
  - Owner: TranscriptCleanupSheetModel, one for each Clean Up sheet, on the main actor, in its phase (checking, unavailable, ready, working, or failed): the rules in use and where they came from (TranscriptCleanupRuleFile.Lookup: transcript cleanup rules, below), what they would change (TranscriptCleanup.Preview: the transcript as read, the transcript cleaned, each rule's corrections with up to three examples, and how many sentences changed), and whether Undo Cleanup is offered: the transcript records a cleanup and transcript.json.before-cleanup is there, by a look that never downloads. TranscriptCleanup applies the rules in order to each sentence: a whole-word rule matches whole words, in any case and with any apostrophe, keeping the punctuation around them and a possessive after them, and any other rule matches inside words too, the replacement taking the case of what it replaces; it reads and writes nothing. A sentence a rule would leave with no text keeps its text, and none of its corrections is counted or listed, since the install would refuse a sentence with no text after Apply was offered. TranscriptCleanupServices is everything the sheet asks of the app, which tests replace.
  - Who may write it: TranscriptionPresenter.cleanUp(_:library:window:), for a row's command or the Book menu's, opens one sheet at a time in a window, for any transcribed audiobook, a feed's episode included. The model reads the rules and the transcript off the main thread as the sheet opens (load(), on the book as the library holds it then, since a sheet left open while the book moved would look where it used to be), and again whenever TextMouth becomes active (refresh()), as after the user edits the rules, VoiceOver hearing the sheet's lines again when anything changed. Apply and Undo Cleanup refuse while the book is being transcribed (TranscriptionJobCenter.current), pause the book's Edit Text session (pauseTextEdit: BookTextEditor.pauseEditing(of:)), run TranscriptStore.cleanUp or undoCleanup (transcripts, above) off the main thread (OffMainWork.runThrowing), on the book as the library holds it then, and begin the session again (resumeTextEdit) when they fail.
  - How others observe it: TranscriptCleanupSheet shows the model, moving VoiceOver and keyboard focus to Apply when the rules change something and to Cancel otherwise (focusTarget, through focusing(_:first:_:)), then announcing its lines once for each phase; TranscriptCleanupWording words everything shown and spoken, and a feed episode's sheet has one more line after the experimental line (feedNoteLine: TranscriptionWording.feedEpisodeTranscriptNote). A cleanup or an undo saved reaches the book's readers through LibraryBookUpdates.transcriptReplaced, and VoiceOver hears it from the sheet's window.
  - Files: ViewModels/TranscriptCleanupSheetModel.swift, Views/Transcription/TranscriptCleanupSheet.swift, Views/Transcription/TranscriptCleanupCommands.swift, Views/Transcription/TranscriptionPresentation.swift, Services/TranscriptCleanup.swift, Services/TranscriptCleanupStore.swift, Models/TranscriptCleanupWording.swift, Models/LibraryAudioCommand.swift.
- Transcript cleanup rules (FR05, experimental): TextMouth's own, and the user's copy.
  - Owner: TranscriptCleanupRuleFile. TextMouth's own rules are transcript-cleanup.json in the app's bundle (Resources/transcript-cleanup.json: format 1, version 1 of 2026-10-04, its rule list empty, with an about and two worked examples that nothing applies); the user's copy, transcript-cleanup.json at the data directory's root beside substitutions.json (TextMouthPaths.transcriptCleanupRulesFile), is used instead whenever it is there and usable. TranscriptCleanupRuleSet holds a file's format, version, date, and rules (TranscriptCleanupRule: pattern, replacement, wholeWord, evidence, and note), and refuses a file, naming the first field at fault and never quoting a rule, whose format isn't 1, whose version is below 1, whose date isn't a day written as 2026-10-04, or one of whose rules has an empty pattern or replacement, a pattern without a letter or figure, a whole-word pattern with a word of punctuation alone, negative evidence, or a replacement its own pattern matches, which every cleanup would change again.
  - Who may write it: the user, in their own editor. TextMouth writes the copy only through prepareUserCopy, for the Clean Up sheet's Edit Rules…, as storage work, and only when there is none: it writes its own file there exactly, staged beside it and moved into place, which fails rather than replace a copy that arrived meanwhile. A copy that is there, usable or not, or only in the cloud, is never written over, and nothing is written while the data directory is unavailable.
  - How others observe it: load(userCopyAt:reader:builtIn:), off the main thread, as the sheet opens and as TextMouth becomes active, reads the copy as substitutions.json is read (SavedFile, with dataless files left in the cloud): a copy only in the cloud is asked of the sync service, and one that can't be read or used is preserved beside itself (SavedFile.preserveUnusable), TextMouth's own rules standing in for either while the sheet says why; while the data directory is unavailable, nothing is read and TextMouth's own rules are used. A TRANSCRIPT_CLEANUP_RULES line tells of each wait and preserved copy, and the sheet says when TextMouth's own rules have a newer version than the copy. A cleaned transcript records the rules' version, date, and source. TextMouth's own rules were derived with TranscriptAccuracy from speech whose text is known (TRANSCRIPT-CLEANUP-RESEARCH-2026-10-04.md), which the opt-in TranscriptAccuracyMeasurementTests measure again.
  - Files: Services/TranscriptCleanupRuleFile.swift, Models/TranscriptCleanupRules.swift, Resources/transcript-cleanup.json, Services/TranscriptAccuracy.swift, TextMouthProductionTests/TranscriptAccuracyMeasurementTests.swift.
- A transcript that comes from a file (FMT23, FMT25; 0.4.2): a WebVTT or SubRip file, or a podcast's own transcript, instead of recognition.
  - Owner: TranscriptStore keeps it as it keeps recognition's, in transcript.json, recording where it came from in a TranscriptSource (Models/Transcript.swift): an Origin of attached, imported, or podcast, the file's name, a TimedTextFormat, and, since 0.4.3, formats: the raw values of every format the files were of, each once, in the order they were read, when files of more than one format were read (01.vtt beside one track and 02.srt beside another), else nil, as in every transcript an earlier TextMouth wrote, which cannot read the field and keeps format as the first file's. knownFormats is nil when a later TextMouth wrote a format this one does not know, and an imported transcript is then worded "Attached from files when the book was imported, on …"; for imported files of several formats it says "Attached from WebVTT and SubRip files when the book was imported, on …". An origin or a format a later TextMouth wrote, which this one can't name, is read as unknown and worded "Attached on …". The files are read by TimedTextReader (WebVTT, SubRip) and PodcastTranscriptReader (Podcasting 2.0 JSON, whose one-word segments of one speaker gather into sentences of at most 60 words, split by a gap of a second), through TimedTextMarkup. TimedTextLimits: 20 MB for a file from this Mac, 5 MB for a podcast transcript, 1 MB for chapters, 250,000 cues, and 5 seconds past the audio's end for a last cue. Since 0.4.3 it also holds the limits on a cue:
    - maximumCueMilliseconds, 1,000 hours (3,600,000,000 ms): the latest a WebVTT or SubRip cue may end. A book's whole transcript is one file timed on the book's timeline, so its times run past the 100 hours a single audio file may last (Transcript.maximumMilliseconds). OutsideTranscript cuts them into the book's files afterwards, each time counted from its file's start.
    - maximumCueCharacters, 10,000: the most a cue's text keeps, and maximumVoiceNameCharacters, 100, for a speaker's name. Reading stops at the cap, so a 5 MB cue costs the cap and not the file, and a Podcasting 2.0 reader gathers no words past it. TimedText.finishedText(of:characterLimit:) cuts the text back to where a sentence ends in its second half, failing that to the last space, failing that at the limit; a cut that falls between two words on a sentence's end goes back nothing. TimedTextCue.isCutShort marks the cue, and TimedTextDocument counts them (cutCueCount) for the Attach announcement (TranscriptionWording.attached(…cut:)), "1 timed passage was too long and was cut short."
    - OutsideTranscript.withinTheLimitOfAFile(_:) holds a sentence to one audio file's 100 hours: nil for a sentence that starts past Transcript.maximumMilliseconds, and one that runs past it ends there, its words kept only when each still ends inside it. Span.place calls it for Attach (transcript(bookTimeline:)), and transcript(sentencesByFile:), a track's own file at import, filters through it, so a file longer than 100 hours is left out past its hundredth hour and not refused whole as unusable. The Attach announcement adds the sentences left out to the passages it could not read. At import the cues left out are not counted or logged.
    OutsideTranscript turns the cues into a Transcript.
  - Who may write it: TranscriptPairing at import, which finds a .vtt, else .srt, named as a track is (besideFile for a single file, inFolder for tracks, a ZIP, or a playlist), tried in lower and upper case, and never fails an import: a file that can't be used becomes ImportedBook.notice (TranscriptionWording.transcriptNotAttached, transcriptsNotAttached). Attach Transcript…, in ReaderBookCommands, through TranscriptAttachments (ViewModels/TranscriptAttachments.swift), a main-actor record of the books being attached to, with a deinit safety net, that both Attach and Transcribe Audio… ask (canAttach, canTranscribe). It reads only a plain file, so a named pipe can't hang it. FeedEpisodeExtras, for a podcast (see Feeds).
  - A transcript file chosen with its audio (0.4.3): TranscriptPairing.droppingTranscriptsChosenWithTheirAudio(_:) takes out of the items to import each .vtt or .srt that a chosen audio file finds as its transcript (besideFile), since the audio's import attaches it. Both loops over user-chosen items call it, importAndOpenFiles (Finder, the Dock, and the router's openFiles) and importFiles (Open Book…). A transcript file chosen alone, or beside audio that does not find it, stays in the list and is refused by FileImportError.unsupportedFormat, whose sentence for a .vtt or .srt is "Unsupported file format: .vtt. A .vtt file is a transcript, not a book. To use it, import its audio, open the book, and choose Attach Transcript… from the Book menu." A transcript chosen with an audio file whose import is then skipped is dropped silently, and is untested. The iOS PhoneImportCopier calls the same filtered functions, and whether its copies sit beside each other for the lookup was not checked.
  - Transcribe Audio… waits (0.4.3): TranscriptionPresenter.transcribe shows the notice TranscriptionWording.transcribeWhileAttaching only for a request of one book that TranscriptAttachments.shared.bookIDs holds. A request for several books gets the sheet that says transcription works on one book at a time, whatever is being attached.
  - Installing: TranscriptInstallation takes the transcript into the book's storage work. Its parameter givingWayToAnUntouchedPodcastTranscript is judged inside that work, by holdsUntouchedPodcastTranscript(in:), so an edit made between the check and the install is kept.
  - Replace Existing: DuplicateReplacement.transcriptOutcome(replacing:with:) returns asBefore, keepsExisting, or broughtReplacesExisting. It reads the old transcript's provenance without its sentences (TranscriptStore.provenance), downloading nothing. The old transcript gives way only when it has a source and isTouched is false, and the question (ImportDecisionWording.replacingKeepsSentence) and the replacement both ask the same function, so they never disagree. The library row follows what the new package holds.
  - How others observe it: Book Information's Transcript detail (TranscriptionWording.bookInfoLine, bookInfoSpokenDetail) and the Transcribe Audio sheet's existing line (outsideTranscript). The book's text is written from the transcript the first time the book opens (TranscriptTextLoader), and TranscribedBooks lists it at once.
  - Files: Services/OutsideTranscript.swift, Services/TranscriptPairing.swift, Services/TranscriptInstallation.swift, Parsers/TimedTextReader.swift, Parsers/PodcastTranscriptReader.swift, Parsers/TimedTextMarkup.swift (TimedTextMarkup.Lines, which keeps the voice of a cue that changes voice partway as lastVoice), Models/TimedText.swift, Models/Transcript.swift, ViewModels/TranscriptAttachments.swift.
