# Third-party code

Part of [TextMouth's documentation](../../README.md).

TextMouth itself is under the MIT License, in LICENSE at the top of the repository. It builds in two libraries by other authors, follows a third author's code closely in its Kindle reader, and uses three Swift packages. The licence files of all three ship inside the app, in Contents/Resources/Licenses, one folder for each: Licenses/LAME holds COPYING and LICENSE, Licenses/liblouis holds COPYING.LESSER and README, and Licenses/foliate-js holds LICENSE. project.yml copies them from Vendor, never into the repository a second time, so each stays its author's own text, and BundledLicenseTests checks that all five reach the built app.

- LAME 3.100's MP3 encoder, "LAME Ain't an MP3 Encoder", by Mike Cheng, Mark Taylor, and The LAME Project (https://lame.sourceforge.io; LAME's own notes give www.mp3dev.org), under the GNU Library General Public License, version 2, whose text is Vendor/lame/COPYING. TextMouth writes MP3 with it (see [Editing audio](../user/editing-audio.md)).
  - Vendor/lame holds the encoder's files of LAME's release tarball, lame-3.100.tar.gz (SHA-256 ddfe36cab873794038ae2c1210557ad34857a4b6bdc515785d1da9e175b1da1e), each unchanged: COPYING, LICENSE, README, include/lame.h, and the sources and headers in libmp3lame that LAME's own Makefile builds its library from, less the decoder's glue and the x86 assembly. TextMouth adds two files of its own: config.h, in place of the one LAME's configure script writes, and include/module.modulemap, through which Swift imports lame.h.
  - project.yml builds it as a static library the app links, so `make build` builds the app from that source, and the app can be rebuilt with a changed LAME: replace those files from another release, compare config.h with the one its configure script writes, and run `make check`.
  - The licence asks that a copy of the app given to anyone else carry this notice and the licence's text, which the app carries in Licenses/LAME (above).
- liblouis 3.39.0, the open-source braille translator and back-translator, by John J. Boyer, its founder, and the liblouis contributors (Vendor/liblouis/AUTHORS), under the GNU Lesser General Public License, version 2.1 or any later version, whose text is Vendor/liblouis/COPYING.LESSER. TextMouth reads and writes braille with it (see [What TextMouth reads](../user/what-textmouth-reads.md) and [Exporting books](../user/exporting-books.md)).
  - Vendor/liblouis holds, unchanged, these files of liblouis's release tarball, liblouis-3.39.0.tar.gz (https://github.com/liblouis/liblouis/releases/tag/v3.39.0; SHA-256 629fa8cb0dfd9ad457c5bf47a42f0953b673e62c8ad6b1d03ddc4e2bd20008f1, the digest GitHub publishes for it, which project.yml records): COPYING.LESSER, README, AUTHORS, NEWS, the sources and headers in liblouis/ that its Makefile.am builds the library from (liblouis.h.in among them), and in tables/ the four English tables built into TextMouth, with the 13 files they include, 17 in all. The four are Unified English uncontracted (en-ueb-g1.ctb) and contracted (en-ueb-g2.ctb) braille, and English uncontracted (en-us-g1.ctb) and contracted (en_US.tbl) braille as used in the U.S. It also holds, unchanged from that tarball, three display tables that only the tests read: en-us-brf.dis (North American Braille ASCII), de-eurobrl6.dis (Eurobraille, six-dot, lowercase, SBS Zürich 2009), and de-eurobrl6u.dis (the same code in capitals), 20 files in all; BrailleFileCodeTests compares TextMouth's own tables with them, 64 cells of 64. No translation table includes them, so the helper never loads them; they are bundled with the tables folder (Vendor/liblouis/tables, into Contents/Resources/liblouis/tables), 6,793 bytes.
  - TextMouth adds two files of its own: config.h, in place of the one liblouis's configure script writes, and include/liblouis.h, the release's liblouis.h.in with its one substitution made, 32-bit wide characters (UCS-4), so every Unicode character and braille cell fits. Nothing of the release was run (not configure, make, or any script), and nothing from liblouis's tools/ folder, which is GPL 3, is used.
  - project.yml builds it as a static library that only the TextMouthBraille helper links, so liblouis runs only in that helper and never in TextMouth's own process: it is C that reads untrusted braille and text, it has had memory-safety bugs, and it is not thread-safe (see Braille files, in [Imports](../architecture/state/imports.md)). Static linking suits the licence, as it does LAME's: the app's whole source, liblouis's included, is in the repository, so `make build` builds the app from that source, and the app can be rebuilt with a changed liblouis.
  - To update it, replace those files from a newer release, make include/liblouis.h again from its liblouis.h.in, compare config.h with what the new sources read, and run `make check`.
  - The licence asks that a copy of the app given to anyone else carry the licence's text, which the app carries in Licenses/liblouis (above).
  - TextMouth also reads, but does not include, VoiceOver's own liblouis tables on the Mac (liblouis 3.34.0 on macOS 26.3, which the Mac records as LGPL 2.1). It reads them where they are on the system volume and never copies, changes, or downloads them, so the app does not grow (see the Braille tab, under [Settings](../user/settings.md)).
- foliate-js's mobi.js, the Kindle reader of the book renderer behind the Foliate e-book reader, by John Factotum (https://github.com/johnfactotum/foliate-js), under the MIT License, whose text is Vendor/foliate-js/LICENSE ("Copyright (c) 2022 John Factotum"; SHA-256 b621ffc351fe263bc9b09dd0bc1c9332fda9c462a3904c1e4f0b4d3236b9c28c, the file as of foliate-js commit c986ba68, unchanged). TextMouth's Kindle reader (see [What TextMouth reads](../user/what-textmouth-reads.md)) is Swift of its own, but three of its files follow mobi.js closely, as read on November 4, 2026 (mobi.js last changed in commit 9a676796, April 3, 2026), and each says so: MOBIText.swift (PalmDOC decompression and the records' trailing entries), MOBIIndex.swift (the NCX index), and MOBIHuffman.swift (HUFF/CDIC decompression, whose format leaves little room for another way). MOBIHeaders.swift and MOBIPalmDatabase.swift take only the header fields' offsets from it.
  - No JavaScript is in the app or the repository: Vendor/foliate-js holds the licence alone.
  - The licence asks that its notice go with every copy of the code or of a substantial part of it, which the app carries in Licenses/foliate-js (above).
- The Swift packages ZIPFoundation, SwiftSoup, and swift-markdown, with the swift-cmark it builds on, each under its own licence; The make check gate, above, says how their versions are pinned.
