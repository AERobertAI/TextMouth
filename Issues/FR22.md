## Description

**FR22 — Menu and context menu items name their keyboard shortcut.** Requested November 15, 2026: "if a command in the context menu or menu bars have a keyboard shortcut add them to the item like "Move Up (cmd+shift+up) with proper formatting for verius shortcuts", then "have agents try researching / planning that nicity". Today a menu item shows and speaks its key only when the key is the item's key equivalent (FR12's branch D, `ShortcutAction.keyEquivalentActions`: Copy Reading Position, Search in Book, and a few more); every other command's keys, Move Book Up's Shift-Command-Up Arrow among them, are taken by `KeyboardShortcutManager`'s event monitor, so the menu bar names no key for them, and no context menu or VoiceOver row action names any. Wanted: every menu bar item, context menu item, and VoiceOver action whose command has a key in force names it, in the Shortcuts tab's words (`KeyBinding.displayString`, a double press "twice"), following the user's edits at once. The user then made it plain: "I was just saying put it as part of the name as saying what other apps do, if they show up on the right visually thats fine VO reads them. I mostly notice the missing shortcuts in the the apps menus like Library and Book in the menu bar and the context menu, actually some seem to have one attached like add feed but the move book up/down and others do not and I haven't seen any in the context menu". So the keys go where the Mac shows them, at the right of each item, which VoiceOver reads; Add Feed shows its key because it is a key equivalent. Research and plan first: how a menu item can show a key in force without the menu acting on it (the shortcut manager keeps acting, and a focused text field keeps Shift-Command-Up), for instance through `NSMenuDelegate`'s `menuHasKeyEquivalent(_:for:target:action:)`; the same in context menus; and a command with two keys or a double press.
