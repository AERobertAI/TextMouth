## Description

**The goal (the user, November 20, 2026).** "Try squeezing all of the languages into 25 MB": the Mac app with English, Spanish, and FR36's nine languages within 25 MB. It is 21.9 MB with two languages, and the nine add about 4.3 MB.

**What was measured.**
- Spanish's files are 466,619 bytes: 357,649 of `.strings` (151,774 bytes of English keys, 182,615 of Spanish values, and the quotes) and 108,970 of `.stringsdict` for its 321 plural strings. Every language repeats the English keys.
- One binary `.loctable` holding every language, as Finder ships its InfoPlist strings, stores the keys once but writes non-ASCII values in UTF-16: for ten Spanish-like languages it came out only 39 KB smaller than ten text files, so it is not worth its risk.
- The two apps use the same keys (the Mac 4,186, the iPhone 4,183), so a separate set of strings for each app saves nothing.
- The Mac executable is 18.1 MB, already built with `-Osize`, whole-module optimization, dead-code stripping, and a full strip.

**What to try.**
1. Write each `.strings` in whichever form is smaller, text or binary: binary stores Chinese, Japanese, and Korean in two bytes a character, not three.
2. Leave out an entry whose value equals its key, since Foundation then returns the key: about 45 a language.
3. Write a plural string whose forms are all the same (every plural string in a language with only `other`) as a plain `.strings` entry.
4. Report what else would close the gap, with its cost: FFmpeg's `--enable-small` (589,520 bytes, measured 6 to 27% slower decoding), and the deeper English cut toward 150 KB, which every language repeats.

Every change is proved by `verify_packs.py`'s probe (each key and plural at 0, 1, 2, 5, 21, 100, and 1,000,000, through `Bundle`, Xcode's files against the compact ones) and by `LanguagePackTests` on both apps.
