## Description

**DR34 — Import BRF, BRL and PEF braille files on the iPhone.** From the ChatGPT docs review of November 16, 2026 (suggested priority P1; list items 12, 13 and 14, one entry because one blocker serves all three). Docs: `docs/user/formats-list.md`, "DAISY and braille books": "BRF braille file (.brf): ... iPhone: no", and the same for BRL (.brl) and PEF (.pef). Code: the readers (`Parsers/BrailleFileReader.swift`, `BrailleBookReader.swift`, `BraillePageAnalyzer.swift`) are shared and format-only; the translation to print goes through liblouis, which on the Mac runs in the separate `TextMouthBraille` helper program under a watchdog (`Services/BrailleTranslator.swift`). **What keeps the iPhone from it today:** iOS lets an app start no other program, so there is no helper and no watchdog that can kill a hang; liblouis would have to run inside the app, one call at a time (it is not thread-safe), with the tables (the four English ones are 332 KB) in the app bundle. The iOS port research says liblouis passes clang's checks for iOS but was never linked there (`research/IOS-PORT-RESEARCH-2026-11-03.md`). Phase 0 made every helper-program conversion throw `IOSUnavailable` ("not available on iPhone yet"). Platform: iPhone (a parity gap; the Mac reads all three). Related: DR07, DR08, FMT22, FMT51. (question only until now: `humanQuestions/2026-11-03.md` question 7, recommended "yes, in a later phase, inside the app with limits on how much it is given at once", or braille on the Mac only if the isolation matters more; and `humanQuestions/2026-11-04.md` question 4, recommended: try iOS 26's `AXBrailleTranslator` first, which would replace liblouis at no cost if it gives an app its English tables, and use liblouis as on the Mac if it fails; the user's answer there: "libraries compiled into the IOS app but not Mac OS is fine though". Phase 0 was built on question 7's recommendation: a refusal sentence.)

The iPhone reads BRF, BRL, and PEF as the Mac does: TextMouth's translation around liblouis (TextMouthBraille/TextMouthBrailleLibrary.c, tmb_translate) runs in the app behind BrailleTranslator's #if os(iOS), through InProcessEngine (one thread, a time limit on each call, a call past it abandoned at the lowest priority and every later call refused until TextMouth is closed and opened again), within the Mac's watchdog limits for a whole book. The 20 tables and liblouis's licence files are in the app; the shared braille tests run in the iPhone's unit bundle; the November 16 review's fixes 1 to 6 and its nits are in. Parity left, for issues of their own: braille export (BRF, PEF) on the iPhone; a braille table choice in iPhone Settings and Book Information's Braille Code; reading a book again in another braille file code; a Mac's own tables stay the Mac's; no crash isolation (a crash in liblouis ends the app). Open before TestFlight or the App Store: LGPL 2.1 and the App Store's terms, and an in-app notice for liblouis and LAME.
