## Description

Since the A11Y-GOTO merge (ff2025a64, November 16, 2026), Scripts/agents/tests/test_run_ios_ui_tests.py fails on main: TheUnitTestsMakeNoSoundTests finds 'ReaderViewModel' in TextMouthiOSTests/PhoneTextFieldScalingTests.swift. The test builds a stopped reader held in memory (services off, content set directly, no play, speak, or resume call) because the Go To and Search sheets take one. The rule (SOUND_PATTERN in Scripts/agents/ios_ui_tests.py) is name-based on purpose, 'a false red is the safe side'. Fix without weakening the rule for any other file: either a narrow, reasoned allowance the scanner checks (for example, ReaderViewModel built only through one named test helper that never calls play, speak, or resume, which the scanner verifies), or a test that needs no ReaderViewModel. The orchestrator's merge of A11Y-GOTO missed it: it ran the train and the Mac class, not the tools' tests.
