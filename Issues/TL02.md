## Description

Found November 16, 2026 by docspass1116 while documenting imagecache's merge. runner_module_cache.py empties ModuleCache.noindex, SDKStatCaches.noindex, ExplicitPrecompiledModules, and PrecompiledHeaders when the runner's toolchain stamp differs, but not the folder where Xcode 26 keeps Swift's explicitly built modules, so a stale Swift module from another toolchain could still fail a build, and the retry would fail the same way. Fix: find that folder in an Xcode 26 derived-data folder (a cached one from GitHub, or this Mac's), add it to the emptied folders if it holds toolchain-made modules, and test it.
