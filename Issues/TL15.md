## Description

**What happens.** Every translator comment passed as `String(localized:comment:)`'s `comment:` is compiled into the app, though nothing reads it at runtime. Foundation declares `comment: Swift.StaticString? = nil` on a public initializer that is not inlinable, so the compiler must keep each comment as a constant string. Measured on 0.5.4's Release builds (November 19, 2026): the catalog's 4,502 distinct comment lines total 571,941 bytes; the Mac executable holds 4,398 of them (561,407 bytes), and the iPhone executable 1,982 (267,775 bytes; the iPhone leaves out the Mac-only screens). That is more than half of the Mac executable's 1,005,888-byte growth from 0.5.3 to 0.5.4, and three times the 177,883 bytes of English interface text. On the iPhone it counts at full size in an App Store download, since encrypted binaries do not compress.

**To find out first.** Whether `xcstringstool sync` (and Xcode's own sync) keeps a comment written in the catalog when the code passes none, so the comments could live in the catalog alone. If it does, a tool can move each comment into the catalog and drop it from the code, with a check that every key still has one. Otherwise, shorter comments: they are three times the text they describe.

**Done when** the apps carry no translator comment (or only short ones), every catalog key keeps a comment for translators, and `l10n.py check` and the scanner enforce it.
