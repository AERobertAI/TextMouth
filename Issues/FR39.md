## Description

The user (November 21, 2026) chose TextMouth's own lookup system over Apple's: every interface string gets a short ID; all languages ship in one compressed pack, and only the language in use is unpacked at launch; users can override any string with a JSON file in the data folder (an Export command writes the full current text to copy from); and Settings gets a language picker (default System) that switches without relaunching. The goal is the Mac app near 22 MB and the iPhone near 17 MB at 25 languages (TL19), keys with two uses get their own IDs (TL14), and every language reads exactly as today, checked string by string.

### 2026-11-21, orchestrator, 3 lines

The design merged at 7b5e7b4e5 (research/STRINGS-SYSTEM-DESIGN-2026-11-21.md); phases 1 to 3 (the engine, the pack builder, the IDs) started on Sonnet at 16:28.

For phase 10, closer to the user's wish to keep "the current used strings" as JSON in the data folder: Edit Interface Text… fills `interface_text.json`, on the person's request only, with every line of the interface language, each with its English, its note, and `base`, the pack's text when the file was written. A line counts as the person's own only when its `text` differs from its `base`, so every line left alone keeps taking each update's better wording, and a file shared by another person applies only what they changed. Lines listing only `text` (written by hand) always apply. The user may still choose the design's file of changed lines only.
