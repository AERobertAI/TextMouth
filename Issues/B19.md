## Description

**What happens.** Before any conversion, the import checks only ASF files (WMA and WMV) for copy protection (`FFmpegAudioConverter.isCopyProtected`). Other protected files reach FFmpeg and end as "damaged", which is untrue:
- an encrypted Matroska or WebM track;
- a RealMedia file with DRM.

The same happens on the Mac and the iPhone.

**Found by** review-phoneffmpeg, November 17, 2026 (finding 7).

**The fix.**
- Tell these files with the copy-protection sentence (`FFmpegAudioConverter.Failure.copyProtected`), first, as for ASF.
- Detect each from its container's own encryption fields, with no FFmpeg source copied. Matroska and WebM have ContentEncryption.
- Add a small sample of each, made in the test or committed under CC0, with a test that fails without the check.

ffmpegleft, branch formats/ffmpeg-leftovers at 342d0fc16 (train 1118-0221 PASSED: Mac 4165 tests, 31 skipped, 0 failures; iPhone 145 tests, 0 failures). An encrypted Matroska or WebM sound track is told with the copy-protection sentence, first, on both platforms, through the one check FFmpegAudioConverter.isCopyProtected. MatroskaHeader (Parsers/FFmpegContainer.swift) walks Segment, Tracks, TrackEntry, ContentEncodings, ContentEncoding, ContentEncryption (ContentEncAlgo not 0), and calls a file protected only when it has a sound track and every sound track is encrypted (a compression, an algorithm of 0, an encrypted picture alone, or a plain sound track beside an encrypted one is not). Not done: RealMedia. Its public format description names no DRM or encryption field, so a protected RealMedia file still ends as damaged; that part stays open until a source for the marker is found. Tests: samples made in the test (FFmpegImportSnifferTests, FFmpegImportConversionTests); every real mka, mkv, and webm sample is not protected.
