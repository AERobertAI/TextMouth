## Description

**What the user asked (November 19, 2026, 23:58, question 15 of humanQuestions/2026-11-18.md):** "Yes please work to compact the spanish and english down ... if a minifier step for the packs would be helpful try that if the wordier format is easier to edit." The catalog (`Localizable.xcstrings`) stays the wordy, editable source; a build step writes each language's compiled files compact before signing.

**Measured on 0.5.4's Release builds**, identical in the Mac and iPhone apps: `en.lproj/Localizable.stringsdict` 158,097 bytes (English needs only its plurals); `es.lproj/Localizable.strings` 458,435 and `Localizable.stringsdict` 193,097, together 651,532. Written compact (UTF-8 text `"key"="value";` for `.strings`, a binary property list for `.stringsdict`), English would be 42,341 bytes and Spanish 478,226 (27% less). Probed on this Mac: `plutil -convert json` reads the compact text back exactly (quotes, backslashes, line breaks, accents), and a `Bundle` reads both compact files, Spanish's `many` plural included ("1.000.000 de libros"). Only 45 Spanish entries equal their English key (about 1 KB), so every entry is kept.

**Done when** both apps ship every `.strings` compact and every `.stringsdict` binary, the step checks its own output with Apple's parser and fails the build rather than ship a changed lookup, a hosted test on each app compares every key's lookup in every language with the catalog, and `make check` reports each language file's size and fails on one left in XML. Item 5 of TL14.
