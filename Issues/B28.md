## Description

TextMouth tells a copy-protected Kindle book and a copy-protected audio file apart from a damaged one, but it never reads an EPUB's META-INF/encryption.xml, so an EPUB whose content documents are encrypted (Adobe ADEPT, Readium LCP, Apple FairPlay) is not recognized as copy-protected: its chapters simply fail to parse, and the book is refused as if it were damaged, or read with chapters missing.

Found by passwordresearch (research/PASSWORD-PROTECTED-BOOKS-2026-11-24.md); the orchestrator checked on November 24, 2026 that no code reads encryption.xml. The refusal's wording for such a book was not observed.

Fix: read encryption.xml; when it names a content document (not only fonts, whose obfuscation is not DRM and needs nothing), refuse the book as copy-protected, in the same words as a copy-protected Kindle book. DRM itself stays out of scope.
