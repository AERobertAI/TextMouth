## Description

**What happens.** In the 0.5.3 release's remote suite (November 18, 2026, at ad9e1f4b4), `BookManifestEditTests.testAHandEditedTitleSurvivesTheFirstLaunchAndALaterManifestEditWins` failed once on GitHub's Mac runner and passed on its second try, under the suite's retry on failure. The failure, at `BookManifestEditTests.swift:1278`:

> XCTAssertEqual failed: ("Optional("Harbour Pilots, Revised")") is not equal to ("Optional("Harbour Pilots, Second Edition")") - The later manifest edit was not taken

The suite log is `build/orchestrator/nov17/remote-suite-0.5.3.log`, line 37090.

**What the test does.** A book's title is edited by hand, and a first launch keeps it. The test then saves a new manifest with "Harbour Pilots, Second Edition", and a second launch should take it. Once, it didn't.

**The likely cause, to be checked.** The second save follows the first launch's own write of that manifest within a fraction of a second. If the launch decides that a manifest changed by its modification date, or by a fingerprint taken at too coarse a resolution, the second edit can look unchanged. Find what the launch compares, and whether a real edit made that soon after TextMouth wrote the file could be missed in the app too. If it could, it is a bug, not only a flaky test.

**The fix.** Make the change test exact (content, or size and nanosecond date), or make the test's second save unmistakably later, whichever is the real cause. Then run the test many times on GitHub to show it holds.
