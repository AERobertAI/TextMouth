## Description

**The question (flakeq16, Q16).** Edit Manifest's session check and Edit Text's (`BookTextEditing.swift`, around line 949) read the file again only when its size or modification date differs from the last ones TextMouth saw. On APFS the date is exact to the nanosecond, so no save is hidden, but on a volume whose dates are coarse (HFS+ keeps 1 second, FAT 2 seconds) a save of the same size within that second would be missed until the session ended.

**What to decide.** Whether the check should read the bytes (or a hash) whenever it can't trust the date, for example on a volume whose date resolution is a second or more. Not Q16's cause; recommended as its own small change with a test that sets a coarse date.
