## Description

**What happens.** The FFmpeg session picks the first sound track marked default (`choose_stream`, `TextMouthFFmpeg/Session/session.c`, about line 439). Matroska's FlagDefault defaults to 1, so in a file whose first sound track is encrypted, beside a plain one, the session decodes the encrypted track. The import ends as damaged or noisy, though the plain track would play.

**Found by** review-ffmpegleft, November 18, 2026 (item 6, `build/orchestrator/nov17/review-ffmpegleft-report.md`), with B19's Matroska check. That check rightly calls such a file not protected, since one sound track is plain.

**The fix.** The session skips a sound track that the Matroska walk (`MatroskaHeader`) found encrypted, and chooses among the plain ones as before. Pass the encrypted tracks' numbers to the session, or let it read the encryption itself, with one copy of the rule (DRY). Test a file with an encrypted first track and a plain second track: it imports the plain one, on both platforms.
