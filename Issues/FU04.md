## Description

**What happens.** The FFmpeg session's file opener, `tmff_open_regular_file` (`TextMouthFFmpeg/Session/session.c`), follows a symbolic link. It checks that what it opened is a regular file, but a link to one passes. That is true of the Mac's helper since FMT50, and of the iPhone's in-app run (FMT54).

**Why it is small.** Imports hand FFmpeg a staged copy, not the listener's own path.

**The fix.**
- Open with `O_NOFOLLOW`, so the opener refuses a link as its words say.
- Add a test: a link to a good file is refused, with the sentence for a file that can't be opened.

**Found by** review-phoneffmpeg, November 17, 2026 (finding 7).
