## Description

**What happens.** The repository's GitHub Actions cache is at its 10 GB limit: 18 entries, 10.39 GB, on November 18, 2026. The 12 largest are iOS build caches of 575 to 604 MiB, saved once per commit, so GitHub is already evicting the older ones. A cache the next run needs may be gone, so builds come up cold and slow, and the train's restored module caches churn (TL06).

**Found by** review-toolsmall, November 18, 2026, answering TL05's request to check the cache after the first remote suite that measures the iPhone's size. The device build's folder is inside the cached iPhone derived-data folder.

**The fix.**
- Save fewer iOS caches. For example, key them by the toolchain and the dependency lock rather than the commit, or save only from main's runs, and keep the device build's folder out of the cache.
- Measure the cache's size before and after: `gh cache list --limit 100`.
- This is a workflow change under `.github`. It is held until the user's next push, and the workflow guard must allow it.
