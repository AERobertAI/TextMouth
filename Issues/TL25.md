## Description

In 11 of 143 trains (1119-0353, 1119-0451, 1119-0514, 1121-1401, 1121-2027, 1122-1847, 1123-1126, 1123-1323, 1123-1533, 1125-1049, 1126-0023) one iPhone job lost its tests: the first boot gave up at 180 seconds (FIRST_BOOT_SECONDS) and the new device's boot at 300 (BOOT_SECONDS), both printing 'Waiting on BackBoard' (run-ios-ui-tests.py ready_simulator). Each costs a whole retrain, about 40 minutes. A guess to test first: each job downloads the iOS platform, so the first boot after it builds the runtime's dyld shared cache; starting 'xcrun simctl runtime dyld_shared_cache update' as the build begins would hide that cost. Other remedies to compare: restarting CoreSimulatorService before the second try, a longer single wait, and re-running only the lost job once the workflow's uploads carry overwrite: true (tools/fast-runs-workflow). Needs several GitHub runs to prove; after the 0.6.0 release.
