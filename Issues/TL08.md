## Description

**What happens.** `parse_errors` in `Scripts/agents/run-ios-build.py` drops every "fatal error:" line that has a file and line in front of it. A real fatal error in the iPhone build, such as `'foo.h' file not found`, is then not counted as an error. The summary ends "xcodebuild ended with status 65 and no error line", which hides the cause from the agent.

**Found by** review-trainfix, November 17, 2026 (item 7, `build/orchestrator/nov17/review-trainfix-report.md`). It is older than `tools/train-watch`, which made the module-cache errors their own case (TL06).

**The fix.**
- Count a located "fatal error:" as an error line, with its file, unless it is one of the cache errors `runner_module_cache.cache_failure` names.
- Test a missing header, and the two cache errors, with the trains' real lines.
