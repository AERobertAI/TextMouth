## Description

ZIPFoundation 0.9.20 returns no entry for an encrypted one (`Entry.init`: "We currently don't support encrypted archives", `guard !centralDirectoryStructure.isEncrypted else { return nil }`), and its iterator (`Archive.makeIterator`) ends at that nil. So every entry from the first password-protected one on is invisible: a ZIP whose entries all have a password lists nothing, and one with a protected entry part way through imports short, and neither import says a password is the reason. This covers every ZIP TextMouth opens (book packages, EPUB and the other ZIP-based formats, comic archives, audiobook folders), on both platforms.

Found by passwordresearch (research/PASSWORD-PROTECTED-BOOKS-2026-11-24.md); checked by the orchestrator in ZIPFoundation's source on November 24, 2026.

Fix before password support: read the central directory's general purpose bit 0 for every entry, and refuse a ZIP with any encrypted entry in words that name its password (and that TextMouth cannot open password-protected ZIPs yet), rather than importing it empty or short. Password support itself is the report's phase 1.
