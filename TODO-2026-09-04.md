Review emphasized data preservation, reading-content fidelity, playback state, multiple windows, and accessibility.

New fixes use production code and disposable fixtures. Dangerous deletion regressions exercise validation or isolated test storage.

The pre-existing edits in `DAISYParser.swift`, `AudioZIPClassificationTests.swift`, and `LegacyScenarioHarness.swift` were preserved and included in verification. They remain uncommitted and separate from this audit's commits.

Evidence labels below distinguish:

- **Verified:** exercised by a regression test or build experiment in this audit.
- **Confirmed:** a concrete defect follows from the current implementation; its stated trigger still needs a dedicated regression test before repair.
- **Risk:** a credible failure path requiring controlled reproduction, such as concurrent writes or system callback ordering.
- **Design:** the intended behavior needs to be settled before changing it.
- **Manual:** requires running the interface, assistive technology, or audio hardware.

## Behaviors checked and deliberately preserved

- Per-book settings override global defaults. The existing audio schema stores a multiplier in `localWPM`; the audit keeps compatibility while separating UI/runtime units.
- Duplicate detection and Keep Both are intentional. Two books with equal content hashes can be distinct library entries.
- Folder depth is limited to four. Ordinary slashes in a user-entered name become hyphens. Reserved path components and `.tmb` names cannot serve as ordinary folders.
- Trash failures must remain failures; they do not authorize a fallback to permanent deletion. Successful data-root migration intentionally retains the source as a recovery copy.
- Orphan adoption is a recovery feature. S06 concerns its interaction with explicit removal and pending writes, rather than removing recovery itself.
- There is one global sleep timer with book ownership. Pausing its owner freezes a minutes countdown; explicit cancellation is global; fade duration is captured when the timer starts. The two-boundary heading policy has existing tests and needs the P01 design decision before alteration.
- Media-control focus and active playback ownership are separate. Explicit release of headphone controls and Bluetooth-disconnect suppression are intentional.
- The reader's sliding display window and speech chunking support performance; they are not evidence that the full document was truncated.
- Return-to-position is intentionally one saved departure point. A history stack is a separate feature request.
- Plain-text heading heuristics and duplicate navigation stripping are intentional. Changes need content-preservation fixtures instead of removing heuristics indiscriminately.
- Automatic restoration of all old reader windows is explicitly disabled at launch. The app remaining open after its final window closes is deliberate macOS behavior.

The DOCX outline-level correction follows [Microsoft's OOXML outline-level documentation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.outlinelevel?view=openxml-3.0.1): level 9 carries no outline heading level. Markdown leaf handling was checked against the [official Swift Markdown visitor implementation](https://github.com/swiftlang/swift-markdown/blob/main/Sources/Markdown/Visitor/MarkupVisitor.swift).
