Evidence labels below distinguish:

- **Verified:** exercised by a regression test or build experiment in this audit.
- **Confirmed:** a concrete defect follows from the current implementation; its stated trigger still needs a dedicated regression test before repair.
- **Risk:** a credible failure path requiring controlled reproduction, such as concurrent writes or system callback ordering.
- **Design:** the intended behavior needs to be settled before changing it.
- **Manual:** requires running the interface, assistive technology, or audio hardware.

## S — Storage, persistence, and recovery

- [ ] **S01 — Recover unreadable library indexes without replacing the evidence.** P1 · Impact 5 · Difficulty 4 · Confirmed. [LibraryPersistenceService](TextMouth/Services/LibraryPersistenceService.swift) `loadFrom` returns an empty `Library` on decoding/read failure. Startup repair can subsequently save that replacement. Preserve/quarantine the failing index, report the error, and offer recovery with an explicit state. Acceptance: truncated JSON, unreadable storage, and unknown enum values leave the original bytes recoverable and do not silently reset folders/order/state.

- [ ] **S02 — Make every import commit conditional on readable content and durable metadata.** P1 · Impact 5 · Difficulty 4 · Confirmed. [FileImportService](TextMouth/Services/FileImportService.swift) has import paths that suppress analysis and `bookInfo.json` write failures, then return a successful `Book`. Original deletion can follow. Stage a package, validate its content and metadata, then publish success; clean up failed staging. Acceptance: corrupt documents/audio, full disk, and denied metadata writes preserve the source and never publish an unreadable “successful” import. F08 only addresses failures reported by the batch operation.

- [ ] **S03 — Verify legacy migration destinations before deleting source content.** P1 · Impact 5 · Difficulty 3 · Confirmed. `FileImportService.migrateBookToTMB` skips copying when a destination already exists, removes the source, and suppresses metadata/cache failures. Verify content identity and commit metadata first; retain a recovery copy on uncertainty. Acceptance: an existing different destination and a metadata-write failure both preserve the original file.

- [ ] **S04 — Coordinate imports, moves, deletion, extraction, and data-directory migration.** P1 · Impact 5 · Difficulty 5 · Risk. [Library persistence](TextMouth/Services/LibraryPersistenceService.swift), [migration](TextMouth/ViewModels/LibraryViewModel+Migration.swift), and the serial import queue use separate executors. Writers can retain old paths while other writers resolve the changing global root. Add a storage transaction/generation boundary and quiesce affected work. Acceptance: move/delete/migrate during a deliberately blocked import, cache rebuild, and debounced save; no files reappear or land under the wrong root.

- [ ] **S05 — Merge completed analysis with the latest durable book state.** P1 · Impact 4 · Difficulty 4 · Confirmed. `LibraryPersistenceService.saveContentAnalysis` merges a pending snapshot if present, otherwise uses the older `Book` passed into the parser. A newer snapshot may already have finished writing. Merge only analysis fields into the latest state, using revisions to reject stale work. Acceptance: finalize a newer bookmark/position/metadata write before releasing an older analysis result, then reload the package and verify all newer fields.

- [ ] **S06 — Keep Remove from Library Only removed across pending saves and restart.** P1 · Impact 4 · Difficulty 4 · Confirmed. [Book operations](TextMouth/ViewModels/LibraryViewModel+BookOperations.swift) suppress metadata-removal errors, while queued saves and background analysis can recreate the `bookInfo.json` used for orphan adoption. Introduce a durable exclusion/tombstone or equivalent retirement state. Acceptance: remove with a queued write, open reader, failed metadata removal, and active extraction; restart and rebuild must honor the removal while retaining the content file.

- [ ] **S07 — Detect filesystem-equivalent folder-name collisions.** P1 · Impact 4 · Difficulty 3 · Confirmed. [Library](TextMouth/Models/Library.swift) compares folder paths as case-sensitive strings, while common macOS volumes do not. `Reports` and `reports` can become separate rows sharing storage. Use volume-aware equivalence, including Unicode normalization, and handle existing collisions. Acceptance: case-sensitive and case-insensitive volumes, case-only renames, and composed/decomposed names produce distinct safe outcomes.

- [ ] **S08 — Validate the entire subtree when removing a folder and reparenting its children.** P1 · Impact 4 · Difficulty 3 · Confirmed. `Library.removeFolder(movingContentsTo:)` lacks the destination collision/depth checks used by other folder operations. Validate child-name conflicts, self/descendant destinations, and maximum depth before publication. Acceptance: duplicate child names and a subtree that would exceed four levels leave both disk and model unchanged.

- [ ] **S09 — Surface persistence and cleanup failures consistently.** P1 · Impact 4 · Difficulty 4 · Confirmed. Library/config/statistics writes, some `Book.saveBookInfo` calls, and original-file deletion report only to logs or use `try?`. Carry actionable errors to the owning view and distinguish “readable in memory” from “saved.” Acceptance: unavailable storage during edits, shutdown flush, and original deletion yields accurate status and a retry path without false success.

- [ ] **S10 — Harden migration publication against destination changes and aliases.** P2 · Impact 5 · Difficulty 4 · Risk. [DataDirectoryMigrator](TextMouth/Services/TextMouthPaths.swift) checks destination emptiness before a potentially long copy, then removes that destination at publication. Revalidate/coordinate publication and explicitly support or reject source/destination aliases. Acceptance: create a destination sentinel while copying and test an independently located source-root symlink; no newly arrived data is overwritten. F20 handles containment, not concurrent publication.

## I — Import orchestration and audio packages

- [ ] **I01 — Queue import decisions as well as file operations.** P1 · Impact 4 · Difficulty 4 · Confirmed. [Import](TextMouth/ViewModels/LibraryViewModel+Import.swift) and [duplicate handling](TextMouth/ViewModels/LibraryViewModel+Duplicates.swift) store one pending duplicate, original URL, and ZIP-folder request. Serial disk work does not wait for these decisions; later completions can replace them. Use a queued import-result state machine. Acceptance: several duplicate/ask-to-delete/multi-book ZIP imports preserve every decision, URL, and open-after-import intent.

- [ ] **I02 — Import loose DAISY packages with their dependent files.** P1 · Impact 4 · Difficulty 4 · Confirmed. Generic import copies individual files. An OPF needs its DTBook/SMIL/audio siblings; a directory package encountered inside a generic ZIP also needs one package-level traversal. Acceptance: loose OPF, NCC-based folder, and a ZIP containing multiple packaged books remain readable after the extraction/source directory disappears, with each book imported once.

- [ ] **I03 — Preserve DAISY audio that crosses files within one navigation section.** P1 · Impact 4 · Difficulty 5 · Confirmed. [DAISYAudioConverter](TextMouth/Parsers/DAISYParser+Audio.swift) builds one segment from the selected clip/file for each navigation reference. Later clips in other files are copied but can be absent from the manifest's playback sequence. Represent a logical section as multiple clips. Acceptance: one heading spanning three audio files plays every clip in order with correct navigation and duration.

- [ ] **I04 — Validate actual media duration against segment ranges.** P1 · Impact 4 · Difficulty 3 · Confirmed. [AudioBookParser](TextMouth/Parsers/AudioBookParser.swift) now rejects malformed references/ranges, but explicit positive end times are still trusted without checking the media. Verify supported decodable media, start/end bounds, and tolerances for encoder padding. Acceptance: corrupt media, a start past EOF, and an end far past EOF fail clearly; legitimate DAISY padding remains supported.

- [ ] **I05 — Bound archive and recursive-import resource use.** P2 · Impact 4 · Difficulty 4 · Risk. [FileImportService](TextMouth/Services/FileImportService.swift) has no explicit total expansion, entry-count, nesting, or cancellation budget. Confirm ZIPFoundation's current path protections separately; this audit does not assert an unverified ZIP-slip vulnerability. Acceptance: large/nested archives terminate predictably, preserve the source, clean staging, and keep the interface responsive.

- [ ] **I06 — Report partial EPUB/DAISY chapter extraction.** P1 · Impact 4 · Difficulty 3 · Confirmed. Chapter loops in [EPUBParser](TextMouth/Parsers/EPUBParser.swift), [MarkdownCacheService](TextMouth/Services/MarkdownCacheService.swift), and DAISY conversion skip missing/unreadable members. Returning the surviving chapters can look like complete success. Preserve tolerant reading where useful while surfacing omissions and preventing source deletion. Acceptance: remove the middle chapter from a fixture and obtain a precise warning/failed-import result.

- [ ] **I07 — Preserve all text in DAISY 2.02 inline fragments.** P1 · Impact 4 · Difficulty 3 · Confirmed. `DAISYParser.convertDAISY202FragmentElement` descends into only the first child of some inline containers; siblings and surrounding text can disappear. The user's pre-existing edits to this file were left intact. Acceptance: a SMIL fragment pointing to a span with text plus multiple emphasized children retains all words once, in order.

## C — Configuration and listening statistics

- [ ] **C01 — Apply configuration atomically during startup and synchronization.** P1 · Impact 4 · Difficulty 4 · Confirmed. - [ ] **C04 — Complete configuration mirroring and refresh open settings views.** P2 · Impact 2 · Difficulty 3 · Confirmed. ## Behaviors checked and deliberately preserved

- Per-book settings override global defaults. The existing audio schema stores a multiplier in `localWPM`; the audit keeps compatibility while separating UI/runtime units.
- Duplicate detection and Keep Both are intentional. Two books with equal content hashes can be distinct library entries.
- Folder depth is limited to four. Ordinary slashes in a user-entered name become hyphens. Reserved path components and `.tmb` names cannot serve as ordinary folders.
- Trash failures must remain failures; they do not authorize a fallback to permanent deletion. Successful data-root migration intentionally retains the source as a recovery copy.
- Orphan adoption is a recovery feature. S06 concerns its interaction with explicit removal and pending writes, rather than removing recovery itself.
- There is one global sleep timer with book ownership. Pausing its owner freezes a minutes countdown; explicit cancellation is global; fade duration is captured when the timer starts. The two-boundary heading policy has existing tests and needs the P01 design decision before alteration.
- Media-control focus and active playback ownership are separate. Explicit release of headphone controls and Bluetooth-disconnect suppression are intentional.
- The reader's sliding display window and speech chunking support performance; they are not evidence that the full document was truncated.
- Return-to-position is intentionally one saved departure point. A history stack is a separate feature request.
- Plain-text heading heuristics and duplicate navigation stripping are intentional. Changes need content-preservation fixtures instead of removing heuristics indiscriminately.
- Automatic restoration of all old reader windows is explicitly disabled at launch. The app remaining open after its final window closes is deliberate macOS behavior.

The DOCX outline-level correction follows [Microsoft's OOXML outline-level documentation](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.outlinelevel?view=openxml-3.0.1): level 9 carries no outline heading level. Markdown leaf handling was checked against the [official Swift Markdown visitor implementation](https://github.com/swiftlang/swift-markdown/blob/main/Sources/Markdown/Visitor/MarkupVisitor.swift).
